# API endpoints are host-wide and reached through the daemon's gateway

An **API endpoint** used to be one provider's own list of third-party connections, with at most one active, and activating it wrote that endpoint's URL, key, and model into the CLI's config ([ADR 0004](0004-api-endpoint-rewrites-cli-config.md)). Now an endpoint belongs to the host, carries one key and up to three request-format URLs, and the CLI never sees it: the daemon writes its own gateway, `http://127.0.0.1:<port>/api-endpoint-gateway`, into the CLI config, and the gateway picks the endpoint per request, swaps in the real key, translates between Anthropic Messages, OpenAI Chat, and OpenAI Responses, and moves to another endpoint that serves the same model when the current one runs out of quota. We chose this because the user's goal is to keep working through several relays without touching anything when one of them is exhausted, and the CLI can only point at one URL. The design is a TypeScript port of magpie's (MIT) gateway, not a hosted magpie binary, so it runs inside the daemon on every platform the daemon runs on and phones use it through the daemon as before.

Partly superseded by [ADR 0008](0008-gateway-reshapes-rejected-requests-and-fails-over-refusals.md): the failover point, the vendor-rewrite exceptions, the no-reshape rule and the error headers below, each marked _Superseded by ADR 0008_ where it stands. Partly superseded by [ADR 0010](0010-codex-wiring-and-gateway-caller-recognition.md) (Codex wiring, how the gateway recognises callers, the Codex table after Official) and [ADR 0012](0012-cli-config-rewrite-follows-the-cli.md) (the tier-name fallback, `ANTHROPIC_SMALL_FAST_MODEL`, an empty token for the claude.ai sign-in), marked the same way. Changed on 2026-10-19: endpoints are tried in the **Endpoint order** the user sets, not in creation order, and **Use only this format** overrides the protocol choice, each marked _Changed 2026-10-19_ where it stands. Changed on 2026-10-24: the gateway also translates to Gemini, marked _Changed 2026-10-24_.

ADR 0004's file-editing rules stay in force: owned keys only, originals recorded and restored, atomic replace, parse-or-refuse, re-read before rename, external-change detection, the WebSearch deny rule, `jsonc-parser` for `settings.json`, node-position splicing for `config.toml`, and the dedicated Codex table `osuna_api_endpoint`. This ADR replaces the rules in 0004 that say _what_ those keys hold. _Parse-or-refuse and external-change detection are narrowed by [ADR 0012](0012-cli-config-rewrite-follows-the-cli.md), the WebSearch deny rule by [ADR 0009](0009-web-search-allowed-per-endpoint.md), and the Codex table by [ADR 0010](0010-codex-wiring-and-gateway-caller-recognition.md)._

## What changes from ADR 0004

- **The written URL and token are the daemon's, not the endpoint's.** Claude gets `ANTHROPIC_BASE_URL` = the gateway and `ANTHROPIC_AUTH_TOKEN` = a per-provider random gateway token; Codex gets `base_url` = the gateway's `/v1` and `experimental_bearer_token` = the same kind of token. Pi and Oh My Pi get the gateway's `/v1` and a token of their own each, and speak OpenAI Chat to the gateway's `/v1/chat/completions` unless a model is better asked in Responses or Anthropic Messages (task `10-16-pi-omp-endpoints`). _Superseded by [ADR 0010](0010-codex-wiring-and-gateway-caller-recognition.md): Codex signed in with ChatGPT is pointed at the gateway through `openai_base_url` instead of `model_provider`; Osuna's Codex table, with its token, is still written for every sign-in. With the claude.ai sign-in kept, Claude's token is written empty ([ADR 0012](0012-cli-config-rewrite-follows-the-cli.md))._ The real API key never leaves the daemon. The token is the gateway's authentication and also says which provider is calling, so the gateway can apply that provider's switch and default model. It is only accepted from a loopback source. _Superseded by [ADR 0010](0010-codex-wiring-and-gateway-caller-recognition.md): every loopback request without a forwarding header is accepted; the token only identifies the agent, and path and `User-Agent` identify it when the token does not match._
- **Codex gets the token in plain text, and `auth.command` goes.** ADR 0004 put the key behind `auth.command` so no secret sat in `config.toml`. The gateway token is not the user's key, it is useless off this machine, and it is revoked when the switch goes back to Official (_superseded by [ADR 0010](0010-codex-wiring-and-gateway-caller-recognition.md): it no longer changes with the switch_), so a plain value is acceptable and it drops the `codex-api-key` file, the `/bin/cat` indirection, and the Codex 0.118 minimum version check. Because the key name starts with `experimental_`, it has to be tracked across Codex releases.
- **Claude's model is written as top-level `model`, not `env.ANTHROPIC_MODEL`.** `ANTHROPIC_MODEL` in `env` outranks `/model`, so a model picked inside a session was lost on the next session. A top-level `model` is the start value only. `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` and `ANTHROPIC_SMALL_FAST_MODEL` are no longer written (_superseded by [ADR 0012](0012-cli-config-rewrite-follows-the-cli.md): `ANTHROPIC_SMALL_FAST_MODEL` is written when the user picks a background model_): tier mapping is per endpoint and has to follow the endpoint the gateway chose, so the gateway translates tier names. All of these, if present on takeover, are recorded and removed, and restored on the way back.
- **Codex gets a model catalog.** `model_catalog_json` points at a daemon-owned file listing every selected model of every endpoint that is on, because Codex warns about unknown model ids on each turn otherwise. Codex rejects the whole catalog if an entry has no instructions, so each entry carries Codex's own base instructions for unknown models (vendored from openai/codex, Apache-2.0) and the rest of Codex's fallback metadata.
- **Claude gets a `modelPicker`.** Top-level `modelPicker.options` lists every selected model of every endpoint that is on as `<slug>/<model>`, labelled with the model name and described with the endpoint name, so Claude Code's `/model` can pick them; the gateway's model discovery only accepts ids containing `claude` or `anthropic`. A `modelPicker` the user already wrote is theirs and is never touched, so their list stays as it is (magpie does the same).
- **Claude is told what each endpoint model can do.** Claude Code takes any model it doesn't know for a 200K window, a 32000-token reply and no effort levels, so it compacts early, cuts long replies and ignores `/effort`. A model known to hold 1M tokens or more gets `[1m]` after its name in `model` and `modelPicker` (Claude Code drops the mark before sending), and `env` gets `CLAUDE_CODE_MAX_CONTEXT_TOKENS` (the start model's window), `CLAUDE_CODE_MAX_OUTPUT_TOKENS` (the least reply length of every listed model, only when every one is known and above 32000, and never under a Claude start model) and `CLAUDE_CODE_MODEL_CAPABILITIES` (each model's effort levels, lowercased, since Claude Code lowercases the model before matching). The numbers come from the endpoint's own model list first and models.dev second; anything unknown is left unwritten. A value the user set, or changed after Osuna wrote it, is theirs and is never touched (magpie does the same).
- **Official removes the dedicated Codex table.** ADR 0004 left `[model_providers.osuna_api_endpoint]` in place after Official so old sessions could resume through it. The table now only points at the gateway, which is useless once the switch is off, so Official returns `config.toml` byte for byte, and the daemon removes a table and `codex-api-key` that an older version left behind. _Superseded by [ADR 0010](0010-codex-wiring-and-gateway-caller-recognition.md): the table stays after Official so conversations recorded under it still resume through the gateway; the `codex-api-key` cleanup stands._
- **One switch per provider, one switch per endpoint.** A provider has "Use API endpoints" on or off and one bare default model name; an endpoint has its own on/off that applies to every provider. There is no "active endpoint" any more. Which endpoint a session uses comes from its model name: Osuna sessions send `<slug>/<model>` for a specific endpoint, everything else sends a bare model name and the gateway resolves it in endpoint creation order. _Changed 2026-10-19: the gateway resolves it in the [**Endpoint order**](../glossary.md) the user sets. That order also decides which endpoint a request tries first, where **Failover** goes next, and which endpoint an endpoint row names as taking a provider's default model. A new endpoint goes last._
- **Sessions no longer record the mode they started in.** The `apiEndpointId` session field and the resume-time warning go. The gateway resolves the model name at request time and, if nothing can serve it, returns the upstream error to the CLI, which shows it in the conversation.

## Rules the gateway adds

- It is mounted on the daemon's existing HTTP listener under `/api-endpoint-gateway`, ahead of the password middleware and the global JSON body limit, and streams bodies both ways. The relay never exposes it. A daemon listening on a socket cannot host it, so the provider switch refuses to turn on.
- On every start the daemon compares the URL it wrote with the URL it is bound to and rewrites the CLI config if they differ, because the port can change between runs.
- Failover happens only before the first byte of the response and only to an endpoint that serves the same model name. A failed endpoint cools down in memory, by the magpie failure classes; cooldown does not survive a daemon restart. _Superseded by [ADR 0014](0014-gateway-ledger-merges-with-cli-logs.md): cooldowns survive a restart._ _Superseded by [ADR 0008](0008-gateway-reshapes-rejected-requests-and-fails-over-refusals.md): failover happens before the reply opens at its first content, and "same model" compares normalized names._
- Per request, the gateway sends the agent's own protocol straight through when the endpoint has a URL for it, except that a Claude model always goes over the Anthropic URL when there is one, to keep prompt caching. Otherwise it translates to the first protocol the endpoint has. _Changed 2026-10-19: a model set to **Use only this format** on that endpoint goes only in that format, Claude model or not, translating when the agent speaks another ([ADR 0008](0008-gateway-reshapes-rejected-requests-and-fails-over-refusals.md#what-the-user-sets-on-an-endpoint))._ _Changed 2026-10-24 (task `10-16-gemini-upstream`): four **Request formats** translate, Gemini (Google's `generateContent`) as an upstream format only. It is tried last, Chat → Responses → Anthropic → Gemini, as in magpie's `Speaks`, so a Gemini URL is used when it is the endpoint's only URL, when the model is set to use only Gemini, or when the formats before it turned the model down. No agent speaks Gemini, so a Gemini URL is always reached by translation._
- Translation covers what magpie covers, minus vendor-specific rewrites (except the thinking fields of requests to non-Claude models, Claude models' own way of turning thinking off, and DeepSeek's reasoning replay), the "remember what was rejected" retry, web search, and file attachments beyond magpie's own handling. A rejected request is never re-sent to the same endpoint in a changed shape and the upstream error goes to the CLI, with one exception: when the endpoint refuses reasoning turned off (effort `none`, or thinking disabled on a model that always thinks), the gateway asks it once more with reasoning at its lowest and remembers that for the endpoint's model until the daemon restarts. Codex sends `none` from the user's own `config.toml`, and Claude Code turns thinking off for its auto-mode check, so without this every such request failed. _Superseded by [ADR 0008](0008-gateway-reshapes-rejected-requests-and-fails-over-refusals.md): the vendor-rewrite exceptions now include Kimi, MiniMax, DeepSeek and Grok, and a rejected shape is re-asked and remembered._
- Translated or not, the error body the CLI sees is `"<endpoint name>: <upstream text>"` in the CLI's own error shape, with `Retry-After` passed through. _Superseded by [ADR 0008](0008-gateway-reshapes-rejected-requests-and-fails-over-refusals.md): after a keepalive began, the error is an event in the stream and carries no headers._

## Considered Options

- **Keep ADR 0004 as is and add an ordered fallback list per endpoint** (magpie's model). Rejected: the CLI still points at one URL, so failover needs a gateway anyway, and the user chose automatic same-model failover over a hand-maintained list.
- **Run magpie itself and manage its process.** Rejected: a Go binary per platform in the desktop bundle, its own port and config files, and no way to keep its UI out of the way. The user chose a rewrite in the daemon.
- **A separate port for the gateway.** Rejected: the daemon already has a listener with Host filtering, 0600 file helpers, and a port recorded in `paseo.pid`; one more port means one more thing that can be taken.
- **Keep `auth.command` for Codex.** Rejected once the token became a revocable gateway token rather than the user's key; the indirection only bought a version floor and a second file.
- **Record the gateway's own usage.** Rejected: the CLIs already log every turn and the usage page reads those logs; a second ledger would double count. _Superseded by [ADR 0014](0014-gateway-ledger-merges-with-cli-logs.md): the gateway keeps a ledger, and a call in both the ledger and a CLI log counts once._
- **Change the official Paseo mobile app.** Rejected: the user runs the upstream app on the phone and does not build it. Old clients get a projection of the host-wide model onto the one-active-endpoint protocol they know, and that projection is permanent, not a COMPAT shim.

## Consequences

- A custom provider that `extends: "claude"` with its own `ANTHROPIC_BASE_URL` is overridden by the gateway while the Claude switch is on, as `settings.json` `env` outranks process env. Turn off Use API endpoints for Claude Code to give it its own URL again.
- Turning a provider's switch off sends its sessions back to the official URL; a session on an endpoint model then gets "model not found" from Anthropic or OpenAI. Accepted. _Superseded by [ADR 0010](0010-codex-wiring-and-gateway-caller-recognition.md): running sessions stay on the gateway until they restart, and Codex conversations recorded under Osuna's Codex model provider still resume through it._
- Every request from a terminal session passes through the daemon, so the daemon must be running for the CLI to work while the switch is on. The CLI's connection-refused error is the only message.
- Tier mapping has to be configured on every endpoint that should answer `opus`, `sonnet`, `haiku`, or `fable`; an endpoint without a mapping gets the tier name as the model id. _Superseded by [ADR 0012](0012-cli-config-rewrite-follows-the-cli.md): the code answered 404, not the tier name; now a tier name no endpoint maps falls back to the provider's default model._
- `model_catalog_json` has to be regenerated whenever an endpoint, its selected models, or a switch changes, or Codex warns on every turn.
- Old clients, including the official mobile app, see only bare model names and cannot pick which endpoint serves a model.
- Files borrowed from magpie's design keep its MIT notice at the top and the full text goes in the root [`THIRD_PARTY_NOTICES`](../../THIRD_PARTY_NOTICES).
