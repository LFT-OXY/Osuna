# Markdown file preview: DOM renderer on web, Lezer for highlighting

The markdown file preview on web/Electron renders through a DOM-only component (`markdown-preview/index.web.tsx`, react-markdown + remark-gfm + GitHub alerts + rehype-raw + rehype-sanitize, ported from t3code under MIT) while iOS/Android keep the shared React Native renderer (`react-native-markdown-display`). The RN renderer cannot do browser inline flow, raw HTML or `align`, so README-style documents (centered headers, badge rows, `[!NOTE]` alerts) can only look right on a DOM surface; we accepted two preview renderers and a native experience that lags web, rather than a WebView on native (height measurement and nested scrolling cost) or patching markdown-it (never reaches parity). Only the file preview moved; agent chat, PR comments, changelog and plan cards still use the RN renderer.

Code highlighting in the DOM preview deliberately does **not** use Shiki, even though t3code does. We extend `@getpaseo/highlight` (Lezer, missing languages via `@codemirror/legacy-modes`) and emit its tokens as `<span>`s, so the whole app keeps one engine and one user-selectable syntax theme. A full switch to Shiki was rejected: the CodeMirror editor needs Lezer's incremental parsing, diff tokens are produced server-side, Hermes has no WebAssembly for Shiki's default regex engine, and the syntax theme system is keyed on Lezer token categories rather than TextMate scopes.
