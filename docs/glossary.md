# Paseo Glossary

Authoritative terminology. UI label wins. Don't invent synonyms; use what's here.

- **Osuna** — This fork's product: the desktop app and the UI it renders. UI says "Osuna". Identifiers inherited from upstream keep the `paseo` spelling and are not product names: the `paseo` CLI command, `paseo.json`, `~/.paseo`, `PASEO_*`, `@getpaseo/*`, the `paseo://` scheme. Forbidden: "Paseo" as a label for this product.
- **Paseo** — The upstream project, and its official app-store mobile app, which is the mobile client for an Osuna daemon. UI keeps "Paseo" only where it means that mobile app (e.g. "Scan this QR code with Paseo on your phone"). Don't confuse with **Osuna**.

- **Project** — A stable, exact selected-root record. Its host-local `projectId` is an opaque `prj_<16 hex>` value. Its persisted `projectKey` is an opaque equivalence key that may group the logical project across hosts. A normalized Git remote is the current key producer, but consumers must not parse or rederive it. Git facts can update mutable kind and grouping metadata but never the ID, root, or default display name. UI: "Project" / "Add project". zh-CN UI: "项目". Forbidden: "Repo", "Repository" as UI label.
- **Workspace** — One concrete `cwd` on one daemon, with git state; belongs to exactly one project. Its `id` is opaque workspace identity; its `cwd` is the filesystem directory. UI: "Workspace". Code: `WorkspaceDescriptorPayload` (`packages/protocol/src/messages.ts:2178`). Don't confuse with: Branch (one branch can back many workspaces via worktrees). Forbidden: "Folder", "Directory" as UI label. zh-CN UI: "工作区".
- **Archive workspace** — Removes one workspace from active use and archives everything it owns. UI, CLI, and MCP always say "Archive workspace", regardless of backing. The daemon leaves ordinary directories intact and removes a Paseo-owned worktree only when no active workspace still references it.
- **Workspace kind** — `"directory" | "local_checkout" | "worktree"`. The git-derived, persisted property of a workspace, used across its lifetime (archive safety, sidebar, grouping). Derived from the cwd's git reality by `deriveWorkspaceKind` in `workspace-registry-model.ts`, not stored from a user choice. Don't confuse with **Isolation** (the create-time intent).
- **Isolation** — Create-time choice for a new workspace: reuse the existing checkout (**Local**) or cut a dedicated git worktree (**New worktree**). A transient setup input, also remembered as a create-form preference; it is not a workspace property. UI: "Isolation" control on the New Workspace screen. Code: `isolation` (`"local" | "worktree"`), `useWorkspaceIsolation` (`packages/app/src/screens/new-workspace-screen.tsx`); persisted as `FormPreferences.isolation` (`packages/app/src/create-agent-preferences/preferences.ts`). Distinct from **Workspace kind**, which is the git-derived property the intent produces (Local → `local_checkout` or `directory` by git-ness; New worktree → `worktree`). On the wire it is the create request's `source.kind` (`directory | worktree`, `packages/protocol/src/messages.ts:1693`).
- **Agent** — See **Agent session**. UI still says "Agent" / "New Agent" in places, but moving toward **Agent session** as the canonical term. Code: `AgentSnapshotPayload` (`packages/protocol/src/messages.ts:608`). Forbidden: "Task", "Job", "Run". zh-CN UI: "Agent", kept in English; not "智能体" or "代理".
- **Daemon** — Local Paseo server process; identified by `serverId`. UI: "Daemon" (system contexts only). Code: `serverId` in `ServerInfoStatusPayloadSchema` (`packages/protocol/src/messages.ts:1936`), `DaemonClient` (`packages/client/src/daemon-client.ts`). zh-CN UI: "守护进程".
- **Host** — Client-side connection profile pointing at a daemon; bundles one or more `HostConnection`s. UI: "Host" / "Add host" / "Switch host". Code: `HostProfile` (`packages/app/src/types/host-connection.ts:37`). Forbidden: "Connection" (means `HostConnection`, not host). zh-CN UI: "主机".
- **Host badge** — The item on a sidebar workspace row's meta row naming which host that workspace lives on. Three things gate it, and they compose as a lattice rather than competing: the sidebar must span more than one host (automatic), **Show → Host** in the sidebar's display preferences must be on (global, all hosts at once), and then that host's own display mode decides _how_ it draws — **Name** / **Icon only** / **Hidden**. Name, color, and display mode are per-host, per-device, and live client-side on `HostProfile.appearance`; nothing about it reaches the daemon. Never add a fourth way to hide it. UI: the "Appearance" group on a host's settings page, and the "Show" submenu in the sidebar's display preferences. Code: `selectHostBadges` (`packages/app/src/hosts/appearance.ts`) takes the first two as its `enabled` input; `WorkspaceMetaRow` (`packages/app/src/components/sidebar/workspace-meta-row/index.tsx`) draws it. Don't confuse with **Status pill**, which reports state rather than identity.
- **Project host entry** — One row in a project for a single (project, daemon) pair, aggregating that daemon's workspaces in the project. Internal. Code: `ProjectHostEntry` (`packages/app/src/utils/projects.ts:11`). Don't introduce "Checkout" as a synonym.
- **Placement** — One workspace's stable foreign-key relationship to its project plus its git checkout snapshot. Internal. An explicit creation `projectId` is authoritative when active.
- **Branch** — Plain git branch. UI: "Switch branch". Code: `currentBranch` in `WorkspaceGitRuntimePayloadSchema` (`packages/protocol/src/messages.ts:2136`); `BranchSwitcher` (`packages/app/src/components/branch-switcher.tsx`).
- **Forge** — Git hosting service behind Paseo's change-request features: GitHub, GitLab, Gitea, Forgejo, or a future registered adapter. Code: `ForgeService`, `forge-registry`, `forge-resolver`. Use `forge` for internal abstraction and registry IDs; use concrete forge names only when a behavior or RPC is forge-specific.
- **Change request** — Forge-neutral term for a proposed branch-to-branch code change. UI normally renders the forge noun instead: GitHub/Gitea/Forgejo "PR", GitLab "MR". zh-CN UI keeps "PR" / "MR" and spells the full noun "拉取请求" / "合并请求". Code: `forge_change_request` attachments, `checkoutSource: { kind: "change_request" }`, and PR/MR status payloads.
- **MR** — GitLab merge request. UI label for GitLab change requests only; do not use MR for GitHub/Gitea/Forgejo.
- **Worktree** — Paseo-managed git worktree (`~/.paseo/worktrees/{name}`); also a `workspaceKind` value. User-facing creation treats it as the `worktree` workspace isolation choice. Code and `paseo.json` retain worktree terminology for git lifecycle implementation. Forbidden: "Checkout" as a product synonym. zh-CN UI: "工作树", following VS Code; not "工作区", which is Workspace.
- **Repository / Remote** — Internal Git observations. They may produce mutable kind, branch, and project-grouping metadata but never the host-local project ID, root, display name, or workspace membership. No UI label.
- **Sidebar items** — The top-level rows at the head of the app sidebar: New workspace, History, Search, Schedules, and every plugin sidebar contribution. Order and visibility are one per-device preference (`AppSettings.sidebarNavItems`); all of them may be off. UI: the "Sidebar" section on the Appearance settings page. Code: `packages/app/src/sidebar-nav/model.ts` resolves the list, and both the sidebar (`components/sidebar/sidebar-nav-rows.tsx`) and the settings section (`screens/settings/appearance/sidebar-nav-section.tsx`) read it through `useSidebarNavItems`. Never hardcode one of these rows or add a second place that decides which ones show. Don't confuse with **Explorer sidebar**.
- **Interface font** — The font for everything that isn't code: navigation, controls, labels, chat text. Paired with two sizes: **Interface size** (navigation, controls, labels) and **Content size** (chat text and rendered Markdown). A chosen font is placed in front of the platform default stack, never replacing it. Per-device. UI: "Interface font" on the Appearance settings page; desktop and web only. Code: `AppSettings.uiFontFamily`.
- **Code font** — The monospace font for code blocks, diffs, and the file editor, and the default for the terminal. Paired with **Code size**. A chosen font is placed in front of the one default monospace stack. Per-device. UI: "Code font". Code: `AppSettings.monoFontFamily`.
- **Terminal font** — The terminal's own font and size override. Empty means "Follow code font" / follow **Code size**; never a third default. UI: "Terminal font" / "Terminal size"; the font row is desktop and web only. Code: `AppSettings.terminalFontFamily` / `terminalFontSize`, resolved by `resolveTerminalFont` in `appearance/font-stack.ts`. Don't confuse with **Terminal profile**, which picks the shell, not how it looks.
- **Explorer sidebar** — The dedicated navigation dock containing the Files and Changes trees. UI: "Explorer sidebar". Code: `packages/app/src/workspace-tabs/explorer-sidebar.ts`; persisted pane identifiers retain the `explorer` spelling. See [explorer-sidebar.md](explorer-sidebar.md).
- **Side pane** — An ordinary right-side workspace pane used for content opened beside the user's work. It closes and participates in workspace splits like every other main-host pane. See [explorer-sidebar.md](explorer-sidebar.md#side-pane). Forbidden: "Side panel".
- **Directory-backed surface** — A right-sidebar surface whose content is determined by the workspace's `cwd`, so two workspaces on the same directory see identical content: git diff/status, forge change-request info, file preview/explorer contents. Keyed by `(serverId, cwd)`, never `workspaceId`. See [architecture.md](architecture.md#right-sidebar-boundary-directory-backed-vs-workspace-owned).
- **Workspace-owned state** — Per-workspace state that never leaks to a same-`cwd` sibling: tabs, agents, terminals, panes, title, plus review drafts, diff-mode overrides, composer attachments, and file-explorer open/expand state. Keyed by `workspaceId` (`cwd` only as a fallback for old payloads). See [architecture.md](architecture.md#right-sidebar-boundary-directory-backed-vs-workspace-owned).
- **Workspace status bucket** — Aggregate activity signal for a workspace row. Same-`cwd` workspaces intentionally share agent and terminal status buckets, while tab, agent, and terminal visibility remains scoped by `workspaceId`.
- **Agent session** — One running instance of an agent inside a workspace (one provider, one model, one cwd, one timeline). The conceptual unit; in the UI this opens as a tab. Moving toward this as the canonical term over "Agent". Code: `AgentSnapshotPayload` (`packages/protocol/src/messages.ts:608`).
- **Session** — Two senses: (a) per-client connection to a daemon, internal; (b) user-facing agent session, see **Agent session**. Code: `Session` (`packages/server/src/server/session.ts`) for (a). Don't confuse with: **Provider session**.
- **Provider session** — A conversation record a provider left on a host, regardless of who started it: a Paseo agent, the user in a terminal, or another client. Identified by the provider's own handle (`providerHandleId`). An **Agent session** may be backed by one; most provider sessions have no Paseo agent at all. Listing comes from `fetch_recent_provider_sessions`; turning one into an Agent session is **Import**. zh-CN UI: "提供方会话". Code: `RecentProviderSessionDescriptorPayload` (`packages/protocol/src/messages.ts:913`). Forbidden: "External session", "Third-party session", "History item" for this.
- **Session history** — The Explorer sidebar view that lists provider sessions for the current host, scoped to the workspace, the project, or the whole host. Rows resume in a new terminal tab. UI: "Session history". Don't confuse with the sidebar item **History**, which lists Agent sessions Paseo created. Planned in `.atw/tasks/09-17-session-history-panel`.
- **Backing sessions** — The provider sessions an Agent session has run on, oldest first. Claude Code adds one per resume, because the SDK starts a new session file and copies the old history into it; Codex, Pi, and OMP keep the same one for life. Usage sums an agent over all of them, shows a Claude chain as one session row, and marks the sum incomplete while any of them has no scanned log. Not a UI label. Code: `providerSessionIds` on the stored agent record ([data-model.md](data-model.md#1-agent-record)). Don't confuse with **Fork**, which starts a new Agent session with backing sessions of its own, or with **Provider session**, which is one of them.
- **Profile** — Internal name for the persisted shape of a host. Code: `HostProfile` (`packages/app/src/types/host-connection.ts:37`). Never user-facing. Three other things are called "profile" in this codebase, so always qualify: **Agent profile**, **Terminal profile**, and the provider aliases in [custom-providers.md](custom-providers.md). Bare "profile" is forbidden in UI copy.
- **Agent profile** — A named launch bundle: provider, model, mode, thinking option, feature values, and free-text notes. Applying one writes those values into the **Agent controls** and is then forgotten — there is no selected profile, no default profile, and no drift tracking. The notes are written for orchestrating agents and are what the `list_profiles` MCP tool surfaces. Stored host-wide in daemon config as `agentProfiles`. UI: "Agent profiles". zh-CN UI: "Agent 配置". Code: `AgentProfile` (`packages/protocol/src/messages.ts:161`). Carries no system prompt, because a per-agent system prompt can only be set at creation. Forbidden: "Favourite", which this replaced.
- **Terminal profile** — A named shell command a terminal can launch. Stored host-wide in daemon config as `terminalProfiles`. UI: "Terminal profiles". zh-CN UI: "终端配置". Code: `TerminalProfile` (`packages/protocol/src/messages.ts:135`), `resolveTerminalProfiles` (`packages/protocol/src/terminal-profiles.ts`). Also selectable as a New Workspace launch target, where the alternative is the chat agent.
- **Provider** — Agent backend (Claude Code, Codex, Copilot, OpenCode, Pi, Oh My Pi). UI: "Provider". zh-CN UI: "提供方". Code: `ProviderSnapshotEntry` (`packages/protocol/src/messages.ts:426`). Users casually call these "agents"; in copy and docs they are Providers, because **Agent** means an Agent session. Forbidden: "Agent" for a provider.
- **Custom provider** — A provider added on a host that extends one built-in provider (or `acp`) with its own label, environment, and models. It is its own row in the provider list, next to the built-in it extends. Code: `source: "custom"` on `ProviderSnapshotEntry`; persisted under `agents.providers` ([custom-providers.md](custom-providers.md)). Don't confuse with **API endpoint**, which switches a built-in provider itself rather than adding a row. Forbidden: bare "Profile", "Alias" in UI copy.
- **Add provider** — The dialog behind the "+" on the Providers settings list. It holds only the ACP catalog: third-party ACP agents that picking adds as a new **Custom provider**, which then opens its details. Every provider the host already knows lives on the Providers list itself, in two groups by the `enabled` flag: "Enabled" (available, checking, failing, or not installed, each with its status) and "Disabled". Turning a provider off moves it to "Disabled"; nothing is deleted. A disabled row never says "Not installed", because the daemon does not probe disabled providers. UI: "Add provider"; groups "Enabled" and "Disabled". zh-CN UI: "添加提供方"; dialog group "ACP 目录"; list groups "已启用" and "已停用". Forbidden: "Catalog" alone as the dialog name.
- **API endpoint** — A saved third-party connection for one provider (Claude Code or Codex): base URL, API key, and the models picked from that endpoint. A provider can keep several; at most one is active. With none active the provider runs on its **official** setup, meaning whatever the CLI itself is configured with, usually the subscription login. Activating one switches the CLI itself, including when the user runs it in a terminal, not only agent sessions Osuna starts. UI: "API endpoint", the section in Claude Code's and Codex's provider settings that lists "Official" and every saved endpoint, marking the active row "In use"; copy names one as "the API endpoint {name}", and which of Official or an endpoint a provider runs on is its "mode" ("the current mode is Official"), which is not **Mode**. zh-CN UI: "第三方接口"; "Official" is "官方", "In use" is "使用中". Forbidden: "Channel", "Supplier", "Relay" in UI copy.
- **Model** — A specific LLM offered by a provider. UI: "Model" / "Select model". zh-CN UI: "模型". Code: `AgentModelDefinition` (`packages/protocol/src/messages.ts:187`).
- **Tab** — UI surface representing one session inside a workspace. Not a conceptual unit; use **Agent session** when talking about the model. Code: `WorkspaceTabDescriptor` (`packages/app/src/screens/workspace/workspace-tabs-types.ts`).
- **Turn** — One user message and everything the agent produced in response to it, ending at the next user message or the provider's turn-complete marker. The unit Usage counts tokens and duration by inside a session; subagent activity belongs to the parent's turn and is not a turn of its own. UI: the turn footer ("Worked for …" plus per-turn tokens and estimated cost) and the "Turns" column on the Usage page. zh-CN UI: "轮次" as a noun, "第 N 轮" as an ordinal. Code: `turn_completed`, `turnId` (`packages/protocol/src/messages.ts`). Forbidden: "Round", "Exchange".
- **Turn usage** — The tokens and estimated cost of one **Turn**, per model, stored by the daemon as its own row next to the **Usage bucket** rows so the turn footer can show what each turn cost. Keyed by the provider's own turn marker (Claude `promptId`, Codex `turn_id`, Pi/OMP the user entry id); subagent tokens count toward the parent's turn. Duration is derived from the turn's first and last entry, not stored. UI: the turn footer ("Worked for … · ↑ ↓ · $"). zh-CN UI: "本轮用量". Not the same as the turn's `turnId`, which is Paseo's own id for a live turn and is attached to the row only when the daemon saw the turn end. Code: the turn rows in [data-model.md](data-model.md#7-usage).
- **Usage** — Token consumption and estimated cost of agent sessions on a host, aggregated by usage source, model, time, and project. Measured by the daemon from each provider's own session logs, so it covers every session on the host, not only the ones Paseo created. UI: "Usage" (sidebar item and page). zh-CN UI: "用量". The host settings section that used to be labelled "Usage" is now "Price table", so only one thing is called Usage. Don't confuse with **Plan usage**, which is remaining quota, not consumption. See [usage.md](usage.md).
- **Usage source** — Where a usage row is attributed to: which CLI produced it, and for router CLIs (Pi, OMP) which backend it routed to, because each backend is priced differently. Values look like "Claude Code", "Codex", "Pi · Anthropic", "OMP · OpenAI". Both routers write the backend on every assistant entry, so there is no backend-less fallback. Not the same as **Provider**: a `zai` alias that `extends: claude` writes the same Claude Code log and lands in the Claude Code source. UI: "Source" cards on the Usage page. zh-CN UI: "来源". Forbidden: "Tool", "Engine".
- **Usage bucket** — The 15-minute UTC slot a usage row belongs to. Bucketed in UTC and this narrow so any client timezone, including +5:30 and +5:45, can regroup rows into its own local days and hours without splitting one. Tokens land in the bucket of the assistant message that produced them; a turn counts in the bucket where its user message started. Not a UI term. Forbidden: "bucket" for usage sources (use **Usage source**).
- **Backfill** — The scan the daemon runs once at startup over every provider log it has not fully read yet, so Usage covers history from before this daemon version existed. It is the same scan the daemon repeats every minute afterwards; only the first pass reports progress, and a restart resumes where the cursors left off. Newest logs are read first so recent days fill in within seconds. UI: progress on the Usage page while it runs. zh-CN UI: "回填". See [usage.md](usage.md#the-scan). Don't confuse with **Import**, which turns one provider session into an Agent session.
- **Plan usage** — What a provider's subscription reports about its own limits: rate windows, balances, plan label. Fetched from the provider's account API with the CLI's stored login; says nothing about how many tokens were used. UI: "Plan usage" section on the Usage page. zh-CN UI: "套餐用量". Code: `ProviderUsageSchema` (`packages/protocol/src/messages.ts:6225`), `packages/server/src/services/quota-fetcher/`. Forbidden: "Quota" as a UI label.
- **Estimated cost** — What a usage row would have cost at the model's public API price, in USD, computed from its five token columns (input, cached input, cache write, output, reasoning). Always an estimate: subscription sessions are priced the same way, and a model with no known price shows $0 marked "no price data". UI: always qualified as "Estimated". zh-CN UI: "估算成本". Forbidden: "Cost", "Spend" unqualified in UI copy.
- **Price table** — The per-model unit prices the daemon uses to compute **Estimated cost**: a built-in LiteLLM snapshot, refreshed from the network once a day when auto-update is on, in USD per token for the four priced columns (input, cached input, cache write, output). Each host has its own table; nothing syncs between hosts. UI: "Price table" page in host settings (where Plan usage used to live), which lists every model seen in two groups: "Custom prices" (models with a **Custom price** or no price data) and "LiteLLM prices" (everything the table prices, collapsed by default). zh-CN UI: "价格表", groups "自定义价格" and "LiteLLM 价格". See [usage.md](usage.md#the-price-table). Forbidden: "Pricing", "Rates".
- **Custom price** — A user-entered price for one exact model id that beats the **Price table**, given per million tokens for the same four columns. A custom price of 0 means the model is priced, not that it lacks price data. Per host, stored in daemon config. UI: the "Custom prices" group of the Price table, the "Customize" action on a LiteLLM row, and "Remove custom price", which returns the model to its LiteLLM price or to no price data. zh-CN UI: "自定义价格", "自定义", "移除自定义价格". Code: `UsagePricingOverride` (`packages/protocol/src/usage/types.ts`). Forbidden: "Override" in UI copy.
- **Terminal** — Workspace-scoped PTY shell streamed over the binary mux channel. UI: "Terminal". Code: `TerminalStreamFrame` (`packages/protocol/src/terminal-stream-protocol.ts`). zh-CN UI: "终端".
- **Workspace script** — A named command a workspace can run, declared in `paseo.json`. Two types: `service` and `script` (a command that runs and finishes). UI: "Scripts" for the panel and the menu, both of which list either type. zh-CN UI: "脚本". Code: `WorkspaceScriptPayload` (`packages/protocol/src/messages.ts:3126`). Don't confuse with **Service**, which is one of the two types rather than a synonym for the pair.
- **Service** — A workspace script of type `service`: long-running, may bind a port, and carries `health` of `healthy | unhealthy | null` once the daemon has observed it. The only type a sidebar workspace row reports, because a running plain script says nothing about whether the workspace is up; the row names the service and turns danger when its health fails, and where several run the failing one takes the row's single slot. UI: "Services" in the sidebar's display preferences (**Show → Services**). Code: `selectWorkspaceServiceSummary` (`packages/app/src/components/sidebar/workspace-meta-row/service-summary.ts`), `WorkspaceScriptHealthSchema` (`packages/protocol/src/messages.ts:3124`). Forbidden: "Service" as a label for the Scripts panel, which lists both types.
- **Schedule** — Cron-style trigger that creates new agents. UI: CLI/MCP (`paseo schedule`, `create_schedule`). Don't confuse with: Heartbeat (cron prompt back into the same agent). zh-CN UI: "计划" (shared with the sidebar item; "Plan" mode is also "计划", the context disambiguates).
- **Heartbeat** — Ephemeral cron prompt sent back into the same agent/conversation. Agent surfaces expose create, update cron, and delete only. Use for reminders and babysitting where status should return inline. zh-CN UI: "心跳".
- **Mode** — Provider-specific operational mode (plan, default, full-access, …). UI: icon-only. zh-CN UI: "模式" in labels and hints. Code: `modeId` in `AgentSessionConfig` (`packages/protocol/src/messages.ts:257`).
- **Attachment** — External or local context bound to an agent prompt: forge issue/change request, review context, uploaded file, text, or image. UI: "Attach issue or PR/MR". Code: `AgentAttachment` (`packages/protocol/src/messages.ts:782`).
- **Composer** — The whole prompt surface for sending work to an agent. Code: `Composer` (`packages/app/src/composer/index.tsx`). Don't call this "message input" except for the text-entry subcomponent. zh-CN UI: "输入区".
- **Composer input** — The text-entry surface inside the composer. zh-CN UI: "输入框". Code: `MessageInput` (`packages/app/src/composer/input/input.tsx`).
- **Composer toolbar** — The bottom control row inside the composer input. Contains agent controls, attachment button, voice controls, and stop/send controls. Code: `leftContent`, `beforeVoiceContent`, and `rightContent` slots in `MessageInput` (`packages/app/src/composer/input/input.tsx`). Forbidden: "Status bar".
- **Agent controls** — Provider, model, mode, thinking, and provider-feature controls for an agent or draft agent. Code: `AgentControls` / `DraftAgentControls` (`packages/app/src/composer/agent-controls/index.tsx`). Forbidden: "Agent status bar".
- **Composer footer** — Optional area rendered below the composer input but still inside the keyboard-shifted composer layout. Code: `Composer.footer` (`packages/app/src/composer/index.tsx`).
- **Composer context strip** — The thin strip attached under the composer input showing the workspace kind (read-only), the current branch (clickable to switch branch), and the **Plan usage** windows of the active agent's provider (hover for the full plan usage card). Desktop only; phones have no strip and keep plan usage in the context window popover. Code: `ComposerContextStrip` (`packages/app/src/composer/context-strip/index.tsx`). Not the **Composer footer**, not a **Composer track**.
- **Composer track** — A contextual lane at the foot of a pane, by the composer input. Specific tracks use the `<thing> track` form: **Queue track**, **Subagents track**, **Tasks track**. The subagents and tasks tracks are pills floating over the transcript, each opening a panel with its rows; the queue track is a lane inside the composer itself. Code: queue track inside `Composer` (`packages/app/src/composer/index.tsx`), pill and panel frame in `packages/app/src/composer/tracks.tsx`, `SubagentsTrack` (`packages/app/src/subagents/track.tsx`), `AgentTaskList` (`packages/app/src/composer/task-list/index.tsx`).
- **Steer** — A follow-up admitted into an agent's already-running turn instead of interrupting it. Interrupting the turn discards steers the provider has not read yet; there is no take-back short of that, and no provider offers one. The stop button and Escape both interrupt. A steer the provider never read keeps its transcript row, matching Codex. Sending while the agent waits on a permission denies that request first, so the message reaches the same turn instead of stalling behind it. UI: "Send and steer". Code: `steerActiveTurn` (`packages/server/src/server/agent/agent-sdk-types.ts`). Don't confuse with **Queue track**, which holds messages client-side until the turn ends and never enters the running turn. Forbidden: "Delivery", "Queued prompt".
- **Subagent** — User-facing term for an agent session related to a parent agent session. Use **subagents** in UI copy and docs. Internal daemon/provider plumbing may say "child agent"; do not surface it as a product term. zh-CN UI: "Subagent", kept in English; not "子智能体".
- **Attachment tray** — The selected-attachments row inside the composer input, above the text input. Holds only pasted or dropped attachments; anything picked from the `/` or `@` list becomes an **Inline block** instead. Code: `ComposerAttachmentTray` (`packages/app/src/composer/attachment-tray.tsx`). Forbidden: "Attachment bar".
- **Inline block** — An atomic block in the composer text, and in the sent user message, standing for something picked from the command menu or the `@` list: a type icon plus a name. The cursor stops before or after it, never inside; deleting any part of it deletes all of it. In the composer, only picking from a list makes one; typed `/name` or `@path` text stays text. Kinds: **Skill block**, **File mention**, **Agent mention**. Don't confuse with **Attachment**, which is content sent alongside the prompt; an inline block is part of the prompt text.
- **Skill block** — An **Inline block** for a skill picked from the command menu, shown by the skill's raw name. Skill blocks always lead the message, in picking order; picking one mid-text puts it at the start. Commands picked from the same menu still insert text. Code: `pickSkillBlock` (`packages/app/src/inline-blocks/index.ts`), drawn by `InlineBlockView` (`packages/app/src/inline-blocks/block-view.tsx`). Formerly "Skill chip". Forbidden: "Skill chip".
- **File mention** — An **Inline block** for a file, directory, or image picked from the file group of the `@` list, shown by its base name with an icon for its type. A picked image is a path reference like any file; its content is not sent. Don't confuse with an image pasted or dropped into the **Attachment tray**, which is sent.
- **Agent mention** — An enabled provider or **Agent profile** picked from the agent group of the `@` list, standing as an **Inline block** in the message text, so its position says which part of the message it is for. Sending asks the current agent to start one new **Subagent** per mention, even when the same provider is mentioned twice; the mention never targets an agent that is already running. zh-CN UI: "提及 Agent". Don't confuse with **File mention**, which shares the list. Forbidden: "Delegation", "Agent tag".
- **Mention defaults** — The model, thinking option, and mode an **Agent mention** of a provider starts its **Subagent** with, set per provider in Settings → Host → Agents and stored in daemon config. Unset fields, and values the provider no longer offers, fall back to the provider's own defaults, resolved by the daemon when the message is sent; the parent agent's mode is never inherited. A mentioned **Agent profile** uses its own fields first, then its provider's mention defaults. Don't confuse with the new-agent preferences the app remembers per device. zh-CN UI: "提及 Agent 默认值". Code: `ProviderMentionDefaultsSchema` (`packages/protocol/src/provider-config.ts`), stored at `agents.providers.<id>.mentionDefaults`, resolved in `resolveRoutingBlock` (`packages/server/src/server/agent/routing-block.ts`); the settings card is `MentionDefaultsSection` (`packages/app/src/screens/settings/mention-defaults-section.tsx`). UI label: "Mention defaults". Forbidden: "Delegation defaults".
- **Routing block** — The `<paseo-system>` block the daemon appends to a user message that carries **Agent mentions**, listing each mention in order with its resolved provider, model, and settings, or why it cannot start. Only the copy sent to the provider carries it; the timeline keeps the text as sent, and the trailing block is stripped from provider history, imports, and previews. No UI label. Code: `resolveRoutingBlock` (`packages/server/src/server/agent/routing-block.ts`), `stripTrailingRoutingBlock` (`packages/server/src/server/agent/trailing-routing-block.ts`). Forbidden: "Routing frame", "Delegation instruction".
- **Command menu** — The menu that opens when you type `/` in the composer input, listing the agent's commands and skills in two groups. Code: `ComposerAutocomplete` (`packages/app/src/composer/index.tsx`), list in `packages/app/src/components/ui/autocomplete.tsx`. The `@` file list shares the list component but is not the command menu.
- **Fork** — Starting a NEW agent session seeded with a copy of another session's curated chat history. The history rides along as a `chat_history` composer attachment on a draft; the fork does **not** resume or branch the provider-side session, and the source session keeps running untouched. Two targets, one surface, one RPC (`agent.fork_context`, gated on the `agentForkContext` host feature). UI: the fork menu lives in the assistant turn footer and offers "Fork in a new tab" / "Fork in a new workspace". On a **completed** turn it sits beside the copy button and pins a boundary to that turn, so the fork stops where the turn ended. On the **in-flight** turn it sits beside the progress loader and elapsed timer, and omits the boundary entirely — `selectForkContextRows` projects the whole timeline when no boundary is given, so the fork captures everything **up to now**, including the response still streaming. That omission is what makes mid-run forking work; pinning a boundary there would silently drop the live response. Forbidden on provider-subagent (read-only) panes. Code: `useForkAgent` (`packages/app/src/hooks/use-fork-agent.ts`), `selectForkContextRows` (`packages/server/src/server/agent/activity-curator.ts`). Don't confuse with: git fork (unrelated; Paseo has no such concept), **Worktree** (filesystem isolation, not history copying).
- **Conflict** — Two distinct senses; do NOT use the bare word in UI copy without qualifying which: (a) **stale-write conflict** on `paseo.json` ("Config changed on disk", code `stale_project_config`, `packages/app/src/screens/project-settings-screen.tsx:593`); (b) **git merge conflict** (no current UI string).
- **Product discussion** — Where non-bug product talk goes: [GitHub Discussions](https://github.com/getpaseo/paseo/discussions) and `#product` in Discord. Covers workflows, features, and product direction. The container term; the ask inside it is always a **workflow** — what you're doing, how you do it today, where Paseo gets in the way. Issues are bugs only. Forbidden: "Feature request" as a Paseo surface, label, or invitation; the phrase is only used when answering someone who arrived with it. Don't invent "feature discussion", "idea", or "workflow thread" as synonyms. See [CONTRIBUTING.md](../CONTRIBUTING.md).

## Inconsistencies (documented, not papered over)

- CLI `--host <host>` description `"Daemon host target"` (`packages/cli/src/utils/command-options.ts:5`) blurs daemon/host; the app keeps them distinct.
- `WorkspaceDescriptorPayloadSchema.workspaceKind` accepts legacy `"checkout"` on the wire (`packages/protocol/src/messages.ts:2187`) while `PersistedWorkspaceKind` does not (`packages/server/src/server/workspace-registry-model.ts:8`).
