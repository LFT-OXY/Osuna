# Paseo Glossary

Authoritative terminology. UI label wins. Don't invent synonyms; use what's here.

- **Osuna** — This fork's product: the desktop app and the UI it renders. UI says "Osuna". Identifiers inherited from upstream keep the `paseo` spelling and are not product names: the `paseo` CLI command, `paseo.json`, `~/.paseo`, `PASEO_*`, `@getpaseo/*`, the `paseo://` scheme. Forbidden: "Paseo" as a label for this product.
- **Paseo** — The upstream project, and its official app-store mobile app, which is the mobile client for an Osuna daemon. UI keeps "Paseo" only where it means that mobile app (e.g. "Scan this QR code with Paseo on your phone"). Don't confuse with **Osuna**.

- **Project** — A stable, exact selected-root record. Its host-local `projectId` is an opaque `prj_<16 hex>` value. Its persisted `projectKey` is an opaque equivalence key that may group the logical project across hosts. A normalized Git remote is the current key producer, but consumers must not parse or rederive it. Git facts can update mutable kind and grouping metadata but never the ID, root, or default display name. UI: "Project" / "Add project". zh-CN UI: "项目". Forbidden: "Repo", "Repository" as UI label.
- **Workspace** — One concrete `cwd` on one daemon, with git state; belongs to exactly one project. Its `id` is opaque workspace identity; its `cwd` is the filesystem directory. UI: "Workspace". Code: `WorkspaceDescriptorPayload` (`packages/protocol/src/messages.ts:2178`). Don't confuse with: Branch (one branch can back many workspaces via worktrees). Forbidden: "Folder", "Directory" as UI label. zh-CN UI: "工作区".
- **Archive workspace** — Removes one workspace from active use and archives everything it owns. UI, CLI, and MCP always say "Archive workspace", regardless of backing. The daemon leaves ordinary directories intact and removes a Paseo-owned worktree only when no active workspace still references it.
- **Workspace kind** — `"directory" | "local_checkout" | "worktree"`. The git-derived, persisted property of a workspace, used across its lifetime (archive safety, sidebar, grouping). Derived from the cwd's git reality by `deriveWorkspaceKind` in `workspace-registry-model.ts`, not stored from a user choice. Don't confuse with **Isolation** (the create-time intent).
- **Isolation** — Create-time choice for a new workspace: reuse the existing checkout (**Local**) or cut a dedicated git worktree (**New worktree**). A transient setup input, also remembered as a create-form preference; it is not a workspace property. UI: "Isolation" control on the New Workspace screen. Code: `isolation` (`"local" | "worktree"`), `useWorkspaceIsolation` (`packages/app/src/screens/new-workspace-screen.tsx`); persisted as `FormPreferences.isolation` (`packages/app/src/create-agent-preferences/preferences.ts`). Distinct from **Workspace kind**, which is the git-derived property the intent produces (Local → `local_checkout` or `directory` by git-ness; New worktree → `worktree`). On the wire it is the create request's `source.kind` (`directory | worktree`, `packages/protocol/src/messages.ts:1693`).
- **Agent** — See **Agent session**. UI still says "Agent" / "New Agent" in places, but moving toward **Agent session** as the canonical term. Code: `AgentSnapshotPayload` (`packages/protocol/src/messages.ts:608`). Forbidden: "Task", "Job", "Run". zh-CN UI: "Agent", kept in English; not "智能体" or "代理".
- **Daemon** — Local Paseo server process; identified by `serverId`. UI: "Daemon" (system contexts only). Code: `serverId` in `ServerInfoStatusPayloadSchema` (`packages/protocol/src/messages.ts:1936`), `DaemonClient` (`packages/client/src/daemon-client.ts`). zh-CN UI: "守护进程".
- **Host** — Client-side connection profile pointing at a daemon; bundles one or more `HostConnection`s. UI: "Host" / "Add host" / "Switch host". Code: `HostProfile` (`packages/app/src/types/host-connection.ts:37`). Forbidden: "Connection" (means `HostConnection`, not host). zh-CN UI: "主机".
- **Host badge** — The item on a sidebar workspace row's meta row naming which host that workspace lives on. Three things gate it, and they compose as a lattice rather than competing: the sidebar must span more than one host (automatic), **Show → Host** in the sidebar's display preferences must be on (global, all hosts at once), and then that host's own display mode decides _how_ it draws — **Name** / **Icon only** / **Hidden**. Name, color, and display mode are per-host, per-device, and live client-side on `HostProfile.appearance`; nothing about it reaches the daemon. Never add a fourth way to hide it. UI: the "Appearance" group on a host's settings page, and the "Show" submenu in the sidebar's display preferences. Code: `selectHostBadges` (`packages/app/src/hosts/appearance.ts`) takes the first two as its `enabled` input; `WorkspaceMetaRow` (`packages/app/src/components/sidebar/workspace-meta-row/index.tsx`) draws it. Don't confuse with **Status pill**, which reports state rather than identity.
- **Project host entry** — One row in a project for a single (project, daemon) pair, aggregating that daemon's workspaces in the project. Internal. Code: `ProjectHostEntry` (`packages/app/src/utils/projects.ts:11`). Don't introduce "Checkout" as a synonym.
- **Placement** — One workspace's stable foreign-key relationship to its project plus its git checkout snapshot. Internal. An explicit creation `projectId` is authoritative when active.
- **Branch** — Plain git branch. UI: "Switch branch". Code: `currentBranch` in `WorkspaceGitRuntimePayloadSchema` (`packages/protocol/src/messages.ts:2136`); `BranchSwitcher` (`packages/app/src/components/branch-switcher.tsx`).
- **Forge** — Git hosting service behind Paseo's change-request features: GitHub, GitLab, Gitea, Forgejo, or a future registered adapter. Code: `ForgeService`, `forge-registry`, `forge-resolver`. Use `forge` for internal abstraction and registry IDs; use concrete forge names only when a behavior or RPC is forge-specific.
- **Change request** — Forge-neutral term for a proposed branch-to-branch code change. UI normally renders the forge noun instead: GitHub/Gitea/Forgejo "PR", GitLab "MR". zh-CN UI keeps "PR" / "MR" and spells the full noun "拉取请求" / "合并请求". Code: `forge_change_request` attachments, `checkoutSource: { kind: "change_request" }`, and PR/MR status payloads.
- **MR** — GitLab merge request. UI label for GitLab change requests only; do not use MR for GitHub/Gitea/Forgejo.
- **Worktree** — Paseo-managed git worktree (`~/.paseo/worktrees/{name}`); also a `workspaceKind` value. User-facing creation treats it as the `worktree` workspace isolation choice. Code and `paseo.json` retain worktree terminology for git lifecycle implementation. Forbidden: "Checkout" as a product synonym. zh-CN UI: "工作树", following VS Code; not "工作区", which is Workspace.
- **Repository / Remote** — Internal Git observations. They may produce mutable kind, branch, and project-grouping metadata but never the host-local project ID, root, display name, or workspace membership. No UI label.
- **Sidebar items** — The configurable entries of the app sidebar, in two sections. Header: the rows at the head of the sidebar — New workspace, History, Search, Schedules, Usage, and plugin header items. Footer: the full-width rows above the footer icon row — the **Plan usage summary** and plugin footer items. Add project and the icon row (Hosts, Help and support, Settings) are fixed and are not sidebar items. A plugin item may render several rows, such as one per bot; it is still one item that moves and hides as a block. Each section's order and visibility is one per-device preference (`AppSettings.sidebarNavItems`, `AppSettings.sidebarFooterItems`); every item may be off. UI: the Header and Footer cards on the Sidebar settings page. Code: `packages/app/src/sidebar-nav/model.ts` resolves a section, and the sidebar (`components/sidebar/sidebar-nav-rows.tsx`, the footer in `components/left-sidebar.tsx`) and the settings page (`screens/settings/sidebar/sidebar-nav-section.tsx`) read it through `useSidebarNavItems(section)`. Never hardcode one of these entries or add a second place that decides which ones show. Don't confuse with **Explorer sidebar**.
- **Interface font** — The font for everything that isn't code: navigation, controls, labels, chat text. Paired with two sizes: **Interface size** (navigation, controls, labels) and **Content size** (chat text and rendered Markdown). A chosen font is placed in front of the platform default stack, never replacing it. Per-device. UI: "Interface font" on the Appearance settings page; desktop and web only. Code: `AppSettings.uiFontFamily`.
- **Code font** — The monospace font for code blocks, diffs, and the file editor, and the default for the terminal. Paired with **Code size**. A chosen font is placed in front of the one default monospace stack. Per-device. UI: "Code font". Code: `AppSettings.monoFontFamily`.
- **Terminal font** — The terminal's own font and size override. Empty means "Follow code font" / follow **Code size**; never a third default. UI: "Terminal font" / "Terminal size"; the font row is desktop and web only. Code: `AppSettings.terminalFontFamily` / `terminalFontSize`, resolved by `resolveTerminalFont` in `appearance/font-stack.ts`. Don't confuse with **Terminal profile**, which picks the shell, not how it looks.
- **Explorer sidebar** — The dedicated navigation dock containing the Files and Changes trees. UI: "Explorer sidebar". Code: `packages/app/src/workspace-tabs/explorer-sidebar.ts`; persisted pane identifiers retain the `explorer` spelling. See [explorer-sidebar.md](explorer-sidebar.md).
- **Side pane** — An ordinary right-side workspace pane used for content opened beside the user's work. It closes and participates in workspace splits like every other main-host pane. See [explorer-sidebar.md](explorer-sidebar.md#side-pane). Forbidden: "Side panel".
- **Directory-backed surface** — A right-sidebar surface whose content is determined by the workspace's `cwd`, so two workspaces on the same directory see identical content: git diff/status, forge change-request info, file preview/explorer contents. Keyed by `(serverId, cwd)`, never `workspaceId`. See [architecture.md](architecture.md#right-sidebar-boundary-directory-backed-vs-workspace-owned).
- **Workspace-owned state** — Per-workspace state that never leaks to a same-`cwd` sibling: tabs, agents, terminals, panes, title, plus review drafts, diff-mode overrides, composer attachments, and file-explorer open/expand state. Keyed by `workspaceId` (`cwd` only as a fallback for old payloads). See [architecture.md](architecture.md#right-sidebar-boundary-directory-backed-vs-workspace-owned).
- **Workspace status bucket** — Aggregate activity signal for a workspace row. Same-`cwd` workspaces intentionally share agent and terminal status buckets, while tab, agent, and terminal visibility remains scoped by `workspaceId`.
- **Agent session** — One running instance of an agent inside a workspace (one provider, one model, one cwd, one timeline). The conceptual unit; in the UI this opens as a tab. Moving toward this as the canonical term over "Agent". Code: `AgentSnapshotPayload` (`packages/protocol/src/messages.ts:608`).
- **Session** — Two senses: (a) per-client connection to a daemon, internal; (b) user-facing agent session, see **Agent session**. Code: `Session` (`packages/server/src/server/session.ts`) for (a). Don't confuse with: **Provider session**.
- **Provider session** — A conversation record a provider left on a host, regardless of who started it: a Paseo agent, the user in a terminal, or another client. Identified by the provider's own handle (`providerHandleId`). An **Agent session** may be backed by one; most provider sessions have no Paseo agent at all. Listing comes from `fetch_recent_provider_sessions`; turning one into an Agent session is **Import**. zh-CN UI: "提供方会话". Code: `RecentProviderSessionDescriptorPayload` (`packages/protocol/src/messages.ts:913`). Forbidden: "External session", "Third-party session", "History item" for this.
- **Session history** — The Explorer sidebar view that lists provider sessions for the current host, scoped to the workspace, the project, or the whole host. Rows resume in a new terminal tab. A Codex row names its **Codex model provider** and can be moved to another one. UI: "Session history". zh-CN UI: "会话历史". Don't confuse with the sidebar item **History**, which lists Agent sessions Paseo created.
- **Backing sessions** — The provider sessions an Agent session has run on, oldest first. Claude Code adds one per resume, because the SDK starts a new session file and copies the old history into it; Codex, Pi, and OMP keep the same one for life. Usage sums an agent over all of them, shows a Claude chain as one session row, and marks the sum incomplete while any of them has no scanned log. Not a UI label. Code: `providerSessionIds` on the stored agent record ([data-model.md](data-model.md#1-agent-record)). Don't confuse with **Fork**, which starts a new Agent session with backing sessions of its own, or with **Provider session**, which is one of them.
- **Profile** — Internal name for the persisted shape of a host. Code: `HostProfile` (`packages/app/src/types/host-connection.ts:37`). Never user-facing. Three other things are called "profile" in this codebase, so always qualify: **Agent profile**, **Terminal profile**, and the provider aliases in [custom-providers.md](custom-providers.md). Bare "profile" is forbidden in UI copy.
- **Agent profile** — A named launch bundle: provider, model, mode, thinking option, feature values, and free-text notes. Applying one writes those values into the **Agent controls** and is then forgotten — there is no selected profile, no default profile, and no drift tracking. The notes are written for orchestrating agents and are what the `list_profiles` MCP tool surfaces. Stored host-wide in daemon config as `agentProfiles`. UI: "Agent profiles". zh-CN UI: "Agent 配置". Code: `AgentProfile` (`packages/protocol/src/messages.ts:161`). Carries no system prompt, because a per-agent system prompt can only be set at creation. Forbidden: "Favourite", which this replaced.
- **Terminal profile** — A named shell command a terminal can launch. Stored host-wide in daemon config as `terminalProfiles`. UI: "Terminal profiles". zh-CN UI: "终端配置". Code: `TerminalProfile` (`packages/protocol/src/messages.ts:135`), `resolveTerminalProfiles` (`packages/protocol/src/terminal-profiles.ts`). Also selectable as a New Workspace launch target, where the alternative is the chat agent.
- **Provider** — Agent backend (Claude Code, Codex, Copilot, OpenCode, Pi, Oh My Pi). UI: "Provider". zh-CN UI: "提供方". Code: `ProviderSnapshotEntry` (`packages/protocol/src/messages.ts:426`). Users casually call these "agents"; in copy and docs they are Providers, because **Agent** means an Agent session. Forbidden: "Agent" for a provider. Don't confuse with **Codex model provider**.
- **Codex model provider** — An entry in Codex's own config that says where Codex sends its requests: its built-in `openai`, the **Gateway**'s own entry, or one another tool wrote. Codex files each conversation under the one it started on and resumes it there, and its own resume list shows only the current one's conversations; Session history lists Codex conversations under all of them. A conversation can be moved to another one, several at a time from Session history, or from the error shown when it can't resume because its own entry is gone. Osuna keeps a copy of the conversation first, leaves alone one written in the last minute, and moving it back undoes the move. UI: "Codex model provider", the row action "Move to another Codex model provider…", the button in a resume error "Move conversation…". zh-CN UI: "Codex 服务商", "挪到另一个 Codex 服务商…", "挪动对话…". Forbidden: "Provider" or "提供方" for this.
- **Custom provider** — A provider added on a host that extends one built-in provider (or `acp`) with its own label, environment, and models. It is its own row in the provider list, next to the built-in it extends. Code: `source: "custom"` on `ProviderSnapshotEntry`; persisted under `agents.providers` ([custom-providers.md](custom-providers.md)). Don't confuse with **API endpoint**, which routes a built-in provider through the **Gateway** rather than adding a row. Forbidden: bare "Profile", "Alias" in UI copy.
- **Add provider** — The dialog behind the "+" on the Providers settings list. It holds only the ACP catalog: third-party ACP agents that picking adds as a new **Custom provider**, which then opens its details. Every provider the host already knows lives on the Providers list itself, in two groups by the `enabled` flag: "Enabled" (available, checking, failing, or not installed, each with its status) and "Disabled". Turning a provider off moves it to "Disabled"; nothing is deleted. A disabled row never says "Not installed", because the daemon does not probe disabled providers. UI: "Add provider"; groups "Enabled" and "Disabled". zh-CN UI: "添加提供方"; dialog group "ACP 目录"; list groups "已启用" and "已停用". Forbidden: "Catalog" alone as the dialog name.
- **API endpoint** — A third-party connection shared by the whole host: a name, an optional API key (a local model server needs none), up to three base URLs (one per **Request format**, at least one), its **Model scope**, an optional Claude tier mapping, its **Endpoint switch**, its place in the **Endpoint order**, whether it **Searches the web by itself**, and, for one added with "Custom", an icon picked from the built-in ones or a picture the host keeps a copy of. It belongs to no provider and has no default model of its own. Claude Code and Codex use the selected models of every endpoint that is on once their **Use API endpoints** switch is on; the CLI itself follows too, including when the user runs it in a terminal, because its config points at the **Gateway**. Without the switch the provider runs on its **official** setup, meaning whatever the CLI itself is configured with, usually the subscription login. UI: "API endpoints", the host settings page that lists endpoints in two groups, "On" and "Off", with a dialog to add one and a page per endpoint; copy names one as "the API endpoint {name}". zh-CN UI: "第三方接口"; "official" is "官方". Forbidden: "Channel", "Supplier", "Relay" in UI copy; "In use", "active endpoint", and "mode" for which endpoint a provider runs on, since there is no active endpoint any more ([ADR 0007](adr/0007-api-endpoints-route-through-daemon-gateway.md)).
- **Gateway** — The daemon's built-in HTTP gateway that Claude Code and Codex talk to while **Use API endpoints** is on. It picks the API endpoint per request, swaps in the real key, translates between request formats, and performs **Failover**. For Codex signed in with ChatGPT it also carries the requests for ChatGPT's own models to ChatGPT as sent, and lists those models next to the endpoints' ones. UI mentions it only when it cannot run: "built-in gateway". zh-CN UI: "中转站" ("内置中转站"). Code: `packages/server/src/server/api-endpoints/gateway/`. Forbidden: "Proxy", "Relay"; zh-CN "代理", "中继".
- **Endpoint switch** — An API endpoint's own on/off. It applies to every provider and is saved; an endpoint that is off is never used, not even for **Failover**. UI: the switch on each row and on the endpoint's page, accessible name "Use {name}". zh-CN UI: "接口开关：{name}". Code: `enabled` on the stored endpoint.
- **Endpoint order** — The one order of all API endpoints, set by the user. It decides which endpoint a request tries first and where **Failover** goes next, and which endpoint a bare model name goes to when several offer it. The "On" and "Off" groups both follow it. UI: drag a row, or the row menu's "Move up", "Move down", "Move to top", "Move to bottom". zh-CN UI: "上移", "下移", "移到最前", "移到最后". Forbidden: "Priority", "Creation order".
- **Template** — A built-in starting point for adding an API endpoint for a known vendor, relay service or local model server: its base URLs, where to get a key, and, for some, a region or plan to switch between, so the user only pastes a key. "Custom" is the blank form. An endpoint added from one remembers the template and its region or plan, so its page can switch them and offer "Add another"; everything else is the endpoint's own and can be changed. A local server's template asks only for the server address (zh-CN UI: "服务地址"); changing it moves each format's base URL to that scheme, host and port and keeps the path. UI: the add dialog lists them in the groups "Vendors", "Relay services" and "On this machine", after "Custom"; "Get a key ↗", "Region" or "Plan"; "Add another" adds one more from the same template. zh-CN UI: "模板", groups "厂商", "中转服务", "本机", "自定义", "去拿 key ↗", "区域" / "套餐", "再加一家". Forbidden: "Preset" / "预设".
- **Duplicate** — Opening the add dialog filled with everything of one API endpoint, its key included, under the name "<name> copy", so another key or address of the same service becomes its own endpoint. Nothing is added until it is saved. UI: "Duplicate". zh-CN UI: "复制", name "<name> 副本".
- **Model scope** — Which of an API endpoint's models it serves: **Vendor's list**, the models it lists, at most the first 24, following the list as it changes; or **Picked only**, the models the user turned on. New endpoints start on Vendor's list. "Selected models" of an endpoint means the ones its scope serves. On Picked only, "Auto-pick rules" are name patterns whose new models get turned on when the list is fetched again. UI: "Vendor's list", "Picked only", "Auto-pick rules". zh-CN UI: "服务范围", "跟随接口清单", "只用挑选的", "自动勾选规则".
- **Endpoint name in model lists** — A host setting for whether a model offered by an endpoint shows the endpoint's name after it in model lists, the **Default model** choices and Codex's `/model`: always (the default), only when several endpoints offer that name, or never. UI: "Endpoint name in model lists", choices "Always", "Only when names clash", "Never". zh-CN UI: "接口名显示方式", "一直显示", "同名时显示", "不显示".
- **Model settings** — What the user sets for one model on one API endpoint, over what Osuna found out by itself: display name, context window, output limit, thinking levels, whether it takes images, the **Upstream name**, **Compact at**, and **Use only this format**. An endpoint can also set some of them once for all its models, under "Defaults for all models"; a model's own setting comes first. Ticking no thinking level means no thinking parameters are sent. "Restore default" goes back to what Osuna found. A field's "Restore default" clears that field; "Restore all defaults" takes away all of the model's settings. UI: "Model settings", "Defaults for all models", "Restore default", "Restore all defaults". zh-CN UI: "模型设置", "整家默认", "恢复默认", "全部恢复默认".
- **Upstream name** — The name a model is sent under to its endpoint, when the vendor wants a different one from the name agents pick. UI: "Upstream name". zh-CN UI: "上游模型名".
- **Compact at** — The number of tokens at which Claude Code and Codex compact a conversation on this model. A token count, not a percentage. UI: "Compact at". zh-CN UI: "压缩阈值".
- **Long conversations** — The host-wide setting at the bottom of the API endpoints page that says where Claude Code and Codex compact a conversation when neither the model nor its endpoint sets **Compact at**: at 272K, at the size typed in its own "Compact at", or never under **Full window**. UI: "Long conversations". zh-CN UI: "长对话".
- **Full window** — The **Long conversations** switch that tells Claude Code and Codex a model's whole context window instead of compacting at 272K or the typed size. A model's own **Compact at** still comes first. UI: "Full window". zh-CN UI: "完整窗口".
- **Use only this format** — A model on one endpoint pinned to one **Request format**: the **Gateway** asks that endpoint for that model only in that format. UI: "Use only this format". zh-CN UI: "只用这种格式".
- **Test models** — Sending each model an endpoint serves one tiny request and showing per model whether it answered, in which format and how fast. Results last only while the page is open; "Working only" drops the models whose last test failed. UI: "Test models", also "Test as Claude Code" and "Test as Codex", which send the headers the CLI itself last sent through the **Gateway**; filters "Free only" and "Working only". zh-CN UI: "测试模型", "只看免费", "只看能用". Don't confuse with the endpoint's connection test.
- **Disabled models** — Model names or patterns the user turned off for the whole host: no endpoint offers them and the **Gateway** turns a request for one down, saying which entry did it. UI: "Disabled models". zh-CN UI: "已禁用的模型".
- **Don't check its certificate** — An API endpoint's setting to accept its own https server's certificate without checking it, for a self-signed or company certificate. Only for an endpoint added from "Custom". Turning it on asks first, and its row shows it while on. UI: "Don't check its certificate". zh-CN UI: "不校验证书".
- **Headers** — What an API endpoint adds to each request it is sent, its tests included: "Headers", which win over the ones Osuna sets; "Extra body", JSON added to each request body; and "Key header", which header carries the key on an Anthropic base URL. zh-CN UI: "请求头", "附加请求体", "key 放在哪个头".
- **Cooldown settings** — An API endpoint's own lengths of **Cooling down**, under "Advanced": "Rest after quota runs out" (when the vendor doesn't say when it is back: "Minutes", 15 when empty, or "Until a time" each day, such as 08:00 on the host's clock or 00:00+08:00 on the vendor's) and "Longest rest" (the most it rests while it keeps failing or being rate-limited; 10 and 30 minutes when empty), or "Don't rest after unknown failures" in place of the longest rest. A time the vendor gives still wins. "Rest" in these labels is **Cooling down**. zh-CN UI: "额度用完后冷却多久"（"按分钟" / "到某个时刻"）, "冷却最长多久", "原因不明的失败不冷却".
- **Import** — Adding API endpoints from the configs of other apps on the host (CC Switch, Claude Code, Codex, OpenCode, Alma), read only, or from an import link that opens Osuna. Each found entry shows whether it is new, already added, under a name in use, or the same service with another key. An import link always asks first, naming the hosts that would get the prompts and the key. UI: "Import", the dialog "Import from other apps", statuses "New", "Already added", "Name in use", "Same service, another key"; the endpoints page's prompt "Found {count} local configurations" with "Review" and "Ignore"; the link's dialog "Import link". zh-CN UI: "导入", "从别的软件导入", "新的", "已添加", "名称已被占用", "同一家、key 不同", "发现 {count} 个本地配置", "查看", "忽略", "导入链接".
- **Searches the web by itself** — An API endpoint's setting saying the vendor behind it runs web search itself. Shown only for an endpoint with an Anthropic or OpenAI Responses base URL; off by default, and Osuna never turns it on by itself. While at least one endpoint that is on has it on, Claude Code's WebSearch is available; a search then goes only to an endpoint that is on, has it on and serves the same model, and fails with an error when there is none. Codex's own search tool reaches an endpoint only when that endpoint has it on. Osuna never searches on an endpoint's behalf. A `WebSearch` deny rule the user wrote stays and keeps WebSearch off. UI: "Searches the web by itself", in the "Web search" row on the endpoint's page. zh-CN UI: "自己能联网搜索", row "联网搜索".
- **Use API endpoints** — The per-provider switch on Claude Code's and Codex's settings. On: the provider can use the selected models of every endpoint that is on. Off: new sessions run **official**; a session already running keeps using the **Gateway** until it is reopened, and a Codex conversation that Codex recorded under the Gateway keeps resuming through it. Turning it off first lists what goes back in the CLI's config. It can be turned on only when at least one endpoint is on and has a model selected, and only while the daemon listens on TCP. UI: "Use API endpoints". zh-CN UI: "使用第三方接口". Code: `agents.<provider>.enabled` in `endpoints.json`.
- **Default model** — The model a provider starts with while **Use API endpoints** is on, chosen from the selected models of the endpoints that are on: a bare model name, which any endpoint offering it may serve, or one endpoint's model, which starts at that endpoint and fails over to the others offering it. Written into the CLI's own config, so new terminal sessions start with it; when the user saves another model the endpoints offer as the default from the CLI's own model picker, it follows. A new Osuna chat uses it only when there is no remembered last choice.
