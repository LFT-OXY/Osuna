# Component Guidelines

`docs/design.md` is the design system: character, hierarchy, buttons, borders, density, states, and the forbidden list. This guide is the component-level mechanics that reviewers check.

## Reuse the primitive

Before writing markup, find the canonical surface in `docs/design.md` §15 and copy its shape. The primitives in `components/ui/`:

| Need                       | Use                                                                                        | Not                                                |

| A list row                 | `components/ui/row.tsx` `<Row>`; own press target → `getRowSurfaceStyle`                   | Per-file hover / selected / pressed fills          |
| A button                   | `components/ui/button.tsx`                                                                 | `<Pressable>` wrapping `<Text>`                    |

> **Warning**: on macOS Electron, `confirmDialog()` shows only `message`. It goes to `dialog.showMessageBox` (`packages/desktop/src/features/dialogs.ts`), which puts `title` in the window title that a macOS sheet never draws. A confirmation whose `title` carries the subject ("Switch Claude Code to QA Relay?", "Delete QA Relay?") reaches the user without saying what it acts on. Until the desktop handler moves `title` into `message`, make `message` name the subject on its own.

A collapsible group inside a `Combobox` ("More agents (N)") is one more option, not a second list: put a sentinel option between the visible rows and the folded ones, append the folded rows only while expanded, set `keepOpenOnSelect`, and in `onSelect` toggle on the sentinel and close yourself on everything else. Arrow keys and Enter then reach the toggle row like any other, which a `Pressable` footer below the list would not. Leave `searchable` off — filtering a list with a fold in it hides the toggle. Reference: `composer/agent-controls/provider-control.tsx`; its required `surface` picks the icon-only toolbar button with a tooltip, or a labelled sheet row whose list opens with `presentation="push"` over the Agent controls sheet.

The Composer thinking control is `ThinkingPicker` (`composer/agent-controls/thinking-picker.tsx`) with a required `surface` like the provider control: the same component serves the toolbar popover and the Agent controls sheet's push page, and always holds the slider (Styling "Thinking slider"). Its `onSelect` keeps the popover open. Whether the trigger shows, and whether it is enabled, comes from `resolveThinkingControlState` in `composer/agent-controls/index.tsx`: a single option is a disabled trigger, not a one-stop slider.

`useModelBrowser` and `CombinedModelSelector` take a required `scope`. Pass `"selectedProvider"` only where a separate provider control sits next to the model trigger — the composer toolbar when `hasProviderControl`, and both browsers in `composer/agent-controls/model-sheet.tsx`, whose settings list carries the provider row. The browser then sees only the current provider, opens on its view even before the provider is listed, drops the back button, shows every profile the picker offers, and moves an open provider view to the new provider when it changes underneath (`followSelectedProviderView`; the narrow-composer dialog shows the list and the provider row side by side). Open it with `prepareToOpen()`, not `showAll()`/`drillDown()` — the root view under this scope is only the compact sheet's settings list. Every other surface passes `"allProviders"` — a schedule form or settings page with `"selectedProvider"` has no way left to change provider. Pure rules and their tests: `components/model-browser-view.ts`.

## Fallible actions own their three states

Every user action that can fail renders pending, success, and failure in the same context (`docs/testing.md` "Fallible user actions"). Disable the trigger while pending, show the result or an acknowledgement, keep an actionable error visible until retried or dismissed. `screens/settings/host-page.tsx` and `screens/project-settings-screen.tsx` are references. Eleven files still call `Alert.alert`; do not add a twelfth.

An inline editor that expands in place (the Models section's add row, `provider-detail/models.tsx`) follows the same bar: the submit button reads "Adding..." and is disabled while the write runs, success folds the row away, failure stays under the input with the reason while the typed text is kept. Pass the write in as `(value) => Promise<void>` and let the row own its `idle | adding | failed` state; the jsdom test drives all three through a deferred promise.

> **Warning**: Escape never reaches a text field inside a desktop `AdaptiveModalSheet`. `lib/overlay-root.ts` listens for `keydown` on `window` in the capture phase and the top modal's handler closes it with `stopImmediatePropagation`, so the field's `onKeyPress` does not fire. An "Esc collapses this row" rule holds on a settings page and on mobile (no overlay scope is registered there), not inside a desktop modal. Don't add a global listener to fight it (`docs/floating-panels.md`); give the row a visible Cancel.

## Hover

Read `docs/hover.md`. A simple list row is `<Row>` (`components/ui/row.tsx`), which already is the pattern: a plain `View` with `onPointerEnter` / `onPointerLeave` as the hover envelope, a separate inner `Pressable` for press only, fixed `minHeight`, and `renderActions` hidden by `opacity` + `pointerEvents` and drawn over the trailing slot. A row with its own press target copies the workspace row in `components/sidebar-workspace-list.tsx` and paints its states with `getRowSurfaceStyle`. Hover only fires on web, so anything hover-revealed is gated `isHovered || isNative || isCompact` so native and phones always see it. A hover readout that sits outside the envelope — a caption naming the hovered cell — needs the same fixed box: an empty `<Text>` collapses, and the reflow on `pointerleave` swallows the next click aimed anywhere below it (`docs/hover.md` failure mode 2).

`<Row>` paints the sidebar row roles (`surfaceSidebar*`), so it only belongs on the sidebar or canvas. A list inside a `surface2` card — the changed-files list in `agent-stream/turn-changed-files-card.tsx` — paints its own hover with a `Pressable` style callback (`hovered ? surface3`), which is the one legitimate use of `onHoverIn`-style state: the `Pressable` styling itself.

A list row that needs a hover kebab **and** a right-click / long-press menu is `SessionHistoryRowItem` in `session-history/index.tsx`: the plain `View` envelope holds `isHovered` and `contextMenuOpen`; `ContextMenuTrigger` is the inner press target (press opens, right click and native long press open the menu); the kebab sits in a fixed-width trailing slot hidden by `opacity: 0` + `pointerEvents="none"`, never unmounted; `useOpenKebabMenuVisibility(isHovered || isNative || isCompact)` keeps it mounted while its menu is up. Both menus render one `…MenuItems` component switched by a `surface: "context" | "dropdown"` prop (`session-history/internal/row-menu.tsx`, the same shape as `components/sidebar/sidebar-workspace-menu.tsx`) so the two cannot drift; an action the row cannot offer (import for a Paseo-owned session) is passed as `null`, not hidden by a boolean.

A hover envelope that also shows a tooltip wraps the plain `View` in `TooltipTrigger asChild`: the trigger composes its own `onPointerEnter` / `onPointerLeave` with the envelope's, so one element drives both the hover state and the tooltip, and moving onto the inner `Pressable` does not close it (`pointerleave` ignores descendants).

A `TooltipTrigger asChild` around a plain `View` reports opening more than once per hover: it wires `onPointerEnter` and `onMouseEnter` (and `onHoverIn`) to the same handler, and `Tooltip` calls `onOpenChange(true)` for each without comparing to the current state. Anything with a side effect on open (a refetch) runs only on the closed → open transition, tracked in a ref the handler updates. Without it the plan usage gauge sent two `provider.usage.list` requests per hover. Reference: `handleCardOpenChange` in `provider-usage/strip-gauge.tsx`.

A tooltip that is a panel rather than a one-line hint sizes its frame, not its content. Pass `maxWidth` to `TooltipContent` and put `width`, `paddingVertical: 0` / `paddingHorizontal: 0`, and the radius in its `style`; the sections inside pad themselves. Never give the inner content a `minWidth`: the frame is `border-box` with its own border and default padding, so inner `minWidth` equal to the frame's `maxWidth` draws past the border on one side (the old turn usage panel overflowed by 18px and read as off-centre, because positioning centres the frame, not the content). Change the `TooltipContent` defaults only for every caller at once. Reference: `agent-stream/turn-usage-panel.tsx`.

A highlight the arrow keys also move (the Command menu) listens to `onPointerMove` on the envelope and has no leave handler; `docs/hover.md` "A highlight the keyboard also moves" says why.

`onHoverIn` / `onHoverOut` has one legitimate use: a `Pressable` styling itself (`components/ui/button.tsx`), preferably through the render-prop `style={({ hovered }) => …}`. The moment hover state is read by anything else, use the envelope. Never put both handler kinds on one element.

That use still needs a press target. A frame that only recolors on hover and has no `onPress` is not one: react-native-web gives every enabled `Pressable` `tabIndex=0`, so keyboard users land on a dead stop before the input inside it. Use the plain `View` envelope. The expanded "other" row in `components/question-form-card.tsx` (`QuestionOtherInputRow`) is the example. It draws its own field frame because `FormTextInput` cannot hold the number badge inside its border. The frame still takes its states from `createControlGeometry(theme)` (`controlRest` / `controlHover` / `controlActive` / `controlDisabled`) through `resolveControlInteractionStyles`, as `FormTextInput` does. Copying only the border colors drops the focus ring that `controlActive` draws. A field with nothing inside the border is `FormTextInput`.

## Platform gates

Import from `constants/platform.ts`: `isWeb` for DOM APIs, `isNative` for native-only APIs, `getIsElectron()` for the desktop bridge, `useIsCompactFormFactor()` from `constants/layout.ts` for layout. Never redefine `Platform.OS === "web"` locally, never touch `document`/`window` without `isWeb`, never use `Platform.OS` to make a layout decision.

## Accessible names

On web, a screen reader reads `aria-label` only from an element that has a role. `accessibilityLabel` on a `<Text>` or a role-less `View` renders as `aria-label` on a generic `div`; Chromium's accessibility tree drops that name and reads the text content instead. A non-interactive item that needs its own name (an inline block read as "Skill: name") puts the label on a `role="group"` container, as the sidebar project block does (`components/sidebar-workspace-list.tsx`). On native a role-less container is not an accessibility element, so iOS never reads that label; give it to the visible `<Text>` there. `InlineBlockView` (`inline-blocks/block-view.tsx`) splits the two with inline `isWeb ? label : undefined` / `isNative ? label : undefined`. Verify a web name through the AX tree (`Accessibility.getFullAXTree` over CDP shows `group: Skill：atw-tdd`), not by finding the attribute in the DOM.

## Copy

All user-visible strings go through i18next: `const { t } = useTranslation()` and `t("agentList.dateSections.today")` (`components/agent-list.tsx`). Keys live in `i18n/resources/en.ts` and the other nine locales; add the key to every locale file. The word in UI is "workspace", never "checkout" (`docs/glossary.md`).

`i18n/resources.test.ts` is the contract for a new namespace: every locale carries the same key set, fewer than 25% of a locale's strings may equal English, and each key's `{{placeholders}}` must match English exactly. `zh-CN` is stricter: any value equal to English (after stripping `{{placeholders}}`) must be on `zhCNEnglishAllowlist`, and a listed key that no longer equals English fails too — so a new key needs a real Chinese value, and a kept-English one (Agent, PR, brand, named theme, placeholder example) goes on the allowlist in the matching category group. The zh-CN resource never references `en.*` or spreads an English block; write every value literally. A zh-CN value also must not contain a retired spelling from `zhCNRetiredTermPattern` (智能体, 变更, English Host / Workspace / Model / merge …), checked after stripping `{{placeholders}}` and backtick code; write the term the glossary or `docs/i18n.md` names (`"未提交的更改"`, not `"未 commit 的变更"`). A value whose English is a config key, slash command, or placeholder (`model_provider`, `/model opus`) goes on `zhCNRetiredTermExemptKeys` as a whole key. When you retire a spelling that has no other meaning, add it to the pattern. When you replace a hardcoded English string with a key, append the literal to `migratedSourceLiterals` in the same file so the source scan blocks its return. The scan matches only `"literal"` and a template that starts `` `literal ``, so JSX text (`<Text>Enable terminal agent hooks</Text>`) is invisible to it. List the literal anyway, because the same text often also sits in a quoted prop such as `accessibilityLabel`. For a template, list its static prefix (`"Restart acknowledged: "`). Leave a literal off when it would match text that is not the migrated string: a quoted mention in a comment (`Offer "All hosts".`), a prefix of a longer word (`"Browse"` hits `` `Browser ``), a short word that also starts an unrelated template or prop elsewhere (`"Host"` hits `` `Host ``, `"Bottom"` is a sheet placement), or copy another ticket's file still owns (`"Filter: "` in `import-session-sheet.tsx`). The scan then fails on the first run, and removing the entry is the fix. Rules and categories: `docs/i18n.md`. Those checks shape how you key things:

- **A pure module never imports i18n or returns English.** It returns a description the component renders: `ScheduleDescription = { key, params? } | { text }` in `utils/schedule-format.ts`, rendered by `renderScheduleDescription(t, desc)`; params may nest another description (`"{{day}} at {{time}}"` with `day` itself a key). `{ text }` is for verbatim values (a raw cron expression, an agent title). A state union adds a variant rather than carrying client English in a message field: `unsupportedAction` resolves to `{ kind: "needsAppUpdate" }` in `screens/workspace/workspace-route-state.ts`, and `workspace-route-state-views.tsx` renders `workspace.route.recovery.updateToRecover`; `message` stays for daemon text. A constant table that mixes proper nouns with generic labels types each row as `{ name } | { nameKey }` (browser `DEVICE_SIZE_PRESETS`: "iPhone 14" stays, "Laptop" is translated). The pure tests assert the structure; a second set renders through `i18n.t` in `en` and asserts the exact previous English, which is the guard that a refactor changed no user-visible word.
- **A pure async flow throws the description, not English.** An error the client writes itself carries `{ key, params? }` for the render site (`DaemonLifecycleError` in `screens/settings/daemon-lifecycle.ts`); any other error renders as its own text, because daemon and runtime errors stay verbatim. A wrapped cause keeps its previous English shape, including the `Error: ` that `String(error)` used to add. The one sanctioned change is a missing version, which reads "unknown" instead of "null" so no locale shows a JS literal.
- **Vary by key, not by interpolated noun.** "Edit schedule" / "Edit heartbeat" is `schedules.row.menu.edit.{schedule,heartbeat}` and the component assembles the key from a `"schedule" | "heartbeat"` identifier. `"Edit {{product}}"` breaks the moment one locale needs an article, a case ending, or the noun capitalized differently, and the placeholder-parity test forbids a locale from dropping the placeholder. Singular/plural is two keys with `{{count}}` (`interval.minuteOne` / `interval.minuteMany`), matching `modelSelector.modelCountPlural`, not i18next plural suffixes: the parity test allows only the English key set, so `ru` has no `_few`/`_many` and `ar` no `_two`/`_few`, and i18next falls back to the English string for those counts. Where the sentence has no singular case worth a key, phrase it count-agnostic with one key (`"Running {{provider}} sessions that may be affected: {{count}}"`, `settings.providers.apiEndpoints.impact`).
- **A noun only English needs wraps the translated parts.** The PR checks line "3 failing, 21 successful checks" is per-status phrases (`workspace.git.pr.checks.count.<status>`, zh `"{{count}} 项失败"`) joined by `countSeparator` (`", "` / `"，"`), then wrapped by `countLine.one` / `countLine.many` (`"{{parts}} check"` / `"{{parts}} checks"`). zh writes both as `"{{parts}}"`, because 项 already counts and the headline above says 检查. Do not append a separate noun key: zh would need `""` or a stray trailing space. The group header reuses the same wrapper with one part ("2 failing checks" / "2 项失败"). `summarizeChecks` in `git/pull-request-panel/checks-summary.ts` returns only `outcome`, `parts: { status, count }[]`, `total`, and `groups`; `formatChecksHeadline` / `formatChecksCount` / `formatChecksGroupLabel(t, …)` produce the copy, and `checks-summary.test.ts` asserts the structure, the exact English, and `i18n.exists()` for every status in the exported `PRESENTATION_ORDER`. The line renders as one string, so per-part testIDs are gone; select a group by `pr-pane-check-group-<status>`.
- **Keys assembled at runtime get an existence test.** `t()` returns the key string when it is missing, so a renamed family fails silently; `utils/schedule-format.test.ts` asserts `i18n.exists()` for every `family.product` and state key the components build.
- **Never interpolate an internal id into copy.** `` `Add project: ${page.kind}` `` read "添加项目：github-search" in Chinese. Key it per id instead: one pure map from id to key segment (`ADD_PROJECT_PAGE_KEYS` in `add-project-flow/options.ts`) feeds both `addProject.titles.*` and `addProject.panelAccessibilityLabels.*`, so the title and the label cannot drift, and `add-project-flow/model.test.ts` asserts `i18n.exists()` for every segment. English values keep the old text byte-for-byte (`"Add project: github-search"`); other locales write the page name.
- **A set you compare translated text against is built by the same function that renders it.** Plugin themes are disambiguated by comparing a contributed name to the built-in theme names (`plugins/themes/index.ts` `collectPluginThemes`), and both the picker rows and that comparison set resolve through `appearance/theme-labels.ts` — one key path, one `t`. Two call sites building the same label independently drift on the next key rename, and the failure is silent: nothing matches, so the feature quietly stops firing. Such a set is also language-scoped by construction — pass it in as an argument and let the pure function stay pure, rather than importing i18n into it; the comparison then follows the user's language for free, and the unit test swaps the set to prove it.

- **English stays byte-identical to what it replaced.** Playwright specs locate controls by English accessible name (`getByLabel("Schedule name")`, `getByRole("button", { name: "Create schedule" })`); the e2e run is the proof the migration changed nothing. When a localized wrapper has nothing to add in English, the English value is the bare placeholder (`schedules.cadence.errors.invalid: "{{detail}}"` wraps the cron library's English reason; zh-CN is `"无效的 cron 表达式：{{detail}}"`).
- **`utils/time.ts` `formatTimeAgo` ("5m ago") is deliberately English** and shared app-wide; localize the prefix around it (`"Created {{ago}}"`), not the value.
- **Daemon-authored timeline text is localized from structured facts, not from `message`.** A `notification` the daemon adds carries an optional field with the facts (`apiEndpointModeMismatch`), and `message` stays the English fallback for old clients. The render site asks a pure function for `{ key, params } | null` and keeps `message` on `null` (`agent-stream/view.tsx` → `describeApiEndpointModeMismatch`). Vary by key per case (`agentStream.apiEndpointMode.{endpointToOfficial,deletedToOfficial,officialToEndpoint,endpointToEndpoint,deletedToEndpoint}`), not by interpolating "Official" as a noun.
- **A rejected daemon password renders from its reason, not from the error message.** `DaemonAuthenticationError` in `packages/client` carries hardcoded English (`"Password required"`, `"Incorrect password"`), and it also lands in the host snapshot's `lastError`. A render site reads the reason (`getConnectionAuthFailureReason(error)` for a thrown error, `snapshot.authFailureReason` for a stored host) and shows `t(authFailureMessageKey(reason))` (`utils/test-daemon-connection.ts` → `pairing.hostPassword.errors.required` / `incorrect`); any other connection error stays verbatim. Used by the host overview and Connections pages, the direct-connection dialog, and the pair-link dialog. `utils/test-daemon-connection.test.ts` asserts both keys exist and that English equals the client's text, which `e2e/browser/settings-host-page.spec.ts` matches. The Agent panel's offline detail still prints `lastError` raw.
- **Key a string by the surface that shows it, not by the feature that owns the data.** The API endpoint feature's strings live in three namespaces: the conversation notice under `agentStream.apiEndpointMode.*`, the plan usage label under `usage.planUsage.apiEndpointNote`, the provider-detail warning under `settings.providers.apiEndpoints.inheritedTitle` / `inheritedDescription` (`docs/i18n.md`).

## The Composer web input is a Tiptap editor

`composer/input/text-input.web.tsx` keeps the `EditingTextInputHandle` and RN callback shapes, so `MessageInput` does not know it is not a textarea. When you touch it:

- **The text is the sent text.** `getText()`, `onChangeText`, and every offset the Composer sees are in the serialized message: a picked file is `[x.ts](src/x.ts)` there but one ProseMirror position in the editor (an atom `inlineBlock` node, `inline-block-node.web.tsx`). Convert only through `offsetAtPos` / `posAtOffset` in `editor-text.web.ts`; never compute `position - 1`. Send needs no change, and ticket 05 (leading Skill blocks with their `/a /b ` separators) has to keep that mapping exact.
- **Segments are the second channel.** State that outlives the editor reads `getSegments()` and writes back through `replaceSegments(segments)` (whole-document swap, not in the undo history) or the `initialSegments` prop; never through `replaceText`, which never creates a block. What each store keeps is in `state-management.md` ("Unsent Composer content keeps its segments").
- **Node views read the host from context.** `InlineBlockServerIdContext` (`inline-block-node.web.tsx`), provided around `EditorContent` from the `inlineBlockServerId` prop, lets an Agent mention resolve a custom provider icon from the provider snapshot. A profile mention's icon comes from `AgentProfileIconContext` instead (see `testing.md` on why `block-view.tsx` cannot read profiles itself): the profile's `icon`, else its provider's icon, else `Bot` when the profile is gone or config has not arrived. Tiptap renders node views through portals inside `EditorContent`, so context reaches them; editor options and node attributes cannot carry it.
- **`@` and `/` never reach back into a block.** A link target can hold `@` (`node_modules/@types`) or ` /`. The editor reports `blockBoundary` (end offset of the last block before the caret) in `getSelection()` and as a sibling of `selection` in the selection event; `findActiveFileMention` / `findActiveSlashCommand` reject a token that starts before it.
- **`replaceText` keeps blocks it does not touch.** The Composer replaces whole strings (command completion, dictation, clear, draft restore). The editor diffs against its current text and rewrites only the changed middle; a block the change overlaps becomes plain text. A pick goes through `insertInlineBlock(block, range)` instead, which adds one space unless the text after the range already starts with one, and lands in the undo history (undo restores the `@query`). Native has no `insertInlineBlock`; `MessageInput` inserts the link text with `insertInlineBlockText`.
- **Clipboard.** Paste reads only `text/plain`, so link text from outside stays text. A copy or cut whose selection holds a block is taken over: `text/plain` gets the serialized text and `application/x-paseo-inline-segments` gets the segments JSON, which paste checks with `isInlineSegment` before rebuilding blocks. A copy without blocks stays ProseMirror's default.
- **Keys over blocks.** ArrowLeft/Right, Backspace, and Delete next to a block are handled in `InlineBlockKeys`; Chromium adds stray caret stops around inline `contenteditable=false` elements otherwise.
- **Initial selection goes in `onMount`, not `onCreate`.** `onCreate` fires a tick later and overwrites a selection the Composer set in its mount effects (a restored draft, a Rewind).
- **ProseMirror's selection lags the DOM.** It syncs on the async `selectionchange`, and keydown only flushes pending DOM mutations. A handler that runs before that sync (`beforeinput` from `fill` or a text service, a paste right after an arrow key) reads the target range from the DOM selection, not `view.state.selection`: both go through `insertionRange`. Wrong: `tr.replaceSelection(slice)` in `handlePaste`; after Select All then ArrowRight, the paste still replaced the whole document.
- **`useEditor` compares options every render.** Build them once with `useMemo` and read changing props through refs; an inline options object makes every rerender call `setOptions`.
- **Composition.** Report text only when `view.composing` is false, and once more after `compositionend` (ProseMirror clears `composing` inside its own handler).
- **Styling** comes from the Composer's `withUnistyles` `.hash > *` rule landing on the root `div`; the `style` prop is emptied on web and not read.

## The `@` list and the Command menu

Both render through `components/ui/autocomplete.tsx`; `hooks/use-agent-autocomplete.ts` builds the options and `hooks/use-autocomplete.ts` owns highlight and keys.

- **Groups.** `getAutocompleteGroup` maps `kind` to `commands` / `skills` (Command menu) or `agents` / `files` (`@` list); `orderAutocompleteGroups` puts the second group of each pair below the first. A title goes in where the group changes, except a `files` group that opens the list: an `@` list with no agent rows has no titles.
- **Unavailable rows stay visible.** An option with `disabled: true` renders at `opacity[50]`, `aria-disabled`, with no `onPointerMove`; `useAutocomplete` never highlights or selects it, and `getAutocompleteFallbackIndex` / `getAutocompleteNextIndex` step over it. With no selectable row, keys pass through to the input (Enter sends), same as an empty list, and `AutocompletePopover` shows without waiting for a highlight (`hasSelectableAutocompleteOption`).
- **Why a group is unavailable** goes in `groupNotices[group]` (`message`, optional `detail`, optional `action` rendered as an outline `sm` `Button`) under that group's title, never as a fake row.
- **The list opens at the top** whenever the highlight is on the first selectable row, even if that row is then below the fold. A grayed agent group sits above the first file, and its reason must be visible before the highlighted file (decided with the user in multi-agent ticket 06). Keyboard moves past that row follow the highlight as before.
- **The agent group** comes from `useAgentMentionGroup`: enabled providers from the provider snapshot, in snapshot order (the Providers settings order), filtered by label or id; then Agent profiles whose provider is listed, in config order, filtered by name, with the provider label as `description`. A profile whose id fails `isAgentMentionTarget` (empty or containing `/`, only possible by editing config by hand) is skipped: its link would parse back to text and never dispatch. Profiles reach the hook as the `agentProfiles` input, read by `ComposerAutocompleteBinding` through `useAgentProfiles`: importing `@/agent-profiles` at runtime in `use-agent-autocomplete.ts` pulls the settings components into its node unit test. A profile row carries data, not a node — `profileGlyph: { icon, color }` plus the provider icon as `Icon` — and `autocomplete.tsx` draws `AgentProfileGlyph` with `fallbackIcon={Icon}`, so an unknown icon shows the provider's glyph in the profile's colour, matching the block. It shows once `server_info` has arrived, in a composer bound to a loaded agent or in a draft (new agent tab, new workspace screen, workspace setup dialog — any composer given `draftConfig`). A draft has no session, so `resolveDraftCreateAgentsVerdict(entries, draftProvider)` reads the selected provider's prediction from the provider snapshot for the draft's cwd; a provider without prediction fields counts as available. `resolveAgentMentionNotice({ isDraft })` swaps the `tools_not_injected` detail for `toolsNotInjectedDraftDetail` (no "reload this agent": the prediction updates as soon as the switch flips). `resolveAgentMentionAvailability` grays the group when the host lacks `features.agentMentions` or the verdict says `canCreateAgents: false`; a snapshot without the field (stored agent, replica cache) counts as available, because sending resumes the session and the daemon decides. Unknown reason codes get the generic message.

## Timeline tool-call groups

`tool-calls/detail-level/grouping.ts` groups consecutive tool calls by a run key: `runKeyOf(item: ToolCallItem) => key | null`. `null` keeps a call out of every group; a change of key closes the run and starts another. `projection.ts` picks the key function from the detail level and `dispatchGroups`:

| level | `dispatchGroups` | key |
|---|---|---|
| `detailed` | false | none, calls pass through |
| `detailed` | true | subagent call → `"dispatch"`, the rest `null` |
| `overview` | false | every groupable call → `"overview"` |
| `overview` | true | subagent call → `"dispatch"`, other groupable calls → `"overview"` |

A subagent call is `isDispatchToolCall` in `tool-calls/detail-level/dispatch/model.ts`: `isCreateAgentCall` (the Paseo tool leaf name is `create_agent`) or `isProviderSubagentCall` (`detail.type === "sub_agent"`). The key is decided from the item alone, so a `sub_agent` call from a provider that never publishes descriptors (Pi) still leaves its overview group and renders as a standalone generic card. That cost is accepted.

`ToolCallDetailGroup` is a union on `mode`, and `agent-stream/view.tsx` branches on it. A new kind of group adds a mode and a key, and must not become a second grouping pass. `dispatchGroups` is `useDispatchGroupsEnabled`: the host has `subagentCallLinks` and the view was given `onOpenSubagent`. The read-only provider-subagent panel and drafts don't pass it, so their `create_agent` calls stay generic cards. Whether a call links to a child is decided at render time in `subagents/select.ts`. `resolveDispatchCall` handles `create_agent`: store hit → row, running or lookup pending → `starting`, else generic. `resolveProviderDispatchCall` handles provider calls: one `provider` row per descriptor whose `toolCallId` is the call id (OMP's task starts several), row key `${callId}:${subagentId}`, else generic. Provider calls get no `starting` state: the app cannot tell which providers publish descriptors, and a Pi call would sit on a row that never opens. Only `create_agent` calls get the `includeArchived` lookup. Provider subagents hidden from the track by "Archive finished" still render in the group. A call that doesn't link splits its card and renders through the generic tool-call renderer passed in as `renderGenericCall`. The projection can't know ahead of time.

## React rules that matter most here

- Components render and dispatch. Transitions live in reducers, stores, or the form model.
- Never define a component inside another component.
- oxlint caps a function's `complexity` at 20, and the large render functions (`DesktopAgentControlsContent`, `CombinedModelSelector`) sit near it, so one more `a && b ? <X /> : null` fails lint. Move the decision into a pure resolver next to the layout code (`resolveComposerSeparators` in `composer/agent-controls/layout.ts`, unit-tested) or the branch into a child component (`DefaultTriggerContent` in `components/combined-model-selector.tsx`). Do not add an `oxlint-disable`.
- Collection rows do not subscribe to the session store individually; the list owner selects once and passes row models (`docs/coding-standards.md` "React").
- Retained native panels use `RetainedPanel` / `RetainedPanelActivity`, keep a stable sibling order, and gate effects through `useRetainedPanelActive` (`docs/mobile-panels.md`).
- Anchored panels go through the portal and lifecycle gates in `docs/floating-panels.md`; the flash and the Android hit-test bug are both documented there.
- On web, `onLayout` fires only when the element's own size changes (react-native-web drives it from a `ResizeObserver`). A row that filtering slides up without resizing never reports its new `y`, so a cache of row positions keyed by index goes stale, and clearing it in an effect leaves it empty. Bind the cache to a signature of what decides the positions and remount the list when it changes: `components/ui/autocomplete.tsx` keys the list `View` by the options' `kind:id` string and keeps `ListLayoutCache` tagged with the same signature, swapping it inside the layout callbacks rather than in an effect, because on native a new row's `onLayout` can land before any effect runs. The regression test filters, then walks the highlight and asserts the row and its group title are inside the scroller (`autocomplete.browser.test.tsx`).
- When a row hides whole items to fit, measure each item's natural width from an invisible copy, not from the visible item: a visible item that has already been squeezed or hidden reports the wrong width or nothing at all. The copy is an `absolute`, `opacity: 0`, `pointerEvents: "none"` column with `alignItems: "flex-start"`, so each child takes its content width. It carries `accessibilityElementsHidden` and `importantForAccessibility="no-hide-descendants"`, and no `testID` or `accessibilityLabel`, so e2e locators and screen readers see each item once. Render nothing visible until every item and the container have been measured. Ignore non-positive widths (`docs/coding-standards.md` "Retained panel measurements"). References: `tabLabelMeasurements` in `screens/workspace/workspace-desktop-tabs-row.tsx`, and the plan usage gauge in `provider-usage/strip-gauge.tsx` (`MeasuredSegment`). The gauge's container, `composer/context-strip/index.tsx`, also measures a hidden `StripBranchTrigger` to learn the branch name's untruncated width. The pure fitting stays out of the component: `fitPlanUsageStripSegments` (`provider-usage/strip.ts`) and `resolvePlanUsageSpace` (`composer/context-strip/model.ts`) are unit-tested in Node.
- A table whose columns must line up across rows (name / bar / percent / trailing) is rows, not columns, so each row reads in order for screen readers. Each measured cell is an outer `View` with `minWidth` = the column's widest cell and `alignItems: "flex-start"` / `"flex-end"`, and the `onLayout` goes on an inner wrapper so it reports the text's own width, never the stretched one; the column width therefore follows the content in both directions. Key the measurements by column and a row key, and take the max over the current rows only. Several tables that sit one above another share one measurement (pass it down) so their bars start on one line. Reference: `useProviderUsageTableColumns` / `providerUsageTableRowKeys` in `provider-usage/card.tsx`, shared across providers by `provider-usage/list.tsx`. A hidden sizer that renders every label in every cell avoids measuring, but it duplicates the text and breaks `getByText` in e2e.
- An icon beside a label that truncates goes in `ToolbarLabelTriggerIcon` (`components/ui/toolbar-label-trigger.tsx`, `flexShrink: 0`). A bare lucide icon in a shrinking row shrinks with the text: the strip branch trigger's 12px icon was squashed to about 4px at a 420px Composer.
- A settings page with its own list of items stacks list and detail at every width: the section route shows the list and a row `router.push`es the item route (Providers: `screens/settings/providers-page.tsx`). Don't nest a second pair of columns inside the settings detail pane. The two-column Providers layout was removed because it had to measure the pane with `onLayout` (the app sidebar can sit beside Settings, so the window width overstates it), render nothing until the first measurement, and `router.replace` the section route to the first provider; the stacked page needs none of that.
- The Providers list groups by `enabled` alone, through one pure function, `groupProvidersByEnabled` (`screens/settings/provider-placement.ts`): enabled providers go in "Enabled" whatever their status (ready, loading, error, unavailable), turned-off ones in "Disabled", both in snapshot order. Don't split by `status`: the daemon doesn't probe a disabled provider and reports it `unavailable`, so status can't tell "turned off" from "not installed", and a disabled row must never claim "Not installed" (`resolveProviderStatusLine` returns `statuses.disabledUntilEnabled` for it). The Add provider dialog holds only the ACP catalog and does not read the grouping. A row switch writes `enabled` and waits for the snapshot to move the row; it never moves optimistically. The pending id, the failure message, and the just-moved row are one reducer (`useProviderToggle` in `screens/settings/providers-section.tsx`), and the move highlight is gated on `useReduceMotionEnabled()`. The provider detail follows the same rule from its header: the switch (`ProviderDetailEnabledSwitch`, in the in-page header block on wide screens where Refresh and ⋯ already sit, in the `BackHeader` on a phone) waits for the snapshot, and while `enabled` is false `ProviderDetailSurface` renders only the removal and switch failures plus the disabled card, never the Install and upgrade section: the snapshot's `unavailable` means "not probed" there. Once enabled, that section shows whether or not the CLI is installed, under the version section (`docs/glossary.md` "Install and upgrade"; adding a provider's commands is in `docs/providers.md`). Only its title and the "Install" / "Upgrade" headings are translation keys. Tab names are the install-method names from each provider's official docs and stay as written in every locale, the generic "Install script" included: the task's PRD decided the tabs must read the same as the docs the link opens, which overrides the `{ name } | { nameKey }` rule in Copy below for this table. A row's upgrade button sits in its status line: `ProviderStatusLine` (`screens/settings/provider-status-line.tsx`) renders `{status} · v{version}` and takes the button as `children`, and `ProviderUpgradeButton placement="statusLine"` (`provider-detail/upgrade-view.tsx`) is an `xs` outline with `ArrowUp` reading "Upgrade to v{latest}"; the detail's version section keeps the default `placement="section"` (`sm`, "Upgrade"). The status line never shows "v{from} → v{to}"; that string is the button's tooltip and the version section's value. Pass the button as children, not a JSX prop (lint rejects JSX props on unmemoized elements).
- A settings page that corrects its own address from an effect (`router.replace` back to the list when the address names a missing provider) gates the effect on `useIsFocused()`. Stack entries below the focused one stay mounted and keep running effects; an ungated redirect in the hidden list page would replace the page on top (`ProvidersPage` in `screens/settings/providers-page.tsx`). When the page header and the body both depend on what the address resolves to, they read one hook: `useProvidersView` decides list / detail / missing for both the body and the detail headers (`screens/settings/providers-header.tsx`), so the header never shows "Providers / {name}" over the list's loading or disconnected card.
- A settings card whose first row is a tab strip (`InstallMethodTabs` in `provider-install-guide/index.tsx`, up to seven install methods) is `[settingsStyles.row, column override]` around a horizontal `ScrollView` around one `SegmentedControl size="sm"`. The row's own 16px padding insets the scroll viewport, so a tab that scrolls out is clipped on the card's content rail, not on its border. Give the control `alignSelf: "center"`: a horizontal scroll content container stretches its child to the row's height and the track grows past its 28 / 32. Padding never goes on this `ScrollView`'s `contentContainerStyle` (`docs/unistyles.md` "Main Gotcha").
- A settings list built from `SettingsCard` and `SettingsRow` (`components/settings/index.tsx`, the plugin-facing primitives) gets the card and the row dividers from `settingsStyles`: `SettingsCard` wraps each child and puts `rowBorder` on every one after the first. Rows inside it carry no divider of their own and no `isFirst` prop (`PluginRow` in `screens/settings/plugins-page.tsx`). Hand-composed `[settingsStyles.row, !isFirst && settingsStyles.rowBorder]` is for rows that are not direct children of a `SettingsCard`. `SettingsRow` takes a status badge through `labelAccessory` and a multi-line description through a `ReactNode` `hint`. Every line of that description is `settingsStyles.rowHint` (`caption`, `foregroundMuted`): a settings row has one hint style, so a second line (the plugin's install source under its description) is not a size or a tone lower. `foregroundExtraMuted` is for passive chrome (`docs/design.md` §3), not for text the user reads.
- A row's trailing actions menu in settings is a 28×28 `DropdownMenuTrigger` with `radius.md`, `surface2` on hover or open and `surface3` on press, around a `withUnistyles(MoreHorizontal)` at `ICON_SIZE.sm` that goes from `foregroundMuted` to `foreground` on hover or open. Pass the style and the icon as functions of `DropdownMenuTriggerState`. Three copies exist (`screens/settings/keyboard-shortcuts-section.tsx`, `provider-detail/header.tsx`, `screens/settings/plugins-page.tsx`); a fourth call site extracts the primitive instead of copying again.
- A ghost `<Button>` in a card row's trailing slot takes `marginRight: -theme.spacing[3]` (the `sm` horizontal padding) so its label ends on the card's trailing rail with the row values around it (`docs/design.md` §8); the hit area grows outward. When the row's content wraps to several lines, put the vertical padding on the text, not the row, and keep a caption above the text outside the row that holds the button: the button then centers on the command, and a one-line and a wrapped command sit the same distance under their heading (`InstallCommandRow`, same file).
- `key` is a stable id, never an index (lint enforces `react/no-array-index-key`). A label repeats where a position does not — seven weekday initials are `M T W T F S S` — so key by a stable id list beside the labels, not by the label text (`components/usage/usage-heatmap-card.tsx`, `WEEKDAY_IDS`).
- JSX never travels through a prop, not even via a local variable (`react-perf/jsx-no-jsx-as-prop`; `components/tree-rail.tsx` documents the same wall). A component that hands its caller a slot takes a render function, not a node: `renderHeaderRight?: () => ReactNode` called as `renderHeaderRight?.()` (`components/usage/usage-card.tsx`), with the caller's function in a `useCallback`. The same slot also breaks import cycles: `AssistantTurnFooter` in `components/message.tsx` takes `renderUsage` so `agent-stream/turn-usage-segment.tsx` can import the font constant back out of `message.tsx` without the two files importing each other. Typing the slot `ReactNode` compiles and then fails lint at every call site. `Alert`'s `description` is typed `ReactNode`, but the lint rule rejects JSX there, so a list of raw lines is `lines.join("\n")`; richer content goes in `children` or a sibling element. Wrapping the node in `useMemo` slips past the rule but is still JSX through a prop. The provider start-error card (`ProviderStartErrorAlert` in `provider-detail/index.tsx`) puts its monospace error text and its buttons in `children`, and cancels the actions slot's top margin so the text sits where a description would. The same plugin's `jsx-no-new-function-as-prop` makes every handler passed to a component a `useCallback`, which is the one case where the "only for memoized children" rule in Hooks and Data yields to the linter.

## Forbidden (from `docs/design.md` §14, enforced in review)

`fontWeight.medium` outside the structural-label tier; hardcoded hex or new color tokens outside the exceptions §14 names; spacing outside the scale (`padding: 20`, `gap: 10`); color changes for disabled state; a muted paragraph under a section header; a "Settings" CTA on a detail page; placeholder text dimmed beyond `foregroundMuted`; raw DOM without `isWeb`; destructive actions without a confirmation (`confirmDialog`, or a sheet whose footer holds the destructive button).
