# Testing

`docs/testing.md` is the bar: two categories, no mocks by default, determinism, every fallible action covered for success and failure. This is the app-specific mechanics.

## Three runners, three suffixes

| Suffix                  | Runner                                     | Environment                                                                                                 | Use for                                                                                                                                                               |
| ----------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `*.test.ts(x)`          | Vitest `unit` project (`vitest.config.ts`) | Node, `pool: "forks"`, `vitest.setup.ts` shims `expo`, `__DEV__`, and a few native-only modules             | Pure modules: reducers, view models, stores, form models, selectors, key builders                                                                                     |
| `*.browser.test.ts(x)`  | Vitest `browser` project                   | Headless Chromium through Playwright, real DOM, real `WebSocket` (`runtime/websocket-test-global-setup.ts`) | Things that need a browser: `components/adaptive-text-input.web.browser.test.tsx`, `runtime/websocket-transport.browser.test.ts`, `lib/overlay-root.browser.test.tsx` |
| `e2e/browser/*.spec.ts` | Playwright (`npm run test:e2e`)            | Real Metro, real isolated daemon per worker, real browser                                                   | RPC-backed UI and every fallible user action: `agent-message-submission.spec.ts`, `add-project-flow.spec.ts`, `agent-message-rewind.spec.ts`                          |

`*.real.spec.ts` under `e2e/browser/` hits a real provider and runs only through `npm run test:e2e:real`. Shared Playwright harness code lives in `e2e/support/`; specs never go there. Specs that only exercise the daemon import `daemonTest` so they skip the browser context.

## Unit tests are ports-and-adapters tests

There are over 600 `*.test.ts` files and the good ones look like `hooks/use-archive-agent.test.ts`: seed the session store with `test/seed-session.ts`, build a full `Agent` with a `makeAgent(overrides)` helper, call the exported pure functions, assert the resulting store and query-cache state with `toEqual`. No renderer, no JSDOM, no `@testing-library`.

45 test files still use `vi.mock`. They predate the current rule and are not a license. A new test that wants `vi.mock`, `vi.hoisted`, `vi.spyOn` of the module's own exports, or a monkey-patched global is telling you the production module lacks a port: add the injected interface, write a typed fake next to the adapter, test against the fake. The stubs in `vitest.setup.ts` are for modules with no meaningful Node behavior (`react-native-unistyles`, `react-native-svg`, `expo-linking`, `@xterm/addon-ligatures`), not for app code.

A screen test with `vi.mock` stubs breaks when the screen starts importing another feature's entry: the entry loads its own components at import time. `screens/settings/providers-section.tsx` importing `selectInheritedApiEndpoint` from `@/api-endpoints` pulled in the mode section and `<Alert>`, and the existing `providers-section.test.tsx` failed at load on `No "Info" export is defined on the "lucide-react-native" mock` and then on `theme.colors.palette.blue[300]`. Extend that suite's icon mock and theme stub (the error names the next missing one). Don't import from `internal/` to dodge it: the entry is the public surface (`directory-structure.md`).

React Query behavior (refetch on `enabled` flipping, data kept during a refetch, a prefetch observer feeding a second observer) does not need a renderer either. Export the options builder with the client as a parameter, then drive the real cache in Node: `new QueryObserver(new QueryClient(...), fetchQueryOptions(inputs.menu))`, `subscribe`, `setOptions` to flip flags, and a fake client whose promises the test resolves. `hooks/use-agent-commands-query.test.ts` is the reference. "Did not fetch" is a synchronous check (`fetchStatus === "idle"` and an empty call list), never an assertion after a `setTimeout`.

## When a spec prescribes a rendered component seam

Some PRDs name "component + fake `DaemonClient`" as the test seam (`components/import-session-sheet.test.tsx`, `session-history/index.test.tsx`). Those run in the `unit` project under `@vitest-environment jsdom` with `@testing-library/react`, which is the tolerated exception above, not the default. These facts about the runners decide whether such a test can exist at all:

- **JSX is the classic runtime under Vitest.** A component rendered in jsdom, and every shared component it renders (`components/ui/alert.tsx`), needs `import React from "react"` or it throws `React is not defined`. Metro uses the automatic runtime, so nothing else catches this.
- **i18n has no instance until something imports it.** `useTranslation()` logs `NO_I18NEXT_INSTANCE` and returns keys. Import `{ i18n } from "@/i18n/i18next"` in the test and assert through `i18n.t(...)`, which also satisfies the no-unassigned-import lint rule.
- **Rendered tests run from `packages/app`, not the repo root.** The root has no Vitest config, so a root-run `npx vitest run packages/app/src/x.test.tsx` gets Vitest's defaults: no `resolve.extensions` for `.web.tsx`, no transform for `react-native-reanimated`. Pure tests happen to survive that; a component that reaches `components/ui/tooltip.tsx` → `ui/floating.tsx` → reanimated dies at load with `SyntaxError: Unexpected token 'typeof'` and reports "no tests", which a reviewer reads as a broken suite. `cd packages/app && npx vitest run src/session-history` is the command; CI runs `vitest run` inside the workspace too.
- **The `browser` project cannot load the layout store.** `stores/workspace-layout-store.ts` reaches `@react-native-async-storage/async-storage` → `expo-modules-core` → `TurboModuleRegistry`, which react-native-web does not export; `vitest.setup.ts` shims that only for the `unit` project. A component that opens tabs stays a jsdom test with the async-storage `vi.mock` copied from `workspace-tabs/explorer-sidebar.test.ts`, or its tab-opening moves behind an injected callback so the surface itself has no store import. The same chain rules out `composer/index.tsx` and `composer/input/input.tsx` (`MessageInput`): a composer behavior that needs the real editor is tested with `ComposerTextInput` from `composer/input/text-input.web.tsx` (the Tiptap input the web Composer renders), or the piece under test extracted into its own file (`composer/attachment-tray.tsx`). The `MessageInput` → Composer key path stays uncovered there; prove it once in Electron over CDP.
- **`Combobox` renders in the `browser` project.** The Unistyles stub has no breakpoint, so `useIsCompactFormFactor()` is `false` and the desktop popover path runs. The popover portals to the overlay root, so query options from `document`, not from the test's container. The stub theme (`test-stubs/react-native-unistyles.ts`) has to carry every token the component reads at render time. A missing one fails every test in the file with `Cannot read properties of undefined (reading '600')`, which is how `palette.zinc[600]` (the sheet handle color) got added. Add the real theme's value there, not a guard in the component. `screens/settings/appearance/font-picker-row.browser.test.tsx` is the reference.
- **The entry file must stay loadable.** A `SyntaxError: Unexpected token 'typeof'` with no file name means something under the test's import graph is untranspiled Flow or an untransformed Expo module; `expo-clipboard`, `hosts/host-chooser`, and `components/import-session-sheet` are known ones. Bisect with one throwaway test per suspect import (`import * as mod from "@/x"; it("loads", …)`), then move the offending runtime wiring out of the entry into `view.tsx` (Directory Structure). Do not alias the module in `vitest.config.ts` for one feature.
- **The menu engine renders for real in jsdom.** `@gorhom/bottom-sheet` and `react-native-safe-area-context` are already aliased to stubs, so a kebab (`DropdownMenu`) or a row's `ContextMenu` opens in the test: `fireEvent.click(getByTestId("…-kebab-…"))` or `fireEvent.contextMenu(rowElement)`, then `findByTestId` the item and click it; `onSelect` runs synchronously on web. The one precondition is the classic-runtime rule above: every shared file in the engine's render path (`components/ui/menu/*.tsx`, `context-menu.tsx`, `dropdown-menu.tsx`, `press-highlight.tsx`, `floating.tsx`) carries `import React`. The older tests that `vi.mock("@/components/ui/dropdown-menu")` predate this; a new test does not need the mock. `session-history/index.test.tsx` is the reference.
- **Media features in a browser test go through CDP.** `cdp().send("Emulation.setEmulatedMedia", { features: [{ name: "prefers-reduced-motion", value: "reduce" }] })` from `@vitest/browser/context` (Chromium only); reset it in `afterEach`. `components/status-ring/status-ring.browser.test.tsx` asserts the result through `container.getAnimations({ subtree: true })`. Do not stub `window.matchMedia`. Reanimated's `useReducedMotion` samples once at module load, so code that must follow a live change reads the media query (web) or `AccessibilityInfo` (native) itself.
- **Reanimated animated styles work in the browser project through a resolver plugin.** Reanimated's web glue `require()`s react-native-web's `createReactDOMStyle` / `preprocess` inside a try/catch; unbundled there is no `require`, so every `useAnimatedStyle` update throws "Cannot convert undefined or null to object" as an unhandled error and fails the file even when every test passes. The `reanimated-web-utils` plugin in `vitest.config.ts` swaps Reanimated's own `./webUtils` import (scoped by importer) for `test-stubs/reanimated-web-utils.ts`; types for those internals live in `test-stubs/react-native-web-internals.d.ts`. It is runner infrastructure, not a per-feature alias.
- **Gesture Handler drags need real input.** Synthetic `PointerEvent`s dispatched on the element do not activate a `Gesture.Pan()`. Send real mouse input with `cdp().send("Input.dispatchMouseEvent", …)`, converting coordinates to the top page: add `window.frameElement.getBoundingClientRect()` and scale by `frame.width / window.innerWidth`, because the test runs in a possibly scaled iframe (`composer/agent-controls/thinking-slider.browser.test.tsx` `mouse()`). A tap is fine through `userEvent.click(el, { position })`; an element with `aria-disabled="true"` needs `force: true`, or Playwright waits for it to become enabled.
- **react-native-web omits `aria-expanded` when `accessibilityState.expanded` is false.** `toHaveAttribute("aria-expanded", "false")` fails on a collapsed row. Assert what the user sees instead: the collapsed tool row has no `tool-call-badge-details`, and it appears after the click (`agent-stream-ui.spec.ts` "keeps execution quiet").
- **Pressed state on react-native-web starts at `mousedown`,** not `pointerdown`: the responder system ignores pointer events. `row.browser.test.tsx` dispatches `mousedown` / `mouseup`; hover uses `userEvent.hover` / `unhover`.
- **A hand-written theme in `vi.mock("react-native-unistyles")` must carry what the controls read.** Anything that renders `<Button>`, `<Switch>`, or a form field calls `createControlGeometry(theme)`, which reads `theme.radius` and `theme.controlHeight`; a fixture without them dies at import with `Cannot read properties of undefined (reading 'sm')`. The same happens when a migrated component's own `StyleSheet.create` reads `theme.radius.*` (`workspace-scripts-button.test.tsx` died on `reading 'md'`). Copy the tokens from `test-stubs/react-native-unistyles.ts` (`components/ui/switch.test.tsx`). After migrating a component, run `grep -rl 'vi.mock("react-native-unistyles"' src | xargs grep -L "radius:"` and run those files.
- **Reset feature-owned stores in `afterEach`.** An in-memory store under a feature's `internal/` (`session-history/internal/resume-terminals.ts`) leaks between tests in the same file; export a `reset…ForTests()` next to it and call it beside `cleanup()`.

Keep the surface's props the seam: `client: Pick<DaemonClient, ...> | null`, `isConnected`, and callbacks for what the shell decides (`onOpenTerminal`, `onCopyResumeCommand`, `onImported`). The fake client is a plain object of `vi.fn` implementations typed from `DaemonClient`; nothing else is mocked except `@/components/provider-icons`, whose SVG icons have no Node behavior.

## Fallible user actions

Every action that can fail needs behavioral coverage for success and for failure, and the failure test asserts what the user can see and do afterwards, not a state field. RPC-backed UI uses a Playwright spec with the real daemon. Distinct timeout and disconnect cases get their own tests when the recovery differs.

## Assertions that outlived their feature

A spec fails because the product legitimately grew, and the cheap fix loosens the assertion so the
next growth cannot break it. That trade is not available here — `docs/testing.md` "Assert the full
intended behavior, not fragments" outranks the wish for a test nobody has to touch again.

- A list assertion stays a list. Turning `toHaveText([...])` into `expect.poll` +
  `expect.arrayContaining` drops order and stops noticing extra items. When the list has real
  groups, name them and compare the concatenation exactly:
  `toHaveText([...builtInViews, ...pluginPanels])` (`e2e/support/helpers/explorer-plugin-menu.ts`)
  keeps the full check and still says which half a new entry belongs in.
- A locator that hits one row today and three tomorrow gets the exact label, not a regex.
  `getByLabel(/Theme:/)` broke the moment the appearance section grew its system-pairing rows;
  `getByLabel("Theme: System", { exact: true })` says which row it meant.
- When an assertion uses a concrete value as a proxy for a defect ("white can only come from the
  browser"), and the product makes that value legitimate, pin the input instead of relaxing the
  assertion. `terminal-protocol-query.spec.ts` seeds `theme: "dark"` through
  `localStorage.setItem("@paseo:app-settings", …)` in `addInitScript` before the first navigation,
  then asserts the dark theme's real terminal background — so "no pure white" means leakage again.
- Prove a rewritten assertion still bites: break the production path once, watch the test fail on
  the line you rewrote, restore. A test that only verifies the setting the test itself seeded
  passes for the wrong reason.

## Fixtures and isolation

- Playwright gives every worker its own daemon and `PASEO_HOME`; specs in one file share it. Helpers that create projects or workspaces own them until cleanup, and a fixture fails any test that leaks a project record. Deleting the temp directory is not cleanup.
- Tests about daemon-global state (empty history, restart) start a dedicated host explicitly.
- The failure screenshot is taken after the test body's `finally` has run, so a spec that archives its workspace in `finally` shows "Workspace unavailable" no matter what failed. Read the assertion and `error-context.md`, not the screenshot; add a temporary `console.log(await locator.evaluate(n => n.outerHTML))` before the failing line when the DOM matters.
- Retained-panel geometry is tested through a real retained surface across hide and reveal (`docs/coding-standards.md` "Retained panel measurements").
- Sidebar callouts (the desktop update card, the Rosetta hint) stay mounted on the settings screen. A settings assertion on text or a button name that a callout can also show ("Update", "Installing...", an error message) resolves to two elements and fails strict mode, or clicks the card. Scope it to `page.getByTestId("settings-detail-pane")`; `packages/desktop/e2e/updates.spec.ts` "a download started in settings that fails…" is the reference.
- Filenames describe product behavior (`add-changed-file-to-chat.spec.ts`), never order or isolation mechanics.
- A seeded workspace opens on the New tab launcher, not a composer. Anything under the composer (the Composer context strip, its branch switcher) needs a draft first: `switchWorkspaceViaSidebar` then `clickNewChat` (`e2e/support/helpers/launcher.ts`). `branch-switcher.spec.ts` `openDraftInSeededWorkspace` is the reference.
- `createTempGitRepo({ withRemote: true })` keeps its bare remote at `<repo>/remote.git`, which `git status --porcelain` lists as untracked, so the daemon reports the workspace dirty and a branch switch detours through "Stash & Switch". A spec that needs a clean tree calls `leaveBranchOnlyOnRemote` (or writes `remote.git/` to `.git/info/exclude`) in `e2e/support/helpers/workspace.ts`. Git fixture moves (`git worktree add`, deleting a branch, reading an upstream) live there as named helpers, not as `execSync` in the spec body.
- A seeded agent route does not survive a reload or a second navigation: startup restore bounces it to "Workspace unavailable". Anything a spec wants to change before reaching the agent (app language, settings) has to be in place before the first navigation, or be changed from inside the loaded app without navigating.
- A helper under `e2e/support/` imports `@getpaseo/protocol/*` for types only (`import type`), apart from the small leaf modules already used at runtime (`terminal-profiles`, `agent-labels`, `connection-offer`). A runtime import of `@getpaseo/protocol/messages` loads a second copy of that module beside the one the dist daemon client imports (`daemon-client-loader.ts`), and every test in the file then fails in the worker fixture with `does not provide an export named 'AgentSnapshotPayloadSchema'`. To rewrite a daemon frame, narrow the parsed JSON with an `isRecord` guard and spread the payload (`rewriteListCommandsFrame` in `e2e/support/helpers/inline-blocks.ts`).
- The `browser` project cannot load anything that imports the session store (same async-storage chain as "The `browser` project cannot load the layout store"), which is why the block presentation `InlineBlockView` lives in `inline-blocks/block-view.tsx` and the store-backed `useAgentSkillNames` / `InlineBlockText` stay in `view.tsx`. The editor's block node imports only the former, so `text-input.web.browser.test.tsx` can mount real blocks. `@/agent-profiles` is on the same chain (its index loads `useDaemonConfig` and the session store), so an Agent profile mention's icon reaches `block-view.tsx` through `AgentProfileIconContext`, filled by `AgentProfileIconProvider` in `view.tsx`; `InlineBlockText` and the Composer input (`composer/input/input.tsx`) wrap themselves in it. Importing either module from `block-view.tsx` fails the whole file at Vite dependency optimization (`No matching export ... "TurboModuleRegistry"`), before any test runs. Block node views render through React asynchronously: wait for `[data-inline-block]` with `vi.waitFor` before asserting on it.
- A copy in the composer lands on the real macOS clipboard asynchronously. Poll `navigator.clipboard.readText()` until it holds the copied text before pressing paste, or the paste intermittently reads the previous clipboard (`composer-inline-blocks.spec.ts`). Don't assert on undo right after typing: ProseMirror groups steps within 500 ms into one undo event.
- Icons are not observable in unit or browser tests: `test-stubs/react-native-svg.ts` and `test-stubs/lucide-react-native.ts` render `null`, so which icon a block picked (Agent mention with a host's custom provider icon) cannot be asserted there.
- `expectComposerText` reads what the composer shows, so a block counts as its name: a restored `[widget.ts](src/widget.ts)` reads `widget.ts`. Assert the serialized text through the sent message or the clipboard, and blocks with `expectInlineBlocks`.
- Whether an agent can dispatch (`canCreateAgents`) is decided when its session starts, from the worker daemon's `mcp.injectIntoAgents`. The `mock` provider declares `supportsMcpServers`, so under `test.use({ e2eInjectPaseoTools: true })` a mock agent can dispatch. That option is worker-scoped: Playwright rejects it inside `test.describe`, so put it at the top of the file. For the grayed-out case in the same file, `patchDaemonConfig({ mcp: { injectIntoAgents: false } })` before seeding the agent and restore it in `finally` (`composer-agent-mentions.spec.ts`). The new agent screen reads the provider snapshot's prediction instead, which follows config live, so toggle injection after the draft is open. To give two providers different predictions, install the custom ACP provider (`installThinkingModesProvider`) and patch its `paseoTools.disabledTools`; the daemon refuses `providers.mock.*`. Switch the draft's provider through the Command Center (`Model › Mention ACP › Swift`).
- A disabled `Pressable` gets `pointer-events: none` on web, so `userEvent.hover` / `click` on it times out with "intercepts pointer events". Target its row envelope (`parentElement`) to prove a disabled row ignores the pointer (`autocomplete.browser.test.tsx`).
- The mock provider reports no slash commands. A spec that needs a skill or command in the list installs `installAgentCommandsStub(page, commands)` (`e2e/support/helpers/inline-blocks.ts`) before navigating; the route survives reloads.
- The web composer is a contenteditable Tiptap editor, not a textarea. `toHaveValue`, `inputValue()`, `.value`, and `setSelectionRange` fail on it; read it with `readComposerInput` / `expectComposerText` (`e2e/support/helpers/composer.ts`), which count each `<br>` as a newline and skip ProseMirror's trailing placeholder `<br>`. `fill`, `press`, `toBeEditable`, and `getByRole("textbox", { name: "Message agent..." })` work unchanged. A spec that must change the draft and act before the Composer's deferred publication does both inside one `evaluate` through `element.editor` (Tiptap's test hook, typed as `ComposerTestEditor`): moving only the DOM caret or DOM text in that same tick is invisible to ProseMirror until its async `selectionchange` / mutation flush (`composer-autocomplete.spec.ts` "uses the live cursor…").
- Subagent specs seed the pair with `seedParentWithSubagent` (`e2e/support/helpers/subagents.ts`). `parkSubagentOnPermission` sends the child `Emit synthetic plan approval.`, which leaves one pending permission and returns its id. A track row's status is asserted on the row, not only the pill: the tab icon's needs-input badge carries `aria-label="Agent needs input"` and the running ring `aria-label="Agent running"` (`expectSubagentRowNeedsInput`). Send the prompt after the page is open: attention is broadcast once, when the request arrives, so a page that loads later never sees the frame.
- Seeding QA data into the dev desktop daemon reuses the e2e helpers: `E2E_DAEMON_PORT=6769 npx tsx <script>.ts` from `packages/app` with `seedWorkspace({ port: 6769 })`. Wrap the body in `async function main()` because tsx compiles it as CJS and rejects top-level await. End with `process.exit(0)`, not `client.close()`: `withProjectOwnership` removes every project the client created when it closes, and the window then shows "Workspace unavailable". Clean up with `connectSeedClient({ port, projectOwnership: "host" }).removeProject(id)`.
- Daemon frames the page receives are read through `loadSessionMessageReaders()` (`e2e/support/helpers/new-workspace.ts`), which validates against the protocol schema, not with `JSON.parse(...) as {...}`. `observeAgentAttention` records `agent_attention_required` that way.
- The daemon refuses any config write under `providers.mock` or `providers.mock-slow` (`Custom provider "mock" must declare extends`): `ProviderOverridesSchema` only exempts the six builtin ids, and a production registry would throw on a dev id without `extends`. A spec that saves per-provider config (Mention defaults, enable toggles) registers a custom ACP provider instead: `installThinkingModesProvider()` in `e2e/support/helpers/mention-defaults.ts` points `extends: "acp"` at `e2e/support/fixtures/thinking-modes-acp.cjs` (two models, one shared set of thinking levels, two modes), waits for its snapshot to be `ready`, and `remove()` clears its config with it. ACP reports thinking levels per session, so every model has the same set; a model without levels is only reachable with `mock`.
- A write the daemon refuses is faked with `installDaemonConfigFailureFixture(page, reason, { times })` (`e2e/support/helpers/usage-pricing.ts`): the first `times` `set_daemon_config_request`s get an `rpc_error`, later ones reach the daemon, so a Retry succeeds. The app shows the reason through `extractFailureReason` (`price-table/pricing.ts`), which drops the `requestType=` / `code=` suffixes `DaemonRpcError` appends. An old host without `features.agentMentions` is `installHostWithoutAgentMentions(page)` from the same Mention defaults helper. Both route the WebSocket, so install them before the first navigation.
- The mock agent (`packages/server/src/server/agent/providers/mock-load-test-agent.ts`) scripts its turns from the prompt text, and the daemon runs it from source through `tsx`, so a new scenario needs no rebuild. Dispatch groups: `Emit synthetic create_agent calls: [<steps>]` writes `paseo.create_agent` calls with the given `callId`s into the timeline, one step at a time. Each step is `{ callId, title, provider?, runningMs? }`, `{ callId, providerSubagent: { id, description, subtitle?, runningMs?, permission?: { name } } }`, or `{ text }`. `runningMs` holds that call in running so the "Starting" row, or a provider row's live status, can be asserted. A `providerSubagent` step writes a `sub_agent` tool call plus a provider-subagent descriptor with the same `toolCallId` (running, then completed) and one `user_message` in its timeline, so the read-only panel has content. With `permission`, the mock instead raises a permission on the parent tagged `metadata.providerSubagentId = id` and holds the subagent running until the request is answered (through the parent agentId), then completes it and runs the next step. Locate its row with `providerDispatchRow(page, callId, subagentId)`; its track row is `subagents-track-row-<id>`. Open the read-only tab from the track row, not the dispatch row, when the track panel is open: the panel's backdrop intercepts the click. The steps are parsed with zod and a malformed script throws. The mock does not create the child. Seed it with `seedDispatchChild` (`e2e/support/helpers/subagents.ts`), which writes both `paseo.parent-agent-id` and `paseo.parent-tool-call-id`; the daemon only strips a model-supplied call-id label on the MCP path, not on `client.createAgent`. `emitDispatchCalls`, `dispatchRow`, `expectDispatchHeader`, and `installHostWithoutSubagentCallLinks` are in the same helper; `dispatch-group.spec.ts` is the reference. Question prompts: `Emit synthetic questions.` (two single-selects plus a free-write), `...: two free-write questions.`, `...: one single-choice question with other.`, `...: one multi-select question.`. A turn's `finalText` never reaches the UI; only timeline items do. So when a question is answered the mock also emits an assistant message, `Synthetic questions resolved: header=answer; ...` in question order, or `Synthetic questions dismissed` on deny. Assert it with `getByText(..., { exact: true })` (`expectAgentReceivedAnswers` in `e2e/support/helpers/questions.ts`); "the card disappeared" passes for submit and dismiss alike.

## Running

```bash
npx vitest run packages/app/src/stores/session-store.test.ts --bail=1   # pure tests survive a root run
cd packages/app && npx vitest run src/session-history --bail=1          # rendered tests need the app config
npm run test:browser --workspace=@getpaseo/app                  # all *.browser.test; small set
cd packages/app && npx playwright test --project=browser e2e/browser/agent-message-submission.spec.ts
git diff --name-only | grep -E '\.(ts|tsx)$' | xargs npm run lint --   # zsh does not word-split $FILES
```

A control revealed on hover and hidden with `opacity: 0` + `pointerEvents: "none"` (the attachment `×`) fails Playwright's `locator.click()` with "… intercepts pointer events": the actionability check runs before the hover takes effect. Hover the envelope, then `page.mouse.move` onto the control's box and click with the mouse.

A screenshot taken over CDP from the dev Electron window ends the hover: the hovered control is present before `Page.captureScreenshot` and gone after it. You cannot screenshot a hover state that way; assert it from the DOM instead.

A schema edit is invisible to client and app tests until `npm run build:client` runs (`CLAUDE.md` "Build workspace packages"); the symptom is a passing protocol test next to a client test that cannot see the new field.

Never run the whole Playwright suite locally; it is CI's job. Never `npm run test` for the workspace. Metro readiness for Playwright means `/status` returns `packager-status:running` and the bundle has been fetched; the global setup handles it.
