# 合并上游 Paseo v0.10.0 至 v0.10.3

**Status:** ready-for-agent

依据：`research/discovery.md`（2026-10-10 的模拟合并数据、冲突清单、访谈逐条确认的决定）。做法沿用 `docs/release.md` 的「Fork 分发 → 从上游同步」，本文只写这一次特有的范围、裁决与验收，不重述那一节。相关既有决定：ADR 0001（macOS 自签名证书）、ADR 0002（改名止于桌面 App 身份）、ADR 0003（指令列表不启动进程）。

## Problem Statement

Osuna 在 2026-10-10 把上游 `getpaseo/paseo` 合到了 v0.9.2，此后的同步点是 `c67b7158b`。上游在那之后发了 v0.10.0、v0.10.1、v0.10.2、v0.10.3，共 62 个提交。Osuna 用户现在拿不到其中的东西：

- OpenCode 升到 2.x 之后 Osuna 连不上它（依据上游提交说明推断：2.x 换了对外接口，Osuna 只带 1.x 的客户端；未实测）。
- Pi 的常用扩展（任务清单、子智能体、提问表单）在聊天里不显示。
- daemon 设了密码之后，中继连接不校验密码，配对链接和二维码带不上密码，密码里有空格或 `@`、`/` 时直连失败。
- 配对链接可以不经确认就连上一台新主机。
- Claude 模型列表里没有 Sonnet 5.5。
- 约 25 个缺陷：磁盘写满时 daemon 退出、打开 worktree 已删除的归档 ACP 智能体时 daemon 崩溃、应用启动后侧栏缺工作区、Pi 回退走过头、流式回复把代码块的行连在一起等。

上游已经到了 v0.11.2。每多拖一个版本，两边同时改过的文件就多一批：这一次模拟合并已有 55 个文件冲突，其中 33 个要手工处理。

这一段里有三处两边各走了一条路，不处理好会丢东西：

- 上游把设置页重新分了栏，并顺手调了控件外观；Osuna 的设置页是自己重做过外观的，还多了终端字体等设置项。
- 上游改了取指令列表的两处写法，方向与 ADR 0003 相反。
- 上游按扩展重写了 Pi 的工具调用映射、为 OpenCode 2.x 另写了一套路径；Osuna 在旧写法上加过子智能体派发的命名与权限归属。

另有一件上次没遇到的事：v0.10.1 – v0.10.3 不在上游主线上，而在上游从 v0.10.0 分出的补丁分支上。

## Solution

把上游从 v0.9.2 到 v0.10.3 的 62 个提交整版合并进 main，用保留上游历史的 git merge。

合并在单独分支 `merge-upstream-v0.10.3` 上分五段进行，分段点是上游自己的发布点。每段结束时分支都能通过检查，全部做完后经一个 PR 以 merge commit 并入，main 只变一次。

合并后的 Osuna：

- 多了上游这四个版本的全部功能与修复。
- 设置页的分栏与上游一致：去掉「布局」，新增「侧边栏」「聊天」「终端」「浏览器」，一部分设置项换了页面。外观仍是 Osuna 的。
- Osuna 自己的功能一个不少。`/` 指令菜单的行为不变，终端字体与终端字号仍在「外观」的字体分组。
- 桌面身份、更新源、签名、外链、界面中文、版本号与更新日志继续是 Osuna 的。
- OpenCode 2.x 能用，但 Osuna 加在 1.x 路径上的独有行为在 2.x 上暂缺，缺口列在 PR 正文里。
- `docs/release.md` 里记录的同步点更新到 v0.10.3，并写明补丁分支带来的后果。

## Implementation Decisions

### 合并方式

- 合并分支 `merge-upstream-v0.10.3` 从 main `56cccc196` 开出，在上面依次做五次 merge，每次一个 merge commit。上游发布点用提交 SHA 引用，不抓上游 tag。

| 段  | 上游发布点     | 提交        | 本段上游提交数 | 模拟合并的累计冲突文件（机械性 + 代码） |
| --- | -------------- | ----------- | -------------- | --------------------------------------- |
| 1   | v0.10.0-beta.1 | `52d345db7` | 33             | 14 + 29                                 |
| 2   | v0.10.0        | `c481ecf3e` | 6              | 18 + 29                                 |
| 3   | v0.10.1        | `c5236c00d` | 12             | 22 + 32                                 |
| 4   | v0.10.2        | `919c737c1` | 7              | 22 + 32                                 |
| 5   | v0.10.3        | `b4af508e2` | 4              | 22 + 33                                 |

- 每段的 merge commit 本身通过 typecheck、lint 和该段冲突文件对应的测试。冲突之外的适配紧跟在 merge commit 之后单独提交，进入下一段之前做完。
- 第一段合完就开草稿 PR，目标分支 main，之后每段推送后看 CI。
- 并入 main 用 merge commit，不 squash、不 rebase。合并期间 main 有新提交时把 main 合进合并分支。

### 补丁分支

- 第 3 – 5 段的发布点在上游的 `release/0.10.1`、`release/0.10.2`、`hotfix/0.10.3` 上，不是上游 main 的祖先。照常按 SHA 合并。
- 并入后 `git merge-base main upstream/main` 给出的是 v0.10.0（`c481ecf3e`），不再等于同步点。同步点的自检改为「该提交是 main 的祖先」。
- 以后合 v0.11 时，补丁分支与上游主线分叉的地方会再冲突一次。上游自身的 v0.10.3 对 v0.11.0 模拟合并，版本号类文件之外有 9 个代码文件冲突（清单在 `research/discovery.md`）。裁决固定：上游部分取主线一侧，Osuna 的改动保留。这一条写进 `docs/release.md`。

### 冲突裁决

沿用 `docs/release.md`「冲突裁决」的三条规则与「停下来问维护者」的条件。本次已由维护者逐条确认的几处：

**设置页分栏（第一段）。** 分栏取上游的，外观保持 Osuna 的：

- 应用级栏目清单取上游：通用、外观、侧边栏、聊天、终端、浏览器（仅桌面）、编辑器、快捷键、集成、通知、权限、诊断、关于。「布局」去掉。主机级栏目两边相同，不变。
- 设置项的归属取上游：聊天大纲、详情级别、自动展开思考、工具调用详情进「聊天」；终端回滚行数进「终端」；默认发送方式进「通用」的「发送」分组；侧栏条目顺序进「侧边栏」；「在侧边窗格打开」与服务 URL 进上游的「打开位置」分组；浏览器数据进「浏览器」。
- Osuna 独有的设置项留在「外观」：终端字体与终端字号留在字体分组（维护者 2026-10-10 确认），系统字体选择器、字号重置、带终端样例的预览、深浅色主题配对与 13 套主题变体原样保留。
- Osuna 重做过的页面原样保留：设置 → Providers 的列表 → 详情两级、用量页、设置 → 关于的应用更新卡片、Host → Agents 的提及智能体默认值卡片。
- 外观按 `docs/design.md`：14 圆角卡片、56 高的行、卡片内行分隔为边框色 50%、统一的下拉触发器。上游在同一批改动里对下拉触发器、侧栏标题行、控件尺寸做的纯外观调整不收；上游新页面要用到的属性与能力收下，画出来仍是 Osuna 的样子。
- 上游新增的页面（聊天、终端、发送分组、打开位置分组）用 Osuna 的设置组件搭，不带上游的行高与分割线。
- 栏目标题与新设置项的文案走翻译键，九种语言齐全，zh-CN 为真实翻译。不再被引用的「布局」栏目键删掉。
- 上游把「布局」从栏目地址清单里去掉了。指向它的旧地址按现有的未知栏目处理落到默认栏目，实施时核实这一点。

**提示框组件（第一段）。** 上游为密码功能给提示框加了尺寸属性并改了内部排布，Osuna 给它换过外观。接口取两边的并集（上游的尺寸属性与 Osuna 现有调用方用到的属性都留），排布取上游的，颜色、圆角、浮层质感按 Osuna 的外观。

**指令列表（第一段）。** 保持 Osuna 现有做法，ADR 0003 不变（维护者 2026-10-10 确认：先选了取上游，了解范围后改回）：

- 上游让通用 ACP 智能体首次取指令列表时等待程序报回指令的改动不收。上游为它新增的测试按 Osuna 的行为改写；改写后没有可断言的内容就移除，并在 PR 正文写明。
- 上游让 OpenCode 取指令列表前先重连服务的改动不收。Osuna 只用会话已持有的服务，并在每轮结束后把列表上报给指令目录。
- 上游「切换分支后刷新项目技能」的改动照收。新会话指令查询的键取上游的结构（工作目录在前缀，切分支时按前缀清缓存）；Osuna 有意从键里去掉的 mode / model / thinking / features 不加回来，只换模型或模式时 `/` 菜单不重新加载（实施时对照基点更正：这四个字段是基点原有的，不是上游新加的）。
- 这条决定对 OpenCode 2.x 的路径同样适用（维护者 2026-10-10 确认）：实施时核实 2.x 路径取指令列表是否会启动进程或拉起服务，会就在本次改成只用已持有的服务。
- PR 正文单列一节，写明这两处上游改动没有收、原因是 ADR 0003，以及由此带来的行为差异：自定义 ACP 提供方的新会话 `/` 菜单在该提供方跑过一轮之前只显示扫描到的技能与内置指令。

**Pi（第一段）。** 以上游按扩展拆分的适配器写法为底，补回 Osuna 多出的行为，并由测试证明：

- `create_agent` 派发的子智能体带父工具调用的归属，时间线工具名规范为 `paseo.create_agent`。
- `display:false` 的 custom 消息不进时间线；上游新加的扩展消息映射照常执行。

## Testing Decisions

好的测试只断言外部行为：给定输入与状态，用户或调用方看到什么。这次是合并，测试的作用是证明两边的行为都还在，因此只用已有的测试和上游随合并带来的测试，不新开接缝。

### 接缝

1. **CI 全套作业**（最高接缝）。format、lint、typecheck、server-tests、desktop-tests、app-tests、sdk-tests、playwright 分片、relay-tests、cli-tests。上游为这 62 个提交带来的测试随合并进入这些作业，Osuna 的测试守住 Osuna 的功能。
2. **冲突文件对应的现有测试**，本机逐个文件跑：
   - Pi 的会话测试与工具调用映射测试：上游的扩展适配器用例，加 Osuna 的 `paseo.create_agent` 命名、custom 消息过滤、思考档位过滤用例。
   - OpenCode 桥接的测试：上游的版本选择用例，加 Osuna 的派发命名与权限归属用例。
   - Claude 会话的测试与模型清单的测试：上游的配置目录与 Sonnet 5.5 用例，加 Osuna 的已装版本与升级用例。
   - Codex 会话与提供方注册的测试。
   - 智能体管理的测试里指令目录的用例，以及 Claude 指令列表的 daemon e2e：取列表不启动进程。
   - 新会话指令查询的测试；控件尺寸的测试；上游为状态徽标带来的浏览器测试。
3. **Osuna 不变量的现有测试**。桌面更新源的测试、翻译资源测试、协议的兼容测试。
4. **dev 桌面端实测**。见验收清单。

设置页的分栏没有单元测试接缝，由 Playwright 的设置相关用例（CI）与 dev 桌面端截图把关。改了栏目清单的桌面 e2e 在本机 macOS 上跑不通，只在 CI 上验。

### 规则

- Osuna 原有的测试不删除、不跳过、不放宽断言。因分栏变化而必须跟着改的断言（栏目名、设置项所在的页面）逐条列进 PR 正文。

- 上游带来的测试要通过。与 Osuna 有意做的决定矛盾时改测试，并在 PR 正文说明是哪条决定。本次已知的一处：通用 ACP 智能体「首次取指令列表等待程序报回」的测试。
