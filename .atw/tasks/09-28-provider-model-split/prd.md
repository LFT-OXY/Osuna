# 拆分提供方与模型选择，并接入提供方彩色图标

## Problem Statement

在 Composer 工具栏里，提供方和模型挤在同一个选择器中：新建 Agent 时，想换提供方，得先打开模型菜单，再从一长串跨提供方的分组里找目标提供方、点进去、再选模型。选择器上只能看到模型名，当前用的是哪个提供方要靠图标辨认。而除了 Claude，其他提供方的图标全是单色，模型列表里的图标一律是灰色，几家提供方在视觉上很难区分。

## Solution

在 Composer 工具栏里把提供方和模型拆成两个相邻的控件：

- **提供方按钮**：只显示当前提供方的彩色图标，点开是提供方列表。可用的提供方平铺显示，不可用的折叠在「More agents (N)」里。
- **模型按钮**：只列当前提供方的模型。

新建 Agent 时可以先换提供方、再选模型；运行中的 Agent 上，提供方按钮只用来展示，不能点。有彩色版本的提供方，在 Composer 相关位置显示彩色图标；各提供方的品牌色补齐，供工具栏和后续的思考滑条使用。桌面/Web 工具栏和手机端的 Agent controls sheet 都按这个结构改。

## User Stories

1. 作为新建 Agent 的用户，我想在工具栏上看到一个单独的提供方按钮，以便不打开模型菜单就能换提供方。
2. 作为新建 Agent 的用户，我想让提供方按钮只显示当前提供方的彩色图标，以便一眼认出当前提供方，同时不占用工具栏宽度。
3. 作为新建 Agent 的用户，我想让提供方按钮位于模型按钮左边，以便按「提供方 → 模型 → 思考 → 模式」的顺序从左到右配置。
4. 作为新建 Agent 的用户，我想在提供方列表里看到每个提供方的品牌图标和名字，以便快速找到目标提供方。
5. 作为新建 Agent 的用户，我想让当前提供方在列表里打勾，以便确认现在选的是哪个。
6. 作为新建 Agent 的用户，我想让可用的提供方平铺在列表顶部，以便常用的提供方一步就能选到。
7. 作为新建 Agent 的用户，我想让不可用的提供方折叠进「More agents (N)」，以便列表保持简短，需要时仍能展开找到它们。
8. 作为新建 Agent 的用户，我想展开「More agents (N)」后仍能选中一个不可用的提供方，以便在模型菜单里看到它的错误状态并重试。
9. 作为新建 Agent 的用户，我想在切换提供方后自动选中我上次给该提供方选过的模型，以便不用每次重新挑。
10. 作为新建 Agent 的用户，我想在从没用过某个提供方时自动选中它的默认模型，以便切换后能立即发送。
11. 作为新建 Agent 的用户，我想让模型菜单只列当前提供方的模型，以便不在其他提供方的模型里翻找。
12. 作为新建 Agent 的用户，我想让模型菜单里的搜索只在当前提供方的模型里匹配，以便搜索结果不混入别家模型。
13. 作为收藏过模型的用户，我想在模型菜单里只看到属于当前提供方的收藏，以便收藏区和当前提供方保持一致。
14. 作为使用 Agent profiles 的用户，我想让 Agent profiles 继续留在模型菜单里，以便一键套用一组配置（包括跨提供方的配置）。
15. 作为套用了某个 Agent profile 的用户，我想在它指向别的提供方时让提供方按钮同步切换，以便工具栏显示的就是实际要用的提供方。
16. 作为已有运行中 Agent 的用户，我想在工具栏上仍然看到提供方图标，以便工具栏布局和新建时一致。
17. 作为已有运行中 Agent 的用户，我想让提供方按钮不可点击，以便不会误以为运行中的 Agent 能换提供方。
18. 作为已有运行中 Agent 的用户，我想让模型按钮照常切换同一提供方下的模型，以便拆分不影响现有的换模型能力。
19. 作为手机端用户，我想在 Agent controls sheet 里看到单独的「提供方」一行，行上有品牌色图标和提供方名字，以便在手机上也能单独换提供方。
20. 作为手机端用户，我想点「提供方」行后进入提供方列表并选中目标，以便操作方式和桌面端一致。
21. 作为手机端用户，我想让「模型」行只列当前提供方的模型，以便和桌面端的模型菜单行为一致。
22. 作为手机端的运行中 Agent 用户，我想让「提供方」行只读，以便和桌面端的限制一致。
23. 作为用户，我想让 Codex、Kiro、MiniMax、Kimi、Gemini CLI、Oh My Pi 在 Composer 里显示各自的彩色图标，以便按颜色区分提供方。
24. 作为用户，我想让 Claude Code 的图标继续保持现在的星芒图形和陶土色，以便它的外观不变。
25. 作为用户，我想让 GitHub Copilot、OpenCode、Pi、Cursor 这些没有彩色版的提供方继续显示单色图标，以便它们在亮色和暗色主题下都看得清。
26. 作为深色主题用户，我想让 Codex 的彩色图标不带白色方底，以便它在深色工具栏里不会变成一块刺眼的白色。
27. 作为用户，我想让模型列表每一行的提供方图标都用品牌色或彩色版，以便和工具栏上的图标一致。
28. 作为使用定时任务表单、元数据生成设置的用户，我想在这些页面的模型列表里看到同样的品牌色图标，以便全应用的模型选择器外观统一。
29. 作为用户，我想让侧边栏、标签页等 Composer 以外的位置继续显示原来的单色图标，以便这次改版不改变其他界面的视觉层级。
30. 作为使用自定义或 ACP 提供方的用户，我想让没有内置彩色版的提供方继续使用它自带的图标或默认图标，以便它们的显示不受影响。
31. 作为用户，我想在提供方列表加载中时看到占位图标而不是空白按钮，以便知道控件存在且正在加载。
32. 作为键盘用户，我想用键盘打开提供方列表、在其中移动并选中，以便不用鼠标也能切换提供方。
33. 作为读屏用户，我想让提供方按钮带有包含当前提供方名字的无障碍标签，以便在只有图标的情况下也知道它是什么。
34. 作为桌面用户，我想把鼠标悬停在提供方按钮上时看到提示，以便理解这个纯图标按钮的用途。

## Implementation Decisions

- **拆分方式**
  - 工具栏上的现有合并选择器拆成两个控件：提供方选择器和模型选择器。
  - 独立的提供方选择器沿用 Agent controls 里已有但从未启用的提供方 Combobox 结构，改成纯图标触发器加自定义行渲染：行内有品牌图标、名字、勾选状态，末尾是「More agents (N)」折叠区。实现在 `composer/agent-controls/provider-control.tsx`（`AgentProviderControl`），旧的文字版提供方 Combobox 结构随之删除。
  - 「More agents (N)」是 Combobox 选项列表里的一个哨兵行，配合 `keepOpenOnSelect`：选中它只展开或收起，不关闭列表，所以键盘上下移动和回车对它同样有效。当前提供方在折叠区里时，打开列表即自动展开。
  - 提供方列表不带搜索：条目少，搜索和折叠区同时存在时折叠区会被过滤打乱。
  - 桌面 toolbar 上出现提供方按钮时，模型按钮不再画提供方图标，只显示模型名（`CombinedModelSelector` 的 `toolbar.showProviderGlyph`），对应故事 2「不占用工具栏宽度」。工具栏密度预算里提供方按钮计 28，模型按钮相应扣掉图标加间距的 20，净增 12（`composer/agent-controls/layout.ts` 的 `hasProvider`）。其他页面的模型选择器和手机端不受影响。
- **提供方分组规则**
  - 平铺：状态为 `ready` 或 `loading` 的已启用提供方。
  - 折叠进「More agents (N)」：状态为 `error` 或 `unavailable` 的已启用提供方。
  - 未启用（`enabled: false`）的提供方不出现，和现有规则一致。
  - 组内顺序沿用现有提供方顺序。
  - 这条规则做成 provider-selection 模块里的一个纯函数：输入提供方快照，输出「平铺」和「更多」两组。
- **模型选择器限定为单一提供方**
  - 模型浏览器改为只作用于当前提供方：初始视图固定为该提供方，不再有跨提供方的「全部」视图和返回入口。
  - 搜索只在该提供方的模型行里做。
  - 收藏区只展示属于当前提供方的收藏。
  - Agent profiles 区保留，并展示全部 profiles。套用指向其他提供方的 profile 时，走现有的套用流程，提供方随之切换。
- **草稿切换提供方**
  - 只选提供方时，模型取该提供方已记忆的上次选择，没有记录则取默认模型。
  - 复用 Agent 表单状态里现有的提供方与模型设置入口和按提供方记忆的偏好，不新增状态。入口是 `setProviderFromUser(provider)`，与 `setProviderAndModelFromUser` 共用同一个 reducer 动作和偏好写入。
  - 两个入口的门槛不同：`setProviderAndModelFromUser` 只接受 `ready` 的提供方（选模型的前提是有模型列表）；`setProviderFromUser` 接受任何已启用的提供方，`loading`、`error`、`unavailable` 都能选中，这样折叠区里的提供方才能选中后到模型菜单看错误并重试。
  - 非 `ready` 的提供方模型列表未知，记住的模型 id 原样保留，等列表到达后再解析；没有记忆时模型为空，提交和模型按钮都回落到该提供方的默认模型（`resolveEffectiveComposerModelId`）。
- **运行中的 Agent**：提供方按钮渲染为禁用态，只显示图标，不能打开。
- **紧凑布局（sheet）**
  - Agent controls sheet 增加「提供方」行，点进去是提供方列表，分组规则和桌面端相同。
  - 「模型」行进入的模型列表同样只含当前提供方。
  - 运行中的 Agent 上，「提供方」行只读。
- **图标机制**
  - 每个提供方可以有两个版本：
    - 单色版：沿用现有的 `color`/`currentColor` 上色。
    - 彩色版：SVG 自带颜色，忽略 `color`。
  - 提供方图标的取用接口按 `tone` 决定版本：`resolveProviderGlyph({ provider, serverId, tone })` 返回图标和品牌色。`tone` 为 brand 且该提供方有彩色版时返回彩色版，否则返回单色版并按现有规则上色。`getProviderIcon` 签名不变，供单色调用方使用。
  - 彩色版的品牌色部分不受 `color` 影响。中性部分（Kimi 的 K）用 `currentColor`，由调用方传入主题前景色。
  - 每个彩色图标实例给渐变 id 加 `useId` 后缀，避免 Web 上同名 id 取到 `display:none` 子树里的定义。
  - 模型浏览器行（模型行与提供方行）上的提供方图标改用 brand tone；提供方视图的标题图标保持 foreground。
- **彩色 SVG 资源**
  - 从 LobeHub Icons 取 Codex、Kiro、MiniMax、Kimi、Gemini CLI 的彩色 SVG。
  - Oh My Pi 取官网 favicon。
  - Codex 去掉白色圆角方底，只保留渐变图形。
  - Kimi 彩色版的 K 原为 `#fff`，亮色主题下不可见，改为 `currentColor` 跟随主题前景色，蓝点 `#1783FF` 固定（2026-09-28 用户决策）。
  - Oh My Pi 的渐变 id 由 `g` 改为 `omp-color-gradient`。
  - 所有 SVG 去掉 `width="1em"`、`style`、`<title>` 等根节点属性，存放在应用的 assets 里。
  - 一并提交 LobeHub Icons 的 MIT LICENSE 文本。
  - 不新增 npm 依赖。
- **品牌色表补齐**：Codex `#3941FF`、Kiro `#9046FF`、MiniMax `#E73562`、Kimi `#1783FF`、Oh My Pi `#9B4DFF`、Gemini `#207CFE`；Claude 保持 `#D97757`。品牌色和亮暗主题无关。
- **彩色版的使用范围**：只在 Composer 工具栏的提供方按钮、提供方列表、模型列表里用彩色版。其他调用方仍用原来的 tone，因此外观不变。
- **协议**：不变。提供方状态、启用标记、模型列表都来自现有的提供方快照。

## Testing Decisions

- **好的测试只验证外部行为**：用户看到哪些提供方、分在哪一组、选中后模型菜单列出什么、按钮是否可点、图标取的是哪个版本。不测试组件内部状态和样式细节。
- **接缝 1（最高层，主接缝）：浏览器 e2e，覆盖 New workspace 草稿 Composer**
  - 用现有的提供方种子 helper 构造多个提供方（含一个不可用的），然后验证：
    - 提供方按钮存在
    - 列表的平铺和折叠分组正确
    - 切换提供方后模型菜单只列该提供方的模型
    - 搜索不命中其他提供方的模型
    - 切回一个用过的提供方时恢复上次的模型
  - 另加一个用例：在已运行的 Agent 上，提供方按钮为禁用态。
  - 先例：New workspace 在提供方恢复后还原模型的 e2e 用例，以及 Agent profiles 的 e2e helper。
- **接缝 2（纯函数单元测试）：provider-selection 模块**
  - 验证提供方分组函数：`ready`/`loading` 平铺；`error`/`unavailable` 进「更多」；未启用的排除；保持顺序。
  - 验证模型浏览器视图在单一提供方下的初始视图、搜索范围和收藏过滤。
  - 先例：provider-selection 和 model-browser-view 现有的单元测试。
- **接缝 3（单元测试）：提供方图标模块**
  - 验证 brand tone 下有彩色版的提供方返回彩色版，并且不受 `color` 影响。
  - 验证没有彩色版的提供方仍按 `color` 渲染。
  - 验证补齐后的品牌色表。
  - 先例：provider-icons 现有的单元测试。
- **手机端**：不新增 Maestro 流程。如果现有的模型 sheet 流程因为多出「提供方」行而失效，就更新对应流程，不在本地跑，交给 CI。
- **验证方式**：按仓库规定只跑改动的单个测试文件；每次改动后跑 typecheck 和 lint。

## Out of Scope

- Command chip（Slash command 在输入框和对话记录里渲染成块），后续单独立任务。
- 思考等级滑条，见任务 `09-28-thinking-slider`。
- 侧边栏、标签页、设置页等 Composer 以外位置的图标换彩色。
- 新增「常用提供方」之类的用户设置。
- 运行中的 Agent 更换提供方。
- 为 GitHub Copilot、OpenCode、Pi、Cursor 自制彩色图标。
- 协议和 daemon 的任何改动。
