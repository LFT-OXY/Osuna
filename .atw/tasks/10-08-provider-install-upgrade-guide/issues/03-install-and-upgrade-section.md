# 03 — 常驻的"安装与升级"区块

**What to build:** 六家内置提供方（Claude Code、Codex、Copilot、OpenCode、Pi、Oh My Pi）的详情页，在版本一节下面常驻显示"安装与升级"区块，提供方装没装都显示。区块按官方文档的分法分成标签，默认选中第一个适用于主机系统的标签。每个标签下分别列出"安装"和"升级"命令，每条都能复制。底部是"在运行 Osuna 守护进程的机器上执行"的提示和官方文档链接。继承内置提供方的自定义提供方，显示所继承那家的区块。规格见 `prd.md` 的"安装与升级数据""详情页""UI and Design"三节，命令原文见 `research/official-commands.md`。

**Blocked by:** None — can start immediately
**Status:** ready-for-agent
**Impl:** ready

- [ ] 安装与升级数据替换现在"按系统列首推命令"的安装指引数据。六家的安装方式、命令和文档链接与 `prd.md` 里的表一致，命令照录官方原文。Pi 的 Windows 用官方的 PowerShell 安装脚本；Pi 和 OMP 的文档链接换成各自的 GitHub README。
- [ ] 默认标签是"官方顺序里第一个适用于主机系统的安装方式"；主机系统未知时，选第一个标签。
- [ ] 自定义提供方显示所继承那家的数据，标题能看出是哪个 CLI；继承 `acp` 的或者未知 id，不显示区块。
- [ ] 详情页上，提供方装没装都在同一个位置显示区块，顺序是：错误卡片 → 继承接口的警告 → 版本 → 安装与升级 → 第三方接口 → 模型 → 诊断。被关闭的提供方仍然只显示"已关闭"卡片。
- [ ] 删掉"选择主机的操作系统"的占位和它的文案。区块标题、"安装"、"升级"等新文案补齐 9 种语言；命令和标签名不翻译。
- [ ] 安装指引模块的解析测试：六家都有数据；Windows 主机上，Copilot 和 OpenCode 默认选 npm，Pi 默认选 PowerShell；主机未知时选第一个标签；自定义提供方用所继承那家的数据；继承 `acp` 或者未知 id 时没有区块。
- [ ] 详情页组件测试：装没装都显示区块，位置在版本一节和第三方接口之间；被关闭的提供方不显示；切换标签后命令跟着变；点复制会带上那条命令。改写现有的"版本和安装指引二选一""已安装不显示指引"和排序用例。
- [ ] `docs/providers.md` 写明：新增内置提供方时，要在 App 的安装与升级表里补上它的数据。
- [ ] UI：已安装的 Claude Code 详情页 / 桌面 1280。截图里，版本一节下面能看到"安装与升级"区块，默认选中 macOS/Linux 标签，"安装"和"升级"两组命令都能看到。
- [ ] UI：OpenCode 详情页 / 桌面 1280。7 个标签全部可见，或者能滚动到；标签文字不被截断，不撑破卡片。
- [ ] UI：Claude Code 详情页，选中 Windows 标签 / Web 390。最长的那条 CMD 安装命令能完整看到，或者能横向滚动；复制按钮没有被挤出卡片。
