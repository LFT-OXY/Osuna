# 04 — 升级失败时，引导用户去看"安装与升级"区块

**What to build:** 一键升级失败时（"正在升级"除外），详情页的失败块在原因下面加一句引导，让用户按下方"安装与升级"区块里的命令手动升级，或者查看官方文档。原来只在"判断不出安装方式"时才出现的手动提示和它附带的文档链接一起去掉。没有区块的提供方不显示这句引导。规格见 `prd.md` 的"升级失败块"一节。

**Blocked by:** 01 — 升级"成功"但版本没变时判为失败；03 — 常驻的"安装与升级"区块
**Status:** ready-for-agent
**Impl:** done

- [x] `command_failed`、`timeout`、`version_unchanged`、`install_method_unknown`、`not_installed`、`unsupported`、请求没送达，以及不认识的错误码，详情页的失败块都显示这句引导。`in_progress` 不显示。列表行的失败块不带引导（Q21）。
- [x] `install_method_unknown` 不再显示单独的手动提示，也不再带文档链接。
- [x] 没有区块的提供方（比如继承 `acp` 的）失败时不显示这句引导。
- [x] 引导文案补齐 9 种语言。
- [x] 详情页组件测试：上面每一类失败显示或者不显示引导，都有对应用例；列表行不带引导在列表的组件测试里断言。改写现有的"判断不出安装方式时指向手动升级提示"用例。
- [x] UI：提供方详情页 / 版本一节的升级失败块 / 桌面 1280。截图里，原因下面有指向"安装与升级"的引导，同一屏也能看到区块本身。
- [x] typecheck 和 lint 通过。
