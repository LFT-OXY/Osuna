# 02 — Agent 读图、改图的工具和 daemon 校验

**What to build:** 新建 daemon 的逻辑图模块，独占逻辑图的读、写、校验和变更通知；Agent 工具和客户端 RPC 都只经过它。通过 Osuna 自己的 MCP 工具（与 `create_agent` 同一套注册方式）给 Agent 两个工具：**读取**返回整张图；**更新**一次带一组增量操作——新增或修改节点、删除节点、新增或删除连线、设标题、记录 spec 框架判断、写入或替换节点文档内容、把节点改成指向外部文档（文件加标题文字）。整组操作要么全部生效，要么全部不生效。校验：id 唯一；连线两端节点都存在；判断节点至少两条带条件文字的出线；文档来源合法、指向的外部文件存在。不合格整体拒绝并返回 Agent 看得懂的错误；某一层超过 20 个节点照常写入但附提醒，建议收进 **Subgraph node**。节点改成指向外部文档时删除它原来的自有文档文件。Agent 第一次更新时用正式标题替换 01 建的临时名。工具按调用方 Agent 找到它的 workspace 和它维护的那张图；没开开关的 Agent 调用更新会被拒绝。两个对话同时更新同一张图，各自的改动都保留。另加客户端 RPC：列出 workspace 的逻辑图、读取一张图（文件被手动改坏时返回"哪张图、哪个文件、什么问题"的可读错误），以及"图已变更"推送事件。骨架存放与字段见 PRD 的"数据与存放"和 ADR 0013。
