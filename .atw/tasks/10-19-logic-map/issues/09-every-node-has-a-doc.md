# 09 — 没有 spec 框架时每个节点都有节点文档

**What to build:** 07 真机验收里，在没有 spec 框架的项目中，Claude Code 给 40 个节点都写了自有文档，Codex 43 个节点只写了 3 份、Pi 20 个节点只写了 7 份，点那些节点什么都打不开（`research/07-real-agent-acceptance-notes.md` 问题 3）。让这条规则不靠 Agent 自觉：`update_logic_map` 写入后，凡是该有文档却没有的节点（spec 框架判为没有时的每个节点；有 spec 框架时是没有临时要点也没有外部指向的节点），在返回给 Agent 的结果里逐个列出并要求补上，照常写入、不拒绝，与"超过 20 个节点"的提醒同一种方式。说明块里把"每个节点都要有文档"写得更明确，并说明工具会列出缺文档的节点。图上缺文档的节点在卡片上有可见的标记，用户点它时提示"这个节点还没有文档"，不再什么都不发生。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent
