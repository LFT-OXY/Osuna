# 逻辑图：边聊边生成的流程图，节点挂需求文档

来源：2026-10-19 用户访谈 5 轮 25 题，用户已确认。术语见 `docs/glossary.md` 的 **Logic map**（逻辑图）、**Node**（节点）、**Node doc**（节点文档）、**Subgraph node**（子图节点）；关键取舍见 [ADR 0013](../../../docs/adr/0013-logic-map-stores-skeleton-and-links-existing-docs.md)。

## Problem Statement

用户接到一个功能时，往往自己也没完全想清楚，需要和 **Agent** 来回讨论。讨论结果全是文字，功能一多，分支、失败情况和前后顺序就把人绕晕，人和 Agent 对业务的理解也可能悄悄出现偏差。想看图，得每聊一段就专门叫 Agent "画个图"。画出来的只是一张图片，背后没有对应的需求文档，也和之后开发用的文档对不上。

## Solution

在 Osuna 桌面端，用户可以给某个对话打开"逻辑图"开关。打开后，这个对话里的 Agent 每轮聊出新结论，就自动维护一张 **Logic map**：一张以流程为主的图，线表示"接下来发生什么"，判断点画出每条分支（包括失败的那条）。图显示在右边栏新增的"逻辑图"标签里，可以拖动、缩放；点一个 **Node**，主区域会开一个新标签，显示它的 **Node doc**。图由 Osuna 根据骨架自动排版，画图本身不花 token。项目里已有 spec 框架（自带需求文档体系，比如 ATW）时，节点直接指向那套文档里对应的段落，不另写一份。聊完之后图和文档都已就绪，可以直接开发。

## User Stories

开关与对话

1. 作为用户，我想在对话输入框下方的工具栏里有一个"逻辑图"开关，这样不用记命令就能开启。
2. 作为用户，我想让开关默认关闭，这样平时修 bug 的对话不会冒出图来、白花 token。
3. 作为用户，我想在打开开关时选"新建一张逻辑图"或"接着某张已有的逻辑图"，这样隔天开新对话也能接着补同一张图。
4. 作为用户，我想在新对话还没发出第一条消息时就能打开开关，这样从第一轮起就有图。
5. 作为用户，我想关掉开关后 Agent 停止更新，但已画好的图和文档原样保留，这样关开关不会丢东西。
6. 作为用户，我想让开关状态在 Osuna 重启后保持不变，这样不用重新设置。
7. 作为用户，我想在桌面端连到一台还不支持逻辑图的旧版 Osuna 主机时，看到"需要更新这台主机上的 Osuna"的提示，而不是一个点了没用的开关。

Agent 的行为

8. 作为用户，我想让 Agent 在开关开着的对话里，只要聊出新结论就自动更新逻辑图，不用我每次说"画个图"。
9. 作为用户，我想让 Agent 每次更新后在回复里用一两句话说明加了、改了、删了哪些节点，这样我能马上发现它理解错的地方。
10. 作为用户，我想让 Agent 按"一个节点 = 一件能单独说清、单独开发、单独验收的事"来切节点，这样图既不会细到绕晕，也不会粗到看不出逻辑。
11. 作为用户，我想让一层图保持在大约 7 到 20 个节点，超出的收进一个 **Subgraph node**，这样每一层都看得过来。
12. 作为用户，我想让判断点画出每一条分支，尤其是出错、失败的那条，这样异常情况不会被漏掉。
13. 作为用户，我想让功能拆解（比如"登录"分成"密码登录""验证码登录"）只出现在最顶层，每一部分再展开成流程，这样图读起来始终是"事情怎么走"。
14. 作为用户，我想在聊天里说"把锁定改成 5 次"就能改图，而不是自己拖方块，这样图和文档永远出自同一个来源。
15. 作为用户，我想让 Agent 在第一次为某张图开工时告诉我它的判断：这个项目有没有 spec 框架、节点文档会指向哪里。这样判断错了我能马上纠正。
16. 作为用户，我想在 Agent 判断错时直接在对话里纠正它，它会改正并记在这张图里。
17. 作为用户，我想在 Agent 写错图的格式时，由 Osuna 拒绝这次写入并告诉它错在哪，这样图永远不会坏掉。
18. 作为用户，我想在两个对话同时维护同一张图时，各自的改动都保留下来、互不覆盖。

节点文档

19. 作为没装 spec 框架的用户，我想让每个节点都有一份完整的节点文档，写清这一块怎么做，这样聊完就能直接开发。
20. 作为装了 spec 框架的用户，我想让节点指向框架文档里对应的段落、不另写一份，这样只有一份需求，不会前后矛盾，也不重复花 token。
21. 作为装了 spec 框架的用户，我想在框架还没写出正式文档时，节点里先有 3 到 6 句临时要点（这一步做什么、有哪些规则、走哪条分支），这样聊天过程中点开也能看懂。
22. 作为装了 spec 框架的用户，我想在框架写出正式文档后，由 Agent 把节点从临时要点改成指向对应段落。
23. 作为装了 spec 框架的用户，我想让还停留在临时要点的节点带一个"还没指向正式文档"的小标记，这样我知道哪些还没对上。
24. 作为用户，我想在任何对话里接着某张图重新打开开关时，Agent 先把带标记的节点补上指向，再继续聊。
25. 作为用户，我想让自写的节点文档和图的骨架存放在项目的 `docs/logic-maps/<图名>/` 里，这样开发用的 Agent 和队友都能读到，文件也跟着代码进版本记录。

看图

26. 作为用户，我想在右边栏看到"逻辑图"标签，和 Files、Changes、Session history 并排，这样看图不用离开工作区。
27. 作为用户，我想让"逻辑图"标签在某个对话第一次打开开关时自动出现在右边栏；没用过逻辑图的工作区里它不出现，需要时可以从右边栏的 + 菜单加回来。
28. 作为用户，我想在 Agent 更新图后，不用手动刷新就看到新版本。
29. 作为用户，我想用标签顶部的下拉框，在这个工作区的各张逻辑图之间切换，默认显示当前对话正在维护的那张。
30. 作为用户，我想能拖动、缩放逻辑图，这样大一点的图也能看全。
31. 作为用户，我想从形状上区分开始/结束、普通步骤、判断点、子图节点，这样一眼看出逻辑走向。
32. 作为用户，我想在分支的线上看到条件文字（比如"密码错误"），这样不用点开就知道什么情况走哪条路。
33. 作为用户，我想点开子图节点就进入下一层，并在顶部看到"登录 › 密码登录"这样的路径，点前一级就能回去。
34. 作为用户，我想点一个节点就在主区域开一个新标签显示它的文档，逻辑图留在原处，这样能一边看图一边读文档。
35. 作为用户，我想在节点指向的是框架文档时，点开后打开那份文档并直接定位到对应段落。
36. 作为用户，我想让我正在读的那份节点文档对应的节点在图上高亮，这样我知道自己读到了图的哪里。
37. 作为用户，我想在一个还没有逻辑图的工作区里打开"逻辑图"标签时，看到一句"怎么开启"的说明，而不是一片空白。
38. 作为用户，我想在某张图的文件被手动改坏时，看到"哪张图、哪个文件出了什么问题"的提示，而不是空白或崩溃。
39. 作为用户，我想在简体中文和英文界面下都看到正确的文字，"逻辑图""节点"等叫法与术语表一致。

## Implementation Decisions

**数据与存放**

- 每张逻辑图是项目里 `docs/logic-maps/<图名>/` 下的一个文件夹，里面放一份骨架文件，以及 Osuna 自写的节点文档（每个节点一个 Markdown 文件）。存放位置跟随 **Workspace** 的 `cwd`，所以不同 worktree 各有各的副本，跟着 git 走。
- 骨架记录这些内容：图标题；对 spec 框架的判断（有或没有，以及框架文档在哪）；节点列表，每个节点有稳定 id、标题、种类（开始 / 结束 / 步骤 / 判断 / 子图）、所属子图层级、文档来源；连线，带可选的条件文字。
- 节点的文档来源只有两种：
  - **自有文档**：图文件夹里的一个 Markdown 文件。装了 spec 框架时，这个文件就是临时要点，节点同时带"还没指向正式文档"标记。
  - **指向外部文档**：项目里的某个文件加上其中的某个标题。存的是标题文字而不是行号，打开时再换算成行号，这样文档改动后也不会指错位置。
- 节点改成指向外部文档时，Osuna 删除它原来的临时要点文件。
- 骨架用 zod schema 校验，按 `docs/data-model.md` 的约定原子写入，不做迁移。

**Daemon 侧（新的逻辑图模块）**

- 新建一个模块，独占逻辑图的读、写、校验和变更通知。Agent 工具和客户端 RPC 都只经过它。
- 通过 Osuna 自己的 MCP 工具（与 `create_agent` 等同一套注册方式）提供两个工具：
  - **读取**：返回整张图，供 Agent 接着已有的图继续干活。
  - **更新**：一次调用带一组增量操作，包括新增或修改节点、删除节点、新增或删除连线、设标题、记录 spec 框架判断、写入或替换节点文档内容、把节点改成指向外部文档。整组操作要么全部生效，要么全部不生效。用增量操作而不是整图重写，一来省 token，二来两个对话同时改同一张图时不会互相覆盖。
- 更新时的校验规则：
  - id 唯一；
  - 连线两端的节点都存在；
  - 判断节点至少有两条带条件文字的出线；
  - 文档来源合法，指向的外部文件存在。

  任一条不合格就整体拒绝，并返回 Agent 能看懂的错误。某一层超过 20 个节点时照常写入，但附一条提醒，建议收进子图节点。
- 工具按调用方 Agent 找到它的 workspace 和它维护的那张图。没开开关的 Agent 调用更新工具时会被拒绝。
- 每个 Agent 是否开启逻辑图、维护哪张图，由 daemon 随 Agent 记录持久保存。
- 开关开着时，daemon 在发给 provider 的每条用户消息末尾附加一段逻辑图说明块，做法和 **Routing block** 一样：只附在发给 provider 的那份里，时间线保留原文，并从 provider 历史、导入和预览里剥掉。说明块写明以下内容：
  - 当前维护的是哪张图；
  - 节点粒度和每层数量的规则；
  - 每轮有新结论就更新，并在回复里说明改了什么；
  - 第一次开工时先判断项目有没有 spec 框架；
  - 临时要点写 3 到 6 句；
  - 带"还没指向正式文档"标记的节点要先补上指向。
- 新建图时，daemon 先创建一张带临时名字的空图，Agent 第一次更新时定下正式标题。
- 新增 RPC，按 `docs/rpc-namespacing.md` 用带点的命名空间和成对的 `.request` / `.response`：列出 workspace 的逻辑图；读取一张图；给 Agent 或草稿设置逻辑图开关（关闭、新建或接着某张图）。另加一个"图已变更"推送事件。
- 在 `server_info.features` 里加一个逻辑图功能标记。客户端只在这一处做判断，标记不在就显示"需要更新主机"，不写兜底路径。所有协议新增字段都是可选的。

**App 侧**

- 新增"逻辑图"面板，注册到面板注册表，只允许放在 Explorer sidebar，并且是单例（一个右边栏里只有一个）。它不是每个 workspace 一出生就带的默认标签：某个对话第一次开启开关时自动加入并选中，也可以从 + 菜单打开。
- 面板顶部是逻辑图下拉框和面包屑导航（Breadcrumb），主体是可拖动、缩放的画布，复用现有的可缩放视图组件。
- 自动排版用一个层级布局库（候选 `@dagrejs/dagre`，在原型阶段最终确认），这会新增一个外部依赖。现有 Mermaid 渲染跑在隔离 iframe 里，做不了节点点击、高亮和自定义样式，所以不用它来画图。排版是一个纯函数：输入骨架，输出坐标。
- 点击节点时，通过现有的"打开文件"入口在主区域开文件标签。指向外部文档的节点，会带上由标题换算出的起始行号。当前聚焦的主区域文件标签如果是某个节点的文档，这个节点在图上高亮。
- 输入框工具栏加"逻辑图"开关（用 Switch 组件）。打开时弹出选择：新建，或从这个 workspace 已有的图里挑一张。草稿对话和运行中的对话都能用。
- 界面文字全部走 i18n，zh-CN 和 en 都要有，用词与术语表一致。

## UI and Design

- **视觉方向已定：贴近 Dify / Coze。** 2026-10-19 第 01 轮对比了五个方向（`style-explorer.html`），用户选 04。画布从上往下排；节点是白色卡片，每种节点一个彩色图标块；判断卡片里一行写一个"如果 / 否则"，出口在行尾；正常连线用靛紫色，失败的线用红色；背景是灰底点阵；选中节点用蓝色描边。完整的方向卡、色表和各状态的样子见 [ui-direction.md](ui-direction.md)，正式界面照此实现。
- **必须有的画面与状态：**
  - 空状态：这个 workspace 还没有逻辑图，显示开启说明；
  - 加载中；
  - 正常的图；
  - 新建后 Agent 还没写入的空图；
  - 子图内层，带面包屑；
  - 节点选中高亮；
  - 带"还没指向正式文档"标记的节点；
  - 图文件损坏的错误提示；
  - 主机版本太旧的提示；
  - 输入框工具栏开关的开、关两态，以及打开时的选择弹层。
- **目标视口：** 桌面端（Electron），窗口宽 1280、右边栏默认宽度。不做手机和紧凑布局。
- **适用的设计规则：** `docs/design.md`、`docs/hover.md`、`docs/unistyles.md`、`docs/floating-panels.md`（选择弹层）、`docs/i18n.md`。开关用 Switch，图名不用等宽字体。**例外：** 逻辑图画布内部使用 `ui-direction.md` 色表里的颜色，超出 `docs/design.md` 第 14 节"禁止新增颜色"的规定；实现时要在 `docs/design.md` 里登记这个例外，范围只限画布内部，面板头部、标签栏和弹层仍用应用的主题色。每张节点卡片在悬停时显示完整标题，因为适应宽度后会缩到约 57%，长标题会被截断。
- **截图上能检查的验收点：**
  - 1280 宽窗口、默认宽度的右边栏里，一张 10 个节点的图缩放到"适应宽度"后，节点标题要么完整显示，要么截断但有完整标题的提示；
  - 判断点和普通步骤在形状上能一眼区分；
  - 每条出线的条件文字可读，不与线或节点重叠；
  - 选中节点与其他节点明显不同；
  - 带标记的节点能看到标记；
  - 内层图里能看到面包屑，最后一级是当前层。

## Testing Decisions

- **什么是好测试：** 只看外部行为，也就是 Agent 调了工具之后磁盘上留下了什么、客户端读到了什么、界面显示了什么，不测内部实现。按 `docs/testing.md` 的要求用真实依赖和临时目录，不用模拟对象。
- **主接缝是 daemon 的逻辑图模块，从工具入口测。** 以开着开关的 Agent 身份调用更新工具，然后检查磁盘上的骨架和节点文档、读取 RPC 的返回，以及变更事件。要覆盖：
  - 合法写入；
  - 每条校验规则的拒绝；
  - 一组操作的原子性；
  - 两个调用方并发更新互不覆盖；
  - 改成指向外部文档后，临时要点文件被删除；
  - 没开开关的 Agent 调用被拒绝；
  - 文件被手动改坏时，读取返回可读的错误。

  先例：`mcp-server.test.ts`、`mcp-parity.e2e.test.ts`。
- **说明块：** 开关开着时发出的消息带说明块，关着时不带；时间线和历史里都看不到它。先例：`routing-block.test.ts`、`trailing-routing-block.test.ts`。
- **排版纯函数：** 单元测试节点互不重叠、子图正确分层、分支顺序稳定。先例：可缩放视图的 `geometry.test.ts`。
- **面板：** Playwright 浏览器测试，喂假数据，覆盖空状态、正常图、子图与面包屑、点击节点触发打开文件、高亮、标记、损坏提示。先例：`*.browser.test.tsx`（如 `turn-usage-panel.browser.test.tsx`）。
- **协议：** 新字段都是可选的；旧客户端能解析新消息，新 daemon 能解析旧消息。先例：packages/protocol 里已有的兼容性测试。
- **真机验收：** 在 Claude Code、Codex、Pi 里各开一次开关，聊一个小功能，确认图会自动出现和更新、回复里有改动说明、点开节点能看到文档。不在本机测 CLI 登录；需要真实 Agent 的验收，先征得用户同意再做。

## Acceptance Criteria

- [ ] 输入框工具栏有"逻辑图"开关，默认关闭；打开时可选新建或接着已有的图；草稿对话也能用；重启后状态保留。
- [ ] 开关开着时，Agent 每轮有新结论就通过 Osuna 工具更新逻辑图，并在回复里说明增、改、删了哪些节点；关闭后不再更新，已有的图和文档保留。
- [ ] 右边栏出现"逻辑图"标签，与 Files、Changes、Session history 并排；第一次开启时自动出现，也能从 + 菜单打开。
- [ ] Agent 更新后面板不用手动刷新就显示新图；下拉框能切换 workspace 里的各张图，默认显示当前对话维护的那张。
- [ ] 图能拖动、缩放；开始/结束、步骤、判断、子图节点形状可区分；分支线上有条件文字。
- [ ] 点子图节点进入下一层，面包屑能回到上一层。
- [ ] 点节点在主区域开标签显示节点文档；指向框架文档的节点打开那份文档并定位到对应段落；当前文档对应的节点在图上高亮。
- [ ] 无 spec 框架的项目，图和节点文档写在 `docs/logic-maps/<图名>/`；有 spec 框架的项目不另写正式文档，只写临时要点，框架文档出现后改为指向。
