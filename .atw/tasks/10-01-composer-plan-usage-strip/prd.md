# 输入框窄栏常驻显示套餐用量，并重整上下文弹层

## Problem Statement

用 Claude Code、Codex 这类订阅制提供方干活时，用户最关心的是「这个 5 小时窗口和这周的额度还剩多少、多久后重置」。现在这些信息只藏在输入框上下文圆环的弹层里：要先把鼠标移到圆环上，等弹层打开，再往下找到弹层底部的套餐用量部分。每次想看一眼都得来回悬停，额度快用完时也没有任何主动提示，往往是 Agent 被限流了才发现。

上下文弹层本身也乱。标题「上下文窗口」和「已使用 5%」字号差不多，层级不清；上下文部分是纯文字堆叠，本会话合计却是左右对齐的数值行，两种排法混在一起。弹层里还同时出现两个对不上的「估算成本」（上下文部分 $0.52，本会话合计 $0.40），用户无从判断该信哪个。

## Solution

在桌面端输入框下方的 **Composer context strip**（窄栏）右侧，常驻显示当前 Agent 所属提供方的 **Plan usage（套餐用量）**。它是一块分段仪表：

- 第一段是提供方图标和套餐名（如 `Max 20x`）。
- 后面每个限额窗口一段，显示「小圆环 + 短名 + 百分比 + 重置时长」，例如 `◔ 周 45% 4d`。
- 圆环按用量变色：充足时绿色，紧张时橙色，快满时红色。
- 预测会在重置前用完的窗口，时长换成红字 `1h后用完`。

鼠标悬停在这块仪表上，会弹出完整的套餐用量卡片。

上下文弹层在桌面端去掉套餐部分，改成左右两栏：左栏讲上下文窗口，右栏讲本会话合计；上下文部分的估算成本删掉，只保留本会话合计里的那一个。手机端没有窄栏，弹层改成单栏，依次是上下文、本会话合计、套餐用量卡片。

## User Stories

1. 作为桌面端用户，我想在输入框下方直接看到当前提供方各个限额窗口的用量百分比，这样不用悬停就知道还能放心用多少。
2. 作为桌面端用户，我想在每个窗口旁边看到多久后重置，这样能决定是现在继续还是等额度恢复。
3. 作为桌面端用户，我想让小圆环按用量变色（绿 / 橙 / 红），这样扫一眼就知道哪个窗口紧张。
4. 作为桌面端用户，我想在某个窗口预计会在重置前用完时看到红字「X后用完」，这样能在被限流之前调整节奏。
5. 作为桌面端用户，我想看到套餐名（如 Max 20x、Pro）和提供方图标，这样知道这些额度属于哪个账户的哪个套餐。
6. 作为桌面端用户，我想让窄栏里的窗口名用短名（5h、周、模型名、审查），这样一行能放下全部窗口。
7. 作为使用多个按模型细分周额度的 Claude 用户，我想让细分窗口在窄栏里只显示模型名（如 Fable），这样不会和总的周额度混淆，也不会太宽。
8. 作为桌面端用户，我想悬停在套餐仪表上看到完整卡片（完整窗口名、进度条、百分比、「X 后重置」、Extra usage 等余额、更新时间），这样需要细节时随手就能看。
9. 作为同时用 Claude 和 Codex 的用户，我想让窄栏只显示当前 Agent 所属提供方的套餐用量，这样信息和眼前的对话相关，窄栏也不会被挤满。
10. 作为 Codex 用户，我想看到 Codex 的 5h、周、审查三个窗口，这样和 Claude 用户得到一样的体验。
11. 作为使用 OpenCode 等没有套餐数据的提供方的用户，我想让窄栏不出现任何套餐内容，这样不会看到空壳或误导性的 0%。
12. 作为把提供方指向第三方 API 接口的用户，我想让窄栏不显示套餐用量，因为那时订阅额度不代表实际消耗；需要知道原因时，可以在「用量」页面（手机端在上下文弹层）的套餐用量卡片里看到说明。
13. 作为桌面端用户，我想在套餐数据加载中、取数出错或主机版本过旧时，窄栏保持安静而不是闪烁或报错，这样窄栏原有的工作区和分支信息不受干扰。
14. 作为窗口较窄或开了分屏的桌面端用户，我想让分支名始终保留可读的长度，空间不够时先隐藏末尾的窗口段，再隐藏套餐名段，至少保留第一个窗口段，这样窄栏原有的切换分支功能不会被挤没。
15. 作为长时间开着 Agent 的用户，我想让套餐用量自动定期刷新，重置倒计时也随时间更新，这样窄栏上的数字不会一直停在打开时的样子。
16. 作为在意提供方接口调用次数的用户，我想让自动刷新的频率不超过守护进程自己的缓存周期，这样常驻显示不会额外增加对提供方账户接口的请求。
17. 作为桌面端用户，我想让上下文弹层只讲上下文和本会话，不再重复窄栏上已有的套餐用量，这样弹层更短、更聚焦。
18. 作为桌面端用户，我想让上下文弹层分成左右两栏，左边是上下文用量（大号百分比、进度条、tokens），右边是本会话合计，这样两类信息层级分明。
19. 作为用户，我想让弹层里只出现一个估算成本（本会话合计里的那个），这样不会被两个对不上的数字搞糊涂。
20. 作为手机端用户，我想继续在上下文弹层里看到套餐用量，因为手机上没有窄栏。
21. 作为手机端用户，我想让手机弹层单栏叠放（上下文、本会话合计、套餐用量卡片），这样窄屏上也能顺畅阅读。
22. 作为中文界面用户，我想让窄栏短名、区块标签等新增文案都显示为中文，其他语言也有对应翻译。
23. 作为依赖读屏的用户，我想让窄栏的套餐仪表带有完整的无障碍描述（窗口全名、百分比、重置或用完时间），这样不用看图也能拿到同样的信息。
24. 作为使用其他主题（亮色、各种暗色）的用户，我想让窄栏和弹层的配色都跟随当前主题，这样换主题后不会出现突兀的硬编码颜色。
25. 作为在新建 Agent 草稿标签页里选择提供方的用户，我想在窄栏看到所选提供方的套餐用量，这样能在开始之前判断用哪个提供方更合适。

## Implementation Decisions

- **术语**：界面和代码统一用 Plan usage（套餐用量）；禁止在界面上写「额度 / Quota」。术语表中 Composer context strip 的定义已更新为包含套餐用量（见 `docs/glossary.md`）。
- **只改客户端，不改协议**。数据沿用现有 `provider.usage.list` RPC 和 `ProviderUsage` 结构（窗口、余额、明细、套餐名、`resetsAt`、`runsOutAt`、`shortfallPct`、`tone`）。能力判断沿用现有的 `providerUsageList` 主机特性。
- **新增一个纯逻辑模块（窄栏套餐视图模型）**，放在套餐用量功能目录下。输入是套餐用量取数结果、当前提供方 id、当前是否启用第三方接口、当前时间；输出是「不显示」，或者有序的分段列表。
  - 分段列表的第一项是套餐名段（图标 + `planLabel`；`planLabel` 为空时省略），后面是每个窗口段：短名、用量百分比、tone、尾部文字（重置时长或用完时长）、无障碍描述。
  - 余额（balances）和明细（details）不进窄栏。
- **「不显示」的条件**：取数加载中、出错、主机未连接、主机不支持、当前提供方在结果里没有条目、该条目状态不是 available、该条目没有窗口、当前提供方启用了第三方接口。已经拿到过数据后，后台刷新出错时沿用上次的数据，不隐藏（与圆环弹层、「用量」页共用的取数状态一致：有数据时数据优先）。提供方快照还没到、还不知道是否启用第三方接口时也先不显示，免得仪表出现后又消失。
- **短名映射**：按窗口 id 映射到翻译键。`five_hour` 和 `session` →「5h」，`weekly` →「周」，`code_review` →「审查」。Claude 按模型细分的周窗口（label 形如 `Weekly · <模型>`）只取模型名。不认识的 id 回退显示守护进程给的 label。悬停卡片仍显示完整 label。
- **tone**：优先使用守护进程给的窗口 tone（Claude、Codex 按 <70 ok、70–90 warning、>90 danger 下发）；缺失时用客户端已有的兜底推导。ok / warning / danger 分别对应主题的 statusSuccess / statusWarning / statusDanger；default 显示为 foregroundMuted。
- **尾部文字**：窗口同时有 `runsOutAt` 和 `shortfallPct` 时，显示用完时长（危险色，短语「X后用完」）；否则显示重置时长（只写时长，如 `4d`）；已到重置时间显示「正在重置」。时长格式沿用现有的短时长格式化。
- **宽度取舍是一个纯函数**：输入是可用宽度、分支名保留宽度、各分段的实测宽度，输出是要显示的分段（`fitPlanUsageStripSegments`）。隐藏顺序依次是：末尾窗口段 → 套餐名段 → 第一个窗口段始终保留。分支名在剩余空间内照常截断。
  - 分支名保留宽度取 80px 与分支名不截断时宽度中较小的一个（`resolvePlanUsageSpace`）。比 80px 短的分支名（如 `main`）只保留它自己的宽度，否则输入框 640px 时会多藏掉一个窗口段。
  - 分支项占满剩余空间，把仪表推到右侧。分支名与仪表之间只有一个间距，截断时省略号紧挨着仪表。
  - 实测宽度来自布局回调：窄栏量出分支名与仪表所在区域的宽度；分支名不截断时的宽度和每个分段的宽度，由看不见的副本量出。区域、分支名、各分段都量到之前，仪表一段也不显示，免得先溢出再收回。
- **取数**：窄栏可见时启用套餐用量查询，挂载时拉一次，之后每 5 分钟自动刷新（与守护进程 5 分钟缓存对齐）。打开悬停卡片时和今天的圆环弹层一样触发一次刷新；守护进程缓存挡住了重复请求，不会多打提供方接口。重置和用完倒计时在本地每分钟重新计算。窄栏和圆环弹层共用同一个查询键，数据只存一份。
- **窄栏组件**：Composer context strip 新增可选的套餐用量区，接收当前提供方 id。Agent 面板传 Agent 的提供方；草稿标签页传草稿当前选中的提供方。窄栏原有的显示条件（只在非紧凑布局显示）不变。
- **悬停卡片**：沿用现有的 Tooltip 浮层（与上下文圆环同一套，桌面端启用），仪表本身就是悬停外框；卡片宽 300px，向上弹出、右边与仪表对齐，内容是重排后的套餐用量卡片。悬停交互遵循 `docs/hover.md`。每次打开都刷新一次，只在从关到开时取数。
- **套餐用量卡片重排**：表格式布局（完整窗口名 / 进度条 / 百分比 / 尾部文字），名称、百分比、尾部三列按最宽的一格对齐，「用量」页里各提供方共用一套列宽。头部为提供方图标、名称、套餐徽标（`StatusBadge`）、出错或不可用时的状态徽标、右侧「更新于 X」。余额和明细是表格下方的键值行，余额不再画进度条。数据来源说明（`sourceLabel`，如 OpenUsage）放在卡片最后一行。窗口的显示值（百分比、tone、尾部文字）由 `resolveWindowRow` 统一计算，卡片和窄栏都从它取，窄栏只在它的尾部文字上改写短说法。出错信息和第三方接口说明保留在卡片里，出错信息按 `docs/design.md` 的内联错误写成 red-300 的 caption。这两种情况下窄栏不显示，所以桌面端只能在「用量」页面看到这两条说明，手机端在上下文弹层里看到（Q18）。「用量」页面也使用这张卡片，会一起换成新布局。
- **上下文弹层**：
  - 是否包含套餐用量，取决于这个输入框的窄栏是否可见：窄栏可见时不包含，否则包含。这样手机端，以及将来任何不带窄栏的输入框，都不会丢掉套餐信息。
  - 桌面端为左右两栏，手机端（紧凑布局）为单栏叠放。
  - 删除上下文部分的估算成本（Agent 状态里的 `totalCostUsd`），只保留本会话合计里的估算成本。
  - 上下文圆环本身的配色规则不变（<70% 灰）。
- **新增文案**全部走 i18n，所有语言资源同时补齐。

## UI and Design

- 选定方向是第 01 轮原型的 **03 分段仪表**，窄栏和弹层都用这个方向。完整方向卡、尺寸和 token 见 `ui-direction.md`；小样是 `prototype/c.html`，对比页是 `style-explorer.html`。用户直接选定，没有附加备注。已知代价是分段仪表最占宽度，由宽度取舍规则（Q17）解决。
- 设计规范以 `docs/design.md` 为准（项目在 `.atw/spec/` 下没有单独的 design-system 文档）：不新增颜色 token、不写硬编码色值，间距只用间距刻度，徽标用 `StatusBadge`，中粗字重只用于区块标签和标题。悬停遵循 `docs/hover.md`。
- 必须存在的状态：
  - 窄栏：余量充足；警告；危险；即将用完；Codex；窄宽度下隐藏末尾窗口段；再窄时隐藏套餐名段；加载中、出错、主机过旧、无套餐数据、第三方接口时不显示套餐区。
  - 套餐用量卡片：正常；出错（显示错误信息）；第三方接口（显示说明）。后两种只出现在「用量」页面和手机端上下文弹层，因为这时窄栏没有可悬停的套餐区。
  - 上下文弹层：桌面两栏；手机单栏含套餐卡片；本会话合计不完整、主机过旧等现有状态照常显示。
- 目标视口：桌面 1280（输入框最宽 820px，分屏时可窄到约 420px）；手机 390。
- 截图可验收的标准：
  - 桌面 1280、Claude Agent、三个窗口都有数据时，窄栏右侧依次显示 Claude 图标与 `Max 20x`、`5h`、`周`、模型名三个窗口段，高度与改动前相同（28px），分支名完整显示。
  - 用量 45% 的窗口圆环为绿色（statusSuccess），82% 的为橙色（statusWarning），93% 的为红色（statusDanger）；0% 的圆环只有轨道。
  - 预计在重置前用完的窗口，时长位置显示红色的「1h后用完」。
  - 输入框宽 420px、分支名很长时，分支名至少保留约 80px 并以省略号结尾，套餐区只剩第一个窗口段。
  - 当前 Agent 是 OpenCode、套餐取数出错、或 Claude 启用了第三方接口时，窄栏右侧没有任何套餐内容，左侧工作区与分支显示不变。
  - 桌面端悬停窄栏套餐区，弹出卡片显示完整窗口名、进度条、百分比和「X 后重置」，以及 Extra usage 行。
  - 桌面端打开上下文圆环弹层：左右两栏，左栏有大号百分比、进度条和 tokens，没有估算成本；右栏是本会话合计；没有套餐用量部分。
  - 手机 390 打开上下文圆环弹层：单栏，依次是上下文、本会话合计、套餐用量卡片。
  - 亮色主题下窄栏与弹层配色正确，没有暗色主题的残留色。

## Testing Decisions

- 好的测试只断言外部行为：用户看到的文字、颜色对应的 tone、出现或消失的元素、发出的请求次数。不断言组件内部状态或样式实现。
- **最高切入点：Playwright e2e（`e2e/browser/`）+ 现有套餐用量 fixture。** 现有 fixture 在 WebSocket 层注入 `providerUsageList` 特性和套餐用量响应，并能统计请求次数。在它上面覆盖：
  - 桌面端窄栏显示当前提供方的各个窗口段和套餐名；
  - 悬停窄栏出现完整卡片；
  - 桌面端上下文弹层不再包含套餐用量，手机视口下仍然包含；
  - 出错、无条目、主机不支持时窄栏没有套餐区；
  - 窄栏挂载时发出一次请求。
  - 现有 `provider-usage-tooltip.spec.ts`（断言桌面弹层渲染套餐用量、每次打开都刷新）随行为变化改写：桌面端的这些断言移到窄栏悬停卡片上，手机端保留弹层断言。
  - 现有 `context-window-token-label.spec.ts` 的视口切换写法是参照。
- **第二切入点：纯逻辑单元测试（Vitest unit，Node）。** 覆盖窄栏套餐视图模型（各种「不显示」条件、短名映射与回退、tone 回退、用完优先于重置、正在重置），以及宽度取舍函数（隐藏顺序、第一个窗口段始终保留、分支最小宽度）。参照 `provider-usage/view.test.ts`、`provider-usage/format.test.ts`、`composer/context-strip/model.test.ts` 的写法：构造输入、调用导出函数、`toEqual` 断言。
- **5 分钟自动刷新**：按 app 测试指南，用真实 `QueryClient` + `QueryObserver` 驱动导出的查询选项来断言刷新间隔与启用条件，参照 `hooks/use-agent-commands-query.test.ts`，不用渲染器，也不用定时器等待。
- 不用 `vi.mock` 替换本功能自己的模块；需要隔离的地方通过参数注入。
- 本地只跑改动涉及的单个测试文件；e2e 只跑目标 spec，全量交给 CI。原生端实机验收免做。

## Out of Scope

- 守护进程侧的任何改动：新提供方的套餐取数、缓存周期、tone 规则、窗口 label 本地化。
- 在窄栏显示余额类数据（Extra usage、Codex credits）。
- 同时显示多个提供方的套餐用量。
- 手机端新增常驻的套餐用量位置。
- 上下文圆环本身的形态与配色。
- 「用量」页面除了套餐用量卡片换新布局之外的任何改动。
- 额度不足时的主动通知（推送、弹窗）。
