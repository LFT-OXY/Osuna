# 01 — 第一条通路：DeepSeek 余额显示在列表行与详情分区

**What to build:** 用户加一家地址是 `api.deepseek.com` 的接口后，「第三方接口」列表行多一小段余额，详情页出现「余额与套餐用量」分区，写出余额与读数时间，有刷新按钮；查不到时分区就地写原因，行上写「余额查不到」；认不出查法的接口行上不多显示，分区写「没认出这家的余额查法」。这一张搭起后面所有工单共用的骨架：daemon 的厂商表与按主机名认、读余额 RPC、余额项与结果的协议形状、能力位、五类失败原因、测试 daemon 的厂商地址注入。

**Blocked by:** None — can start immediately
**Status:** ready-for-agent
**Impl:** done

- [x] daemon 按接口各格式地址的主机名认出 DeepSeek，`GET /user/balance`，带 key 的 Bearer 头、`Accept: application/json`、`User-Agent: Osuna/<version>`；接口设了请求头时照带，用户的请求头可盖过 User-Agent；「不校验证书」的接口沿用现有上游 fetch。
- [x] 取 `balance_infos[].total_balance`，币种按 `currency` 显示（¥ / $ / 「代码 + 空格」），两位小数；这一张只取第一个币种（多币种与拆分在 02）。
- [x] 新 RPC（`provider.api_endpoint.` 下，带点命名加 `.request` / `.response`）按一批接口 id 返回每家的结果：有读数 / 不支持 / 失败（地址不对、令牌被拒、这家不给查余额、取不到值、暂时查不到，附打码后截到 200 字的对方原话）与读数时间。余额项形状：标签、显示文字、数值、币种或单位、可选比例。新字段全部可选。
- [x] 新能力位 `server_info.features.apiEndpointBalance`；没有它时客户端不显示本任务的界面，旧视图照旧。
- [x] 测试 daemon 把厂商表的真实地址注入成本机地址，缺省指到没人听的端口（同厂商状态页的注入写法）；端到端测试用本机假 DeepSeek 验证请求与读数，以及五类失败各一例。 （「这家不给查余额」一类 DeepSeek 产不出，协议与界面已认，端到端用例随 02 的 OpenCode Zen 补；其余四类各有用例。）
- [x] 客户端打开列表页 / 详情页时请求一次读数（定时与开关在 03）。
- [x] `docs/usage.md`「Outbound requests」新增读余额一节：发给谁、带什么、什么时候发（本工单的时机），后面的工单在这一节里补。
- [x] 9 种语言的新文字齐全，中文用词与术语表一致（余额、余额与套餐用量、余额查不到、没认出这家的余额查法）。
- [x] 浏览器测试：有读数、失败、认不出三种情况。
- [x] UI：列表页 / 有读数与「余额查不到」两行 / 1280 与 390 — 余额小段不截断接口主名称。
- [x] UI：详情页分区 / 有读数、失败（原因加对方原话）、认不出 / 1280 与 390 — 读数时间与刷新按钮可见，刷新不是蓝色链接。
