# 03 — 设置页的提示区：把「设置被改过」放回设置页

**What to build:** Claude Code、Codex 的提供方设置页，「使用第三方接口」区里有一个提示区，显示 Osuna 读状态时查出的问题，每条带处理按钮。10-13 那次改版把健康提示去掉了；本张把它放回来，先放 Osuna 现在已经能查出的三种，按 prd 第 34 条的表命名：

| 情况 | 本张什么时候算 | 按钮 |
|---|---|---|
| 不再经过中转站 | CLI 配置里的中转站地址或口令被别的程序改了 | 重新应用、切回官方、保留当前设置 |
| 读不懂 | 现有 | 不变（说明原因） |
| Codex profile 盖过开关 | 现有 | 不变（说明原因） |

- 「重新应用」按当前设置重写；「切回官方」= 关掉开关并按接管记录还原；「保留当前设置」是新 RPC，这里的意思是关掉开关、但不改回文件、不再提示。
- 提示带「代码 + 参数」，app 按代码翻译成用户的界面语言；英文 `message` 照旧给旧客户端。
- 新增一个 `server_info.features` 能力位（带 `COMPAT(...)` 标记）。本任务所有新界面都只在主机声明它时显示；没声明时请用户更新主机，不做兼容分支。旧客户端（含官方 Paseo 手机 App）照常工作。
- 其余负责的键被外部改了：本张保持现有判断。模型与思考档位归 21 号工单；magpie 对其余键另有做法的，对照后写进实现记录。
- 后面的工单会往这里加情况：设置文件带注释（15）、云平台开关与管理员设置（16）、保留 claude.ai 登录的两种不一致（18）、模型被换掉（21）、multi_agent_v2 盖过（24）、被绕过（25）、要重开谁（27）、代理不转发（28）。新情况要能直接加进来。
