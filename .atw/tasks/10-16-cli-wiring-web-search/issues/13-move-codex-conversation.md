# 13 — 把一段 Codex 对话挪到另一个 Codex 服务商

**What to build:** 会话历史里 Codex 对话的行菜单和右键菜单加「挪到另一个 Codex 服务商…」。挪完后这段对话出现在终端 `codex resume` 的列表里，用新的 Codex 服务商续。

- **对话框**：选目标（Codex 设置里现有的服务商、内置 `openai`、Osuna 自己的服务商）；说明会先备份、挪回原来的服务商就是撤销；进行中、成功、失败三态；最近一分钟写过的对话不挪，说明原因。
- **后台**（新 RPC，挂在 Codex 会话的命名空间下，照 magpie `internal/sessions/codex_provider.go`）：
  - 对话文件一分钟内写过的不挪，结果里说明。
  - 先把对话文件（含压缩过的孪生文件）复制到 Osuna 自己的备份目录，并写一份挪动记录（对话 id、原服务商、目标服务商、时间、文件对照）。
  - 改每个文件里每一条带服务商的 `session_meta`：只改服务商，其余字节不动；压缩的照样压回；写到旁边的临时文件、落盘、保留修改时间、改名替换。再把每个 `state_*.sqlite` 里这条对话的服务商改掉（库里没有这张表就跳过）。
  - 中途失败就用备份把已改的文件改回去。
  - 已知局限照 magpie：设置快照事件里的旧服务商不改。
  - 读写 SQLite、zstd 用 Node 自带的能力（现有代码已经在用），不新加外部依赖；确实需要时先问用户。
- **一次性核实**（真的 Codex，临时 `CODEX_HOME`，不碰 `~/.codex`、不登录）：挪过的对话在 Codex 里列在新服务商下、能续上；Codex 从对话文件重建状态库后，挪动会不会被改回。会被改回的话，对话框说明里写明，并留给 30 号工单补进 ADR。
