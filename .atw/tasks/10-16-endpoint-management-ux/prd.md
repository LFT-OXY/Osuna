# 接口管理好用性

来源：总任务 [`10-16-magpie-osuna-gaps`](../10-16-magpie-osuna-gaps/prd.md) 的第 3 个子任务。访谈分 3 轮（R1–R3），2026-10-19 用户逐题回答；全部决定、照 magpie 记下的细则与 magpie 源码出处见 [`research/decisions.md`](research/decisions.md)。总任务的 Constraints、Implementation Decisions、Testing Decisions 对本任务全部适用，下面只写本任务特有的。本任务改动了总任务第 15 条「身份如实」：「按 Claude Code / Codex 的样子测模型」是用户选定的例外（本文第 30 条）。对照基准：magpie `7597c132`。差距明细：块 3，02·A01–A10, A18, A20–A24, A27, A31–A33, A35–A36, A39–A66, A78–A80；01·A10–A11, C12, E05, F09；03·H13（逐行去向见 Further Notes）。

## Problem Statement

用户靠多家中转服务在 Claude Code、Codex 里干活，每家在 Osuna 里是一家第三方接口（**API endpoint**）。添加和管理它们费事：

1. 添加一家要自己查地址、抄 key、认请求格式。没有常见厂商和中转服务的模板，不能粘贴服务商文档里的 curl 命令。
2. 同一家中转服务的第二把 key 只能从头再建一家，不能复制已有的那家。
3. 本机模型服务（Ollama、LM Studio 等）不要 key，Osuna 却必须填 key 才能保存。
4. 接口按创建先后排队：自动切换（**Failover**）先去哪家、只写模型名时归哪家，都由建的先后决定，用户调不了。
5. 接口多了找不到某一家；列表行上看不出哪个提供方的默认模型（**Default model**）落在这家，也看不到 key 是哪一把。保存后只能看到打码的 key，读不回原文。
6. 有的中转服务要求多带请求头、在请求正文里加字段，或者只认 `x-api-key` 和 `Authorization` 其中一个头；自建的中转服务用自签证书。Osuna 都不支持。
7. 模型清单要先保存再进详情页才拉得到；有几种格式地址时只留第一个拉成功的清单；不会自己刷新。新建一家时所有模型都是关的，要逐个勾。
8. 中转服务给的模型资料常常不准：显示名、上下文、回复上限、思考档位、能否看图都改不了；发给上游的模型名必须和选单里的一样；Codex 一律写成 272K、四档；压缩时机由 CLI 自己猜。
9. 不知道哪些模型真能用：测试连接只挑一个模型试；有的模型在某家只有一种格式能用，Osuna 改不了它走哪种格式。
10. 想彻底不用某些模型（如所有 preview 版）时，只能一家一家地关。
11. 冷却多久是全局写死的，额度型套餐和按量付费的接口只能用同一套时长。
12. 官方服务出故障时，接口行上看不出来，只能自己去状态页查。
13. CC Switch、Claude Code、Codex、OpenCode、Alma 里已经配好的中转服务，要在 Osuna 里重新填一遍；别人分享的接入配置也没法一点就加。

## Solution

做完后，用户看到的是：

- 点「+」先出模板（**Template**）列表：厂商、中转服务、本机三组，可搜索，第一项是「自定义」。选模板只要贴 key；国际站和中国站、不同套餐在表单里切换；「去拿 key ↗」直达。往地址框或 key 框粘贴一行 curl，表单自动填好。
- 每家接口的菜单里有「复制」（**Duplicate**）和「再加一家」。key 可以不填。
- 列表可以拖动、用菜单上移下移，这个接口顺序（**Endpoint order**）决定切换先后和裸模型名归属。列表顶上有搜索框。每行显示 key 打码、模型数、哪些提供方的默认模型落在这家；点提供方名跳去改。key 原文可以读回。
- 添加窗口里保存前就能拉模型；多个格式的清单合并；清单每天自动刷新。新建一家默认「跟随接口清单」（**Model scope**），最多 24 个模型，跟着上游清单变。
- 每个模型有「模型设置」（**Model settings**），能改显示名、上下文、回复上限、思考档位、能否看图、上游模型名（**Upstream name**）、压缩阈值（**Compact at**），能设「只用这种格式」（**Use only this format**）；整家还能统一设默认。改了的值写进 Claude Code 和 Codex。
- 「测试模型」（**Test models**）把在服务的模型逐个试一遍，也能按 Claude Code 或 Codex 的样子测；能按「只看免费」「只看能用」筛选。
- 主机级的「已禁用的模型」（**Disabled models**）一处禁用，所有接口都不提供。
- 每家可以加请求头、附加请求体、选 key 放在哪个头（**Headers**）；自定义添加的 https 接口可以「不校验证书」（**Don't check its certificate**）；「高级」区能设这家的冷却时长。
- Anthropic、OpenAI、Moonshot 的官方状态页报告异常时，对应接口行上有提示和链接。
- 「导入」（**Import**）从别的软件读出已有的接口，接口页会主动提示发现了几个；桌面端能打开 `paseo://import` 导入链接，确认后添加。

## User Stories

### 添加接口

1. 作为用户，我希望点「+」后先看到模板列表，以便从常见厂商、中转服务或本机服务里挑一家开始。
2. 作为用户，我希望模板分「厂商 / 中转服务 / 本机」三组，并能搜索，以便在几十个模板里快速找到要的那家。
3. 作为用户，我希望列表第一项是「自定义」，以便模板里没有的服务仍能像现在一样手填。
4. 作为用户，我希望选了模板以后只要贴 key，地址和请求格式都已填好，以便不用自己查文档。
5. 作为国内用户，我希望同一厂商的国际站和中国站合成一行，进表单后再切「国际 / 中国」，以便不在列表里看到两行几乎一样的选项。
6. 作为套餐用户（如智谱 Coding Plan、方舟 Coding Plan），我希望在表单里切换「套餐」，地址跟着换成套餐的地址，以便不填错地址。
7. 作为用户，我希望切换区域或套餐时已填的 key 保留，其余跟着模板换，以便不用重贴 key。
8. 作为还没有 key 的用户，我希望表单顶上有「去拿 key ↗」，跟着所选区域或套餐变，以便直接去对的页面申请。
9. 作为用户，我希望模板和接口行上显示品牌图标，以便一眼认出是哪家。
10. 作为 Amazon Bedrock 用户，我希望用 Bedrock 的 API key 和区域就能添加，模型清单由 Osuna 内置，以便不用配 AWS 签名。
11. 作为 Azure OpenAI 用户，我希望填自己资源的地址和 key 就能添加，Osuna 列出我的部署名，以便不用手抄部署名。
12. 作为用户，我希望往地址框或 key 框粘贴服务商文档里的 curl 命令，表单自动认出请求格式、地址和 key，以便不用逐项抄。
13. 作为用户，我希望 curl 里像 `$OPENAI_API_KEY` 这样的占位符不被当成 key，并提示我换成自己的 key，以便不保存一把假 key。
14. 作为用户，我希望 curl 的地址里还有没替换的占位符时得到提示，以便知道哪一段要自己改。
15. 作为用「自定义」添加的用户，我希望 curl 正文里的模型名自动加进模型清单，以便马上就能用这个模型。
16. 作为用模板添加的用户，我希望粘贴 curl 只取 key，不改模板的地址，以便模板的地址不被文档里的示例地址盖掉。
17. 作为 Ollama、LM Studio 这类本机服务的用户，我希望 key 可以不填，以便直接保存接口。
18. 作为用免费模型（如 OpenCode Zen、Kilo 的免费模型）的用户，我希望不填 key 也能用，以便不用为免费模型申请 key。
19. 作为没填 key 的用户，我希望 Osuna 不发任何认证头，以便上游不因为一把空 key 拒绝请求。

### 复制与再加一家

20. 作为同一中转服务有几把 key 的用户，我希望在接口菜单里点「复制」，打开内容全填好的添加窗口，以便只改 key 就得到另一家接口。
21. 作为用户，我希望复制出的名字自动是「原名 副本」，重名时加编号，以便不和原来那家撞名。
22. 作为用户，我希望复制时 key 框留空并提示「沿用原来的 key」，不填就带上原 key，以便只改地址时不用重贴 key。
23. 作为用户，我希望复制的内容在我点保存前不生效，以便不会多出一家和原来一模一样、同时开着的接口。
24. 作为用户，我希望复制带上已选模型、档位映射、联网搜索开关、模型设置、请求头和冷却设置，以便副本和原来那家用起来一样。
25. 作为用模板添加过一家的用户，我希望在这家的页面上点「再加一家」，用同一模板打开新表单，以便同一厂商的第二个账号或工作区也能快速加上。

### 顺序、搜索与列表行

26. 作为用户，我希望拖动接口行改变顺序，以便决定自动切换时先换到哪家。
27. 作为在手机或窄窗口上的用户，我希望行菜单里有「上移 / 下移 / 移到最前 / 移到最后」，以便不拖动也能排顺序。
28. 作为用户，我希望几家都有同一个模型、默认模型只写了模型名时，请求先去顺序最靠前的那家，以便由我决定先用哪家。
29. 作为用户，我希望「已开启」「已关闭」两组都按同一个顺序排，接口在两组之间移动时保留它的位置，以便关了再开不用重新排。
30. 作为用户，我希望新加的接口排在最后，以便不打乱我排好的顺序。
31. 作为接口很多的用户，我希望列表顶上有搜索框，按名称、地址、模型名找，以便快速找到某一家。
32. 作为用户，我希望行上显示这把 key 的打码（如 `sk-…a1b2`）和模型数，以便分清同一中转服务的几把 key。
33. 作为用户，我希望行上写出哪些提供方的默认模型落在这家，以便改这家之前知道会影响谁。
34. 作为用户，我希望默认模型只写了模型名时，算到顺序最靠前、开着、选了它的那家，以便行上显示的就是请求实际先去的那家。
35. 作为用户，我希望点行上的提供方名就跳到它的设置页，以便马上改默认模型。
36. 作为用户，我希望在编辑窗口里点「显示」读回已存 key 的原文，以便核对或拷到别处。

### 模型清单

37. 作为用户，我希望在添加窗口里保存之前就能用填好的地址和 key 拉模型，以便边看清单边决定这家值不值得加。
38. 作为有多种格式地址的用户，我希望各地址拉到的清单合在一起，以便只在某一种格式下列出的模型也看得到。
39. 作为用户，我希望 Osuna 每天自动刷新一次开着的接口的清单，打开接口页时也刷新，以便清单不过时。
40. 作为用户，我希望有「丢掉拉回的清单」，以便清掉一份错的清单重新拉。
41. 作为新建接口的用户，我希望默认「跟随接口清单」：不超过 24 个就全用，超过就按清单顺序用前 24 个，以便不用逐个勾就能开始用。
42. 作为用「跟随接口清单」的用户，我希望上游新出的模型自动进来、下架的自动消失，以便不用手动维护。
43. 作为已有接口的用户，我希望升级后我的接口保持「只用挑选的」，勾好的模型一个不变，以便升级不改我的设置。
44. 作为用户，我希望从「跟随接口清单」切到「只用挑选的」时，先把当前在用的那些勾上，以便切换不让模型突然全部消失。
45. 作为用户，我希望手动加模型时可以一次用逗号分隔加几个，以便清单里没有的几个模型一次加完。

### 模型设置

46. 作为用户，我希望在模型行的菜单里打开「模型设置」，以便单独调整这家的这个模型。
47. 作为用户，我希望改模型的显示名，并能「恢复默认」，以便在选单里看到我认得的名字。
48. 作为用户，我希望改上下文长度和回复上限，以便中转服务的清单写错时 CLI 仍按真实能力使用这个模型。
49. 作为用户，我希望选这个模型可用的思考档位，一档都不勾就不发思考参数，以便不支持思考的模型不被拒绝。
50. 作为用户，我希望标明这个模型能不能看图，以便 Codex 知道能不能发图片给它。
51. 作为用户，我希望设上游模型名，发给这家时用另一个名字，以便中转服务要求带前缀（如 `zhipu/glm-4.6`）时选单里仍是短名。
52. 作为用户，我希望设压缩阈值（按 token 数），以便 Claude Code 和 Codex 在我定的长度压缩对话。
53. 作为用户，我希望把这个模型在这家固定成「只用这种格式」，以便只有一种格式能用的模型不在别的格式上失败。
54. 作为用户，我希望在接口页「整家默认」里一次给所有模型设上下文、回复上限、压缩阈值和上游模型名，上游名里的 `*` 换成模型名，以便不用逐个模型设。
55. 作为用户，我希望单个模型的设置优先于整家默认，整家默认优先于 Osuna 自动取到的值，以便越具体的设置越优先。
56. 作为用户，我希望没手改的项继续用 Osuna 自动取到的值，models.dev 还补上显示名，以便不改也有合理的默认。
57. 作为 Codex 用户，我希望 Codex 的模型清单按每个模型的上下文、思考档位、能否看图、压缩阈值来写，以便不再一律 272K、四档。
58. 作为 Claude Code 用户，我希望 Claude Code 收到它在跑的模型的上下文、回复上限、思考档位和压缩阈值，以便它按真实能力工作。
59. 作为用户，我希望界面写明哪些设置对哪个 CLI 不起作用（Claude Code 没有显示名和看图的设置，Codex 没有回复上限的设置），以便不白改。
60. 作为读中转站模型列表的程序，我希望列表带上显示名、思考档位、上下文、回复上限和输入类型，以便不用另查模型资料。

### 测试模型

61. 作为用户，我希望点「测试模型」把这家在服务的模型逐个试一遍，看到每个的红绿点、走的格式和耗时，以便知道哪些真能用。
62. 作为用户，我希望也能只测一个模型，以便改完一个模型的设置后马上验证。
63. 作为用户，我希望测试在进行中能看到进度，能取消，以便不必干等几十个模型测完。
64. 作为用户，我希望每次测试只花很少的 token，以便放心多测几次。
65. 作为用「只允许 Claude Code」分组的中转服务用户，我希望「按 Claude Code 的样子测」，以便知道 key 在这种分组里能不能用。
66. 作为 Codex 用户，我希望「按 Codex 的样子测」，以便知道这家对 Codex 的请求是否放行。
67. 作为还没让 Claude Code 经过中转站的用户，我希望「按 Claude Code 的样子测」说明要先用 Claude Code 跑一次，以便知道为什么现在测不了。
68. 作为用户，我希望挑模型时能「只看免费」，以便先试免费模型。
69. 作为用户，我希望挑模型时能「只看能用」，去掉最近一次测试失败的，没测过的仍保留，以便只留下能用的模型。
70. 作为用户，我希望模型旁有「免费」和上下文大小的小标，以便挑模型时一眼看到。

### 已禁用的模型

71. 作为用户，我希望在「第三方接口」页底部填「已禁用的模型」，可以写完整名或用 `*` 通配，不分大小写，以便一处禁掉所有接口里的某类模型。
72. 作为用户，我希望被禁的模型从所有模型选单里消失，测试时也跳过，以便不再看到它们。
73. 作为在终端里硬要用被禁模型的用户，我希望收到的错误写明是哪条规则禁的、在哪改，以便知道怎么解开。

### 请求头、证书与冷却

74. 作为接入要求特殊的中转服务的用户，我希望给这家加自定义请求头，以便满足它的要求。
75. 作为用户，我希望我填的头盖过 Osuna 自己填的同名头（包括认证头），以便服务要求的写法优先。
76. 作为用户，我希望 `anthropic-beta` 头和 CLI 原有的值合并，不互相覆盖，以便 CLI 的 beta 功能和服务要求的 beta 同时生效。
77. 作为用户，我希望给这家的每个请求正文加一段 JSON，名字前加 `!` 表示强制覆盖，`${sessionId}` 换成会话编号，以便传服务要求的额外参数。
78. 作为用户，我希望附加请求体不能改 `model`、`messages`、`tools` 等核心字段，填了时当场提示，以便不把请求改坏。
79. 作为第三方 Anthropic 地址的用户，我希望选 key 放在哪个头（两个都放 / 只放 x-api-key / 只放 Bearer），以便只认其中一个的服务不拒绝请求。
80. 作为用户，我希望请求头和附加请求体对测试连接、拉模型、测试模型也生效，以便测试结果和真实使用一致。
81. 作为自建中转服务的用户，我希望对用「自定义」添加的 https 接口打开「不校验证书」，以便连上自签证书的服务。
82. 作为用户，我希望打开「不校验证书」之前看到确认框，写明别人可能冒充这个地址、看到我的 key 和对话，以便知道风险再决定。
83. 作为用户，我希望打开了「不校验证书」的接口行上一直有标记，以便不忘记它是关着校验的。
84. 作为额度型套餐用户，我希望在「高级」区设「额度用完后冷却多久」，以便冷却时长贴合套餐的重置周期。
85. 作为用户，我希望设「冷却最长多久」，或选「原因不明的失败不冷却」，以便一家偶发失败时不被冷却太久。
86. 作为不改冷却设置的用户，我希望行为和现在完全一样，以便升级不改变自动切换。

### 厂商状态页

87. 作为直连官方地址的用户，我希望 Anthropic、OpenAI、Moonshot 官方状态页报告异常时，对应接口行上出现「{厂商} 官方报告服务异常」和「状态页 ↗」，以便判断是不是对方故障。
88. 作为 DeepSeek 用户，我希望看到它的状态页链接，以便自己去查。
89. 作为在意对外请求的用户，我希望状态页只在接口页或用量页开着时才查，关掉「价格表自动更新」就不查，以便控制 Osuna 何时上网。

### 导入

90. 作为用过 CC Switch、Claude Code、Codex、Alma 的用户，我希望打开「第三方接口」页时 Osuna 提示「发现 N 个本地配置」，以便一键把已有的中转服务搬进来。

## Implementation Decisions

### 数据与存储

1. **接口的新字段**（都在接口自己的存储里，可选，缺省等于现在的行为，不做迁移，遵守 `docs/data-model.md`）：
   - `templateId`、`region`：来自哪个模板、哪个区域或套餐。只用于切换区域、「再加一家」、Bedrock 内置清单与 Azure 部署名、「不校验证书」只限自定义。
   - `headers`（名字到值）、`extraBody`（一个 JSON 对象）、`keyHeader`（`both` / `x-api-key` / `bearer`，缺省 `both`）。
   - `insecureTls`（布尔）。
   - `modelScope`（`vendor` / `picked`）。字段缺省当 `picked`，所以已有接口不变；新建时客户端写 `vendor`。
   - `modelSettings`：按模型 id 记，外加一份整家默认。每份可有显示名、上下文、回复上限、思考档位列表、能否看图、上游模型名、压缩阈值、只用的格式；整家默认只有上下文、回复上限、压缩阈值、上游模型名。
   - `cooldown`：额度冷却时长、冷却上限（含「原因不明不冷却」），单位分钟，0 到 8 天。
2. **key 选填**：没 key 的接口不在 key 文件里留条目。daemon 发请求时不加任何认证头。线上仍用 `hasApiKey` 表示有没有。
3. **接口顺序**：存储里接口数组的顺序就是接口顺序（**Endpoint order**）。新建追加到末尾；新增 RPC 整体改写顺序。桌面端选中行后 Alt+↑ / Alt+↓ 移动（照 magpie）。中转站选路、裸模型名归属、行上「默认模型落在哪家」都按这个顺序。取代 ADR 0007 的「按创建顺序」，ADR 0007 改写那一条。
4. **主机级新字段**：「已禁用的模型」名单（完整名或 glob，不分大小写）；导入的「已忽略」记录（记被忽略的发现的指纹，不存 key 原文）。
5. **CLI 请求头样本**：中转站每放行一次 Claude Code 或 Codex 的请求，就把请求头记成该 CLI 的最新样本。认证、会话、线程、`anthropic-beta`、Cookie 等去掉，只留表明 CLI 身份的头（照 magpie `test_as.go` 的去除名单）。样本存在 daemon 的接口目录下的单独文件里，写法照持久化规范。不存正文。

### 模板

6. **模板清单由 daemon 持有**，随版本内置、不联网下载，经新 RPC 发给客户端。内容照 magpie `presets.go`：每个模板有 id、名称、分组（厂商 / 中转服务 / 本机）、各格式地址、区域或套餐（每个都有自己的一套地址和「去拿 key」链接）、官网、是否不要 key、是否没有清单接口（附内置模型清单）。国际站和中国站照 magpie 用 id 约定配对。模板还带 models.dev 的 id（一个或几个，用于补模型资料；厂商没有清单接口时用它补清单）、可提示的额外请求头；本机模板只有一个「服务地址」，改它只换各格式地址的协议、主机、端口（照 magpie `local_address.go`）。
7. **收录范围**：magpie 的 57 个，去掉 5 个决策模型、Remote magpie、Google Vertex AI；Google Gemini 官方等子任务 7 再加。Bedrock 用 Bedrock API key（不做 SigV4），Claude 走 Anthropic 格式、只发 `x-api-key`，其余走 Chat / Responses、发 Bearer，用内置模型清单。Azure 统一走 `/openai/v1`，key 放 `api-key` 头（Anthropic 格式例外，用 `x-api-key`），先列 `deployments`、失败再列 `/v1/models`。
8. **图标**由客户端持有：从 magpie 的 `icons` 目录拷入模板用到的图标与可选图标，按模板 id 取，取不到用名称首字。模型家族已有的图标照旧。「自定义」添加的接口可从内置图标里选一个，或选本机一张图片（daemon 存一份副本，经 RPC 取回；照 magpie 的 `file:` 图标）。接口新增可选字段 `icon`。拷入的文件记进 `THIRD_PARTY_NOTICES`。
9. 借鉴 magpie 的文件（模板清单、curl 解析、附加请求体、测试模型、导入、状态页、`/v1/models` 能力字段）文件头保留 MIT 声明，全文收进 `THIRD_PARTY_NOTICES`。

### 添加、复制与 key

10. **curl 解析在客户端**，是表单模型里的纯函数，照 magpie `curlOf`：按 URL 结尾认格式，`respellURL` 规则得出地址；依次从 `Authorization: Bearer`、`x-api-key`、`api-key` 取 key；占位符判定、正文 `model` 读取、三种续行写法、四条提示都照 magpie。用模板添加时只取 key。
11. **复制**：客户端用这家的内容（不含 key 原文）预填添加表单。保存请求带上「沿用哪家的 key」，key 框留空时由 daemon 从那家拷 key。名称冲突加「 2」「 3」……，标识冲突加 `-2`……，避让在 daemon 做，「再加一家」同样。
11a. **保存前测试连接与自动识别格式**：现有的测试连接、自动识别 RPC 接受未保存的表单值（同第 13 条）。自动识别可指定试用的模型，列不出模型时用它试；逐种格式返回耗时或错误，表单有「采用这些」。另可选「逐个模型」：已选模型（最多 30 个）在每种格式上各试一次，只通一种的直接写成「只用这种格式」（照 magpie Detect 的 Each picked model）。
12. **读回 key**：新 RPC，按接口 id 返回 key 原文；没有确认、不限次数（照 magpie）。只有新客户端会调。

### 模型清单与服务范围

13. **保存前拉模型**：现有拉模型 RPC 接受未保存的表单值（地址、key、请求头、附加请求体、key 头、证书设置），不带接口 id 时不记清单。表单里拉到的清单随保存一起写入。
14. **合并清单**：有几种格式地址，就各拉一次，按模型 id 合并；资料以先列出的格式为准，缺的由后面的补。
15. **定时刷新**：daemon 每天给每家开着的接口拉一次清单（错开启动后的第一次）；客户端打开接口页时也触发一次。失败只记日志，不覆盖已有清单。这是 daemon 主动发出、带 key 的请求，写进 `docs/usage.md`「Outbound requests」：发给谁、带什么、什么时候发。随「价格表自动更新」开关关掉（2026-10-19 用户确认）。
16. **「丢掉拉回的清单」**清空这家的上游清单与拉取时间；「只用挑选的」时已选模型保留，「跟随接口清单」时这家暂时没有模型，直到再拉。
17. **服务范围**：`vendor` 时，在服务的模型是上游清单里去掉没有对应地址的模型后的全部，超过 24 个时取清单顺序的前 24 个（照 magpie `models.go`），手动添加的模型总在里面；`picked` 时是用户勾的那些。从 `vendor` 切到 `picked` 时客户端把当时在服务的模型写成已选。「已选模型」（**Selected models**）在各处都指在服务的模型：选单、默认模型、档位映射、自动切换都用它。
18. **手动添加**一次可用逗号分隔加多个。
18a. **自动勾选规则**（02·A47，2026-10-19 用户确认做进界面）：「只用挑选的」时可写几条名字规则（glob，不分大小写），拉到新清单时匹配的新模型自动勾上，已勾的不因规则取消。存为接口的可选字段 `autoPick`。照 magpie `autolist.go` 的匹配语义；magpie 只在命令行能设，Osuna 放在服务范围下面。
18b. **接口名显示方式**（02·A56，2026-10-19 用户确认）：主机级设置，三种：一直显示（缺省，即现在的「模型（接口名）」）/ 只在几家有同名模型时显示 / 不显示。作用于 Osuna 的模型选单、默认模型选项和写给 Codex 的显示名。选「不显示」时 Codex `/model` 里两家同名模型仍靠「接口标识/模型名」的 slug 区分（子任务 2 工单 32），显示名相同。

### 模型设置与写进 CLI

19. **取值顺序**：单个模型的设置 → 整家默认 → 上游清单给的 → models.dev → 内置默认。照 magpie。显示名撞名时（同一选单里两个模型显示名相同），选单改显示模型 id（照 magpie）。
20. **上游模型名**：中转站发往这家时把模型名换成它；含 `*` 时 `*` 换成模型 id，不含时整家都用这个名字（照 magpie `modelprefs.go`）。选单、默认模型、记账、自动切换的同名判断仍用原名。
21. **只用这种格式**：中转站给这家的这个模型只用那种格式的地址；那种地址不在了时设置作废并在模型设置里提示。
22. **写进 Codex**：Osuna 写给 Codex 的模型清单按模型写显示名、思考档位、`input_modalities`、上下文；有压缩阈值时上下文取二者较小值（照 magpie `codexcat`）。
23. **写进 Claude Code**：上下文、回复上限、思考档位、压缩阈值写进 Claude Code 的设置，写法照 magpie（`CLAUDE_CODE_MAX_CONTEXT_TOKENS`、`CLAUDE_CODE_MAX_OUTPUT_TOKENS`、`CLAUDE_CODE_AUTO_COMPACT_WINDOW`、`CLAUDE_CODE_MODEL_CAPABILITIES`），按 ADR 0004 的自有键规则记录与恢复原值。实现时先核对 Osuna 现在写的 `[1m]` 与两个环境变量和 magpie 的写法是否重复，以 magpie 为准合并。
24. 改了模型设置、服务范围、已禁用的模型后，按子任务 2 已有的「哪些会话要重开」提示规则告诉用户。
25. **中转站的 `/v1/models`** 每条带 `display_name`、`reasoning`、`supported_reasoning_levels`、`context_window`、`context_length`、`max_input_tokens`、`max_output_tokens`、`modalities`（照 magpie `gateway.go:827-865`，Cursor 专用字段不加）。

### 测试模型

26. **新 RPC** 开始一次测试：给接口 id、可选的模型 id（只测一个）、测法（普通 / 按 Claude Code / 按 Codex）。daemon 并发 4 个，单个 20 秒，整批 3 分钟；每测完一个推一条进度，最后给汇总；可用现有的取消 RPC 取消。
27. 每个模型发一条「hi」，回复上限 16，按格式用各自的上限字段；带上这家的请求头和附加请求体（`${sessionId}` 换成 `osuna-test-` 加随机串）。被禁用的模型不发，直接标成「已禁用」。
28. 普通测法按这家的地址依次试格式，「只用这种格式」的模型只试那种。
29. 结果只在客户端页面内存里，离开页面就清掉（照 magpie）。「只看能用」用这家最近一次的结果，没测过的不算失败。「免费」= 模型 id 或显示名里有独立单词 `free`。
30. **按 Claude Code / Codex 的样子测**（总任务第 15 条的例外，用户选定，写进新 ADR）：用第 5 条记下的该 CLI 最新请求头样本发出。按 Claude Code 只走 Anthropic 格式，只对中转服务开放：模板分组是「中转服务」的，或用「自定义」添加的。按 Codex 走 Responses，没有就走 Chat，不限地址；还没有 Codex 样本时，用 Osuna 已有的 ChatGPT 后端那套 Codex 请求头。没有 Claude Code 样本时拒绝，并说明要先用 Claude Code 经过一次中转站。

### 已禁用的模型

31. 名单匹配完整 id 或 glob，不分大小写。命中的模型从每家接口的在服务模型里去掉，所以选单、默认模型候选、自动切换都看不到它。CLI 硬请求时，中转站按请求格式回 403，正文写明模型名、命中的条目、在哪改（照 magpie `disabled.go`，把「magpie」换成 Osuna 的说法）。

### 请求头、附加请求体、key 头、证书

32. **请求头**对这家的所有请求生效：中转站转发、测试连接、自动识别格式、拉模型、测试模型。用户的头在 Osuna 填的头之后写，大小写不同也算同名、被替换；`anthropic-beta` 按逗号合并去重，CLI 原有的在前。用户自己填了认证头时，ADR 0008「两个认证头被拒就改用一个」的重发不触发。
33. **附加请求体**对 Messages、Chat、Responses 生效，直连转发与格式互译后的请求都算；只数 token 的请求不带。保留字段、`!` 覆盖、`${sessionId}`（取 CLI 的会话头，没有就由第一条用户消息推导，同一对话每轮相同）照 magpie `extrabody.go`。保存时 daemon 拒收含保留字段的附加请求体，表单当场提示。
34. **key 头**只对第三方 Anthropic 地址有效。官方 Anthropic 地址、Bedrock、Azure 不显示这一项。
35. **ADR 0008 修改**：中转站改请求原本只限模型名、认证和拒收后的改写；现在用户设的请求头、附加请求体、上游模型名、只用这种格式也改请求，用户的认证头盖过 Osuna 的。ADR 0008 写明这一变化。
36. **不校验证书**：只对 `templateId` 为空、地址是 https 的接口可开，只作用于这家自己的各格式地址。daemon 发往这家的两条路径（拉模型和测试用的 fetch、中转站用的 https 请求）都按这家设置决定是否校验。daemon 拒绝为模板接口打开。

### 冷却设置

37. 中转站算冷却时用这家的设置：额度冷却缺省 15 分钟（厂商给的时间仍优先）；冷却上限缺省为失败 10 分钟、限流 30 分钟，选「原因不明不冷却」时不明原因的失败不冷却。缺省值就是现在的常量，不设等于不变。

### 厂商状态页

38. 新 RPC 返回各厂商当前状态。daemon 查 Anthropic（`status.claude.com`）、OpenAI（`status.openai.com`）、Moonshot（`status.moonshot.cn`）的 `/api/v2/summary.json`，缓存 5 分钟；DeepSeek 只给链接。客户端只在「第三方接口」页或用量页开着时每 5 分钟调一次。接口按各格式地址的主机名对上厂商。「价格表自动更新」关着时 daemon 不发，RPC 返回「未开启」。写进 `docs/usage.md`「Outbound requests」：不带认证的公开 GET。

### 导入

39. **扫描在 daemon**（读的是 daemon 所在主机的文件），照 magpie `importapps.go`：CC Switch 的 `~/.cc-switch/cc-switch.db`（没有就读 `config.json`），Claude Code 的 `settings.json`（Osuna 接管中时读 ADR 0004 记下的原值），Codex 的 `config.toml`，Alma 的 `chat_threads.db`，OpenCode 的 `auth.json`。数据库用 Node 自带的只读 SQLite 打开。全程只读。
40. 新 RPC：扫描（可选是否含 OpenCode），返回发现列表；每条有名称、各格式地址、key 打码、模型、来源软件、状态（新的 / 已添加 / 名称已被占用 / 同一家、key 不同）、指纹。key 原文留在 daemon，导入时按指纹取。判定照 magpie `settle`：key、主机、请求头都同为「已添加」；地址和请求头同、key 不同为「同一家、key 不同」；名称或标识撞上为「名称已被占用」。
41. 新 RPC：导入选中的发现，每条带操作（新增一家 / 替换某家 / 改名后新增）。「同一家、key 不同」的操作是新增一家（Osuna 没有一家多把 key）。
42. 客户端打开「第三方接口」页时调扫描（不含 OpenCode），daemon 一分钟内只真扫一次。发现新条目时页顶出提示「发现 N 个本地配置」，可「查看」或「忽略」。忽略记进主机级的已忽略记录，同一批指纹不再提示。
43. **导入链接**：桌面端主进程认 `paseo://import?...`（已注册的 `paseo` 链接类型，ADR 0002），交给窗口打开确认框。字段、拒收规则照 magpie `importurl.go`：只收 https，本机与局域网地址允许 http；地址不能带账号、查询串或片段；key 不超过 4096 字节、不含控制字符；名称截到 80 字节；模型最多 200 个；未知模板、Vertex、没有任何地址都拒收，拒收时说明原因。`gemini` 地址在子任务 7 之前忽略。确认框加到这个窗口当前所在的主机（2026-10-19 用户确认）。主机没开 `apiEndpointManagement` 时说明要升级。
44. **新 ADR**：Osuna 自动读别的软件的配置（含 key），接收导入链接，记下 CLI 的请求头并按它的样子测，是总任务第 15 条的例外。ADR 写明理由（照 magpie，sub2api 一类「只允许某 CLI」的分组）、范围与防护。

### 协议

45. 新 RPC 都在 `provider.api_endpoint.` 下，带点命名加 `.request` / `.response`（`docs/rpc-namespacing.md`）：模板清单、改顺序、读回 key、测试模型（含进度消息）、状态页、导入扫描、导入执行、已禁用的模型读写。接口与保存请求里的新字段全部可选。
46. 新能力位 `server_info.features.apiEndpointManagement`。客户端在它为真时才显示本任务的新界面；没有时照旧（模板列表不出现，「+」直接打开现在的表单）。官方 Paseo 手机 App 看不到新字段，照常工作。ADR 0007 给旧客户端的「单个启用接口」投影不变。
47. 旧客户端保存接口时不带新字段：daemon 按「没给就保留原值」处理，不把新字段清掉。

## UI and Design

- **方向**：沿用现有的「第三方接口」列表页、接口详情页、添加 / 编辑窗口，不另做视觉风格。遵守 `docs/design.md`、`docs/forms.md`、`docs/hover.md`、`docs/menus.md`、`docs/unistyles.md`、`docs/i18n.md` 与 `.atw/spec/app/frontend/`。用户定过的偏好：开 / 关一律 Switch；模型名不用等宽字体；次要操作不用蓝色链接。
- **用词**以 `docs/glossary.md` 本次新增的词条为准：模板、再加一家、复制（副本）、上移 / 下移 / 移到最前 / 移到最后、服务范围（跟随接口清单 / 只用挑选的）、模型设置、整家默认、上游模型名、压缩阈值、只用这种格式、测试模型、只看免费 / 只看能用、已禁用的模型、请求头 / 附加请求体 / key 放在哪个头、不校验证书、高级、额度用完后冷却多久 / 冷却最长多久、导入；状态页提示「{厂商} 官方报告服务异常」「状态页 ↗」。
- **要有的界面**：
  - 模板列表：搜索框、三组、「自定义」第一项、品牌图标；搜不到时显示空状态。
  - 添加 / 编辑窗口：区域或套餐切换、「去拿 key ↗」、key「显示」、粘贴 curl 后的提示条、保存前「拉取模型」与清单预览、请求头与附加请求体编辑、key 头、不校验证书（带确认框）。复制时 key 框提示「沿用原来的 key」。
  - 列表页：搜索框（无结果时空状态）、拖动与行菜单、行上 key 打码、模型数、「Claude Code、Codex 的默认模型」（可点）、不校验证书标记、厂商状态提示、导入提示条、底部「已禁用的模型」。
  - 接口详情页：服务范围、模型行菜单（模型设置、测试这个、只用这种格式）、「整家默认」、「测试模型」与进度、筛选、小标、「丢掉拉回的清单」、「高级」区、「再加一家」。
  - 模型设置窗口：八项、「恢复默认」、对某个 CLI 不生效的说明。
  - 导入窗口：发现列表、每条状态与操作、就地改名；导入链接确认框（发往哪些地址的警告、可改名称和 key、替换提示）。
- **状态**：拉模型、测试连接、测试模型、导入扫描、导入执行、保存、读回 key、改顺序都有进行中、成功、失败三种状态，失败信息留在原处，直到用户重试或关掉（`docs/testing.md`「Fallible user actions」）。列表、模板、发现清单有空状态和加载状态。daemon 拒收（保留字段、模板接口开不校验证书、不安全的导入链接）在表单里就地说明原因。
- **视口**：桌面端（Electron 与浏览器，宽 1280）和窄窗口（compact，宽 390）。原生端免实机验收。
- **界面验收**（看截图能判断）：
  - 1280 与 390 下，模板列表、添加窗口、列表页、详情页、模型设置、测试进度、导入窗口、导入链接确认框各一张，浅色与深色各一套。
  - 中文界面新文字全是中文，用词与术语表一致；英文界面没有露出翻译键名。
  - 所有新开关是 Switch；模型名不是等宽字体；次要操作不是蓝色链接。
  - 390 下行菜单能完成排序；保存、导入、测试这几个主要操作不被遮住。
  - 行上的提供方名、key 打码、模型数、不校验证书标记在 390 下不截断主名称。
  - 测试模型时每行能看清红绿点、格式与耗时；失败行有原因。

## Testing Decisions

- **好测试的标准**：只测外部看得到的行为，即上游收到什么、CLI 收到什么、RPC 返回什么、界面显示什么、写进 CLI 配置的是什么；不测内部结构。确定性要求见 `docs/testing.md`。
- **接缝一（主）：daemon 端到端测试**。进程内启动真实 daemon，本机起假上游，用客户端调 RPC，用 fetch 扮演 CLI 打中转站。覆盖：
  - key 选填时不发认证头；复制时沿用原 key；避让命名；读回 key。
  - 改顺序后的选路、自动切换先后、裸模型名归属。
  - 保存前拉模型、多格式合并、服务范围（24 个上限、新模型进来、下架消失、切换时勾上）、丢掉清单、定时刷新（用可控的时钟，不真等一天）。
  - 模型设置：上游模型名与 `*` 模板、只用这种格式、取值顺序；写进 Codex 模型清单与 Claude Code 设置的值（临时 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`）。
  - `/v1/models` 的能力字段；已禁用的模型的 403 与各处消失。
  - 请求头覆盖与 `anthropic-beta` 合并、附加请求体（保留字段拒收、`!` 覆盖、`${sessionId}`）、key 头三种、用户认证头时不触发 ADR 0008 的重发；以上对拉模型与测试也生效。
  - 不校验证书：本机起自签证书的假上游，开与不开两种结果；模板接口拒绝打开。
  - 每家冷却设置改变冷却时长；不设时与现在一致。
  - 测试模型：并发、进度、取消、单个超时、禁用跳过、按 Claude Code / Codex 测用记下的请求头样本、没有样本时的拒绝。
  - Bedrock、Azure 模板：假上游验证认证头、地址与部署名列表。
  - 状态页：假状态页服务，缓存 5 分钟，「价格表自动更新」关着时不发。
  - 导入：临时 HOME 里放假的 CC Switch 数据库、Claude Code 设置（含接管中的原值）、Codex 配置、Alma 数据库、OpenCode 文件；状态判定、三种操作、只读（文件修改时间不变）、一分钟只扫一次、忽略记录。
  - 旧客户端保存不清掉新字段。
  - 先例：daemon 端到端目录下接口的 gateway、models、test-connection、detect、claude、codex 几组测试和它们的假上游写法。
- **接缝二：app 浏览器测试**。Playwright 加真实 daemon 加本机假中转服务（现有接口设置页测试共用的那个夹具，按需扩展）。覆盖每个新界面，每个会失败的操作测成功和失败两种：模板选择与区域切换、粘贴 curl、复制、拖动与菜单排序、搜索、行信息与跳转、读回 key、保存前拉模型、服务范围切换、模型设置、整家默认、测试模型与筛选、已禁用的模型、请求头与附加请求体（含保留字段提示）、不校验证书确认框、高级区、状态页提示、导入提示与导入窗口。测试 daemon 用假 CLI 与临时配置目录，不碰真实 `~/.claude`、`~/.codex`，不会真升级 CLI。
- **导入链接**：解析与拒收规则用纯逻辑单元测试；桌面端收链接到打开确认框的那一段放进桌面端已有的链接处理测试里。
- **纯逻辑**：curl 解析、附加请求体合并、glob 匹配、服务范围计算、取值顺序、导入状态判定加进已有的同类测试文件，不另建套件、不加 npm 脚本或 CI 任务。
- **协议**：新字段与新 RPC 的解析测试加进现有的接口协议测试；用旧形状的消息验证兼容。
- **不连真实中转服务、厂商或状态页**；本机只跑改到的测试文件，全量交给 CI。

## Out of Scope

- 网络代理：全局代理与每家代理都不做（R1-Q9）。
- 改接口标识（R1-Q17b）。
- 一家多把 key（块 4，用复制代替）；导入时的「加为另一把 key」随之改为新增一家。
- 服务范围的「只看用量」、价格倍率小标：等子任务 5。
- 上游说模型下线时从清单拿掉一周：子任务 1 已做（**Retired model**）。
- Gemini 格式地址、Google Gemini 官方模板、导入链接里的 `gemini` 地址：等子任务 7。
- Google Vertex、决策模型模板、Remote magpie。
- `Same as`（02·A57，不同名模型声明为同一个）：属块 8 路由组，总任务范围外；只差写法的同一模型已由子任务 1 归一。
- 把模型标成图片 / 视频模型（02·A54 的一部分）：画图、视频入口在总任务范围外。
- 余额与额度：子任务 4。
