# 接口管理好用性

来源：总任务 [`10-16-magpie-osuna-gaps`](../10-16-magpie-osuna-gaps/prd.md) 的第 3 个子任务。这是起步稿，写明范围、依据和要在本任务里定的问题；需求还在 discover，`/atw-spec` 时整份重写。总任务的 Constraints、Implementation Decisions、Testing Decisions 对本任务全部适用，下面只写本任务特有的。

## Problem Statement

添加和管理第三方接口费事：不能粘贴 curl，没有服务商模板，不能复制一家，不能排顺序；模型的显示名、上下文、档位改不了，不能逐个测模型。同一家中转服务的多把 key 只能手工各建一家接口。

## Scope

### 已定要做

- 「复制这家接口」：复制后改 key 或地址，代替「一家多把 key」（Q9）。

### 候选（在本任务里挑）

- 粘贴 curl 自动填表。
- 服务商模板（magpie 有 57 个；上次明确不做，这次重新问），同一模板再加一家。
- 自定义请求头与附加请求体；选 key 放在哪个请求头。
- 每家接口单独设网络代理。
- 跳过证书校验：安全取舍，单独问。
- 调整接口顺序，决定自动切换时先换到哪家。
- 搜索接口。
- 接口行上显示哪些提供方会用到它的模型。
- 保存前先拉模型；合并各格式的模型清单；定时拉清单。
- 手改模型的显示名、上下文与回复上限、推理档位、能否看图、发给上游的名字。
- 逐个测模型；按「免费」「能用」筛选。
- 本机模型服务可不填 key。
- 接口出问题时显示厂商状态页。

### 不做

- 一家多把 key（块 4，Q9）。

## Decisions So Far

- Q9：块 3 做，条目进本任务再挑；块 4 不做，用「复制这家接口」代替。

## Constraints

- 调整接口顺序会改掉 ADR 0007 的「裸模型名按接口创建顺序解析」，做的话要更新那一条。
- 界面规矩见总任务「UI and Design」；表单按 `docs/forms.md` 的表单模型做。

## Testing

- 浏览器测试为主：先例是第三方接口设置页那组测试和它的假中转服务夹具。
- daemon 侧的新行为（顺序、模型信息、测模型）加 daemon 端到端测试。
