# 05 — 只重新处理变了的文件

**What to build:** 改动里只有一个文件又变了时，daemon 只为这个文件重取 patch、重读全文、重做高亮，其余文件直接复用上一次的结果。刷新快慢不再和改动总量成正比。客户端看到的数据和改前逐字一致。

- 每个文件算出的 patch 与高亮结果按文件身份缓存：compare 参数 + 路径 + 旧侧 blob + 工作区一侧的 stat 签名（大小 + mtime + inode）。身份没变就复用。
- 文件监听拿到的变动路径往下传，作为「哪些文件该失效」的提示。身份比对是兜底判断，所以收到不带路径的「有变化」信号（轮询降级、base 模式快照）时结果也正确。
- 整份结果缓存的 key、去重指纹、推送消息的形状都不变。按文件缓存跟着整份缓存一起淘汰；cwd 不再被订阅时一起释放。
- 这是和上游冲突风险最高的一张。尽量用新增模块包住，少改 `checkout-git.ts`、`workspace-git-service.ts` 里原有的函数体。
