# 05 — Codex 自动换号规则：定时检查、上限、固定登录到

**What to build:** 打开「多号自动轮换」后，Osuna 在 daemon 启动 1 分钟后、之后每 5 分钟检查一次：当前号任一窗口用到 98% 或到了用户设的上限，就把 Codex 换到下一个还有余量的号；排在前面的号所有窗口回到 90% 以下就换回。用户可以给每个号的每个窗口「设上限」，也可以「固定登录到」某个号。列表上的状态标签跟着变。

**Blocked by:** 04
**Status:** ready-for-agent
**Impl:** ready

- [ ] 「没有余量」：任一窗口用到 98%、到了用户的上限、`allowed` 为假且没有 credits、或某窗口重置时间已过但读数没更新（照 magpie）。
- [ ] 选目标：按用户排的顺序，第一个不是当前号、没有失效、有已知且无错的读数、没到 98% 和上限的号；没有就停在当前号不动。
- [ ] 换回：排在当前号前面的号所有窗口都低于 90% 时，换回排得最靠前的那个。
- [ ] 节奏：daemon 启动 1 分钟后一次，之后每 5 分钟；「立即使用」「重新登录」完成后立刻检查一次。换号沿用 04 的步骤与换号记录，原因写明哪个窗口到了多少或「到了你设的上限」。
- [ ] 「设上限」对话框：每个窗口一个 1–99 的百分比输入框，可清空；保存中、保存失败留在框里。设了上限的窗口在用量条上标出上限。
- [ ] 「固定登录到」：选择框，「不固定」与每个号；固定后完全不自动换，用完也不换，直到改回「不固定」。
- [ ] 状态标签：「使用中」「第一」「暂时第一」（排在前面的号没有余量）「有余量后回到第一」「需要重新登录」。
- [ ] 换号规则做成 Codex 与 Claude Code 共用的一份（08 直接用）。
- [ ] 测试：daemon 端到端（可拨的时钟；98% 换走、上限换走、90% 换回、没有余量不动、固定不换、不换到没读过 / 读错 / 失效的号、立即使用后立刻检查）；app 浏览器测试（设上限成功 / 失败、固定与取消固定、状态标签）。
- [ ] UI: 账号列表 / 第一个号用完、暂时换到第二个 / 1280 — 第一个号「有余量后回到第一」，第二个号「使用中」「暂时第一」，「最近换号」有写明窗口与百分比的记录。
- [ ] UI: 设上限对话框与用量条 / 设了上限 / 1280 与 390 — 用量条上能看到上限位置，对话框在 390 下完整可用。
