# 04 — Codex 手动换号：立即使用、移除、排序、换号记录

**What to build:** 用户在 Codex 的账号行菜单点「立即使用」，Codex 的登录马上换成这个号：新开的 Codex 会话（含终端里新开的）用这个号，开着的仍在原来的号上。用户可以拖动或用菜单调号的先后、「设为第一」、「移除」。账号一节下方列出最近的换号。Agent 的套餐用量卡片显示这个 Agent 用的号。

**Blocked by:** 03
**Status:** ready-for-agent
**Impl:** ready

- [ ] 换号步骤：在跨进程锁里，先把 CLI 里当前的登录（最新一份）收回到它自己的记录，再把目标号的登录按 `cli_auth_credentials_store` 写进 CLI（`file` 写 `auth.json`；`keyring` / `auto` 写钥匙串 `Codex Auth`、账号 `cli|<CODEX_HOME 的 sha256 前 16 位>`），然后清掉目标号在 Osuna 这边的那份；每步写前重读，守 ADR 0004 的改写规则（只动登录、原子替换、保留权限、读不懂不写）。换号前后任何时刻一个号的 token 只在一处。
- [ ] 当前登录的号：到期前 5 分钟内或请求遇到 401 `token_expired` 时由 Osuna 续期并写回 CLI 的存储（照 magpie）。
- [ ] 「移除」只删 Osuna 存的那份，不登出 CLI；移除确认框写明「Osuna 删掉自己存的这个号；CLI 不会被登出」。
- [ ] 排序：拖动，或行菜单「设为第一」「上移」「下移」「移到最前」「移到最后」，与第三方接口列表同样的交互。
- [ ] 换号记录：每条写时间、从哪个号到哪个号、原因（这张只有「你按了立即使用」与「号失效」）；每个提供方保留最近 50 条，重启不丢；默认显示 5 条，可展开。不弹通知。
- [ ] 换号失败（写不进 CLI 的登录、号失效）时，这一节醒目显示原因和处理办法。
- [ ] Agent 的套餐用量卡片显示这个 Agent 用的号（邮箱）。
- [ ] 「读取 CLI 登录凭证」关着时不换号。
- [ ] 测试：daemon 端到端（`file` 与 `keyring` 两种存法换号后 CLI 存储里是目标号、旧号收回、token 只在一处；当前号续期写回；移除在用的号不动 CLI；排序；换号记录重启后还在；总开关关着时拒绝）；app 浏览器测试（立即使用成功 / 失败、移除、拖动与菜单排序、换号记录展开）。
- [ ] UI: 账号列表 / 换过一次号 / 1280 与 390 — 新号「使用中」，「最近换号」有一条写明原因；390 下行菜单完整可用。
