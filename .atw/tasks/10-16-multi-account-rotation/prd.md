## Problem Statement

有多个 ChatGPT 或 Claude 订阅号的用户，一个号的 5 小时窗口或每周窗口用完，只能手动 `codex login` / `/login` 换号；换的时候正在跑的对话直接报额度用完。

官方给的多号办法是每个号一个配置目录（`CODEX_HOME`、`CLAUDE_CONFIG_DIR`），但那样每个目录里的会话、技能、MCP、指令文件各管各的，用户说过不要这种分家的做法。

Osuna 已经会读当前登录的号还剩多少（**Plan usage**），也已经让 Codex 的 ChatGPT 请求经过内置中转站（**Gateway**，子任务 2），但不会记住别的号，也不会替用户换号。

## Solution

Codex、Claude Code 的提供方设置页各多一节「账号」（**Account**）。用户在这里加号、排先后、给号的每个窗口设上限（**Limit**），并打开「多号自动轮换」（**Rotate accounts**）。

- **第一层：换登录**（Codex 与 Claude Code）。Osuna 每 5 分钟看一次各号的额度。当前登录的号任一窗口用到 98%，或到了用户设的上限，就把 CLI 自己保存的登录换成下一个还有余量的号。排在前面的号所有窗口都回到 90% 以下，就换回去。
  - 只有新开的会话用上新号，用户在终端里新开的 CLI 也算。
  - 用户可以「固定登录到」某一个号，固定后完全不自动换。
- **第二层：经过中转站换号**（只有 Codex）。Codex 的请求经过内置中转站。当前号接不了的请求（额度用完、登录失效、对方出错等），在回复第一个字之前交给下一个号，开着的对话不报错。可以关成「只换登录」（**Only switch the sign-in**）。
- **第一次打开时提示风险**。为 Codex、Claude Code 各自第一次打开轮换时，弹出这家条款原文和可能的后果，记在主机上，每家只提示一次。
- **加号照 magpie**。Codex 由 Osuna 打开 OpenAI 的登录页；Claude Code 由 Osuna 在后台运行真的 `claude auth login`，替用户打开浏览器。打开轮换时，CLI 当前登录的号自动成为第 1 个号。
- **存着的号**放在 Osuna 自己的数据目录里，与第三方接口的 key 一样处理。
  - Codex 的号照 magpie 由 Osuna 自己续期。
  - Claude 的号各有一个私有配置目录，由真的 Claude Code 在里面续期、查额度。
- **只记录、不通知**。账号一节列出最近的换号和原因；Agent 的套餐用量卡片显示它用的号；中转站的请求记录写上答话的号。
- 关掉子任务 8 的「读取 CLI 登录凭证」（**Read CLI sign-ins**）时，这一切都停，存着的号保留。

## User Stories

### 打开轮换与风险提示

1. 作为有多个 ChatGPT 号的 Codex 用户，我希望在 Codex 的设置页打开「多号自动轮换」，以便一个号用完时 Osuna 替我换号。
2. 作为有多个 Claude 订阅号的 Claude Code 用户，我希望在 Claude Code 的设置页同样打开，以便 Claude Code 也不因一个号用完而中断。
3. 作为用户，我希望轮换默认关着，以便升级 Osuna 后什么都不变，直到我自己打开。
4. 作为用户，我希望第一次为 Codex 打开时，先看到 OpenAI 条款原文、链接和可能的后果，以便自己决定要不要冒这个险。
5. 作为用户，我希望第一次为 Claude Code 打开时，看到 Anthropic 的相关原文和链接，以便知道两家的说法不同。
6. 作为用户，我希望风险提示里分清条款原文和员工的公开说法，以便知道哪句是条款。
7. 作为用户，我希望在风险提示里点「取消」时开关保持关着，以便误点不出事。
8. 作为用户，我希望看过一次风险提示后，在这台主机上不再被提示，换设备也不再提示，以便不被反复打扰。
9. 作为用户，我希望关掉再打开轮换时不再弹提示，以便来回开关不多一步。
10. 作为用户，我希望 Codex 和 Claude Code 各提示一次，以便打开其中一家时看到的是那一家的条款。

### 账号列表

11. 作为用户，我希望打开轮换时，CLI 现在登录的号自动出现在列表第 1 位，以便不用为它再登录一次。
12. 作为用户，我希望每个号显示邮箱、套餐、各窗口用了多少、几时重置，以便知道每个号还剩多少。
13. 作为用户，我希望看到哪个号是「使用中」、哪个是「第一」，以便知道 CLI 现在登录的是谁、我排在最前面的是谁。
14. 作为用户，我希望第一个号用完、暂时换到别的号时，那个号显示「暂时第一」、原来的号显示「有余量后回到第一」，以便知道之后会换回去。
15. 作为用户，我希望号的登录失效时显示「需要重新登录」和「重新登录」按钮，以便修好它。
16. 作为用户，我希望拖动或用菜单里的「上移」「下移」「移到最前」「移到最后」「设为第一」调号的先后，以便决定先换到谁、优先用谁。
17. 作为用户，我希望用「立即使用」把 CLI 马上换到某个号，以便不等 5 分钟的检查。
18. 作为用户，我希望「移除」一个号时，Osuna 只删掉自己存的那份，不把 CLI 登出，以便移除不打断我正在用的登录。
19. 作为用户，我希望移除当前在用的号后，轮换在下次检查时按规则换到排第一、还有余量的号，以便移除后一切照常。
20. 作为用户，我希望列表里有一个号都没有、只有一个号时有清楚的说明和「添加账号」，以便知道下一步做什么。
21. 作为用户，我希望列表在读取额度时有加载状态、读不到时说明原因，以便分清「还没读」和「读失败」。

### 加号

22. 作为 Codex 用户，我希望点「添加账号」后浏览器打开 OpenAI 的登录页，登录完号就出现在列表里，以便加号像平常登录一样简单。
23. 作为 Claude Code 用户，我希望点「添加账号」后浏览器打开 Claude 的登录页，不弹终端，登录完号就出现在列表里，以便同样简单。
24. 作为在手机或别的电脑上用 Osuna 的用户，我希望拿到登录链接，在任意设备上登录后，把浏览器最后跳到的地址（Codex）或页面上显示的代码（Claude）粘回来，以便不在主机前也能加号。
25. 作为用户，我希望登录超时、被我取消或失败时看到原因，可以重试，以便知道没加上。
26. 作为用户，我希望加的号如果已经在列表里，Osuna 告诉我「已经有这个号」并更新它的登录，以便不出现重复的号。
27. 作为用户，我希望用「重新登录」修好失效的号时走同一个登录流程，以便不用先移除再加。

### 第一层：换登录

28. 作为用户，我希望 Osuna 在 daemon 启动 1 分钟后、之后每 5 分钟看一次各号的额度，以便及时发现快用完的号。
29. 作为用户，我希望当前号任一窗口用到 98% 就换到下一个还有余量的号，以便新会话不撞上额度用完。
30. 作为给号设过上限的用户，我希望当前号某个窗口到了我设的百分比就换走，以便给那个号留出我自己手动用的余量。
31. 作为用户，我希望排在前面的号所有窗口都回到 90% 以下时换回去，以便优先用我排在前面的号，又不在号刚恢复一点时来回换。
32. 作为用户，我希望 Osuna 不把 CLI 换到一个从没读到过额度、读额度出错、登录失效或也没有余量的号上，以便不换到一个更糟的号。
33. 作为用户，我希望没有任何号有余量时 Osuna 停在当前号不动，以便不在几个用完的号之间乱换。
34. 作为用户，我希望「固定登录到」某个号后，Osuna 完全不自动换，用完也不换，直到我取消固定，以便我需要时能只用一个号。
35. 作为用户，我希望换号后在终端里新开的 Codex / Claude Code 也用上新号，以便终端和 Osuna 用的是同一套会话和配置。
36. 作为用户，我希望列表上写明「开着的会话仍在原来的号上，新会话用新号」，以便知道换号什么时候生效。
37. 作为 Codex 用户，我希望不管 Codex 把登录存在 `auth.json` 还是钥匙串里，轮换都能用，以便不用为轮换改 Codex 的设置。
38. 作为 Codex 用户，我希望 Codex 设成只在内存里存登录（`ephemeral`）或 Osuna 读不懂它的存法时，看到「Osuna 换不了这种登录」和原因，以便知道为什么不换。
39. 作为在 Linux 或 Windows 上用 Claude Code 的用户，我希望轮换同样能换存在文件里的登录，以便不只在 Mac 上能用。

### 第二层：经过中转站换号（Codex）

40. 作为在 Osuna 里开着 Codex 对话的用户，我希望当前号额度用完时，这次请求在回复第一个字之前交给下一个号，以便开着的对话不报额度错误。
41. 作为用户，我希望登录失效、对方服务出错、模型被下线这些情况也换下一个号重发，以便偶发的问题不打断对话。
42. 作为用户，我希望对话太长这类换号也没用的错误不换号，以便不白白消耗别的号。
43. 作为用户，我希望换过去以后，同一轮对话留在新号上；写过提示缓存的对话在 5 分钟内跨轮也留着，以便缓存不白写。
44. 作为号里还有 credits 的用户，我希望额度用完的回复先用这个号再问一次，以便先用掉我另买的额度。
45. 作为不想让订阅请求经过内置中转站的用户，我希望打开「只换登录」，以便 Codex 直连 OpenAI、只保留第一层。
46. 作为没开「使用第三方接口」的 Codex 用户，我希望有两个以上的号时第二层照样工作，以便不用为了换号去开第三方接口。
47. 作为同时开着「使用第三方接口」的 Codex 用户，我希望第三方模型照常可用，ChatGPT 自带的模型也在多个号之间换，以便两样同时生效。
48. 作为所有号都用完的用户，我希望 Codex 照常显示「额度用完、几点恢复」，以便知道要等到什么时候。
49. 作为在终端里直接跑 Codex 的用户，我希望设置页写明 Osuna 没在运行时 Codex 会连不上、关掉「只换登录」以外的办法，以便出问题时知道原因。
50. 作为用户，我希望换号重发只用号的登录替换原请求的登录，请求的其余部分保持 Codex 自己的样子，以便不额外增加被识别为异常的风险。

### 存放、续期与失效

51. 作为在意安全的用户，我希望存着的号放在只有我自己的系统用户能读的文件里，以便别的用户读不到。
52. 作为用户，我希望存号的文件写坏时用上一份好的，以便一次写坏不丢掉所有号。
53. 作为用户，我希望一个号的登录在任何时候只存在一个地方（Osuna 存的那份或 CLI 当前的登录），以便同一个续期凭证不被两处同时用、导致号失效。
54. 作为用户，我希望 Osuna 让存着的 Codex 号保持能用，以便换上去时不用重新登录。
55. 作为用户，我希望存着的 Claude 号由 Claude Code 自己续期，以便 Osuna 不替 Anthropic 的程序续期。
56. 作为用户，我希望号被 OpenAI 或 Anthropic 吊销、续期被拒时，这个号标「需要重新登录」并退出轮换，以便不再换到它上面。
57. 作为用户，我希望旧会话碰巧续期让一个号失效时，同样看到「需要重新登录」，以便知道怎么修。
58. 作为用户，我希望 Osuna 用来续期、查额度的请求都写进 `docs/usage.md` 的「Outbound requests」，以便知道 Osuna 带着我的登录去了哪里、什么时候去。

## Implementation Decisions

### 推翻的规则与身份例外（ADR 0015）

- 新写一篇 ADR（[ADR 0015](../../../docs/adr/0015-account-rotation-holds-cli-logins.md)），推翻 ADR 0004 的「`~/.codex/auth.json` is never read or written」与 ADR 0010 的「不靠读 `auth.json` 认登录」中与轮换冲突的部分，并在 ADR 0004、0010 里标出被它取代。旧规则防的坑（refresh token 只能用一次、快照还原会写回用过的 token）由下面的「一个登录只有一个持有者」承接。
- 同一篇 ADR 记下总任务 Implementation Decisions 第 15 条（身份如实）的三处例外。总任务第 15 条写明「登录续期如果必须由 Osuna 代办，在子任务 9 单独决定」，下面就是这个决定，由用户在访谈 Q6、Q7、Q14 选定：
  1. Codex 的续期由 Osuna 用 Codex 的 OAuth 客户端身份发出（照 magpie）。
  2. Codex 的加号由 Osuna 自己跑 OAuth，带 Codex 的客户端身份（照 magpie）。
  3. 查 Codex 额度保持上游 Paseo 的浏览器 User-Agent，存着的号的额度读取走同一处代码。
- ADR 写明被否决的做法：助手推荐的「在每个号的私有 `CODEX_HOME` 里起真的 Codex app-server，用 `account/login/start` 登录、用 `account/rateLimits/read` 续期与查额度」，以及否决理由（用户选择照 magpie）。
- 总任务 `prd.md` 第 15 条下加 2026-10-25 注写明这三处例外，「身份」验收项加注指向它；两处都链到本 ADR。
- Claude 一侧不在例外里：登录由真的 `claude auth login` 完成，续期由 Claude Code 自己做，查额度跑真的 Claude Code，当前号的额度沿用现有的套餐用量来源。

### 账号存放

- 新增一个账号存储 `$PASEO_HOME/accounts/accounts.json`。规矩与第三方接口的 key 文件相同：目录 0700、文件 0600、明文不加密、原子替换、保留上一份好的、写坏时用上一份。遵守 `docs/data-model.md`，由存储模块负责原子性。
- 每个号记：稳定 ID、提供方（`codex` / `claude`）、邮箱、套餐、用户排的位置、各窗口的上限、状态（正常 / 需要重新登录及原因）、最近一次读到的额度与读取时间。
  - Codex 的号另存整份登录（与 `auth.json` 同形）。
  - Claude 的号另存 `oauthAccount` 资料。它的凭证放在这个号的私有 `CLAUDE_CONFIG_DIR` 里，由 Claude Code 自己的存法决定：macOS 在钥匙串里、按目录取后缀的那一项，其他系统在该目录的 `.credentials.json`。
- 每个提供方的轮换设置：「多号自动轮换」、「固定登录到」哪个号、Codex 的「只换登录」、这台主机看过哪家的风险提示、最近 50 条换号记录。这些不含秘密，但同样放在账号存储里，不放进会发给客户端的 daemon 配置。工单 02 只存开关与「看过风险提示」，其余各项由用到它的工单加成可选字段。
- **一个登录只有一个持有者**（照 magpie）：
  - 当前在用的号，登录只在 CLI 自己的存储里，Osuna 的存储只留它的资料，不留第二份 token。
  - 存着的号，token 只在 Osuna 的存储里（Codex）或它的私有目录里（Claude）。
  - 换号时先把 CLI 里当前的登录（最新的一份）收回到它自己的记录，再把目标号的登录写进 CLI，然后清掉目标号在 Osuna 这边的那份。
  - 整个过程在跨进程锁里做，每一步写前重读。
- 换号写 CLI 的存储同样守 ADR 0004 的文件改写规则：只动登录本身、原子替换、保留文件权限、写前重读、读不懂就不写。

### Codex 第一层

- **读写 Codex 的登录**：按 Codex 的 `cli_auth_credentials_store` 决定存法。
  - `file`：读写 `$CODEX_HOME/auth.json`。
  - `keyring` / `auto`：读写钥匙串里服务名 `Codex Auth`、账号 `cli|<CODEX_HOME 的 sha256 前 16 位>` 的那一项；`auto` 时钥匙串没有，再看文件。
  - `ephemeral` 或读不懂：拒绝换号并说明原因。
  - `CODEX_HOME` 取提供方环境里的值，否则 `~/.codex`。读写登录的部分做成可替换的适配器（测试用临时目录与假钥匙串）。
- **续期**（照 magpie）：
  - 当前登录的号：在 access token 到期前 5 分钟内，或请求遇到 401 `token_expired` 时，由 Osuna 续期并写回 CLI 的存储。（工单 04 实现时定：只在 Codex 开着「多号自动轮换」时做，守 User Story 3「升级后什么都不变」；「请求遇到 401」以读当前号额度被拒（401 / 403）为准，套餐用量来源拿不到 `token_expired` 这个细分。续期被拒且开着轮换时，换到排在最前、登录还能用的号，原因记「号失效」，更细的选号规则归工单 05。）
  - 存着的号：要用（查额度、换上去、第二层发请求）时续期；另每 24 小时保活一次。
  - 续期前在锁里重读存储，存的 token 已被别人换过就采用新的，不再续。
  - 续期请求一旦发出不中途取消，免得新 token 丢失。
  - 续期被拒（`invalid_grant`、`refresh_token_reused`、`token_revoked`，以及照 magpie 的 `refreshFailed` 任何 HTTP 400 / 401），这个号标「需要重新登录」。
  - 续期请求不随调用方（读额度、保活、daemon 关闭）取消，只有它自己 30 秒的上限（同 magpie）。
  - 保活每 5 分钟的检查里做，只看 `max(Osuna 最近一次续, auth.json 的 last_refresh)` 是否满 24 小时；存着的号的额度只在这家开着轮换时才随检查读（列表打开时照常读）。（工单 03 实现时定）
- **读额度**：所有号都用现有 Codex 套餐用量来源的同一处读法读 `wham/usage`（同样的请求头），存着的号用它自己的 token；回复里带的 `x-codex-*` 头与 `codex.rate_limits` 事件也按号记下。
- **判定「没有余量」**：任一窗口用到 98%、到了用户的上限、`allowed` 为假且没有 credits（照 magpie 的 `codexHeld`，含工作区超额与 spend_control 的判断）。重置时间已过的窗口算已经重新开始、有余量（照 magpie 源码 `usedPast` / `resetPassed`；原先写成「也算没有余量」是研究笔记读错，工单 05 实现时更正，用户 2026-10-25 确认）。只看整个号的窗口：ID 带「:」的是某个模型或功能自己的窗口（如 Code review），不算，也不能设上限。
- **选目标**：按用户排的顺序，第一个满足以下条件的号：不是当前号、没有失效、有已知且无错的读数、没有到 98% 和上限。当前号失效时换号也用这个选法；CLI 登录的号不在列表里（移除了在用的号）时换到这样的号，原因 `not_listed`。
- **换回**：排在当前号前面的号所有窗口都低于 90% 时，换回排得最靠前的那个。只在 Osuna 自动换走（用完、上限、不让发送、号失效）之后才换回，照 magpie 的 login-returns；用户「立即使用」选的号不会被换回（工单 05 实现时定，用户 2026-10-25 确认）。「有余量后回到第一」「暂时第一」两个标签就是这条记录的两端。
- **固定登录到**：固定到的不是 CLI 现在登录的号时，马上换到它上面（magpie `KeepLoginAs`）；固定后完全不自动换，号失效也不换。
- **检查节奏**：daemon 启动 1 分钟后一次，之后每 5 分钟；「立即使用」与「重新登录」完成后立刻检查一次。检查先读各号额度再判断；读的这段时间用户已经换过号时，这次不换。规则在 `provider-accounts/rotation-rules.ts`，Claude Code（工单 08）共用。
- **生效范围**：只对新会话生效。已经开着的 Codex app-server 进程仍在旧号上，靠第二层兜住。
- **Agent 的套餐用量卡片**（工单 04 实现时定）：Codex app-server 启动时记下时刻；之后 CLI 换过号，卡片仍是启动时那个号（邮箱），用它存着的登录读额度。只认 Osuna 换号的那个 `CODEX_HOME`；那个号被移除后卡片照 CLI 现在的登录显示。
- **只用 API key 登录的 Codex**：「立即使用」拒绝（`login_unsupported`），不盖掉 `auth.json`。（工单 04 实现时定）

### Codex 第二层

- **接法**：建在子任务 2 定下的接法上（ADR 0010）。轮换打开、开着的 Codex 号多于一个、没开「只换登录」时，即使没开「使用第三方接口」，也照 magpie 写 `openai_base_url` 指向内置中转站。
  - 关掉轮换、只剩一个号或打开「只换登录」时，按 ADR 0004 / 0012 的规则把这一键还原。
  - 「使用第三方接口」开着时，这一键本来就由它写，两边共用，不重复写、不互相还原。
  - （工单 06 实现时定：「号多于一个」只数没失效的号；「使用第三方接口」打开时先在同一次写入里放回第二层写的值，接管记录才记得到用户原来的值；关掉它（及关前预览）时这一键交给第二层；daemon 启动时跟上新端口。只开第二层时 CC Switch 的镜像表不跟着指到中转站，未做。）
- **选号**：中转站收到 ChatGPT 自带模型（不带「接口标识/」前缀的模型名）的请求，候选是当前登录的号加上存着的、没失效的号；先当前号，再按用户排的顺序；没有余量的号排在最后但不去掉（照 magpie）。
  - 发给某个号时，只把请求里的 ChatGPT 登录和 `ChatGPT-Account-Id` 换成那个号的，其余照 Codex 原样转发。
  - （工单 06 实现时定，照 magpie：「当前号」是请求自己登录的号（按 `ChatGPT-Account-Id` 认，开着的旧会话也一样），原样发；有 credits 的号窗口用满不算没余量，只看用户的上限。发给别的号时另外不带只属于原来那个号的设备证明、Luna Reserve、turn-state 三个头（magpie `codexHeader`）；所有号都不要上游压缩（去掉 `Accept-Encoding`，magpie 同样交给传输层），中转站才读得出开口与错误原文。对话与压缩（`/responses/compact`）都换号，压缩不记账，同原样转发。）
- **换下一个号的条件**：照 magpie 的错误清单——401、402、403、404、408、429、全部 5xx、模型下线、边缘拦截，以及文字像额度用完、模型不支持或拒绝的 400 / 422。对话太长不换。
  - 只在还没有任何内容发给 Codex 时换：中转站扣住错误回复与流的开头，直到第一段内容。
  - （工单 06 实现时定，照 magpie `withoutUnreadable`：换上的号读不了上一个号封存的推理或某个条目（400 / 404，`invalid_encrypted_content` 或点名条目）时，去掉它们再问同一个号，最多 3 次；不去掉的话换号后的第一轮就会被拒。）
- **有 credits 时再问一次**：号里有 credits 时，429 `usage_limit_reached` 先用同一个号再问一次（magpie `bf2e067e`）。
- **粘性**：照 magpie 的默认 auto——同一轮内留在换上的号；读写过至少 1024 个缓存 token、且上次回复在 5 分钟内的对话，跨轮也留着。
- **所有号都不行**：把最后一个上游的错误原样交给 Codex，Codex 照常显示「额度用完、几点恢复」。不做 magpie 为 Codex 桌面应用临时改服务商那一招。
- **记账**：子任务 5 的中转站账本给这类请求记下答话的号（号的 ID 与邮箱）和每次尝试；用量页的分组仍归「官方」（ADR 0014 不变），请求列表显示「官方 · 邮箱」。

### Claude Code 第一层

- **读写 Claude Code 的登录**：macOS 用钥匙串服务名 `Claude Code-credentials`（提供方环境设了 `CLAUDE_CONFIG_DIR` 时加 `-<该目录 sha256 前 8 位>`），账号 `$USER`；其他系统写该配置目录下的 `.credentials.json`。换号同时把 `.claude.json` 的 `oauthAccount` 换成目标号的资料，只动这一键，写前重读。读写同样走可替换的适配器。
- **私有目录**：每个存着的号一个，放在账号存储下。号被换上时，它的凭证移进 CLI 的默认存储，私有目录里的凭证清掉；号被换下时，从默认存储收回到私有目录。
- **续期**：Osuna 从不续 Claude 的 token，也从不连 Anthropic 的登录服务。存着的号在查额度时由 Claude Code 在私有目录里自己续；续出的新 token 留在私有目录。
- **读额度**：
  - 当前登录的号：沿用现有 Claude 套餐用量来源的读法（两家都按报告 ID `codex:<账号 ID>`、`claude:<账号 UUID>.<组织 UUID>` 从套餐用量注册表取；注册表还没发现这个号时，照用量页那样整体发现一次）。
  - 存着的号：照 magpie 在该号的私有目录、临时工作目录里运行真的 `claude -p /usage --output-format json --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence`，解析其中的「Current session / Current week」用量与重置时间。跟随每 5 分钟的检查自动读（Q19，magpie 只在用户刷新时读）。
  - 从没读到过额度的号不当目标。
- **判定、选目标、换回、节奏**：与 Codex 第一层相同。
- **生效范围**：新会话用新号。开着的 Claude Code 进程可能在登录过期、重读存储时跟着换到新号（Claude Code 的行为，见 `cli-login-mechanics.md`），这一点写进说明，不另做处理。
- **与「使用第三方接口」**：Claude Code 开着「使用第三方接口」时订阅号用不上（中转站不转发 claude.ai 登录，ADR 0012），轮换照常转，界面加说明（Q20）。

### 加号

- **Codex**（照 magpie）：Osuna 自己跑 PKCE OAuth，用 Codex 的 OAuth 客户端与范围，回调监听 `127.0.0.1:1455`。
  - 端口被占或用户不在主机前时，用户把浏览器最后跳到的地址粘回来完成登录。端口被占时照 magpie 与 Codex 自己的做法，先请那里等着的 `codex login` 停下再试，仍占不到才只留粘贴。
  - 登录 10 分钟内没完成算超时，可取消。
  - 拿到的登录存进账号存储，按 `id_token` 里的账号认重复：已有就更新这个号的登录，并告诉用户「已经有这个号」。
  - 加的正是 CLI 现在登录的号时，这次拿到的 token 丢掉，只记资料，并清掉 Osuna 这边这个号原有的 token（一个登录只有一个持有者）。
  - 「重新登录」登成了别的号时报失败（「登录的是另一个号」），什么都不写。
  - 浏览器回来时再问一次「读取 CLI 登录凭证」：登录途中关掉了就不去换 token。（以上三条工单 03 实现时定）
- **Claude**（照 magpie）：在新的私有 `CLAUDE_CONFIG_DIR` 里后台运行真的 `claude auth login`，Osuna 截下它要打开的登录地址交给客户端。
  - 主机上的桌面端直接打开浏览器；远程设备显示链接，并提供粘贴代码的输入框，转给这个登录进程。
  - 登录完成后从该目录读出邮箱与套餐，存进账号存储；没读到邮箱的拒收。
- **第一个号**：打开轮换时，把 CLI 当前登录的号登记为第 1 个号（只记资料，登录仍只在 CLI 那里）。打开时 CLI 还没登录的，列表为空；之后 CLI 登录了，下一次读列表时把它补登为第 1 个号。
- **重新登录**：走同一流程，把结果写回同一个号。
- **不做导入**（02·B15）。

### 与「读取 CLI 登录凭证」

- 每次读写 CLI 登录、续期、查额度、第二层换号前都问子任务 8 的同一个闸门；关着时什么都不做，第二层退回只按当前号原样转发。
- 已写的 `openai_base_url` 不因关总开关而改动（子任务 8「关开关本身不改 Codex 配置」的规则不变）。
- 关闭确认框的「会停的事」加一项「多号自动轮换」，并列出开着轮换的提供方。
- 存着的号与设置保留，开回来后下一次检查照常进行。

### 协议与兼容

  - 改设置（轮换、固定、只换登录、上限、顺序）；

  读要 `daemon.read`，改要 `daemon.manage`（`docs/permissions.md`）。

## UI and Design

- **方向**：沿用 Codex、Claude Code 提供方设置页和第三方接口列表的现有样式，不另做视觉。遵守 `docs/design.md`、`docs/forms.md`、`docs/hover.md`、`docs/menus.md`、`docs/unistyles.md`、`docs/i18n.md` 与 `.atw/spec/app/frontend/`。用户偏好：开 / 关一律 Switch；模型名不用等宽字体；次要操作不用蓝色链接。
- **位置**：Codex、Claude Code 的提供方页，在「使用第三方接口」那一节之后、模型清单之前，新加一节「账号」。
- **一节里从上到下**：
  1. 说明行（按情况出现）：
     - Claude Code 开着「使用第三方接口」时的那行；
     - 总开关关着时「已关闭读取 CLI 登录凭证，多号自动轮换已停止」和去开关的按钮；
     - Codex 写不了这种登录时的原因。
  2. Switch「多号自动轮换」，下面一行说明：「换号只对新会话生效，开着的会话仍在原来的号上」；Codex 另写「请求会经过 Osuna，Osuna 没在运行时终端里的 Codex 连不上」。
  3. Codex 的 Switch「只换登录」。
  4. 「固定登录到」：一个选择框，选项是「不固定」和每个号。
  5. 账号列表，每行：
     - 邮箱、套餐、状态标签（「使用中」「第一」「暂时第一」「有余量后回到第一」「需要重新登录」）；
     - 各窗口的用量条与重置时间，设了上限的窗口在条上标出上限；
     - 行菜单：「立即使用」「设为第一」「上移」「下移」「移到最前」「移到最后」「设上限」「移除」；
     - 失效的号行内有「重新登录」按钮；
     - 可拖动排序，与第三方接口列表相同（**Endpoint order**）。
  6. 「添加账号」按钮。
  7. 「最近换号」：最新的在上，每条一行，写时间、从谁到谁、原因；默认显示 5 条，可展开到 50 条。
- **对话框**：
  - **风险提示**：见上文的文字。窄窗口下是底部弹出的面板。
  - **设上限**：每个窗口一个百分比输入框（1–99），可清空；保存中、保存失败都留在框里。
  - **加号**：
    - 进行中：显示「在浏览器里完成登录」，有「打开登录页」、复制链接、取消。
    - 远程设备上多一个输入框：Codex 粘贴地址，Claude 粘贴代码。
    - 成功后关闭并在列表里高亮这个号；失败、超时留在框里显示原因和「重试」。
  - **移除**：确认框写明「Osuna 删掉自己存的这个号；CLI 不会被登出」。
- **状态**：
  - 列表：加载中（骨架行）、一个号都没有（说明 +「添加账号」）、只有一个号（说明「再加一个号才会轮换」）。
  - 每个号的额度：读取中、读不到（原因）。
  - 会失败的操作——开关、排序、立即使用、移除、设上限、加号——都有进行中、成功、失败三种状态，失败信息留在原处直到重试或关掉（`docs/testing.md`「Fallible user actions」）。
  - 只读设备：所有操作不可点，内容照常显示。
- **视口**：桌面端（Electron 与浏览器，宽 1280）、窄窗口（compact 布局，宽 390）。原生端不做实机验收。官方 Paseo 手机 App 不出现新界面。
- **截图可判断的验收**：
  - [ ] 宽 1280 下，Codex 提供方页能看到「账号」一节：「多号自动轮换」「只换登录」都是 Switch，有「固定登录到」与账号列表；每行有邮箱、套餐、状态标签和窗口用量条。
  - [ ] 第一个号用完、暂时换到第二个号时，截图里第一个号显示「有余量后回到第一」，第二个号显示「使用中」「暂时第一」，「最近换号」里有一条写明原因的记录。
  - [ ] 失效的号显示「需要重新登录」和「重新登录」按钮。
  - [ ] 第一次打开轮换时出现风险提示，标题、正文、两个条款链接、「我知道了，打开」「取消」都在；Claude Code 的提示是 Anthropic 的文字。
  - [ ] 设了上限的窗口，用量条上能看到上限位置。
  - [ ] Claude Code 开着「使用第三方接口」时，账号一节顶上有说明行。
  - [ ] 总开关关着时，账号一节显示说明行和去开关的按钮，开关不可点。
  - [ ] 宽 390 下，账号行、行菜单、加号对话框、风险提示都完整可见，主要按钮不被遮住。
  - [ ] 中文界面的新文字全是中文，用词与 `docs/glossary.md` 一致；英文界面没有露出翻译键名；模型名不是等宽字体。

## Testing Decisions

- **好测试的标准**：只测外部看得到的行为——CLI 的登录存储里写进了哪个号、扮演 Codex 的请求收到什么、上游收到什么、RPC 返回什么、界面显示什么——不测内部结构。确定性要求见 `docs/testing.md`。测试接缝由用户在访谈 Q26 确认。
- **接缝一（主）：daemon 端到端测试**。进程内启动真实 daemon，替换以下几样：
  - Codex 与 Claude 的登录存放处：适配器指向临时目录与假钥匙串；
  - OpenAI 登录与续期服务、ChatGPT 后端（`wham/usage`、`/responses`）：本机假服务；
  - Claude Code：一个只回答 `/usage` 与 `auth login` 的假程序；
  - 时钟：可拨快。
  
  要覆盖：
  - 第一层：98% 换走、上限换走、90% 换回、没有余量不动、固定不换、不换到没读过 / 失效的号、立即使用、移除在用的号；
  - Codex 的 `file` 与 `keyring` 两种存法，`ephemeral` 被拒；
  - 一个登录只有一个持有者：换号前后 token 只出现在一处；
  - 续期：到期前续、401 续、续期被拒标失效、并发续期不丢 token；
  - 第二层：
    - 429 在第一个字前交给下一个号；
    - 内容开始后不换；
    - 对话太长不换；
    - 有 credits 时再问一次；
    - 粘性；
    - 只换登录时不写 `openai_base_url`；
    - 与「使用第三方接口」同时开着时两边都工作；
    - 账本记下答话的号；
  - 加号：Codex 回调与粘贴、超时、重复的号；Claude 截下登录地址、粘贴代码；
  - 风险提示「看过了」按主机、按提供方记住；
  - 「读取 CLI 登录凭证」关掉时什么都不读、不写、不发；
  - 换号记录重启后还在。
  
  先例：daemon 端到端目录下测 Codex 登录方式、ChatGPT 后端经过中转站、套餐用量报告、中转站账本的几组测试。
- **接缝二：app 浏览器测试**。Playwright 加真实测试 daemon 与假数据，`CODEX_HOME` / `CLAUDE_CONFIG_DIR` 指向临时目录。覆盖上面每个会失败的操作的成功与失败、风险提示的确认与取消、只读设备、窄窗口。界面截图用无头 Chromium 加假数据拍，不在用户的 Osuna 里拍。先例：第三方接口设置页、子任务 8 的隐私设置那几组浏览器测试。
- **已有的纯逻辑套件**：中转站判错与换家、CLI 配置改写的套件按需加用例；不另建套件，不另加 npm 脚本或 CI 任务。
- **登录相关**：测试绝不读写真实的 `~/.codex`、`~/.claude`、钥匙串，不在本机运行真的 Codex / Claude Code，不连 OpenAI 或 Anthropic。用真实账号的验收由用户自己做。
- **本机只跑改到的测试文件**，全量交给 CI。

## Out of Scope

- 上面「差距明细逐行」里标「不做」的各行。
- 导入别的工具的账号（02·B15），包括用户以前手工准备的每号一个配置目录。
- 第二层的排序模式、路由组（块 8）。
- 每个号单独的开关、暂停在用的号、别名、每号代理、号只服务某些模型。
- 换号通知（系统通知、弹出提示）。
- 为 Codex 桌面应用临时改服务商。
- 用量页按号分组。
- Claude 订阅的请求经过内置中转站（Claude Code 没有第二层）。
- Codex、Claude Code 以外的 Agent 的多号轮换，以及订阅给别的 Agent 用。

## Further Notes

- **已知风险，只写进说明，不专门防**：换号后，还开着的旧 Codex 会话如果正好续了旧号的 token，新 token 写不回（Codex 发现存的是别的号就不写），旧号存着的那份作废，会显示「需要重新登录」。Codex 大约 8 天或 token 快过期时才续一次，所以不常见。
- **未核实的事**：
  - `claude -p /usage` 会不会占用额度（照 magpie 的参数关掉工具与 MCP）；
  - 存着的号长期不续会不会失效；
  - 改成非浏览器的 User-Agent 后 `wham/usage` 是否照常（本任务保持浏览器 UA，不涉及）。
- **顺序**：子任务 2（Codex 接法）、8（总开关与风险提示组件）都已合入 main，本任务直接在其上做。
- **magpie 会继续变**：开工时如果 magpie 的账号相关文件有新提交，按需对照。
