# 03 — 拒收重问：换格式地址、换认证头

**What to build:** 扩展现有「不思考的写法被拒，就换写法重问」的机制，让它能记住更多写法。规则：
- 按「接口 + 模型 + 写法」记在内存里，daemon 重启清零；
- 在开口前、换家判断前，在同一家重问一次；
- 每记住一种写法，写一行 info 日志。

本张加两种写法：
1. 这家某个格式的地址说「这里没有这个模型」：记住这家这个模型在这个格式不行，改用这家的下一个格式地址再问（按现有格式顺序，需要时翻译）。所有格式都说没有时，按现有规则只冷却这家的这个模型，然后换家。
2. 第三方 Anthropic 地址回 401，说「两种认证头不能同时带」：只带一种再问（先换哪一种照 magpie），并记住。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** done

- [ ] 端到端：一家有 Anthropic 和 Chat 两个地址，Anthropic 地址回「这个模型不存在」。同一请求接着翻译成 Chat 格式，发到这家的 Chat 地址并成功；第二次请求直接走 Chat 地址；这家不冷却。
- [ ] 所有格式都说没有时，只冷却这家的这个模型，换到下一家。
- [ ] 端到端：上游第一次因同时带了两个认证头回 401，中转站只带一个头重问并成功；下一次请求只带那一个头；这家不被标「需要检查」。
- [ ] daemon 重启后，记住的写法清零。
- [ ] 每记住一种写法，daemon 日志多一行 info，写明接口名、模型、写法。
