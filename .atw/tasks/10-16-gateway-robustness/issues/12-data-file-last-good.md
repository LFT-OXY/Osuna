# 12 — 数据文件写坏用上一份好的

**What to build:** 接口清单、key、中转站口令这三份 JSON 状态文件：

- 写入前，把上一份好的存成 `.bak`。
- 读到坏文件时，改读 `.bak` 继续服务；坏的那份另存为 `.bad-<时间>`，并写一行警告日志。
- `.bak` 也坏时，照现状报错，不写也不删。

不改的：CLI 配置的接管记录、CLI 自己的配置文件，都仍是「解析不了就不写」。

其他：
- 只有 daemon 写这些文件，不加跨进程锁。
- Windows 上读文件、改名时遇到文件被占用，重试，最多 0.5 秒。用可替换的文件系统适配器来测。
- `docs/data-model.md` 写明 `.bak` 和 `.bad-<时间>` 的规则。

**Blocked by:** None
**Status:** ready-for-agent
**Impl:** ready

- [ ] key 文件、口令文件，同样各有一例。
