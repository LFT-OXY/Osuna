# 对照 magpie 的全部功能补齐 Osuna 的缺口（总任务）

来源：用户 2026-10-16 提出。第三方接口功能上一轮照 magpie（MIT，Go）做了第一版（任务 `10-13-api-endpoint-auto-switch`，已归档）。这次对照 magpie 的**全部**功能找缺口，由用户挑选，再拆成能各自上线的子任务。对照基准：magpie HEAD `7597c132`、Osuna HEAD `21a4f721d`（均为 2026-10-16）。

这是**总任务**：它持有原始需求、子任务清单、跨子任务的规矩与验收，以及最后的集成检查；本身不写代码，不运行 `task.py start`。discover 的产物都在 `research/`：

- `gap-summary.md`：约 690 行明细归成的 25 个功能块，每块的 Osuna 现状、上次的态度、碰到的规矩。
- `gap-01`～`gap-04`：分领域的逐行明细。本文用 `文件号·行编号` 引用，如 `01·A04` 指 `gap-01` 的 A04 行。
- `decisions.md`：9 轮访谈的全部决定（Q1–Q29）与依据。
- `subscription-ban-risk.md`：各家订阅条款与封号风险，附原文出处。

## Problem Statement

用户靠多家第三方中转服务（new-api、sub2api 一类，下称「中转服务」）在 Claude Code、Codex 里干活，由 Osuna 的内置中转站（**Gateway**）在它们之间自动切换（**Failover**）。上一轮只搬了 magpie 中转站的核心：主机共用的第三方接口（**API endpoint**）、三种请求格式互译、判错与冷却、同名模型自动切换、粘性。用起来还有这些缺口：

1. 内置中转站在一些情况下不稳：模型名只差写法（`claude-opus-4.6` 与 `claude-opus-4-6`）就不算同一个模型，不会切换；上游回到一半断开被当成正常结束；空回复、复用连接被掐、慢模型久等，都直接报错给 CLI。
2. 打开、关掉「使用第三方接口」（**Use API endpoints**）前后开的 Codex 对话互相看不见，关掉后经中转站开的对话续不上。Claude Code 走第三方接口时一律不能联网搜索，哪怕那家中转服务自己会搜。
3. 添加和管理接口费事：不能粘贴 curl，没有模板，不能复制一家，不能排顺序，模型的上下文与档位改不了。
4. 不知道每家中转服务还剩多少钱，套餐 key 还剩多少额度。
5. 用量页（**Usage**）只读 CLI 自己的会话记录，分不出哪些用量走了哪家接口、各家花了多少。中转站切换过几次、哪家慢、哪家常失败，只写在 daemon 日志里；冷却状态只在内存里，重启就没了。
6. Pi、Oh My Pi（下称 OMP）用不上第三方接口。
7. 中转服务的 Gemini 模型用不了：内置中转站不会说 Gemini 格式。
8. Osuna 为显示套餐用量（**Plan usage**）会读 CLI 的登录凭证，没有地方关掉；Antigravity 有封号风险，界面上没有提示。
9. 有多个 ChatGPT 或 Claude 订阅号的用户，一个号用完只能手动换。每个号一个配置目录的手工办法会让会话和配置（技能、MCP、指令文件）分家。

另外，magpie 在上次调研之后又有 647 个提交，完整对照见 `research/`。

## Solution

拆成 9 个能各自验收上线的子任务，按顺序做（见「Child Tasks」）。全部做完以后，用户看到的是：

- 中转站更稳：写法不同的同一模型会自动切换，断流、空回复、慢回复不再直接报错。
- 开关「使用第三方接口」前后的 Codex 对话都看得见、续得上；自己会联网搜索的接口可以对 Claude Code 放开搜索。
- 接口更好加、更好管：粘贴 curl、模板、复制一家、排顺序、手改模型信息、逐个测模型。
- 接口页显示每家的余额和套餐 key 的额度窗口。
- 用量页把官方账号和每家第三方接口分开，经过中转站的调用不算两遍。可以给每家设价格倍率，显示人民币和「万 / 亿」，看每家的出字速度和首字等待；逐条请求列表可导出 CSV。接口页的切换、失败、冷却记录重启不丢。
- Pi、OMP 也能用第三方接口。
- 接口可以填 Gemini 格式的地址，Claude Code、Codex、Pi、OMP 都能用中转服务的 Gemini 模型。
- 一个总开关让 Osuna 完全不读 CLI 登录凭证；Antigravity 的设置页有风险提示。
- Codex、Claude Code 可以在多个订阅号之间自动轮换，第一次打开时提示封号风险。

与第三方接口无关的块 17–25 这批不做，做完后再挑。

## User Stories

### 子任务 1：中转站稳健性补齐

1. 作为用第三方接口的用户，我希望内置中转站把只差写法的模型名（如 `claude-opus-4.6` 与 `claude-opus-4-6`）当成同一个模型，以便一家用完时能切换到写法不同的另一家。
2. 作为用户，我希望上游回到一半断开时 CLI 收到明确的错误，以便不把半截回答当成完整结果。
3. 作为用户，我希望上游回了空回复时中转站自动再问一次，以便不用手动重发。
4. 作为用户，我希望中转站在等上游时给 CLI 发保活，以便慢模型思考很久时 CLI 不因超时断开。
5. 作为用户，我希望复用的连接被上游掐断时中转站自动重发，以便偶发的网络问题不打断对话。
6. 作为用户，我希望 402 只有在上游说的是用量上限时才算额度用完，以便别的 402 不让一家接口被误判、冷却很久。
7. 作为用户，我希望中转站认得更多种「什么时候恢复」的写法，以便冷却结束的时间准确。
8. 作为用户，我希望失败按模型计数，以便一家接口的某个模型坏了不连累它的其他模型。
9. 作为用户，我希望中转站跳过上下文装不下这次请求的候选，以便不白白浪费一次失败。
10. 作为 Codex 用户，我希望 `prompt_cache_key` 这类字段原样转给上游，以便上游的提示缓存能命中。
11. 作为用户，我希望中转站按模型真实的推理档位和回复上限填参数，以便请求不被上游拒绝。
12. 作为用 Claude Code 连非 Claude 模型的用户，我希望中转站去掉只有 Anthropic 认得的计费行与审查字段，以便别家不报错。
13. 作为用户，我希望 zstd 或 gzip 压缩过的请求体也能被中转站读懂，以便 CLI 打开压缩时照常工作。
14. 作为用户，我希望中转站的状态文件写坏时自动用上一份好的，以便一次写坏不丢掉全部状态。
15. 作为用户，我希望刚写进某家缓存的对话也算粘在这家，以便下一轮还去这家、缓存不白写。

### 子任务 2：Claude Code / Codex 接入细节与联网搜索放行

以下 17–26 是候选，具体条目进子任务再挑；27 已定要做。

16. 作为 Codex 用户，我希望打开或关掉「使用第三方接口」后，之前开的 Codex 对话都还看得见、续得上，以便来回切换不丢对话。
17. 作为 Claude Code 用户，我希望 Osuna 读得懂带 BOM 或注释的 `settings.json`，以便我手写的设置文件不被当成解析不了。
18. 作为用 claude.ai 登录的 Claude Code 用户，我希望走第三方接口时保留我的登录，以便切回官方时不用重新登录。
19. 作为 Claude Code 用户，我希望给 Subagent 和后台小模型指定第三方接口的模型，以便它们不去请求官方。
20. 作为用户，我希望给新会话设推理强度，以便不用每开一个会话再调。
21. 作为用户，我希望云厂商开关或 managed-settings 让请求绕过中转站时看到提示，以便知道为什么请求没走第三方接口。
22. 作为用户，我希望带点的版本号模型名被改写成上游认得的写法，以便不报模型不存在。
23. 作为用户，我希望 CLI 配置被 Osuna 以外的程序改过时，界面上有提示并能处理，以便不被悄悄覆盖。
24. 作为用户，我希望关掉「使用第三方接口」之前先看到会改回什么，以便放心操作。
25. 作为用户，我希望改完设置后被告知哪些会话要重开才生效，以便知道下一步做什么。
26. 作为 Codex 用户，我希望关掉开关后经中转站开的旧对话仍能续上，以便历史对话不作废。
27. 作为用户，我希望给每家接口打开「这家自己会联网搜索」，以便 Claude Code 用这家时能联网搜索，用别家时仍不发出会被拒绝的搜索。

### 子任务 3：接口管理好用性

以下都是候选，具体条目进子任务再挑。

28. 作为用户，我希望复制一家接口再改 key 或地址，以便同一家中转服务的多把 key 各成一家接口、各自切换。
29. 作为用户，我希望粘贴一条 curl 命令就自动填好接口表单，以便不用逐项抄地址和 key。
30. 作为用户，我希望从服务商模板里选一家来添加接口，并能用同一模板再加一家，以便常见服务商的地址和格式不用自己查。
31. 作为用户，我希望调整接口的先后顺序，以便决定自动切换时先换到哪家。
32. 作为用户，我希望接口多的时候能搜索，以便快速找到某一家。
33. 作为用户，我希望给接口加自定义请求头和附加请求体字段、选 key 放在哪个请求头，以便接入要求特殊的中转服务。
34. 作为用户，我希望给某家接口单独设网络代理，以便只有这家走代理。
35. 作为用户，我希望保存前先拉到模型清单、合并各格式的清单，并定时刷新，以便模型清单总是最新。
36. 作为用户，我希望手改模型的显示名、上下文与回复上限、推理档位、能否看图、发给上游的名字，以便中转服务的清单不准时也能用对。
37. 作为用户，我希望逐个测试模型能不能用，并按「免费」「能用」筛选，以便只挑能用的模型。
38. 作为本机模型服务（如 Ollama）的用户，我希望不填 key 也能保存接口，以便接本机服务。
39. 作为用户，我希望接口出问题时看到厂商状态页的链接，以便判断是不是对方故障。
40. 作为用户，我希望在接口行上看到哪些提供方（**Provider**）会用到它的模型，以便知道改它会影响谁。
41. 作为自建中转服务的用户，我希望能对某家跳过证书校验，并在打开前看到明确的安全说明，以便只在我信任的服务上用。

### 子任务 4：余额与套餐额度显示

42. 作为用 DeepSeek、Kimi、OpenRouter、硅基流动、阶跃等服务的用户，我希望接口页直接显示余额，以便知道什么时候该充值。
43. 作为用 new-api / one-api 中转服务的用户，我希望看到这把 key 还剩多少，以便知道它什么时候用完。
44. 作为 new-api 用户，我希望另填系统访问令牌和用户 ID 后看到整个账户的余额，以便知道账户里还剩多少钱。
45. 作为 sub2api 用户，我希望看到这把 key 的剩余额度，填了登录令牌后还能看到账户余额。
46. 作为用 OpenAI 旧式额度的用户，我希望看到剩余的 credit grants。
47. 作为用别的中转服务的用户，我希望自己填查余额的地址和取值表达式，以便任何能查余额的服务都能显示。
48. 作为用套餐 key（Kimi Code、GLM Coding Plan、MiniMax 等）的用户，我希望看到 key 的额度窗口还剩多少、什么时候重置，以便安排用量。
49. 作为用户，我希望余额查不到时看到原因（地址不对、令牌被拒、服务不支持），以便知道怎么修。
50. 作为在意 key 去向的用户，我希望知道 Osuna 什么时候、带着什么去查余额，并能关掉自动查询，以便控制我的 key 发到哪里。

### 子任务 5：中转站记账与用量页融合

51. 作为用户，我希望用量页把官方账号的用量和每家第三方接口的用量分开，以便知道钱花在哪家。
52. 作为用户，我希望经过内置中转站的调用不被算两遍，以便总数可信。
53. 作为在终端里直接跑 CLI 的用户，我希望这些经过中转站的调用也记进账，以便不在 Osuna 里开的会话也算进去。
54. 作为用户，我希望给每家接口设价格倍率，以便估算成本（**Estimated cost**）贴近这家实际收的价钱。
55. 作为给某个模型设过自定义价格（**Custom price**）的用户，我希望自定义价格优先于倍率，以便我的精确价格不被覆盖。
56. 作为中文用户，我希望估算成本能显示成人民币，大数用「万 / 亿」，以便一眼看懂。
57. 作为用户，我希望汇率取不到时继续按上次的汇率换算，并能看到汇率是哪天的，以便断网时也能用。
58. 作为用户，我希望看到每家接口的出字速度和首字等待，以便挑快的那家。
59. 作为用户，我希望看逐条请求列表（走了哪家、换了几次、失败原因、用了多久、多少 token），以便查哪家中转服务出了问题。
60. 作为用户，我希望把请求列表导出成 CSV，以便自己做表格分析或对账。
61. 作为用户，我希望接口页显示这家最近的切换、失败和冷却记录，重启 Osuna 后也还在，以便事后排查。
62. 作为在意隐私的用户，我希望账本不存任何对话内容，以便不用担心账本泄露对话。

### 子任务 6：Pi / OMP 用上第三方接口

63. 作为 Pi 用户，我希望打开「使用第三方接口」后用上第三方接口的模型，以便 Pi 也能在多家中转服务之间自动切换。
64. 作为 OMP 用户，我希望同样能用第三方接口，以便和 Pi 一样。
65. 作为 Pi / OMP 用户，我希望 Osuna 按模型选对请求格式（默认 OpenAI Chat，个别模型走 Responses 或 Anthropic），以便不用自己配。
66. 作为 Pi / OMP 用户，我希望给它们选默认模型（**Default model**），以便新会话直接用上。
67. 作为 Pi / OMP 用户，我希望关掉开关后它们的配置回到原样，以便回到它们自己的设置。
68. 作为在终端里直接跑 Pi / OMP 的用户，我希望它们也走第三方接口，以便和在 Osuna 里一样。
69. 作为用户，我希望 Pi / OMP 经过中转站的调用也记进账、不算两遍，以便用量页数字一致。

### 子任务 7：Gemini 上游格式

70. 作为用中转服务 Gemini 模型的用户，我希望给接口填 Gemini 格式的地址，以便 Claude Code、Codex、Pi、OMP 都能用这家的 Gemini 模型。
71. 作为用户，我希望 Gemini 模型的思考、工具调用和图片在翻译后照常工作，以便它和别的模型一样好用。
72. 作为用户，我希望 Gemini 格式的接口失败时也会自动切换和冷却，以便和别的格式一样稳。
73. 作为用户，我希望测试连接、自动识别格式、拉模型清单都支持 Gemini 格式的地址，以便添加它和添加别的接口一样简单。

### 子任务 8：登录凭证开关与风险提示

74. 作为在意隐私的用户，我希望有一个总开关让 Osuna 不读任何 CLI 登录凭证，以便确定 Osuna 不碰我的登录。

## Implementation Decisions

1. **重写与许可**：所有改动在 daemon 里用 TypeScript 写，不托管 magpie。借鉴 magpie 设计的文件顶上保留 MIT 声明，全文收进根目录 `THIRD_PARTY_NOTICES`（ADR 0007）。
2. **中转站只服务本机**：新入口（OpenAI Chat）与现有入口同样只收本机回环、凭每个提供方的中转站口令（ADR 0007）。
3. **子任务 1 的两类待问项**：「被拒后改写法重发」和「按厂商专属改写」与 ADR 0007 的两条规则冲突（被拒的请求不改写后重发给同一家；翻译不含厂商专属改写，只有几处例外）。用户同意做哪一类，子任务 1 就写新 ADR 改哪一条。
4. **中转站账本（子任务 5）**：内置中转站给每次经过的请求记一条账（哪家接口、哪个模型、token、耗时、首字等待、切换与失败），不存对话内容。用量服务把账本当作新的用量来源；同一次调用如果在 CLI 会话记录里也有，按 id 对上后只算账本那条：Claude Code 用回复的 `message.id`，Codex 用 `token_usage_record` 的 `response_id`，Pi / OMP 用会话记录里的 provider。这推翻了 ADR 0007 否决的「Record the gateway's own usage」，子任务 5 写新 ADR。存储遵守 `docs/data-model.md`，追加式账本怎么落盘在子任务 5 定。
5. **估算成本（子任务 5）**：公开价 × 接口的价格倍率；自定义价格优先于倍率。人民币由 daemon 每天取一次汇率换算，取不到用上次的。结果仍是估算，不是中转服务实际扣的钱。
6. **余额（子任务 4）**：daemon 带着接口的 key 或用户另填的令牌去查，只显示，不参与选路。查法照 magpie：已知厂商按地址自动认；new-api / one-api 与 sub2api 分 key 级和账户级；OpenAI 的 credit_grants；自定义地址加取值表达式；套餐 key 的额度窗口。中转服务要不要由 Osuna 自动试探余额地址（magpie 不试探），在子任务 4 定。
7. **对外请求（子任务 4、5、9）**：`docs/usage.md` 的「Outbound requests」写着 daemon 主动只发两个不带认证的公开 GET。新增的每一类请求（带 key 查余额、取汇率、查各号额度）都要写进这一节：发给谁、带什么、什么时候发、怎么关。
8. **CLI 配置改写（子任务 2、6、9）**：ADR 0004 的文件改写规则（只动自有键、记录并恢复原值、原子替换、解析不了就不写、写前重读、外部改动检测）适用于每个新写的键和每个新管的文件，包括 Pi / OMP 的配置和子任务 9 改写的登录信息。
9. **Codex 的接法（子任务 2 → 9）**：子任务 2 定 Codex 怎么经过内置中转站。magpie 的做法是：Codex 用 ChatGPT 登录时只写 `openai_base_url`，保留 Codex 自带的 OpenAI 服务商和登录，对话仍记在 OpenAI 名下，第三方模型和 ChatGPT 自带模型同时出现在 Codex 的 `/model` 里；没有登录或用 API key 登录时，才用独立的服务商表。这可能也能解决「开关前后对话互相看不见」，但只对 ChatGPT 登录有效，未核实。子任务 9 的第二层建在子任务 2 定下的接法上。
10. **联网搜索放行（子任务 2）**：按接口的「这家自己会联网搜索」决定要不要对 Claude Code 放开 WebSearch；放开后，搜索请求原样交给这家。代搜不做。ADR 0004 的 WebSearch deny 规则随之修改，子任务 2 写新 ADR 或更新 ADR 0004。能不能做到只对这家生效，在子任务 2 核实。
11. **请求格式（子任务 7）**：请求格式（**Request format**）新增 Gemini，一家接口最多四个地址。只做上游：中转站不新增 Gemini 入口。
12. **Pi / OMP（子任务 6）**：中转站新增 OpenAI Chat 入口。Pi、OMP 的「使用第三方接口」和默认模型跟 Claude Code、Codex 用同一套设置；Osuna 写进 Pi / OMP 配置的服务商默认用 Chat 格式，个别模型改走 Responses 或 Anthropic（照 magpie）。
13. **登录凭证总开关（子任务 8 → 9）**：主机级开关，照 magpie 的账号发现开关：关掉读取后，所有读 CLI 登录的功能（套餐用量来源、多号自动轮换）都停。开关的名字和方向在子任务 8 定。
14. **多号自动轮换（子任务 9）**：
    - Codex 两层。第一层换登录：定时看当前号的额度，快用完或到了用户给这个号设的上限，就让 Codex 换登到下一个还有余量的号；原来的号回落后换回。第二层经过内置中转站换号：当前号接不了的请求，在回复第一个字之前交给别的号；可以关成只换登录。
    - Claude Code 只做第一层，Claude 订阅的请求不经过内置中转站。
    - 换登录只对新会话生效；开着的 Codex 对话靠第二层。
    - 加号由真的 Codex、Claude Code 完成登录，Osuna 收下结果；不像 magpie 那样借 Codex CLI 的登录客户端自己登录。从别的工具的文件导入账号要不要做，在子任务 9 定。
    - 子任务 9 里定：具体数字（magpie 是每 5 分钟看一次、用到 98% 换走、所有窗口回到 90% 以下换回）、号的顺序与每号上限、怎么读 Claude 号的额度（magpie 只靠 Claude Code 自己的 `/usage`）、登录过期后怎么续（尽量让 CLI 自己续）、与「使用第三方接口」怎么同时存在。
    - 这推翻 ADR 0004 的「`~/.codex/auth.json` is never read or written」和上一轮「不读写 CLI 登录文件」的约定，子任务 9 写新 ADR。
    - 风险提示：为 Codex、Claude Code 各自第一次打开时各提示一次，写明条款原文链接和可能的后果；不逐号确认，账号列表上不常驻风险标记。
15. **身份如实（全部子任务）**：Osuna 自己发出的请求（查余额、查额度、取汇率等）用 Osuna 自己的身份；不冒充别的产品（伪造 client ID、User-Agent、originator 等），不为躲避厂商识别改写请求。CLI 自己发出、经过内置中转站的请求保持 CLI 自己的样子，只换模型名与认证。登录续期如果必须由 Osuna 代办，在子任务 9 单独决定，写进它的 ADR。
16. **协议（全部子任务）**：遵守 `docs/protocol-compatibility.md`。新字段可选；新 RPC 用带点命名空间加 `.request` / `.response`；新功能挂在 `server_info.features.*` 上。旧客户端（含官方 Paseo 手机 App）看不到新功能，但照常工作；ADR 0007 给旧客户端的「单个启用接口」投影保持不变。
17. **术语（全部子任务）**：新的界面名词定名后写进 `docs/glossary.md`（界面文字为准，每个概念一个中文名）。被改到的旧词条随子任务更新，例如 Request format（多了 Gemini）、Failover（不再只写日志）、Endpoint status（记录重启不丢）、Usage（不再只读会话记录）、Estimated cost（加倍率与人民币）、Plan usage（与接口余额区分）。

## UI and Design

- **方向**：沿用现有的第三方接口页、提供方设置页、用量页、价格表，不另做视觉风格。遵守 `docs/design.md`、`docs/forms.md`、`docs/hover.md`、`docs/unistyles.md`、`docs/menus.md`、`docs/i18n.md`，以及 `.atw/spec/app/frontend/` 的组件与样式规范（这个项目没有单独的 `design-system.md`，设计系统在 `docs/design.md`）。
- **用户定过的偏好**：开 / 关类选择一律用 Switch，不用复选框；模型名不用等宽字体；次要操作不用蓝色链接。
- **涉及的界面**（每个子任务在自己的 UI 节里细化）：
  - 接口列表与接口页：子任务 2 的联网搜索开关；3 的大部分；4 的余额与额度窗口；5 的记录与价格倍率；7 的 Gemini 地址。
  - Claude Code、Codex、Pi、OMP 的提供方设置页：子任务 2、6、9。
  - 用量页：子任务 5。
  - 主机设置与 Antigravity 提供方页：子任务 8。
  - 账号列表与风险提示框：子任务 9。
- **状态**：每个会失败的操作都有进行中、成功、失败三种状态，失败信息留在原处，直到用户重试或关掉（`docs/testing.md`「Fallible user actions」）；列表有空状态和加载状态。
- **视口**：桌面端（Electron 与浏览器，宽 1280）和窄窗口（compact 布局，宽 390）。原生端不做实机验收；官方 Paseo 手机 App 不出现新界面。
- **跨子任务的界面验收**（看截图就能判断）：
  - 中文界面的新文字全是中文，用词与 `docs/glossary.md` 一致。
  - 新增的开关都是 Switch；模型名不是等宽字体。
  - 英文界面没有露出的翻译键名。
  - 窄窗口（宽 390）下，每个新页面的主要操作不被遮住。

## Testing Decisions

- **好测试的标准**：只测外部看得到的行为，即 CLI 收到什么、上游收到什么、RPC 返回什么、界面显示什么；不测内部结构。确定性要求见 `docs/testing.md`。
- **接缝一（主）：daemon 端到端测试**。进程内启动真实 daemon，本机起假上游（HTTP 服务），用 fetch 扮演 CLI，带上中转站口令打中转站入口。适用：子任务 1；子任务 2 的中转站部分；子任务 4（假的余额接口）；子任务 5（请求经过中转站后读用量 RPC）；子任务 6（Chat 入口）；子任务 7（假的 Gemini 上游）；子任务 9 的第二层（假的 ChatGPT 后端）。先例：daemon 端到端目录下的中转站、Claude 配置、Codex 配置几组测试。
- **接缝二：app 浏览器测试**。Playwright 加真实 daemon 加本机假中转服务，`CLAUDE_CONFIG_DIR` / `CODEX_HOME` 指向临时目录。适用所有改界面的子任务，每个会失败的操作都测成功和失败两种情况。先例：第三方接口设置页、用量页那几组浏览器测试，以及它们共用的假中转服务夹具。
- **已有的纯逻辑套件**（翻译、判错、CLI 配置改写、用量解析与对账）继续往里加用例，不另建套件，也不另加 npm 脚本或 CI 任务。
- **登录相关（子任务 8、9）**：
  - 测试绝不读写真实的 `~/.claude`、`~/.codex`、钥匙串，不在本机运行真的 Claude Code。
  - 读写登录的部分做成可替换的适配器，测试用临时目录里的假凭证；Codex 只在临时 `CODEX_HOME` 里跑。
  - 用真实账号的验收由用户自己做。
  - 做会改写 CLI 配置的界面验收前，先向用户说明怎么隔离，取得同意再做。
- **不连真实中转服务或厂商**：所有上游都是本机假服务。
- **本机只跑改到的测试文件**，全量交给 CI。
