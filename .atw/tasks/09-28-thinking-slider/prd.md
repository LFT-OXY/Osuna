# 思考等级改为带动效的滑条

## Problem Statement

现在调整思考等级，要在 Composer 工具栏点开一个纯文字列表，再从 Low、Medium、High 这类选项里挑一个。思考等级本来就是有先后的，列表却把各档平铺成互不相关的条目：看不出当前在整个区间的哪个位置，也感受不到「更高」意味着什么。选择过程和 Composer 其他部分的视觉语言脱节，而且手机端和桌面端的体验一样平淡。

## Solution

点开思考触发器后，浮层不再是列表，而是一条滑条，上方居中显示当前档位名，字号放大，颜色和滑条填充色一致。滑条的档数等于当前模型的思考选项数，拖动或点击轨道都可以选档，松手才生效。轨道是一条较粗的圆角胶囊，白色圆形滑块比轨道更高、带阴影。已填充部分是一段渐变：从当前提供方品牌色的浅色版过渡到品牌色本身，没有品牌色的提供方（如 Pi、Copilot）用蓝紫兜底。填充区里有光点从左往右源源不断地流过，边走边闪；档位越高，光点越密、流得越快；系统开启「减少动态效果」时不显示光点。只要有 2 个及以上思考选项，一律用滑条，不再有列表和搜索框；只有 1 个选项的模型在工具栏上显示灰色、不可点的思考触发器。桌面/Web 和手机端都这样改。

## User Stories

1. 作为桌面用户，我想点开工具栏上的思考触发器后看到一条滑条，以便直观看出当前思考等级在整个区间里的位置。
2. 作为桌面用户，我想让工具栏上的思考触发器外观保持不变（图标、当前档位名、下拉箭头），以便工具栏布局和以前一样。
3. 作为用户，我想让滑条上方只显示当前档位名，居中、放大、颜色与填充色一致，以便一眼看清当前档位，浮层也不被说明文字干扰。
4. 作为用户，我想让滑条的档数和当前模型的思考选项数一致，以便每一档都对应一个真实可选的等级。
5. 作为用户，我想让滑条的档位按模型给出的顺序从左到右排列，以便越往右思考越深。
6. 作为用户，我想拖动滑块时，滑块吸附到最近的档位，并实时更新上方的档位名，以便松手前就知道会选中哪一档。
7. 作为用户，我想让选择在松手时才生效，以便拖动途中经过的档位不会一次次改掉 Agent 的设置。
8. 作为用户，我想直接点击轨道上的某个位置就能选中最近的一档，以便不用拖动也能快速切换。
9. 作为用户，我想在滑块未占据的每一档位置看到一个小圆点，以便知道还有几档可选。
10. 作为用户，我想让已填充部分用当前提供方的品牌色渐变，以便滑条和工具栏上的提供方图标颜色呼应。
11. 作为 Pi、Copilot 或其他没有品牌色的提供方的用户，我想看到蓝紫兜底渐变，以便滑条在任何提供方下都好看、清晰。
12. 作为用户，我想看到光点在填充区里从左往右持续流动、边走边闪，以便感受到「思考」在进行。
13. 作为用户，我想让档位越高、光点越密、流得越快，以便从动效上就能感受到思考强度的差别；最低档也能看到少量光点在流动。
14. 作为开启了系统「减少动态效果」的用户，我想让光点不出现、滑块移动不带动画，以便界面不给我带来不适。
15. 作为运行中途切换了系统「减少动态效果」的用户，我想让滑条立即按新设置表现，以便不用重开应用。
16. 作为键盘用户，我想用左右方向键逐档调整，并让每次调整立即生效，以便不用鼠标也能选择思考等级。
17. 作为键盘用户，我想用 Escape 关闭浮层且不改变当前选择，以便可以随时放弃。
18. 作为读屏用户，我想让滑条以「可调节」控件的身份朗读当前档位名，并能用增减操作切换，以便在看不到滑条的情况下也能使用。
19. 作为手机端用户，我想在 Agent controls sheet 里点「思考」行后进入滑条页面，以便在手机上也用同样的方式选择思考等级。
20. 作为手机端用户，我想用手指拖动滑块或点击轨道选档，且手势不会和 sheet 的下滑关闭冲突，以便操作顺手。
21. 作为使用思考选项较多的模型（如 Pi 的 7 档）的用户，我想同样看到滑条而不是带搜索框的列表，以便所有模型的体验一致。
22. 作为使用只有 1 个思考选项的模型的用户，我想在工具栏上看到这唯一的思考等级，但它是灰色、不可点的，以便知道当前等级又不会误以为可以切换。
23. 作为切换了模型的用户，我想让滑条的档数和当前档位跟着新模型更新，以便看到的始终是当前模型可选的等级。
24. 作为用户，我想在思考控件被禁用（比如当前状态不允许修改）时看到禁用态、无法拖动，以便不会误以为操作生效。
25. 作为亮色和暗色主题的用户，我想让渐变、光点、滑块和未填充的轨道在两种主题下都清晰可辨，以便滑条在任何主题下都能用。
26. 作为已有草稿偏好的用户，我想让滑条选择的思考等级和以前一样按模型记住，以便重开或切回模型时恢复我的选择。
27. 作为用户，我想让滑块是比轨道更高的白色圆形并带阴影、轨道是较粗的圆角胶囊，以便滑条看起来精致、好拖。

## Implementation Decisions

- **触发器不变，只换浮层内容**：桌面端的思考触发器和它打开的锚定浮层保留，浮层内容从列表换成滑条面板。手机端 sheet 里「思考」行打开的推入页，内容也换成同一个滑条面板。选中后走现有的思考选项设置回调，不新增状态，也不改草稿偏好的存储方式。
- **何时用滑条**：当前模型有 2 个及以上思考选项时一律用滑条，没有上限；Composer 思考控件不再有列表和搜索框。只有 1 个选项时，桌面工具栏和手机 sheet 都显示思考触发器，展示该档位名，呈禁用态（灰、不可点、不打开浮层）；草稿和运行中的 Agent 一致（运行中的 Agent 目前只在多于 1 档时才显示，要改成 1 档也显示）。没有思考选项时仍不显示。
- **滑条面板模块**：新增一个跨平台的滑条面板组件，输入为选项列表、当前选中 id、提供方、是否禁用、选中回调；只显示档位名和滑条。组件放在 Agent controls 模块内，不作为通用 UI 原语对外暴露。
- **视觉（第二版，参考 `research/refs/v2-target.png`；第一版 `v1-rejected.png` 被否）**：
  - 档位名水平居中，字号放大到标题级，颜色取填充渐变的终点色（有品牌色为品牌色，否则为兜底终点色）。
  - 轨道是较粗的圆角胶囊（比第一版的 24px 明显更高），未填充部分用中性浅灰，未被占据的档位有小圆点。
  - 滑块是白色圆形，直径大于轨道高度、上下溢出轨道，带柔和阴影，亮色主题下另有细描边以免和浅色背景糊在一起；滑块中心落在各档位点上。
  - 填充从轨道左端到滑块中心附近，保留「品牌色浅色版 → 品牌色」渐变。
  - 浮层加宽，给更粗的滑条留出空间。
- **纯逻辑单独成模块**：以下计算做成无 React 依赖的纯函数，组件只负责渲染和手势：
  - 按选项数算出各档在轨道上的位置
  - 把拖动或点击位置吸附到最近的档
  - 由档位序号算出光点强度，按线性区间归一化
  - 由提供方算出渐变两端色（品牌色的浅色版 → 品牌色；无品牌色时用兜底色）
- **渐变色**：品牌色取自现有的提供方品牌色表，浅色版用现有的颜色混合工具由品牌色派生。蓝紫兜底色按设计系统的规定作为主题 token 加入，不在组件里硬编码 hex。品牌色表由任务 `09-28-provider-model-split` 补齐；本任务开工时表里没有的提供方会自动走兜底，不阻塞。
- **动画与手势**：拖动和吸附用 reanimated 与 react-native-gesture-handler 实现，渐变用 react-native-svg 的线性渐变，不新增依赖。
- **光点动效（第二版）**：光点从填充区左侧不同高度出发，持续向右移动，到填充区右端（滑块处）淡出，再从左侧重新出发，形成连续的流；移动途中大小和亮度有闪烁变化。位置按填充区宽度计算，不再按整条轨道分布后裁剪，所以最低档也能看到少量光点。档位越高，同时在流动的光点越多、速度越快。第一版原地小幅漂移的做法作废。
- **减少动态效果**：复用现有的「减少动态效果」hook，它能订阅运行中的变化。开启时不渲染光点，滑块移动不带动画；渐变照常显示。
- **生效时机**：指针拖动在松手时生效；点击轨道在点击时生效；键盘和读屏的增减操作每一步立即生效。拖动途中上方的档位名实时显示吸附后的档。选中后浮层保持打开，Escape 或点外面关闭。
- **待回写的显示**：运行中的 Agent 要等 daemon 回写才换选中；这期间滑条显示刚提交的档（组件内的显示状态，不进 store、不持久化）。父级换了选中就作废；回写前退回原档时清掉待定并照常提交。
- **无障碍**：滑条暴露为 adjustable 或 slider 角色，值文本为当前档位名，支持 increment 和 decrement 操作；Escape 关闭浮层，不改变选择。
- **协议和 daemon 不变**。
- **模块落点**：纯函数在 `composer/agent-controls/thinking.ts`，滑条在 `thinking-slider.tsx`，浮层外壳在 `thinking-picker.tsx`（`surface: "toolbar" | "sheet"`，桌面浮层和手机推入页共用），Web 方向键在 `thinking-slider-keyboard.web.ts`。兜底 token 为 `thinkingGradientFrom` / `thinkingGradientTo`，亮色 `blue[500]→purple[600]`，暗色 `blue[400]→purple[500]`；滑块描边 token 为 `thinkingThumbBorder`（亮色 `border`，暗色透明）。轨道 22px、滑块 28px、档位名 `body` 半粗、浮层 220 宽（验收时嫌第二版的 32/40、`title-lg`、320 宽太大，前后收小两轮；浮层仍左对齐触发器）；第一档离轨道左端一个轨道高度，最低档滑块左侧总有一小段填充供光点流动。手势是 `Gesture.Race(Pan, Tap)`：Pan 移动 1px 即激活，只预览；Tap 抬起时提交。

## Testing Decisions

- **好的测试只验证外部行为**：给定选项与交互，用户看到哪一档、回调收到哪个 id、什么时候触发、光点是否出现。不测试动画帧、样式数值和组件内部状态。
- **接缝 1（纯函数单元测试，Node）**
  - 覆盖：档位位置计算、位置吸附（含两端和中点）、光点强度随档位单调递增、渐变两端色（有品牌色时为浅色版到品牌色；无品牌色时为兜底色）、滑条与禁用单档的切换（0、1、2、7、12 个选项）、光点流动的数量与速度随档位单调递增。
  - 先例：Agent controls 模块现有的纯函数单元测试。
- **接缝 2（浏览器组件测试，`*.browser.test.tsx`）**
  - 渲染滑条面板，验证：
    - 点击轨道立即回调最近一档的 id
    - 拖动途中不回调，松手才回调
    - 方向键逐档回调
    - 禁用态下不回调
    - 模拟 `prefers-reduced-motion: reduce` 时不渲染光点
  - 先例：状态环组件的浏览器测试（包括它模拟「减少动态效果」的方式）。
- **接缝 3（浏览器 e2e，回归）**
  - 现有用于切换思考等级的 e2e helper 依赖思考列表菜单，而列表不再出现，因此只保留滑条路径（去掉列表分支），并处理 1 档时触发器禁用的情况。
  - `new-workspace-codex-mode-preferences.spec.ts` 的 `expectThinkingOptionsFit` 按滑条改写：检查档位名和滑条完整显示在浮层内。
  - 保证现有的草稿思考偏好 e2e 用例（按模型记住思考等级、重载后恢复）继续通过。
  - 不另写新的 e2e 用例。
- **手机端**：不新增 Maestro 流程；现有流程如果因为思考页的内容变化而失效，就更新对应流程，不在本地跑，交给 CI。
- **验证方式**：按仓库规定只跑改动的单个测试文件；每次改动后跑 typecheck 和 lint。

## Out of Scope

- 提供方与模型拆分、提供方彩色图标、品牌色表补齐（任务 `09-28-provider-model-split`）。
- Command chip（后续单独立任务）。
- 在滑条上显示选项的 description（如「Default (recommended)」）。
- 命令中心、Agent profile 编辑表单、定时任务表单等 Composer 以外位置的思考选择控件。
- 思考选项的数据结构、顺序和默认值，以及协议和 daemon 的任何改动。
- 把滑条抽成通用 UI 原语供其他功能使用。

### 遗留

- 原生 iOS/Android 上滑条手势与 sheet 下滑关闭的仲裁未在真机验证。
- 1 档模型的禁用触发器只有纯函数测试，没有实机目测或组件测试。

- 运行中 Agent 的 `selectedThinkingId` 为空时滑条显示第 0 档，此时点第 0 档不会提交。
- 亮色主题下，品牌色浅色端上的白色光点对比度偏低；最低档露出的只有浅色起点，Claude 亮色最低档未目测。
