# 02 — 手动下载主链路：发现 → 下载 → 已下载 → 安装

**What to build:**

更新器不再静默下载。用户在侧栏更新卡片里点「更新」才开始下载，下完后点「安装」立即安装。这张做完后，整条手动更新流程可以在打包版里跑通；只是下载中还看不到进度（见 03），也还不能取消（见 04）。

桌面主进程：
- 关闭 electron-updater 的自动下载，并在旁边用一句注释说明原因。
- 更新服务拆出「下载」和「安装」两个动作。下载是幂等的；安装只对已下载的版本生效，未下载时返回「未安装」，不会顺手开始下载。停 daemon、安装交接、失败后拉起 daemon 这些逻辑保持现状。
- 服务维护一份更新状态快照：阶段、目标版本、错误，以及当前平台是否会在退出时安装。每次变化都通过现有的 `paseo:event:*` 通道广播给所有窗口；检查结果也带上这份快照。
- 退出时安装仍然只对已下载的版本生效，Linux AppImage 仍然跳过。

渲染进程：
- 状态机改为镜像主进程推送的快照，状态划分为 `available / downloading / downloaded / installing`。删掉 `pending` 以及等下载就绪的轮询。
- 新增「下载」动作；「安装」动作只在已下载时可用。
- 本次运行的隐藏只存在内存里，按窗口生效：「稍后」和 × 设置隐藏；下载中被隐藏的卡片在进入「已下载」时自动解除隐藏。

侧栏卡片（纯函数描述器 + 现有侧栏提示 API，不传持久化关闭键，改用 `onDismiss`）：

| 阶段 | 标题 | 描述 | 按钮 | × |
|---|---|---|---|---|
| 发现更新 | 有可用更新 | `vX 可用 · 查看更新内容`（链接） | 稍后 / **更新** | 本次运行隐藏 |
| 下载中 | 正在下载更新 | 正在下载…（进度条留给 03） | 无 | 隐藏，下载继续 |
| 已下载 | 更新已下载 | 重启风险提示；「退出 App 时也会自动安装」（AppImage 不显示） | 稍后 / **安装** | 本次运行隐藏 |
| 安装中 | 正在安装更新 | 正在准备重启… | 安装中（禁用） | 无（`dismissible: false`） |

现有的失败展示继续可用（细化见 05）。新增文案补齐 9 种语言，本张改动废弃的 key 一并删除。

**Blocked by:** 01 — 更新状态机改为每窗口单例
**Status:** ready-for-agent
**Impl:** ready

- [ ] 打包版发现新版本后，在用户点「更新」之前不下载任何更新文件；侧栏出现「有可用更新」卡片，显示版本号、「查看更新内容」链接和「稍后 / 更新」按钮。
- [ ] 点「更新」后卡片进入下载中；下完进入「已下载」，显示风险提示和退出时安装的说明（AppImage 不显示后者）。
- [ ] 点「安装」直接开始安装，没有二次确认；安装中卡片不能关闭。
- [ ] 未下载时调用安装命令返回未安装，并且不会触发下载。
- [ ] 「稍后」和 × 只在本次运行期间隐藏卡片，不写入持久化的关闭记录；下载中隐藏的卡片在下完后重新出现。
- [ ] 多个窗口的卡片阶段一致。
- [ ] 下完没装就退出 App 时，退出时会安装（AppImage 除外）；从没点过「更新」的用户退出时不会安装任何东西。
- [ ] 更新服务测试覆盖：检查不触发下载、下载后快照变为已下载并广播、未下载时安装被拒、退出时只安装已下载的版本。状态机和描述器测试覆盖上表的四个阶段和隐藏规则。
- [ ] 9 种语言文案齐全；`npm run typecheck`、`npm run lint` 通过。
