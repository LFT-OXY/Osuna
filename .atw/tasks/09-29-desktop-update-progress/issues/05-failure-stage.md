# 05 — 失败阶段

**What to build:**

区分下载失败和安装失败。卡片的失败阶段显示错误信息，按钮是「重试 / **前往 Releases 手动下载**」，× 只在本次运行期间隐藏。「重试」重新执行失败的那个动作：下载失败就重新下载，安装失败就重新安装。进入失败阶段时解除本次运行的隐藏，保证错误能被看到。

静默自动检查失败仍然只记录日志，不打扰用户。

02 留下的衔接点：失败阶段现在由主进程快照的 `failure.action` 区分；下载失败的「重试」暂时走的是检查，要改为重新下载。阶段为失败时，手动检查再失败，渲染进程的 `checkError` 会盖掉原来的失败原因，要决定哪条优先。`packages/desktop/e2e/updates.spec.ts` 的两条失败用例按 02 的按钮（下载失败：更新内容 / 重试；安装失败：重试 / 前往 Releases）断言，改按钮时一并更新。

**实现中定下的约定：** 渲染状态按失败动作拆为 `check-failed` / `download-failed` / `cancel-failed` / `install-failed`，不用 `failed` 加旁路字段。票里留的优先级问题定为「后发生的优先」：失败阶段里手动检查再失败，显示检查错误、重试走检查；本地错误在下一次动作、手动检查或主进程阶段变化时过期，静默检查不清。取消失败时下载仍在继续，卡片只给「重试」，状态文案用「无法取消下载」。渲染端快照类型改为判别联合，失败阶段必带失败原因，由解析边界保证。
