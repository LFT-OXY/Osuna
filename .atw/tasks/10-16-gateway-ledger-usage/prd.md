# 中转站记账与用量页融合

来源：总任务 [`10-16-magpie-osuna-gaps`](../10-16-magpie-osuna-gaps/prd.md) 的第 5 个子任务。总任务的 Constraints、Implementation Decisions（身份如实、对外请求、协议、术语）、Testing Decisions 对本任务全部适用，下面只写本任务特有的。访谈的全部决定与 magpie 出处见 `research/decisions.md`（Q1–Q21）；架构决定见 [ADR 0014](../../../docs/adr/0014-gateway-ledger-merges-with-cli-logs.md)。对照基准：magpie `7597c132`。

## Problem Statement

用户经 Osuna 的内置中转站（**Gateway**）在多家第三方接口（**API endpoint**）之间切换着用 Claude Code、Codex。用量页（**Usage**）只读 CLI 自己的会话记录，于是：

1. 分不出哪些用量走了哪家接口、哪些走的官方账号，也就不知道钱花在哪家。
2. 估算成本（**Estimated cost**）一律按公开价算，可很多中转服务按公开价打折或加价收钱，数字和实际差很远。
3. 只能看美元和 K / M / B，中文用户不直观。
4. 不知道哪家快、哪家慢、首字要等多久。
5. 中转站切换过几次、哪家失败过、为什么失败，只写在 daemon 日志里；冷却状态只在内存里，重启 Osuna 就没了，重启后会立刻又去试刚坏掉的那家。
6. 子任务 4 做好的接口余额只在接口页上看得到，用量页上没有。

## Solution

内置中转站给经过它的每次请求记一行账（**Gateway ledger**，界面上不出现这个词），用量服务把账本当作新的用量来源，和 CLI 会话记录合并、不算两遍。用户看到的是：

- 用量页多一个「接口」分法：每家接口一张卡片、加一张「官方」卡片，卡片上带这家的余额。
- 每家接口可以设价格倍率，估算成本按「公开价 × 倍率」算；给模型设过的自定义价格优先。
- 金额可以切成人民币，中文界面可以用「万 / 亿」显示大数。
- 一张「速度」卡片：每家接口、每个模型的出字速度和首字等待。
- 明细卡片多一个「请求」标签：逐条列出请求，能筛选、翻页、导出 CSV。
- 接口页多一块「最近异常」：这家最近失败、被换走、进入冷却的请求。冷却状态重启后接着算。

## User Stories

### 账本与合并

1. 作为用第三方接口的用户，我希望经过内置中转站的每次请求都被记下来，以便用量页知道它走了哪家接口。
2. 作为用户，我希望一次调用在用量页只算一次，哪怕 CLI 会话记录里也有它，以便总数可信。
3. 作为用户，我希望走中转站的调用仍然算进它所在的项目和会话，以便「按项目分」和会话列表不缺数。
4. 作为在 Osuna 里开会话的用户，我希望每轮下面的花费仍然包括走中转站的调用，并按这家的价格倍率算，以便每轮花费和用量页一致。
5. 作为在终端里直接跑 Claude Code、Codex 的用户，我希望这些经过中转站的调用也记进账，以便不在 Osuna 里开的会话也算进去。
6. 作为用户，我希望所有接口都失败、CLI 收到报错的请求也记一行（0 token，写明试过哪几家、各自为什么失败），以便查哪家出了问题。
7. 作为用 ChatGPT 登录的 Codex 用户，我希望 ChatGPT 自带模型经过中转站的请求也记进账、算在「官方」，以便官方那组的请求列表和速度也是全的。
8. 作为在意隐私的用户，我希望账本不存任何对话内容，以便账本泄露也不泄露对话。
9. 作为用户，我希望不管 CLI 会话记录和账本哪边先写到硬盘、中间 Osuna 是否重启，同一次调用最后都只算一次，以便数字不跳。
10. 作为升级前就在用中转站的用户，我希望升级前的用量照旧显示、归在「官方」，以便历史不丢（说明文档写明那段分不出接口）。
11. 作为之后要用 Pi、OMP 走第三方接口的用户，我希望它们的对账规则已经定好，以便接上时不算两遍。

### 按接口分开

12. 作为用户，我希望用量页能按「接口」分：每家接口一张卡片，加一张「官方」，以便知道钱花在哪家。
13. 作为用户，我希望按接口筛选用量，以便只看某一家的模型、项目和趋势。
14. 作为用户，我希望接口改名后用量页显示新名字、前后用量合在一起，以便改名不让历史分家。
15. 作为用户，我希望删掉的接口的用量还在，名字后标「（已删除）」，以便总数不变。
16. 作为用户，我希望复制出来的接口单独算，以便同一家中转服务的几把 key 各自看用量。
17. 作为连着多台电脑的用户，我希望各台电脑上同名的接口合成一张卡片，「官方」也跨电脑合并，以便看总数；要分开时用主机筛选。
18. 作为用户，我希望用量页每家接口的卡片上显示它的余额，以便看花费时同时知道还剩多少。

### 价格倍率

19. 作为用户，我希望给每家接口设价格倍率（0–1000，最多三位小数，不填按原价），以便估算成本贴近这家实际收的价。
20. 作为给某个模型设过自定义价格（**Custom price**）的用户，我希望自定义价格优先、不乘倍率，以便我的精确价格不被改。
21. 作为用户，我希望改了倍率后这家过去的花费也按新倍率重算，以便前后口径一致。
22. 作为用户，我希望删掉的接口按删除时的倍率算，以便历史花费不随删除变化。

### 人民币与万 / 亿

23. 作为中文用户，我希望把估算成本切成人民币显示，以便一眼看懂。
24. 作为用户，我希望这个选择每台设备各自记住，默认美元，不随界面语言变，以便不被替我决定。
25. 作为用户，我希望用量页、请求列表、每轮花费、会话列表都按我选的货币显示，以便处处一致。
26. 作为用户，我希望汇率每天自动取一次，取不到继续用上次的，从没取到过按 1 美元 = 7.2 元，以便断网也能用。
27. 作为用户，我希望看得到当前汇率和它是什么时候取的，以便判断准不准。
28. 作为在意对外请求的用户，我希望只在我选了人民币时才取汇率，价格表的「自动更新」关掉时也不取，以便控制 Osuna 往外发什么。
29. 作为中文界面的用户，我希望打开「用『万 / 亿』显示大数」后 token 数显示成「1.2 万」「3.4 亿」，以便符合中文习惯；英文界面不出现这个开关。

### 速度

30. 作为用户，我希望看到每家接口的出字速度和首字等待，以便挑快的那家。
31. 作为用户，我希望速度可以按接口、模型、「模型 · 接口」、Agent 切换分组，以便从不同角度比。
32. 作为用户，我希望样本少的组也显示，旁边写「基于 N 条」，以便自己判断可信度。
33. 作为用户，我希望太短的回复和攒着一次吐出来的回复不计入速度，以便速度不被个别请求带偏。
34. 作为用户，我希望速度跟着用量页选的时段和筛选走，以便看某段时间、某家的速度。

### 请求列表与 CSV

35. 作为用户，我希望在用量页明细里有「请求」标签，逐条列出请求：时间、Agent、模型、接口、输入、输出、缓存读、缓存写、估算成本、耗时、首字等待、出字速度、状态，以便查哪家出了问题。
36. 作为用户，我希望直连官方的调用也出现在列表里（耗时等格子留空），并能按「经过中转站 / 直连」筛选，以便看全部调用。
37. 作为用户，我希望按状态（全部 / 失败 / 换过家）、Agent、接口、模型筛选，并用搜索框搜，以便快速定位。
38. 作为用户，我希望点开一行看每次尝试：试了哪家、结果、失败原因、冷却多久，以便知道中转站为什么换家。
39. 作为用户，我希望列表每页 100 条、可以翻页，以便请求多时也能看完。
40. 作为用户，我希望把符合当前筛选的全部请求导出成 CSV（不只当前一页），以便自己做表或对账。
41. 作为用户，我希望 CSV 比列表多推理 token、失败原因、尝试次数、回复编号、会话编号，金额用美元，以便对账有完整信息。
42. 作为用户，我希望导出失败时看到原因并能重试，以便知道下一步。
43. 作为用户，我希望逐条请求保留 30 天、最多 200 MB，超了从最旧的一天删起，而汇总、按接口分、速度永久保留，以便硬盘不被吃满又不丢总数。

### 接口页的最近异常与冷却

44. 作为用户，我希望接口页显示这家最近 20 次出过事（失败、被换走、进入冷却）的请求：时间、模型、事由，以便事后排查。
45. 作为用户，我希望从「最近异常」点「在请求列表里看全部」，跳到只显示这家接口的请求列表，以便看更多。
46. 作为用户，我希望重启 Osuna 后冷却中的接口接着冷却、到点自动恢复，「立刻恢复」照常能用，以便重启不让中转站去试坏掉的接口。
47. 作为用户，我希望重启后「最近异常」还在，以便重启前的问题也能查。

### 跨部分

48. 作为用官方 Paseo 手机 App 的用户，我希望连上新 daemon 后用量页照常能用，以便不受影响。
49. 作为用别的界面语言的用户，我希望新界面在 9 种语言里都有文字，中文全是中文，以便看得懂。
50. 作为在窄窗口（手机宽度）用 Osuna 的用户，我希望新卡片和请求列表的主要内容不被挡住，次要列收进展开行，以便小屏也能用。

## Implementation Decisions

### 账本

1. **记什么**：中转站给每次经过的请求在结束时记一行（请求开始时不预写；客户端中途取消的也在结束时记，照 magpie 记为取消）。字段：时间、Agent（claude / codex，日后 pi / omp）、CLI 发来的会话编号（中转站粘性已读的那些请求头）、请求的模型名、最后回答的接口编号与那家用的模型名、token 六列（输入、输出、缓存读、缓存写、1 小时缓存写、推理）、总耗时、首字等待、出字速度要用的数（见第 17 条）、回复编号（Claude `message.id`、Responses `response.id`、Chat `id`）、上游的 stop reason、状态（成功 / 失败 / 取消）、每次尝试（接口、模型、开始时间、耗时、结果、失败分类与原因、冷却到何时、是否拒收重问）。不存请求体、回复体、提示词、工具参数，任何对话文字都不存；失败原因里引的上游原话照现有日志的打码规则处理并截短。
2. **哪些请求记**：经过中转站的每个请求，包括所有接口都失败的、拒答的、Codex 用 ChatGPT 登录时 ChatGPT 自带模型的（接口记为「官方」）。中转站的探测、测试连接、拉模型清单、查余额不是 CLI 的请求，不记。
3. **从哪里取数**：中转站已经在转发时解析上游回复里的 usage（现在只用于粘性和空回复判断）；直通路径要把解码出来的回复编号留下来（现在被丢掉），并补上首字时间（中转站收到请求到回复第一个内容——文字、思考或工具调用——发给 CLI 的时刻）。翻译路径用写回给 CLI 的那个编号，保证和 CLI 会话记录里的一致。
4. **身份如实**：记账不改变发给上游或 CLI 的任何字节。

### 合并与对账

5. **合并规则**（ADR 0014）：账本一行和 CLI 会话记录一条按回复编号对上时合成一条：token、接口、耗时、首字等待取账本；项目、会话、轮次（**Turn usage**）取会话记录。只在账本里的行（如失败请求、会话记录没写的）算在「未知项目」，没有会话与轮次。只在会话记录里的即直连，接口为「官方」。
6. **顺序无关**：CLI 会话记录和账本哪边先落盘、合并发生在扫描时还是读数时由实现定，但结果必须与到达顺序、daemon 是否中途重启无关：同一次调用最终在汇总、按项目、按会话、每轮花费里都只出现一次，且带上接口。实现要处理「会话记录先被扫描、账本行稍后才写」和「账本行先写、会话记录几分钟后才被扫描」两种情况。
7. **Claude 子代理与重复行**：会话记录里同一 `message.id` 拆成多行的现有处理不变；合并按去重后的那一条对。
8. **升级前的历史**：账本开始之前的调用只在会话记录里，一律算「官方」。不回头猜它们走了哪家。`docs/usage.md` 写明。
9. **Pi / OMP 规则**（给子任务 6 用，本任务写进 `docs/usage.md` 与解析器的对账接口，子任务 6 接上）：会话记录的条目能按回复编号对上账本时同上合并；对不上且条目的 provider 是 Osuna 写进 Pi / OMP 配置的中转站服务商时，跳过这条（照 magpie `calls_pi.go` 的 `piGateway`），只算账本。服务商名在子任务 6 定。

### 存储

10. **两层**（ADR 0014）：
    - **汇总**：现有的 15 分钟用量汇总行加「接口」一列（接口编号；官方为空）和速度要用的和（第 17 条），照现有规则追加、按月分文件、永久保留。旧行没有接口列即「官方」，不做迁移。
    - **逐条记录**：账本行和直连调用的逐条行（从 CLI 会话记录读出的每次调用：时间、Agent、模型、token、会话、项目）按天分文件追加，保留 30 天、合计最多 200 MB，超了从最旧的一天整天删；修剪最多每小时一次。逐条记录支撑请求列表、CSV、最近异常。
11. **写法**：遵守 `docs/data-model.md`：追加写；读时丢掉写一半的坏行；文件权限与接口目录一致（0600）；位置在 `$PASEO_HOME` 下，由实现定并写进 `docs/data-model.md`。
12. **接口的名字与倍率快照**：用量按接口编号认。daemon 另存一份「接口编号 → 最后的名字、最后的价格倍率、是否已删除」，接口保存、改名、删除时更新；删掉的接口用它显示名字加「（已删除）」并按它的倍率算。
13. **冷却跨重启**：冷却状态（哪家接口的哪个模型、冷却到何时、原因分类）存盘，启动时读回，过期的丢掉，未过期的接着冷却、到点照常恢复；「立刻恢复」同时清掉存盘的那份。失败计数照旧只在内存。写法原子替换；文件坏了当作没有冷却。修改 ADR 0007 对应条（已在 0007 标注）与术语表 **Endpoint status** 的「重启清零」一句。

### 计价

14. **价格倍率**：接口新增可选字段「价格倍率」，0–1000，最多三位小数；没有即按原价（等于 1）；0 表示免费。存在接口自己的存储里，线上与保存请求都是可选字段；旧客户端保存时不带，daemon 保留原值。复制接口时一并复制。
15. **找价顺序**：自定义价格（现有的按模型 id 精确匹配）命中就用它、不乘倍率；否则查价格表（现有规则），再乘这行所属接口的倍率。官方行不乘。估算成本仍是读数时现算、不落盘，所以改倍率即重算历史（照 magpie `priceOf`）。
16. **每轮花费**：Osuna 会话每轮下面的估算成本按合并后的行算，走中转站的那部分乘对应接口的倍率。

### 速度

17. **定义照 magpie**（`usage.go` 的 `DecodeOf` 与过滤）：首字等待 = 中转站收到请求到第一个内容发给 CLI，含之前失败的尝试；出字速度 = 输出 token ÷（总耗时 − 出字起点），有推理且能分出第一个正文时用正文 token 与正文起点；窗口不足 100 ms、超过 10000 token/秒、攒着一次吐出（流动时长 × 4 < 窗口）、正文快于推理 20 倍以上的，不计入速度。组内速度 = Σ计入的输出 token ÷ Σ计入的时长（按 token 加权）；组内首字等待的汇总方式照 magpie。只有经过中转站、流式回复的请求有速度；直连调用没有。
18. **汇总里存和**：每个汇总行存计入速度的输出 token 之和、时长之和，以及首字等待按 magpie 汇总所需的数与条数，使速度在「全部」时段也能算，不依赖 30 天的逐条记录。
19. **分组**：接口、模型、「模型 · 接口」、Agent，可切换；每组显示速度、首字等待与「基于 N 条」；不设最小样本。

### 人民币与汇率

20. **货币**：每台设备一个偏好（客户端的应用设置，和套餐用量的显示偏好放在一起），美元 / 人民币，默认美元，不随界面语言。所有显示估算成本的地方都按它换算：用量页、请求列表、会话列表、每轮花费、Agent 用量卡。价格表、CSV 保持美元。接口余额不换算。
21. **汇率**：daemon 新增一个读汇率的 RPC。客户端选了人民币时才调用；daemon 缓存一份汇率与取得时间（存盘，重启不丢），缓存不满一天直接回，满一天才向 `https://open.er-api.com/v6/latest/USD` 取 `rates.CNY`（照 magpie `fx.go`），GET，不带认证与查询参数，`User-Agent` 为 Osuna 自己的；15 秒超时；失败记 `info` 日志，回上次的值；一次都没取到过回 7.2 并标明是缺省值。价格表自动更新关掉（`features.usage.pricing.autoUpdate: false`）时不发请求，只回缓存或 7.2。
22. **汇率的显示**：货币选项旁写「1 美元 = 7.12 元 · {时间} 取得」；缺省值时写「尚未取到汇率，暂按 7.2 计算」。
23. **万 / 亿**：每台设备一个开关，默认关；只在界面语言是中文时显示与生效。开着时 token 大数显示为「万」「亿」（如「1.2 万」「3.4 亿」，小于一万照常），影响用量页、请求列表、每轮用量与会话列表的 token 数；金额不用万 / 亿。

### 读用量的接口（RPC）

24. **用量报告**：现有 `usage.report.get` 的请求与回复加可选字段：过滤器加「接口」；分组加「按接口」（每组：接口编号、名字、是否已删除、token、估算成本）；速度统计（按请求指定的分组方式）。官方组的接口编号为空。现有 `usage.sessions.list` 等会话、每轮 RPC 的成本按第 15、16 条算。
25. **请求列表**：新 RPC `usage.requests.list.request` / `.response`：时段、筛选（状态、经过中转站 / 直连、Agent、接口、模型、搜索文字）、偏移与条数（每页 100）；回逐条记录与总条数。每条带展开要用的尝试明细。
26. **CSV 导出**：新 RPC `usage.requests.export.request` / `.response`：同一组筛选，回 CSV 文字（全部符合条件的行，不分页）。列：列表的列 + 推理 token、失败原因、尝试次数、回复编号、会话编号；金额列为美元。客户端保存：Electron 用保存对话框，浏览器触发下载，原生端用系统分享。
27. **最近异常**：新 RPC `provider.api_endpoint.recent_problems.request` / `.response`：接口编号；回这家最近 20 次失败、被换走或导致冷却的请求（时间、模型、事由：失败分类与原因、换到了哪家、冷却到何时）。
28. **汇率**：新 RPC `usage.exchange_rate.get.request` / `.response`：回汇率、取得时间、是否缺省值。
29. **推送**：账本写入后照现有 `usage.updated` 的节奏通知客户端重读（回填期间不发的规则不变）；接口页开着时最近异常随 `usage.updated` 重读。
30. **协议兼容**：新字段全部可选，新 RPC 用带点命名（`docs/rpc-namespacing.md`）。新能力位 `server_info.features.gatewayLedger`；客户端只在它为真时显示接口分法、速度卡、请求标签、最近异常、价格倍率；货币与万 / 亿是纯客户端功能，但汇率要 daemon 支持，没有能力位时货币选项不出现。旧客户端（含官方 Paseo 手机 App）看不到新字段，用量页照常。

### 文档与术语

31. `docs/usage.md`：用量来源多了中转站账本；合并规则；升级前历史归官方；Pi / OMP 规则；两层存储与保留；速度定义；倍率与找价顺序；「Outbound requests」加汇率请求（发给谁、带什么、何时发、怎么关）。

## UI and Design

- **方向**：沿用现有用量页、接口页、编辑窗口的样式，不另做视觉风格。遵守 `docs/design.md`、`docs/forms.md`、`docs/hover.md`、`docs/unistyles.md`、`docs/menus.md`、`docs/i18n.md` 与 `.atw/spec/app/frontend/`。用户偏好：开 / 关一律用 Switch；模型名不用等宽字体；次要操作不用蓝色链接。
- **用量页**：
  - 概览卡头部加一个选项菜单（照 `docs/menus.md`），里面是「货币：美元 / 人民币」（带汇率说明一行）和中文界面才有的「用『万 / 亿』显示大数」Switch。
  - 概览卡里，在来源卡片旁加「接口」分法：「官方」卡片 + 每家接口一张卡片（名字、token、估算成本、占比、余额一行；已删除的写「（已删除）」、不显示余额）。点卡片按这家筛选，筛选器里也有「接口」。
  - 接口卡片组下面一张「速度」卡片：分组切换（接口 / 模型 / 模型 · 接口 / Agent），每行：名字、出字速度（token/秒）、首字等待（秒）、「基于 N 条」。没有经过中转站的请求时显示空状态「这段时间没有经过中转站的请求」。
  - 明细卡片的「每日 / 每月 / 项目」后加「请求」标签：筛选条（状态分段、经过中转站 / 直连、Agent、接口、模型、搜索）、表格、翻页、底部「导出 CSV」。点一行展开每次尝试。状态列：成功、失败（原因）、换过 N 家。空状态：「没有符合条件的请求」。加载中显示骨架。导出：进行中按钮转圈并禁用；失败时在按钮旁留红字原因与「重试」，直到重试或关掉；成功不弹窗。
- **接口页**：详情页加「最近异常」分区：最多 20 行（时间、模型、事由），没有时写「最近没有异常」；底部「在请求列表里看全部」（次要按钮样式，不是蓝色链接）跳到用量页「请求」标签并按这家筛选。读取失败时分区内留原因与「重试」。
- **编辑窗口**：「价格倍率」数字输入放在高级区，说明一句「估算成本 = 公开价 × 倍率；模型设了自定义价格时不乘倍率」；超出 0–1000 或多于三位小数时表单内报错、不能保存。
- **视口**：桌面（Electron 与浏览器，宽 1280）、窄窗口（compact，宽 390）。原生端不做实机验收。
- **界面验收（看截图判断）**：
  - 中文界面新文字全是中文，用词与 `docs/glossary.md` 一致；英文界面没有露出的翻译键名，也没有「万 / 亿」开关。
  - 用量页的接口卡片组里有「官方」和各家接口，接口卡片上有余额一行，已删除的接口带「（已删除）」。
  - 选人民币后，概览、请求列表、每轮花费的金额都是「¥」，汇率说明一行可见；打开「万 / 亿」后 token 数显示为「万 / 亿」。
  - 速度卡片每行有「基于 N 条」。
  - 请求标签在宽 390 下表格不横向溢出：只显示时间、模型、接口、状态、成本，其余在展开行。
  - 「导出 CSV」失败时原因和「重试」留在按钮旁。
  - 接口页「最近异常」分区和「在请求列表里看全部」可见；编辑窗口高级区有「价格倍率」。
  - 新增开关都是 Switch；模型名不是等宽字体。

## Testing Decisions

- **好测试的标准**：只测外面看得到的行为——CLI 收到什么、RPC 回什么、界面显示什么；不测内部结构。时钟固定，结果每次一样（`docs/testing.md`）。
- **接缝一（主）：daemon 端到端测试**。进程内起真实 daemon，本机起假中转服务（回复里带编号与 token），用 fetch 扮演 Claude Code、Codex 打中转站；临时目录里放好假 CLI 会话记录，回复编号与假上游一致；再读用量 RPC。覆盖：
  - 同一次调用只算一次；两种到达顺序结果相同；中途重启 daemon 结果相同。
  - 按接口分开、官方组、未知项目；升级前（只有会话记录）的行归官方。
  - 失败请求、取消请求、ChatGPT 自带模型的行。
  - 价格倍率、自定义价格优先、改倍率重算、删除接口后的名字与倍率。
  - 每轮花费含倍率。
  - 速度与首字等待的数值与过滤规则。
  - 请求列表的筛选、分页、总数；CSV 的列与全量导出。
  - 最近异常的内容与上限 20。
  - 重启后冷却接着算、到点恢复、「立刻恢复」清掉存盘。
  - 逐条记录超过 30 天被删、汇总还在；超过大小上限从最旧的一天删。
  - 汇率：本机假汇率服务；只在调用时取、一天内不重取、失败回上次、从未取到回 7.2、自动更新关掉不发请求。
  - 账本文件里不出现假请求里的对话文字。
  - 先例：daemon 端到端目录下的中转站、余额、用量报告、价格几组测试。
- **接缝二：app 浏览器测试**。Playwright + 真实 daemon + 现有的用量夹具与假中转服务夹具。覆盖：接口卡片与官方卡片、余额一行、已删除；速度卡与分组切换；请求标签的筛选、翻页、展开、导出 CSV 成功与失败；货币切换与汇率说明、万 / 亿开关（中文出现、英文不出现）；编辑窗口价格倍率的保存与超范围报错；接口页最近异常与跳转；没有能力位的旧 daemon 时新界面不出现。先例：用量页、用量明细、价格表、第三方接口设置页那几组浏览器测试。
- **已有纯逻辑套件加用例**：CLI 会话记录解析器（回复编号读对）、用量报告聚合、数字格式（万 / 亿）。不另建套件、不加 npm 脚本或 CI 任务。
- **不碰真实的东西**：不读写真实 `~/.claude`、`~/.codex`，不跑真的 CLI，不连真的中转服务与汇率网站。
- **本机只跑改到的测试文件**，全量交给开 PR 时的 CI。
