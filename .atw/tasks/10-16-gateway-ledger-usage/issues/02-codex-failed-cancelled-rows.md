# 02 — Codex 也记账，失败和取消的请求也记

**What to build:** Codex 经过中转站的请求同样记账，并按 `token_usage_record` 的 `response_id` 与 Codex 会话记录合并；Codex 用 ChatGPT 登录时 ChatGPT 自带模型的请求记进账、算「官方」；所有接口都失败的请求、中途取消的请求也记一行（0 token，写试过哪几家、各自原因），算在「未知项目」。

**Blocked by:** 01
**Status:** ready-for-agent
**Impl:** doing

- [ ] Codex 的合并同 01 的规则与顺序无关要求（端到端测试：两种到达顺序 + 中途重启）。
- [ ] ChatGPT 自带模型的请求接口记为官方，不乘倍率，与 Codex 会话记录合并后在「官方」卡片里只算一次。
- [ ] 全部失败的请求：一行 0 token，带每次尝试的接口、结果、失败分类与原因（上游原话打码并截短）、冷却到何时；取消的请求照 magpie 记为取消。
- [ ] 只在账本里的行在按项目分时归「未知项目」，没有会话与轮次。
- [ ] 失败、拒答、拒收重问在尝试明细里区分得开（端到端测试各一例）。
- [ ] 浏览器测试：Codex 的用量出现在对应接口卡片；「未知项目」出现在项目明细里。
- [ ] 9 种语言的新文字齐全（「未知项目」等）。
- [ ] UI：用量页项目标签 / 有失败请求 / 1280 — 「未知项目」一行可见。
