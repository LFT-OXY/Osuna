# 01 — 账本起步：Claude Code 走中转站的用量按接口分开

**What to build:** Claude Code 经过内置中转站的每次请求被记进账本（接口、模型、token、耗时、首字等待、每次尝试、回复编号，不含对话内容）；用量服务把账本和 Claude Code 会话记录按 `message.id` 合成一条（token、接口、耗时取账本，项目、会话、轮次取会话记录），一次调用只算一次。用量页多「接口」分法：「官方」卡片 + 每家接口一张卡片，可按接口筛选；升级前的用量归「官方」。

**Blocked by:** None — can start immediately
**Status:** ready-for-agent
**Impl:** doing

- [ ] 中转站在请求结束时记一行账（prd 第 1–4 条的字段，Claude 部分）：直通与翻译两条路径都留下写回给 CLI 的回复编号，并记首字时间；记账不改变发给上游或 CLI 的任何字节。
- [ ] 账本与逐条存储按 `docs/data-model.md`：追加写、读时丢坏行、0600；15 分钟汇总行加可选的接口列（旧行即官方，不迁移）。
- [ ] 合并与到达顺序、daemon 中途重启无关：端到端测试分别让会话记录先被扫描、账本行先写，以及中间重启，三种情况汇总、按项目、按会话、每轮用量都只算一次且带上接口。
- [ ] 会话记录里同一 `message.id` 拆成多行的现有处理不变，合并按去重后的那条对。
- [ ] 只在会话记录里的调用算「官方」；只有会话记录的历史（升级前）归「官方」。
- [ ] `usage.report.get` 加可选的接口过滤与按接口分组（接口编号、名字、token、估算成本）；新能力位 `server_info.features.gatewayLedger`；旧客户端照常。
- [ ] 账本文件里不出现假请求的对话文字（端到端测试检查）。
- [ ] 文档：`docs/usage.md` 写账本来源、合并规则、升级前归官方、Pi / OMP 规则（prd 第 9 条）；`docs/data-model.md` 写新文件与汇总行的新列。
- [ ] 浏览器测试：用量页接口卡片组有「官方」和夹具里的接口，点卡片按接口筛选；没有能力位的 daemon 时不出现。
- [ ] 9 种语言的新文字齐全。
- [ ] UI：用量页 / 有中转站用量 / 1280 与 390 — 来源卡片旁出现「接口」分法，「官方」与接口卡片显示 token、估算成本、占比，宽 390 不溢出。

参考：prd 第 1–11、24、29、30 条，用户故事 1–3、5、8–12、48；ADR 0014。
