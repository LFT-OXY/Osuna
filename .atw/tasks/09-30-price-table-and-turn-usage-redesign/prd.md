# 价格表分组重设计与每轮用量悬浮面板重设计

## Problem Statement

用户来「价格表」页只有一个原因：用了 LiteLLM 查不到价格的模型（Z.AI、百炼、本地 MLX 之类），要给它补一个**自定义价格**，否则这些模型的**估算成本**一直是 $0。现在的价格表把所有见过的模型塞进一张 7 列定宽表：要填的行和几十行 LiteLLM 参考数据混在一起，无价格的行一进来就是四个 70 宽、只剩 44px 文字宽的输入框，和表头对不齐；行距紧、没有层次，按钮和整体观感都粗糙；设了自定义价格之后也没有办法撤回。

对话流里每轮结束的 footer 上，鼠标悬停 `· ↑14.3K ↓4.6K · $0.17` 弹出的**本轮用量**面板是歪的。实测（`research/baseline-dom.md`）：面板外框最宽 280，内层却要求至少 280，再加外框内边距，内容向右溢出 18px，「估算成本」「$0.11」「7s」画到了边框外，整体偏右 9px；模型列只剩 24px，名字被截成 `g…`；带推理 token 的行把「（N 推理）」拼进输出格，这一格变宽并折行，把模型名挤到 0 宽完全看不见，输入、缓存两列比表头左移 24px。

## Solution

**价格表**拆成上下两组（原型方案一「对齐表格」，`prototype/price-and-usage.html` 画面 A1–A4、AM）：

- 上面是「自定义价格」组，放**无价格数据**的模型和已有自定义价格的模型，默认展开。一张对齐的表：模型名下面一行写状态，四个价格列是等宽、带 `$` 前缀、右对齐的输入框，和表头对齐；无价格数据的行底色带一点琥珀色；已自定义的行显示数值，右侧是「编辑」和「移除自定义价格」两个图标按钮。保存后这一行留在本组，变成已定价。组为空时显示一行「所有模型都有价格。」（居中、次级色，不带图标，`docs/design.md` §11）。
- 下面是「LiteLLM 价格」组，默认折叠成一行「N 个模型由 LiteLLM 定价」，点开后有搜索框和只读价格表；每行悬停时出现「自定义」，点了这一行就进入上面的组、以当前 LiteLLM 价格预填进入编辑。自动更新开关和「立即刷新」挪到这一组的标题右侧，副标题写明价格来自 LiteLLM 快照还是联网更新、多久前更新、单位是每百万 token 美元。

**本轮用量面板**重新设计为「总览 + 明细」（原型方案一，画面 U1–U3、UM）：固定宽 300，顶部是本轮耗时，大字显示本轮估算成本，下面一格一格列出输入、缓存、输出（有推理时多一格「其中推理」）。只用了一个模型时写一行模型名；用了多个模型时列「按模型」明细，每个模型两行：模型名和成本，下面一行小字是输入、缓存、输出与推理。有模型无价格数据时，底部用琥珀色写明哪个模型按 $0 计入、去哪里自定义。手机上点按弹出同一个面板。

## User Stories

1. 作为用了 LiteLLM 查不到价格的模型的用户，我想一打开价格表就看到这些模型排在最上面，这样我不用在几十行参考数据里找要填的那几个。
2. 作为这样的用户，我想看到这些模型被明确标成「无价格数据」、并知道它们目前按 $0 估算，这样我明白不填的后果。
3. 作为用户，我想看到「自定义价格」组的标题上有无价格数据的模型个数，这样我一眼知道还剩几个没填。
4. 作为用户，我想四个价格输入框等宽、和表头对齐、数字右对齐、带 `$` 前缀，这样我填的时候不会填错列。
5. 作为用户，我想在副标题或说明里看到单位是「每百万 token 美元」、0 表示免费，这样我按正确的量级填写。
6. 作为用户，我想填完四列后点「保存」，这样这个模型的用量立刻按我的价格重算。
7. 作为用户，我想保存后这一行留在原处、变成显示数值的已定价状态，这样我能直接核对刚填的数字，而不是看着它跳到别处。
8. 作为用户，我想在四列没填全或填了非数字时看到出错提示，并且出错的是哪几格一目了然，这样我知道要补哪里。
9. 作为用户，我想出错提示出现在模型名下方原本的状态行里、不把下面的行往下推，这样我接下来的点击不会点错行。
10. 作为用户，我想 daemon 拒绝保存时，提示里写着本地化的一句话加上 daemon 给的原因，这样我知道该怎么办。
11. 作为用户，我想对已有自定义价格的模型点「编辑」、改数值、再保存或取消，这样我能修正填错的价格。
12. 作为用户，我想「移除自定义价格」，这样填错或不再需要的覆盖价可以撤回，而不用去手改 `config.json`。
13. 作为用户，我想移除后这个模型回到它的 LiteLLM 价格；如果 LiteLLM 没有它的价格，就回到无价格数据、重新等我填写，这样移除的结果和我预期的一样。
14. 作为用户，我想 LiteLLM 组默认折叠、只占一行并写着有多少个模型，这样页面上最显眼的是我要处理的东西。
15. 作为用户，我想展开 LiteLLM 组后用搜索框按模型名过滤，这样模型很多时也能找到某一个。
16. 作为用户，我想搜索没有结果时看到「没有名称包含 X 的模型」，这样我知道不是页面坏了。
17. 作为发现 LiteLLM 价格和我实际渠道对不上（比如走代理有折扣）的用户，我想在 LiteLLM 行上点「自定义」，这样我能用自己的价格覆盖它。
18. 作为这样的用户，我想点「自定义」后这一行出现在自定义价格组里、以当前 LiteLLM 价格预填，这样我只改需要改的那一格。
19. 作为这样的用户，我想在保存前「取消」，这样这一行回到 LiteLLM 组，什么也没写。
20. 作为用户，我想在 LiteLLM 组的标题旁看到自动更新开关和「立即刷新」，这样我清楚它们只影响 LiteLLM 的价格。
21. 作为用户，我想副标题告诉我价格来自内置快照还是联网更新、多久前更新，这样我判断这些价格新不新。
22. 作为用户，我想切换自动更新或刷新失败时，在 LiteLLM 组里看到失败原因，而不是一个悄悄弹回去的开关。
23. 作为所有模型都有价格的用户，我想看到一行「所有模型都有价格」，这样我知道这一组本来是做什么的，也不会以为页面少了一块。
24. 作为手机用户，我想价格表不用横向滚动：模型名占一行，四个输入框排在下面，这样在窄屏上也能填。
25. 作为手机用户，我想 LiteLLM 行的「自定义」一直可见，因为手机上没有悬停。
26. 作为手机用户，我想自动更新和刷新放在页面底部单独一张卡片里，这样窄屏的组标题不挤。
27. 作为连着一台旧 daemon、还没加载完、或者 daemon 出错的用户，我想看到和现在一样的加载中、需要更新主机、出错可重试的状态，这样新布局不会丢掉这些提示。
28. 作为用过同一模型的多个 CLI 的用户，我想每个模型只出现一行，这样我不会为同一个模型填两次。
29. 作为模型 id 很长的用户（如 `orcarouter/Qwen3.8-27B-Instruct-MLX`），我想模型列尽量宽、放不下时省略，并且能看到完整 id，这样我能分清两个相近的模型。
30. 作为看对话的用户，我想悬停 footer 的用量段时弹出的面板完整地落在自己的边框里、对准触发的那段文字，这样它看起来不再是歪的。
31. 作为这样的用户，我想面板顶部用大字显示本轮估算成本，这样我最关心的数字一眼就能看到。
32. 作为这样的用户，我想看到本轮总的输入、缓存、输出 token，这样我知道成本从哪来。
33. 作为用了推理模型的用户，我想推理 token 单独成一格「其中推理」，而不是拼进输出的数字里，这样数字不会挤坏布局，也不会让我以为要把两者相加。
34. 作为这样的用户，我想面板上方写着本轮耗时，这样我不用再看 footer 左边的「已工作」。
35. 作为只用了一个模型的用户，我想面板只写一行模型名，不出现只有一行的明细表和重复的合计，这样面板简洁。
36. 作为一轮里用了多个模型（比如主模型加子代理用的小模型）的用户，我想看到每个模型的成本和 token 明细，这样我知道钱花在哪个模型上。
37. 作为用了无价格数据模型的用户，我想在明细里看到这个模型标着「无价格数据」，并在面板底部看到一句提示：它按 $0 计入、可在「设置 › 价格表」自定义，这样我知道成本偏低以及怎么补。
38. 作为这样的用户，我想面板里的总成本和 footer 一样带点状下划线，这样我知道这个数是不完整的。
39. 作为手机用户，我想点按用量段弹出同一个面板，并且它在 390 宽的屏幕里完整显示。
40. 作为模型名很长的用户，我想面板里的模型名在一行内省略，而不是撑宽面板或把数字挤走。
41. 作为使用非中文界面的用户，我想价格表和面板的所有新文字都有我的语言，这样界面不会冒出英文或空白。
42. 作为用屏幕阅读器的用户，我想图标按钮（编辑、移除自定义价格）和用量段都有可读的标签，这样我知道它们是做什么的。

## Implementation Decisions

**不改协议。** 分组只依赖现有的 `priceSource`（`null` / `"table"` / `"override"`）。移除自定义价格就是把该模型的覆盖项从 daemon 配置里删掉，走现有的配置写回。从 LiteLLM 行点「自定义」后暂时出现在自定义组，是客户端的界面状态，不写入任何地方。设了自定义价格后，daemon 不再告诉客户端 LiteLLM 是否也有价格，所以界面不显示「覆盖了 LiteLLM」之类的来源说明。

**价格表的纯逻辑**放在价格表模块现有的纯函数文件里，与现有的去重、草稿解析、覆盖项写入函数并列：

- 分组：输入去重后的模型列表和「正在从 LiteLLM 行自定义的模型集合」，输出两组。自定义组 = `priceSource !== "table"`，加上这个集合里的模型；无价格数据的排在已自定义的前面，组内保持 daemon 给的顺序。LiteLLM 组 = 其余，保持 daemon 的顺序。
- 搜索：只作用于 LiteLLM 组，按模型 id 做不区分大小写的子串匹配，去掉首尾空格。
- 移除覆盖项：从覆盖项列表里删掉与该模型匹配的每一项（daemon 取同名的最后一条，只删一条会让剩下的接着生效）。匹配规则与现有的写入函数相同（忽略大小写和首尾空格），其余项原样保留，包括在 App 外设置的 `note`。
- 无价格数据的计数：自定义组里 `priceSource === null` 的个数。
- 自定义组各行的编辑与写回状态（草稿、重新播种输入框的 token、行错误、正在写回的行、正在从 LiteLLM 行自定义的模型集合）是一个纯 reducer（`price-table/price-rows.ts`），组件只 dispatch。「自定义」（`customizeOpened`）把模型加进集合并以 LiteLLM 价格预填草稿；取消与移除自定义价格把它拿出集合；保存成功后仍留在集合里——daemon 广播新价格表之前它还是 LiteLLM 价格，拿掉会让这一行在两组之间跳一下，之后它已是自定义价格，留着不改变分组。覆盖表整段写回，所以一次只写一行：一行在保存或移除时，其余行的「保存」「移除」停用，本行的「编辑」「取消」也停用；daemon 配置还没读到时保存和移除都直接在状态行报错，不拿空表写回。

原型里的分组规则（`prototype/src/render.js`）：

```js
// 自定义组 = 无价格 + 自定义价 + 临时从 LiteLLM 拉进来编辑的
isCustomGroup = (m) => m.priceSource !== "table" || pinned.has(m.model);
// 无价格在前，自定义在后
customRows.sort((a, b) => (a.priceSource === null ? 0 : 1) - (b.priceSource === null ? 0 : 1));
```

**价格表的界面**：

- 页面由两个 SettingsSection 组成：「自定义价格」和「LiteLLM 价格」，标题都用 SettingsSection 的 `count` 显示数量（自定义组为空时不显示数量）。加载中、不可用、出错、空这几种页面级状态沿用现有的状态解析，在两组的位置显示一次：一个标题为「价格表」的 SettingsSection 里一张卡片。
- 两组的说明文字（自定义组的单位说明、LiteLLM 组的副标题）都放在卡片内的第一行，不放在组标题与卡片之间（`docs/design.md` §7、§14 禁止标题与卡片之间的说明段落）。
- 自定义组：卡片内先是一行说明（单位与「0 表示免费」），再是表头和行。列的几何放在现有的列宽模块里：模型列弹性，四个价格列等宽（原型 88），操作列定宽 136（原型的 104 放不下英文「Cancel + Save」，实测 131，法语更宽；按最长的 fr「Enregistrer」加一个 28 宽的图标按钮定）。表头、只读数值和输入框里的数字右对齐到同一条线（输入框左右内边距 8，只读数值与表头右内边距 8 + 1px 边框）。行的最小高度约 60。
- 每行模型名下面有一行固定高度的状态行：无价格数据 → `statusWarning` 圆点加「无价格数据 · 估算 $0」；已自定义 → 强调色圆点加「自定义价格」；从 LiteLLM 行进来编辑的 → 灰色圆点加「LiteLLM 价格」；出错 → 危险色图标加错误文字，替换当前状态，单行省略，悬停 tooltip 显示全文。错误不再单独占一行。校验没过时，空着或不是数字的格子用危险色边框标出来；daemon 拒绝时不标格子。
- 模型 id 单行省略，悬停 tooltip 显示完整 id（两组都是）。
- 无价格数据的行底色用主题现成的警示底色 `surfaceWarning`（amber 10%；原型的 amber 4% 需要新增一档更淡的变体，`docs/design.md` §13 不允许，且 Web 上主题色是 CSS 变量，样式表里不能换算）。徽标用 `StatusBadge` warning。组标题右侧的徽标显示无价格数据的个数，为 0 时不显示，文案沿用术语「无价格数据」（例如「无价格数据 3」），不用「待填写」「未定价」。
- 操作：编辑态是「保存」（default sm，文字），已有价格的行在它左边再加「取消」（✕ 图标按钮，tooltip 与无障碍标签「取消」，testID `price-table-cancel-*`）；只读态是「编辑」（铅笔）和「移除自定义价格」（撤销图标）两个 ghost 图标按钮，都带无障碍标签和 tooltip。图标按钮左右内边距 6，28×28。无价格数据的行始终处于编辑态，没有「取消」。移除不弹确认框：移除后要么回到 LiteLLM 价格，要么回到可以直接重填的无价格数据状态，都能挽回。移除按钮 testID `price-table-remove-*`，写回途中显示 loading；失败时状态行显示「无法移除这个自定义价格。」加 daemon 原因，行保持原状。
- 输入框：新的定宽价格输入样式，带 `$` 前缀，数字右对齐、等宽数字，占位符是 `foregroundMuted` 的 `0.00`（`docs/design.md` §14 不允许比它更淡的占位符）；聚焦和悬停与现有表单输入框一致。实现是给 `FormTextInput` 加两个可选参数：`prefix`（框内文字前的固定前缀）和 `invalid`（危险色边框）。沿用现有的非受控输入加 `resetKey` 重新播种方式。
- LiteLLM 组：标题右侧（仅非紧凑布局）放自动更新开关和「立即刷新」按钮。卡片内第一行是副标题，按 `table.source` 选两个整句键之一（`litellmGroup.subtitle.snapshot` / `.cache`，不往一句里插来源名词，否则 es / pt-BR 的性数对不上），句中是相对时间和单位。卡片折叠时是一行可点的「N 个模型由 LiteLLM 定价 · 展开」；展开后依次是折叠行、搜索框、表头、只读行（最小高度约 40，四列数值与自定义组同一套列宽，0 用 `foregroundMuted`，`foregroundExtraMuted` 留给被动 chrome）。搜索框复用 `SearchField`（自带清除按钮）；搜索词去掉首尾空格后非空且没有匹配时，表头换成一行居中的「没有名称包含「X」的模型。」。搜索只作用于 LiteLLM 组：正在自定义的模型已在上面一组，不参与匹配。「自定义」是 ghost xs 按钮：桌面上悬停行时出现（按 docs/hover.md 的模式：外层普通 View 管 pointerenter/leave，按钮用 opacity + pointerEvents 隐藏、不卸载），原生和紧凑布局常显；表格排法放在操作列里右对齐，窄排放在行的右侧。
- 折叠状态和搜索词只存在组件状态里，离开页面就重置，默认折叠。
- 控件错误（自动更新或刷新失败）换下 LiteLLM 组的副标题，占同一块预留两行 caption 高的位置，出错与恢复都不挪动下面的行；沿用「本地化句子 + daemon 原因」的拼法。没有错误时 `price-table-control-error` 节点不存在，副标题是 `price-table-litellm-subtitle`。
- 窄排（紧凑布局 <720，或价格表自己量到的宽度 < 680——桌面上设置侧栏与应用侧栏会让详情栏窄于 720，`resolvePriceTableLayout`，没量到之前按形态先猜）：自定义组的行变成模型名和状态占一整行，四个输入框排成一行 4 格，操作放在最下面；表头只保留四个价格列名，放不下时折行。LiteLLM 行把四个价格压成模型名下面的一行小字（「入 3 · 读 0.3 · 写 3.75 · 出 15」，每格一个带 `{{price}}` 的短标签键），LiteLLM 组展开后不画表头。自动更新和刷新移到页面底部单独一张卡片。整张表不再横向滚动。
- 保持现有 testID 可用（`price-table-row-*`、`price-table-input-*-*`、`price-table-save-*`、`price-table-edit-*`、`price-table-error-*`、`price-table-auto-update-switch`、`price-table-refresh`），另加移除（`price-table-remove-*`）、分组（`price-table-custom-group` / `price-table-litellm-group`）、折叠开关（`price-table-litellm-toggle`）、搜索框（`price-table-litellm-search`、清除 `price-table-litellm-search-clear`、无结果 `price-table-litellm-no-matches`）、「自定义」（`price-table-customize-*`）的 testID。

**本轮用量面板**：

- 数据层：每轮用量模块（`usage/turn-usage.ts`）的 `buildTurnUsagePanel(turn)` 取代旧的明细构建函数，返回 `{ totals, models, unpricedModels }`：`totals` 取 daemon 给的本轮总计（输入、缓存读+写、输出、推理、估算成本、`priced`），推理只是输出的一部分，不加进输出；`models` 是可辨识联合 `{ kind: "none" } | { kind: "single"; model } | { kind: "multi"; models }`（daemon 没给按模型明细时是 `none`，面板不画模型区）；`unpricedModels` 是无价格数据的模型 id。「全部有价格」直接用 daemon 的 `turn.priced`，与 footer 同源，daemon 端就是按模型 `every(priced)`。面板不再用「合计」行。footer 那一行的摘要函数不变。
- 底部提示由 `describeUnpricedWarning(models, separator)` 选键：一个模型 `message.turnUsage.unpricedWarningOne`，多个 `unpricedWarningMany`；模型名用界面语言的分隔符（`message.turnUsage.modelSeparator`，zh/ja「、」，ar「، 」，其余「, 」）拼接，模型 id 本身不翻译。
- 外框：面板组件 `agent-stream/turn-usage-panel.tsx` 自己渲染 `TooltipContent`（`testID="turn-usage-panel"`），显式传 `maxWidth={300}`，通过 `style` 把外框 `width` 定为 300、padding 设为 0、圆角 `radius.lg`（10），由面板内部分区负责内边距（左右 12；原型的 14、10 不在间距刻度上，按 `docs/design.md` §14 取 12 / 8）。窗口不足时由定位算法把左边夹在 8px；窗口窄于 316 时右侧会越出，App 的最窄目标是 390，不处理。分区之间用 1px border 色分隔线分开。Tooltip 组件本身的默认值和其他调用方不变。
- 内容自上而下：头部「本轮用量」和时钟图标加耗时（12，muted）；估算成本大字（display 24/500，等宽数字），后接「估算成本」（12，muted），本轮有模型无价格数据时加点状下划线；统计格，每格上面是标签（micro 11），下面是数值（label 13），依次为输入、缓存、输出，推理 > 0 时加「其中推理」；格宽按内容伸缩而不是原型的等分（en「Incl. reasoning」、fr「Dont raisonnement」在等分的 62px 里放不下），标签与数值都单行省略；单模型时是一行「模型 <id>」，多模型时是「按模型」小标题加每模型两行（第一行 caption 12 的模型名和成本，第二行 micro 11 的 `↑输入 · 缓存 N · ↓输出`，有推理时追加 ` · 推理 N`，不用原型的括号写法），无价格数据的模型成本位置写「无价格数据」（warning 色）；只用了一个模型且它无价格数据时，「模型 <id>」行不另加标记，靠总成本的点状下划线和底部提示说明（与原型一致）；底部脚注「估算成本 · 按公开 API 价格计算」，有模型无价格数据时上面加一行 warning 色提示，写明哪些模型按 $0 计入、可在「设置 › 价格表」自定义。
- 模型名单行省略，不撑宽面板。所有数字用等宽数字。
- 触发方式（桌面悬停、紧凑布局点按）、`delayDuration`、面板不接收指针事件，都保持现状。
- 骨架条、footer 那段文字和它的悬停底色保持不变。

**文案**：所有新增和修改的文案在 9 种界面语言（en、zh-CN、ja、ko、fr、es、pt-BR、ru、ar）里同时补齐。沿用术语表的叫法：价格表、自定义价格、无价格数据、估算成本、本轮用量、LiteLLM 价格。单复数继续用两个键、由代码选键，不用 i18next 的复数后缀。改版后不再使用的键（面板的列名、合计、推理括号写法，价格表的来源列、操作列、「自定义价格」按钮文案等）随改动删除。

**文档**：`docs/glossary.md` 的 Price table、Custom price 条目已按新的分组与操作更新。`docs/usage.md`「Your own prices」一节里「the price table's amber pill shows」的说法要跟着改成新界面的表述，并补一句：「移除自定义价格」即删除覆盖项。

## Testing Decisions

好的测试只验证外部行为：给定输入，看输出、看用户能看到和能点到的东西，不断言内部状态、组件结构或调用顺序。测试名按行为命名，与现有测试的写法一致。

- **纯逻辑单元测试**（现有的价格表纯函数测试文件与每轮用量测试文件）：
  - 分组：无价格数据和已自定义的进自定义组，且无价格数据在前；LiteLLM 定价的进 LiteLLM 组；正在从 LiteLLM 行自定义的模型出现在自定义组、不出现在 LiteLLM 组；两组都保持 daemon 的顺序；去重后的列表不会产生重复行。
  - 搜索：不区分大小写、去首尾空格、只过滤 LiteLLM 组，空搜索词返回全部。
  - 移除覆盖项：删掉匹配项（忽略大小写和空格，重复的同名项一并删掉），其余项与 `note` 原样保留，列表里没有这个模型时原样返回。
  - 行状态 reducer：编辑、取消、输入、校验失败、写回开始/失败/保存/移除的状态转换，以及一次只写一行的判定（`price-rows.test.ts`）。
  - 无价格数据计数。
  - 面板视图模型：单模型、多模型与没有按模型明细的判定；总计包含推理且推理不重复加进输出；无价格数据的模型被列出（「全部有价格」取 daemon 的 `priced`，不在客户端重算）；成本在全部无价格时为 0；底部提示一个与多个模型各用一个键，且这两个键存在。
  - 先例：现有的 `pricing.test.ts`、`turn-usage.test.ts`。
  - 现有「每个运行时拼出来的键都存在」的资源测试要覆盖新键。
- **浏览器组件测试**（vitest `browser` 项目，新增 `*.browser.test.tsx`）：在真实浏览器里挂载新面板的内容和外框，量几何，覆盖三种情况：单模型带推理、多模型、含无价格数据的模型。断言：内容的左右边都在外框内（不溢出）；外框宽度等于设定宽度；带推理和长模型名时模型名元素宽度大于 0 且不超出面板；统计格的数值（不是格子容器）在同一行对齐。桌面 1280 与 390 两种视口各跑一遍，并断言外框按触发段居中、夹紧在 8px 内。先例：`status-badge.browser.test.tsx`（真实浏览器里用 getComputedStyle 断言）。
- **Playwright e2e**（在现有的价格表 e2e 文件里扩展，走真实 daemon 和用量夹具）：
  - 无价格数据的模型出现在自定义价格组；保存后仍在该组、显示数值，用量页的估算成本跟着变（在现有用例上改）。
  - 移除自定义价格：原本无价格的模型回到无价格数据的编辑态，daemon 配置里只删掉它的覆盖项，别的覆盖项和 `note` 保留；LiteLLM 有价格的模型回到 LiteLLM 组；daemon 拒绝时这一行显示本地化句子加原因、覆盖项不变。
  - 在 LiteLLM 行上点「自定义」：这一行出现在自定义组、预填 LiteLLM 价格；取消后回到 LiteLLM 组；保存后变成自定义价格。
  - LiteLLM 组默认折叠，展开后搜索能过滤、无结果时显示提示。
  - 现有的自动更新、刷新、保存被拒这些用例按新布局调整选择器，行为断言不变。
  - e2e 很重，按项目规矩推到 CI 跑，本机只跑改动的单个文件。
- 本轮用量面板不新增 e2e：现有的真实 Claude 轮次 e2e 会调用真实服务商，布局由浏览器组件测试覆盖。
- 原生端（iOS/Android）没有模拟环境，不做实机验收，在验收项里注明免验。

## Acceptance Criteria

- [ ] 价格表分为「自定义价格」「LiteLLM 价格」两组。自定义组包含所有无价格数据和已自定义价格的模型，无价格数据的在前；LiteLLM 组包含其余模型。每个模型只出现一次。
- [ ] 自定义组的四个价格列：表头、输入框里的数字、只读数值右对齐到同一条线，输入框等宽、带 `$` 前缀；在 720 宽的设置栏里不出现横向滚动。
- [ ] 保存自定义价格后，这一行留在自定义组、显示数值、状态为「自定义价格」，用量页的估算成本随之重算。
- [ ] 四列没填全或非数字时，状态行显示错误，空格子标危险色边框，下面的行不移动；daemon 拒绝时显示本地化句子加 daemon 原因。
- [ ] 已自定义的模型可以编辑后保存或取消，也可以「移除自定义价格」：原本 LiteLLM 有价格的回到 LiteLLM 组，没有的回到无价格数据的编辑态；daemon 配置里只删掉这一项，其他覆盖项和它们的 `note` 保留。
- [ ] 自定义组为空时显示「所有模型都有价格」。组标题显示数量，并在有无价格数据的模型时显示其个数。
- [ ] LiteLLM 组默认折叠，显示模型数；展开后可按模型名搜索（不区分大小写），无结果时有提示。
- [ ] LiteLLM 行的「自定义」在桌面上悬停时出现、在紧凑布局和原生端常显；点后该模型进入自定义组并以 LiteLLM 价格预填，取消后回到 LiteLLM 组。
- [ ] 自动更新开关和「立即刷新」位于 LiteLLM 组标题右侧（紧凑布局在页面底部单独一张卡片）；副标题区分快照与联网更新、显示多久前更新和单位；控件失败的原因显示在 LiteLLM 组里。
- [ ] 加载中、需要连接主机、需要更新主机、出错可重试、没用过任何模型这些页面级状态，都照旧显示。
- [ ] 紧凑布局（390 宽）下价格表不横向滚动：模型名一行，四个输入框一行，操作在下。
- [ ] 本轮用量面板在桌面和 390 宽下，内容都完整落在边框内，面板对准触发的用量段，并夹紧在窗口内 8px。
- [ ] 面板按「总览 + 明细」布局：头部耗时，估算成本大字，输入/缓存/输出统计格，推理 > 0 时有「其中推理」格；单模型一行模型名，多模型逐个列出成本和 token。
- [ ] 带推理的轮次里模型名可见，推理不再拼进输出数字；长模型名在一行内省略。
- [ ] 本轮有无价格数据的模型时：明细里该模型标「无价格数据」，总成本带点状下划线，底部有提示说明它按 $0 计入、可在设置 › 价格表自定义。
- [ ] 新增和修改的文案在 9 种界面语言里都有，不再使用的键已删除；资源测试通过。
- [ ] 编辑、移除自定义价格两个图标按钮和用量段有无障碍标签。
- [ ] 单元测试、面板的浏览器组件测试、价格表 e2e 按 Testing Decisions 补齐；CI 通过；`npm run typecheck`、`npm run lint` 通过。
- [ ] `docs/usage.md` 里描述价格表界面的句子已同步。
- [ ] 原生端（iOS/Android）实机验收：免验（没有模拟环境）。

## Out of Scope

- 为日志里还没出现过的模型手动添加自定义价格。
- 任何协议或 daemon 行为变更，包括让 daemon 告诉客户端「自定义价格覆盖的模型在 LiteLLM 里是否也有价格」。
- 价格表的长上下文分档、一小时缓存写、priority/flex 等计价能力（`docs/usage.md` 的 Known undercounts）。
- 折叠状态、搜索词的持久化。
- Tooltip 组件的通用改动（默认宽度、指针穿透、定位算法），以及其他使用 Tooltip 的地方。
- footer 用量段文字本身的样式、「用量」页上的明细表。
- 原型方案二（卡片式价格表、精修表格式面板）。
