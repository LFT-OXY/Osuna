# 合并上游 Paseo v0.11.0 至 v0.11.2

**Status:** ready-for-agent

依据：`research/discovery.md`（2026-10-11 的模拟合并数据、三方对比、访谈逐条确认的决定）。做法沿用 `docs/release.md` 的「Fork 分发 → 从上游同步」，本文只写这一次特有的范围、裁决与验收，不重述那一节。相关既有决定：ADR 0001（macOS 自签名证书）、ADR 0002（改名止于桌面 App 身份）、ADR 0003（指令列表不启动进程）。

## Problem Statement

Osuna 在 2026-10-11 把上游 `getpaseo/paseo` 合到了 v0.10.3，此后的同步点是 `b4af508e2`。上游在那之后发了 v0.11.0、v0.11.1、v0.11.2，共 247 个提交。Osuna 用户现在拿不到其中的东西：

- 装不了社区插件：上游的插件登记处与 `paseo plugin add 作者/插件名` 的新装法都在 v0.11.0。
- 用不了 Muse Code 与 Antigravity 两个提供方。
- 套餐用量只认得原来那几种登录，认不出 Codex CLI、OpenCode、Pi、OMP 里的 ChatGPT 登录和 Pi、OMP 里的 Claude 登录，没有 OpenCode Go，额度卡不可用时不说原因。
- OMP 不能在轮次中途插话，没有 Fast 模式与 Auto 思考档位。
- Claude 模型列表里没有 Haiku 5.5；Claude Opus 4.7 及以后的模型不显示思考行。
- 没有内容宽度设置、Vue 语法高亮、提供方级的默认选项、平板上的终端按键条。
- 105 条缺陷修复没有拿到：Claude 运行超过 30 秒的工具调用被显示成 Subagent、应用断线期间结束的 Subagent 一直显示运行中、向上翻聊天记录时跳回好几屏、Add Project 搜索目录时 daemon 卡死、ACP 智能体在一次带权限请求的失败轮次之后拒收所有消息等。

每多拖一个版本，两边同时改过的文件就多一批：这一次模拟合并已有 150 个文件冲突，上一次是 55 个。

这一段里有几处两边各走了一条路，不处理好会丢东西或让界面出现两个同名入口：

- **用量。** Osuna 的 **Usage** 是 token 与估算花费的统计，上游没有；Osuna 把订阅额度叫 **Plan usage** 并重做过界面。上游把订阅额度那一套整个重写并直接叫 Usage，代码放进了 Osuna 的 Usage 所在的同名目录，服务端也有一个同名文件，侧栏里两边各有一个编号同为 `usage` 的条目。
- **上下文圆环的提示。** Osuna 往里加了本智能体的 token、花费、用时与当前接口；上游把它拆成悬浮卡并接上了按账号显示的套餐用量。这是冲突块最多的一个文件。
- **Explorer 的标签。** 上游把标签栏整个换成工作区标签那套写法并删掉了旧的标签栏；Osuna 给旧标签栏换过外观，还多一个会话历史视图。
- **daemon 自更新。** Osuna 已下线，上游又修了它。
- **上游的补丁分支。** v0.10.1 – v0.10.3 不在上游主线上，这次合主线版本时分叉处要重解一遍。v0.11.1、v0.11.2 同样在补丁分支上。
- **上游自己的中间设计。** v0.11.0 的前五个 beta 里，上游的套餐用量是一个占用 `/usage` 地址的独立页面，到 v0.11.0 才改成弹窗。Osuna 的 Usage 页就在 `/usage`。

## Solution

把上游从 v0.10.3 到 v0.11.2 的 247 个提交整版合并进 main，用保留上游历史的 git merge。

合并在单独分支 `merge-upstream-v0-11-all` 上进行：先做一个准备提交，把 Osuna 的 Usage 代码从上游要占用的位置挪开；再按上游自己的发布点分八段合并。每段结束时分支都能通过检查，全部做完后经一个 PR 以 merge commit 并入，main 只变一次。

合并后的 Osuna：

- 多了上游这三个版本的全部功能与修复。
- **Usage**（token 与估算花费）原样保留：Usage 页、轮次页脚的花费、价格表、`/usage` 地址。
- **Plan usage** 换成上游的实现：数据、额度卡片、侧栏底部图标打开的弹窗、可选的侧栏摘要、上下文圆环的悬浮卡都是上游的；Osuna 的 Composer 用量条与 Usage 页里的套餐卡片保留，改接上游的数据与卡片。界面上仍叫「套餐用量」。
- 侧栏顶部的「用量」条目不变；底部图标行多一个「套餐用量」，少一个「导入会话」（挪到新建工作区页）。
- Explorer 的标签用上游的新写法，Osuna 的会话历史视图还在，外观仍是 Osuna 的。
- 桌面身份、更新源、签名、外链、界面中文、版本号与更新日志继续是 Osuna 的；daemon 自更新继续不存在。
- `docs/release.md` 里记录的同步点更新到 v0.11.2。

## Implementation Decisions

### 合并方式

- 合并分支 `merge-upstream-v0-11-all` 从 main `802b17d8c` 开出。先做准备提交（见下一节），再依次做八次 merge，每次一个 merge commit。上游发布点用提交 SHA 引用，不抓上游 tag。

| 段  | 上游发布点     | 提交        | 本段上游提交数 | 累计冲突文件（模拟） | 这一段带进来的主要东西                                                                                     |
| --- | -------------- | ----------- | -------------- | -------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1   | v0.11.0-beta.1 | `4aa2f2817` | 79             | 104                  | 套餐用量重写（独立页面形态）、内置插件、Muse Code 与 Antigravity、侧栏分成顶部与底部两组、导入会话挪位置   |
| 2   | v0.11.0-beta.2 | `8498c7416` | 6              | 104                  | 无新增冲突文件                                                                                             |
| 3   | v0.11.0-beta.3 | `6166a7aca` | 4              | 104                  | 无新增冲突文件                                                                                             |
| 4   | v0.11.0-beta.4 | `6b00310f7` | 62             | 125                  | Explorer 标签换写法、插件登记处、上下文圆环悬浮卡接上按账号的套餐用量、上游对 daemon 自更新的修复          |
| 5   | v0.11.0-beta.5 | `15d774d4a` | 23             | 130                  | Codex 速度菜单                                                                                             |
| 6   | v0.11.0        | `22488d450` | 58             | 147                  | 套餐用量从独立页面改成弹窗、PR 面板翻译、补丁分支分叉处的一部分（提供方注册、OpenCode 2.x）、README 与商店说明 |
| 7   | v0.11.1        | `ab10a6694` | 12             | 150                  | Haiku 5.5、Claude 的三处修复                                                                               |

- 第一段合完就开草稿 PR，目标分支 main，之后每段推送后看 CI。
- 并入 main 用 merge commit，不 squash、不 rebase。合并期间 main 有新提交时把 main 合进合并分支。

### 中间段的处理原则

### 套餐用量

## Testing Decisions

好的测试只断言外部行为：给定输入与状态，用户或调用方看到什么。这次是合并，测试的作用是证明两边的行为都还在，因此优先用已有的测试和上游随合并带来的测试。只在一处新开用例：Osuna 的行为要搬到上游的结构上、而原来的用例跟着旧结构一起消失的地方，把用例加进上游或 Osuna 已有的那个测试文件，不另建套件。

### 接缝

1. **CI 全套作业**（最高接缝）。format、lint、typecheck、server-tests、desktop-tests、app-tests、sdk-tests、playwright 分片、relay-tests、cli-tests。上游为这 247 个提交带来的测试随合并进入这些作业，Osuna 的测试守住 Osuna 的功能。
2. **冲突文件对应的现有测试**，本机逐个文件跑：
   - Usage 的全部现有测试，准备提交前后各跑一遍，断言不变。
   - 侧栏条目模型的测试：上游的两组用例，加「已保存的顶部顺序含用量时原样读出」的用例。
   - 套餐用量：上游的模型、固定窗口、偏好、文案测试；Osuna 的用量条与视图测试改接上游数据后仍通过。
   - 上下文圆环的工具函数测试与组件测试：上游的用例，加 Osuna 的 token、花费、用时、升级提示用例。
   - Explorer 标签的测试：上游的用例，会话历史相关的预期按 Osuna 的行为。
   - Composer 控件的工具函数测试；PR 面板的检查汇总与数据测试；设置存储的测试；外观应用的测试。
   - Claude、Codex、OMP、Pi、通用 ACP、OpenCode 2.x 的会话测试；提供方注册、提供方目录会话、提供方快照的测试；Claude 模型清单的测试。
   - 协议的兼容测试；服务端的会话与 websocket 测试中本段改动过的文件。
3. **Osuna 不变量的现有测试**。桌面更新源的测试、翻译资源测试、指令目录的测试与 Claude 指令列表的 daemon e2e（取列表不启动进程）。
4. **Playwright 浏览器用例**（CI）。Osuna 的 Usage 页套餐用量用例与圆环提示用例随上游的同名文件删除而冲突：保留 Osuna 的，改到新的数据来源与新的悬浮卡上；上游为弹窗与侧栏摘要带来的用例照收，文案按「叫法」改预期。
5. **dev 桌面端实测**。见验收清单。
6. **本机打一个 macOS 包**。核对内置插件目录在包里，打开后套餐用量与两个新提供方出现。

Explorer 标签的拖放、弹窗的桌面与窄屏两种形态没有合适的单元测试接缝，由 Playwright 用例（CI）与 dev 桌面端截图把关。改了栏目与侧栏结构的桌面 e2e、涉及快捷键的 e2e 在本机 macOS 上跑不通，只在 CI 上验。

### 规则

- Osuna 原有的测试不删除、不跳过、不放宽断言。因换成上游实现而必须跟着改的断言（圆环提示变悬浮卡、套餐用量的数据来源与 testID、侧栏底部图标）逐条列进 PR 正文。
- 上游改旧用例的断言不会报冲突。每段合完，对该段冲突涉及的测试文件对比合并前后，确认没有 Osuna 的断言行被悄悄删掉。
- 上游带来的测试要通过。与 Osuna 有意做的决定矛盾时改测试，并在 PR 正文说明是哪条决定。本次已知的几类：把订阅额度叫 Usage 的文案断言、`/usage` 上的中间页面、daemon 自更新、主机设置页的套餐用量区块、不知道会话历史标签与顶部「用量」条目的默认值。
- 每段合完，把这一段新增或改动过的测试文件逐个跑一遍（server 与 desktop 的 typecheck 不含测试文件）。
- 本机只跑改动涉及的单个测试文件，整套测试交给 CI。本机复核前先挪开旧的 Vite 预构建缓存与 `.expo` 类型。
