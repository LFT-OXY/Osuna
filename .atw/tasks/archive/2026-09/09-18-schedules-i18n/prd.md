# 计划（Schedules）功能面文案接入 i18n，补齐 9 种语言

## Problem Statement

用户把应用语言切到简体中文后，侧边栏的「计划」入口是中文，但点进去之后整个计划功能面仍是英文：列表页标题、Active/Ended 分段、空态文案、「New schedule」按钮、新建/编辑表单的全部字段与占位符、列表行的状态徽标与时间信息、删除确认框、频率预设和 cron 表达式的人类可读描述。计划功能面从未接入应用已有的 i18n 机制，硬编码英文约 90 处。其它 8 种非英文语言同样受影响。

## Solution

把计划功能面的所有用户可见字符串改为通过 i18next 取值，新增翻译键同时补进全部 9 种语言资源。cron 派生描述与相对时间等由纯函数生成的文案改为返回「翻译键 + 参数」的结构化描述，由组件层渲染成当前语言。术语固定为 Schedule =「计划」、Heartbeat =「心跳」（已写入 `docs/glossary.md`）。

## User Stories

1. 作为中文用户，我希望计划列表页的标题显示「计划」，以便与侧边栏入口一致。
2. 作为中文用户，我希望列表页的 Active/Ended 分段显示「活跃」/「已结束」，以便知道自己在看哪一类计划。
3. 作为中文用户，我希望没有活跃计划时看到中文空态标题、说明和「查看文档」链接，以便理解计划是做什么的。
4. 作为中文用户，我希望没有已结束计划时看到中文空态，以便确认这里确实为空。
5. 作为中文用户，我希望「New schedule」按钮显示「新建计划」，以便知道从哪里创建。
6. 作为中文用户，我希望列表加载失败时看到中文提示，以便知道出了问题。
7. 作为中文用户，我希望新建表单的标题显示「新建计划」，编辑时显示对应的编辑标题，以便区分自己在做什么。
8. 作为中文用户，我希望表单字段标签是中文：名称、提示词、主机、项目、模型、思考、模式、隔离方式、目标、频率、最大运行次数、完成后归档，以便看懂每个字段。
9. 作为中文用户，我希望占位符是中文：名称的「可选」、提示词的「每次运行时 agent 应该做什么？」、最大运行次数的「不限」，以便知道该填什么。
10. 作为中文用户，我希望下拉选择器的占位、空态与提示是中文（如「选择项目」「未找到项目」「请先选择主机」「此模型没有可用模式」），以便理解选择器状态。
11. 作为中文用户，我希望隔离方式的选项显示「本地」和「Worktree」，以便与应用其它地方对 Worktree 的用法一致。
12. 作为中文用户，我希望频率预设显示中文（每分钟、每小时、每天 9:00、工作日 9:00、每周一 9:00、自定义 cron），以便快速选择。
13. 作为中文用户，我希望 cron 输入框下方的人类可读描述是中文（每小时 :15、每天 09:00 UTC、工作日 09:00 UTC、每周日 09:00 UTC），以便确认表达式含义。
14. 作为中文用户，我希望 cron 为空时的校验提示是中文「输入 cron 表达式」，以便知道缺了什么。
15. 作为中文用户，我希望 cron 表达式无效时看到中文的「无效的 cron 表达式」并附带具体原因，以便修正。
16. 作为中文用户，我希望表单底部的按钮显示「取消」「创建计划」「保存更改」，以便明确操作。
17. 作为中文用户，我希望提交前的本地校验错误（如未选择 cron 频率）是中文，以便知道为何不能提交。
18. 作为中文用户，我希望目标 agent 不可用或无标题时显示「Agent 不可用」「未命名 Agent」，以便理解目标状态。
19. 作为中文用户，我希望列表行的状态徽标显示「活跃」「已暂停」「已过期」「已完成」「目标已丢失」，以便一眼看出计划状态。
20. 作为中文用户，我希望列表行的元信息显示「创建于 …」「上次运行 …」「从未运行」「下次运行 …」，以便了解计划历史与未来。
21. 作为中文用户，我希望下次运行的相对时间是中文（即将、3 分钟后、2 小时后、1 天后），以便快速判断。
22. 作为中文用户，我希望列表行的频率描述是中文（每 5 分钟、每 2 小时、每天 09:00 UTC），以便与表单里的描述一致。
23. 作为中文用户，我希望行内操作的进行中文案是中文（恢复中…、暂停中…、启动中…、删除中…），以便知道操作正在执行。
24. 作为中文用户，我希望删除确认框的标题、正文和确认按钮是中文，并按对象显示「删除计划」或「删除心跳」，以便确认删除的是什么。
25. 作为中文用户，我希望无标题的计划或心跳显示「未命名计划」「未命名心跳」，以便区分对象类型。
26. 作为使用屏幕阅读器的中文用户，我希望编辑按钮、输入框等无障碍标签是中文，以便被正确朗读。
27. 作为其它语言（阿拉伯语、西班牙语、法语、日语、韩语、葡萄牙语、俄语）用户，我希望以上全部文案在我的语言下同样本地化，以便获得与中文用户相同的体验。
28. 作为英文用户，我希望所有英文文案与现在逐字相同，以便不受本次改动影响。
29. 作为维护者，我希望翻译键集中在一个命名空间下，以便后续新增计划相关文案时有明确落点。
30. 作为维护者，我希望 cron 描述与相对时间的纯函数保持可单测，以便不依赖 React 环境验证逻辑。
31. 作为维护者，我希望现有浏览器 e2e 无需改动即可通过，以便本次改动不扩大验证面。
32. 作为维护者，我希望 daemon 返回的错误消息不被本次改动触碰，以便不引入协议层变更。

## Implementation Decisions

- **命名空间**：在翻译资源中新增顶层 `schedules` 命名空间，按 screen、form、cadence、row、delete、productName 分组。所有 9 个语言文件同步新增完全相同的键集合。
- **英文原文逐字不变**：英文资源中的字符串与当前硬编码文案完全一致，包括无障碍标签「Schedule name」「Max runs」和按钮「Create schedule」，因为浏览器 e2e 按这些英文无障碍名定位控件。
- **术语**：Schedule =「计划」，Heartbeat =「心跳」；Worktree 不译；Agent 不译；「Plan」模式与 Schedule 在中文里共用「计划」，靠上下文区分（已记入术语表）。
- **纯函数返回结构化描述**：`describeCron`、`formatCadence`、`formatNextRun`、`validateCron` 不再返回英文字符串，而是返回「翻译键 + 参数」的描述对象（无法识别的 cron 形态仍返回 null，调用方回退到原始表达式）。星期几、Daily/Weekdays/Weekends 各自是独立键；「每 N 分钟/小时/天」按单复数拆成独立键并带 count 参数，与现有 `modelCountPlural` 的做法一致，不使用 i18next 复数后缀。
- **渲染助手**：计划模块提供一个把描述对象渲染为字符串的助手，接收 t 函数与描述对象，处理参数里嵌套的翻译键（如「每周 {{day}} 09:00」里的 day）。列表行与频率编辑器都通过它渲染，避免两处各自拼装。
- **产品名与标题**：`scheduleProductName` 改为返回 `"heartbeat" | "schedule"` 标识；组件按标识查「计划/心跳」译名拼装「删除心跳」「未命名心跳」「编辑心跳 X」等文案。`resolveScheduleTitle` 的「Untitled …」回退迁移到组件层。
- **频率预设**：预设选项从携带英文 label 改为携带翻译键；选择器渲染时翻译。`resolveCronPresetDisplay` 同样返回键。
- **cron 校验错误**：空输入返回「空」标识，由组件翻译；来自 cron 解析库的具体原因保留为参数，组件渲染为「无效的 cron 表达式：{{detail}}」，detail 本身保持库返回的英文。
- **表单模型中的显示文案**：`schedule-form-model` 与 `schedule-derivation` 里的「Default mode」「Untitled agent」「Agent unavailable」改为返回标识，由表单组件翻译；模型层不引入 i18n 依赖。
- **状态徽标**：`stateBadge` 保留 variant 判定，label 改为翻译键。
- **保持不动**：`utils/time.ts` 的 `formatTimeAgo`（"5m ago"）是全局共用且注释声明有意保留英文，本次仅把「Created/Last run」前缀本地化，相对时间部分沿用现状。
- **daemon 错误**：提交失败时显示的 daemon 错误消息保持英文，与项目对连接错误的处理惯例一致，不改协议。

## Testing Decisions

- 好的测试只看外部行为：翻译资源是否完整一致、纯函数对给定 cron 返回哪个键与参数、组件在 en 下渲染出的文案是否与之前相同。不测 t 是否被调用。
- **翻译资源**：沿用 `i18n/resources.test.ts`。它已经强制 9 种语言键集合一致、每种语言与英文相同字符串低于 25%、插值占位符一致，新增键自动纳入，不加新用例。
- **纯函数**：`utils/schedule-format.test.ts` 与 `schedules/schedule-cadence-options.test.ts` 的断言从英文字符串改为结构化描述对象；用例集合与覆盖的 cron 形态保持不变，只改期望值。
- **浏览器 e2e**：`e2e/browser/schedules-project-target.spec.ts` 不改动，作为「英文原文逐字不变」的守卫。
- **人工 QA**：启动 dev 桌面端切到 zh-CN，对列表空态与新建表单截图，作为 UI 证据附在完成报告中。
- **常规检查**：`npm run typecheck`、`npm run lint`，改动后必跑。
- 先例：`i18n/resources.test.ts` 的资源约束用例；`screens/project-settings-screen.tsx` 中以 `titleKey`/`placeholderKey` 携带翻译键、组件层 `t()` 的模式。

## Out of Scope

- `formatTimeAgo` 等全局共用时间格式化工具的本地化。
- daemon、CLI、MCP 返回的任何消息。
- cron 解析库产生的错误细节文案。
- 侧边栏、命令中心里已经翻译的计划入口。
- 已回退的 plan-i18n-zh（Agent Plan 模式文案）任务范围。
- 公开文档 paseo.sh/docs/schedules 的中文化；「查看文档」链接目标不变。

## Further Notes

- 验收通过后直接提交到 main。
- 非中英语言的译文由实现方给出，质量以可读、术语一致为准，不承诺母语级。
- 完成后若发现翻译资源测试的 25% 回退阈值被某语言逼近，应优先补译而不是放宽阈值。
