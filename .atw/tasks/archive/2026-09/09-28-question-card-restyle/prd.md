# 美化问题选择卡片

## Problem Statement

Agent 提问时（Claude 的 AskUserQuestion、Codex、OpenCode、Pi、OMP 的选择或输入请求），对话流里会出现一张问题卡片。这张卡片现在显得粗糙：每个选项前是普通单选圆点或复选框，"其他"是常驻在选项下面的一整条输入框，底部并排着"忽略"和强调色的"提交/下一步"两个按钮。即使只是点选一个答案，也要先选中、再去底部按提交，多走一步。卡片的视觉语言也和 Composer、弹窗这些新改过的界面对不上。

另外，这张卡片目前没法只跳过某一道题：要么答完所有题，要么点"忽略"放弃整组问题。

## Solution

问题卡片改成一张干净的编号列表（视觉参考 `research/reference.png`）：

- 顶部是问题文字，右上角是一个 X，用来忽略整组问题。
- 每个选项占一行：左边是带编号的小圆圈，右边是选项名；如果选项有说明，就用弱化的颜色换行显示在选项名下面。选项名里不再重复写编号。
- 桌面和网页上，悬停的行会有底色；点下去就作答的行（单选行）右侧还会出现一个 → 箭头。
- 单选题点一行就算作答，不需要再按提交。只有一道题时直接提交；有多道题时跳到下一道还没处理的题，最后一道处理完就提交。
- 允许自由输入的题，最后一行是带编号的"其他..."行。点击后这一行原地变成输入框，回车或按按钮确认。
- 多选题点一行只是切换选中，选中时编号圆圈填成强调色并打勾，右下角出现"下一步/提交"按钮。
- 右下角始终有"跳过"，只跳过当前这一题。
- 有多道题时，顶部保留题目标签页，样式跟新卡片统一。

## User Stories

1. 作为用户，我想看到每个选项前面有编号圆圈，以便一眼看出有几个选项、它们的顺序。
2. 作为用户，我想让选项名里不再出现重复的「1.」，以便行内容更干净。
3. 作为用户，我想让选项说明换行、用弱化颜色显示在选项名下面，以便长说明也好读，并且能跟选项名区分开。
4. 作为桌面/网页用户，我想在鼠标悬停时看到这一行出现底色；点下去就会作答的单选行右侧还出现 →，以便知道点下去就会作答。
5. 作为手机/平板用户，我想在按下一行时得到按压反馈，以便确认已经点中；原生端不显示悬停箭头。
6. 作为用户，我想在只有一道单选题时点一个选项就直接提交，以便少点一次。
7. 作为用户，我想在有多道题时点完单选项自动跳到下一道还没处理的题，以便连续作答。
8. 作为用户，我想在最后一道还没处理的单选题上点完选项就直接提交整组答案，以便不用再找提交按钮。
9. 作为用户，我想在点标签页回到前面某道题改答案后，卡片跳到下一道还没处理的题；如果已经没有，就直接提交，以便改答案的操作和作答一样一步到位。
10. 作为用户，我想在回到已答的单选题时看到之前选中的那一项处于选中状态，以便知道自己选过什么。
11. 作为用户，我想点右上角的 X 忽略整组问题，以便不回答时能快速关掉。
12. 作为用户，我想点「跳过」只跳过当前这道题、进入下一道还没处理的题，以便不会的题留空、其他题照常回答。
13. 作为用户，我想在跳过最后一道还没处理的题时，把已经作答的答案提交出去，以便部分回答也能送达 Agent。
14. 作为用户，我想在一道题都没有作答（全部跳过）时，结果和点 X 一样，以便 Agent 不会收到一份空答案。
15. 作为只面对一道题的用户，我想让「跳过」和 X 的效果一样，以便操作结果可以预期。
16. 作为 OMP/Pi 可选输入的用户，我想让 provider 自定义的跳过文案（比如 "Skip"）显示在「跳过」按钮上，并且继续提交空答案，以便现有的可选输入流程不受影响。
17. 作为用户，我想在允许自由输入的题里看到带编号的"其他..."最后一行，以便知道可以不选预设选项、自己写。
18. 作为用户，我想点"其他..."行后这一行原地变成输入框并自动获得焦点，以便马上开始输入。
19. 作为用户，我想在输入框里按回车确认答案并进入下一题或提交，以便用键盘完成输入。
20. 作为手机用户，我想在输入框有内容时看到「下一步/提交」按钮，以便软键盘没有回车时也能确认。
21. 作为用户，我想在输入了自定义内容后又点了预设选项时，以预设选项为准，以便答案没有歧义。
22. 作为用户，我想在没有预设选项的纯输入题里直接看到输入框和「下一步/提交」按钮，以便直接作答。
23. 作为用户，我想在允许留空的纯输入题里不填内容也能按「下一步/提交」，以便可选题可以直接略过。
24. 作为多选题用户，我想点一行切换选中，选中时编号圆圈变成强调色并打勾，以便清楚看到选了哪些。
25. 作为多选题用户，我想在至少选了一项后按「下一步/提交」确认，以便选完再统一提交。
26. 作为用户，我想让「下一步/提交」按钮的文字准确反映结果：还有其他没处理的题时显示「下一步」，这是最后一道时显示「提交」，以便知道按下会发生什么。
27. 作为多题用户，我想在顶部标签页里看到每道题的 header，已作答的题带勾，以便掌握进度并能点回任意一题。
28. 作为单题用户，我不想看到标签页，以便卡片保持简洁。
29. 作为用户，我想在答案发送过程中让卡片上的所有控件不可点，并在触发提交的位置看到加载指示，以便不会重复提交。
30. 作为亮色和暗色主题的用户，我想让编号圆圈、悬停底色、选中强调色、边框都清晰可辨，以便在两种主题下都好用。
31. 作为读屏用户，我想让单选行以单选项、多选行以复选框的身份朗读，"其他..."行以按钮朗读，展开后的输入框以题目文字朗读，X 以「忽略」朗读，以便在看不到界面时也能作答。
32. 作为中文和其他 8 种语言的用户，我想让「跳过」按钮以我的语言显示，以便界面语言一致。
33. 作为窄分栏或手机用户，我想让卡片在窄宽度下仍然正常显示：长选项名和说明自动换行，底部按钮靠右排在一行，以便不溢出。

## Implementation Decisions

- **范围只在 app 端的问题卡片及其纯逻辑模块。** 挂载点（Agent stream 里 `request.kind === "question"` 的分支）和它交给卡片的 `permission`、`onRespond`、`isResponding` 接口保持不变；协议和各 provider 的答案映射不动。已核对：Claude、Codex、OpenCode 都会自动略过答案里缺失的题（见 `research/discover-decisions.md`）。
- **每题的处理状态显式记录**：每道题的状态是「未处理 / 已作答 / 已跳过」三者之一（实现里缺省即未处理），只由用户操作改变。点单选项、在多选或输入题上按「下一步/提交」或回车，会把这道题标为已作答；按「跳过」会标为已跳过，并清空这道题已有的选择和输入。在多选题上切换选项、或改动输入框内容，会把这道题退回未处理，需要重新确认；否则标签页的勾和实际提交的答案会对不上。状态不能从"有没有选择"推出来，因为允许留空的输入题本身就算"已答"，推出来会让导航直接越过它。
- **推进规则（纯函数，放进现有 core 模块）**：当前题处理完后，从当前题往后找第一道未处理的题，找不到再从头往前找；都没有就结束。结束时用现有的答案序列化生成答案，已跳过的题不写入；答案为空就走现有的忽略路径。忽略路径里已有的「全部是允许留空的输入题时提交空答案」规则继续保留。
- **「下一步/提交」按钮**：只在多选题、纯输入题、"其他..."行展开时出现。除当前题外已经没有未处理的题时显示「提交」，否则显示「下一步」。可用条件沿用现有的「本题是否可作答」判断，两处收紧：`allowEmpty` 只对没有预设选项的纯输入题生效（有预设选项时空着的"其他..."不算作答，否则会记成已作答却写不出答案）；单选题展开"其他..."后只看输入内容，免得回车误交之前选过的预设项。单选题不显示这个按钮。
- **X 与「跳过」**：X 是图标按钮，走现有的忽略路径，无障碍名称沿用 `common.actions.dismiss`。只有一道题时，「跳过」也走忽略路径。忽略路径提交空答案时不带上已输入的内容，X 和单题的「跳过」因此是同一个结果。「跳过」的文字取 provider 给的 `dismissLabel`，没有就用新增的 i18n key `message.question.skip`（9 个 locale 都要补）。
- **"其他..."行**：编号接在预设选项后面。行文字取题目的 `placeholder`，没有就用现有的 `message.question.otherPlaceholder`。点击后原地换成输入框并自动聚焦；输入框的无障碍名称是题目文字。输入内容会清掉预设选择，点预设选项会清掉输入内容（沿用现有的互斥行为）。
- **视觉**：遵循 `docs/design.md`：
  - 卡片用卡片语言：`surfaceCard` 填充、1px `border`，圆角按参考图比现在大一档。
  - 编号圆圈是固定尺寸的正圆：未选中时浅底、细边、`foregroundMuted` 数字；选中时 `accent` 填充、`accentForeground` 勾。
  - 行悬停用 `interactionHighlight` 底色，→ 只在悬停时出现，而且只出现在点下去就作答的单选行；多选行（点下去只切换）和"其他..."行（点下去只展开）不显示。原生端和紧凑布局不显示 →。
  - 纯输入题用 `FormTextInput` 原语。展开后的"其他..."行框内要保留编号圆圈，所以自绘外框，四态样式（静止、悬停、聚焦描边、禁用）和 `FormTextInput` 一样取自 `control-geometry`。外框不是按压目标，悬停用普通 `View` 的 pointer 事件。
  - 所有文字都用 `fontWeight.normal`。
  - 状态切换不能让行高或布局跳动：编号圆圈和箭头的位置要预留好。
- **按钮用 `<Button>` 原语**：X 用 ghost 图标按钮，「跳过」用 outline，「下一步/提交」用 default（强调色，全卡片唯一的 CTA）。不再用 `Pressable` 包 `Text` 自己拼按钮。
- **去掉 `useUnistyles()`**：改写时按 `docs/unistyles.md` 给的替代顺序处理，主要用 `StyleSheet.create((theme) => …)` 和 variants；图标颜色也用文档里的替代方式。悬停按 `docs/hover.md` 的规则：行只用 `Pressable` 的 hovered 状态给自己上样式。
- **加载态**：发送中所有控件禁用；由选项行触发的提交，在该行的箭头位置显示 `LoadingSpinner`；由按钮触发的，在按钮上显示。
- **测试钩子保持稳定**：`question-form-card`、`question-form-current-question`、`question-form-primary-action`（即「下一步/提交」）、标签页 `Question N of M` 这些 testID 和无障碍名称都保留；新增「跳过」的 testID。
- **mock agent 增加题型变体**（只改测试支持代码）：一道带"其他..."的单选题（`Emit synthetic questions: one single-choice question with other.`）、一道多选题（`... one multi-select question.`），由新的提示词触发，不改动现有的 synthetic questions 提示词。
- **mock agent 回写收到的结果**（实现中经用户确认加入）：问题请求被回答后，mock 发一条助手消息 `Synthetic questions resolved: header=答案; ...`（按题目顺序），被忽略时发 `Synthetic questions dismissed`。否则 e2e 分不清卡片是提交了答案还是走了忽略。

## Testing Decisions

- **好的测试只验证外部行为**：给定题目和一串用户操作，卡片接下来显示哪道题、什么时候提交、提交了什么答案、什么时候走忽略路径。不测试样式数值和组件内部状态。
- **接缝 1（Node 单元测试，现有 `question-form-card-core` 测试文件）**：推进和结束规则：
  - 单题单选作答后结束。
  - 多题时跳到下一道未处理的题，往后找不到就从头找。
  - 回头改答后，如果其余题都已处理，就结束。
  - 跳过会清空这道题的答案，且不写入最终答案。
  - 全部跳过或最终答案为空时，结果是「忽略」。
  - 允许留空的输入题确认后算已作答，不会被导航越过。
  - 「下一步」和「提交」的文字判定。
  - `dismissLabel` 会覆盖「跳过」的文字。
  - 先例：同一个文件里现有的 `buildQuestionFormAnswers`、`shouldSubmitEmptyOnDismiss` 测试。
- **接缝 2（浏览器 e2e，现有 `question-prompt-pagination.spec.ts` + mock agent）**：
  - 先改 `e2e/support/helpers/questions.ts`，保证现有两个用例（多题分页、纯输入题的 Next→Submit）继续通过。
  - 补的用例：单题单选点击即提交；多题中跳过一题后提交；"其他..."行展开、输入、回车提交；多选题勾选后提交；X 忽略。每个用例都用精确文本断言 mock 回写的答案摘要或 dismissed。
  - 其他用到这些 helper 的 spec（`agent-scroll-return`、`permission-steer.real`、`plan-approval.claude.real`）只保证不被改坏。
- **视觉验收**：在 Electron 或浏览器里截亮色和暗色两张图，和 `research/reference.png` 对照。
- **执行方式**：按仓库规则只跑改动的单个测试文件。e2e 本机跑不通时交给 CI。每次改动后跑 typecheck 和 lint。

## Out of Scope

- 键盘操作：数字键选择、上下键移动高亮、Esc 忽略。
- 普通权限请求卡片（允许/拒绝工具调用）和计划审批卡片。
- 协议、daemon、各 provider 的答案映射，以及问题数据结构的任何改动（mock agent 只加测试用的题型变体和结果回写）。
- 标题前加 `[header]` 前缀；用「1/3」进度代替标签页。
- 把编号列表抽成通用 UI 原语。
- 发送失败后的错误提示（现在只打日志，保持不变）。

- [ ] 桌面/网页上悬停选项行有底色，单选行还有 →；原生端没有 →，按下有反馈。
- [ ] 只有一道单选题时，点选项直接提交，卡片消失，Agent 收到这个答案。

- [ ] 「跳过」只跳过当前题；最后一道跳过后提交已有答案；一道都没答时等同忽略；单题时等同忽略。

- [ ] 多题时保留标签页，已作答的题带勾，点标签页能切换；单题时不显示标签页。

## Further Notes

- 讨论记录、代码事实、各 provider 对部分答案的处理，见 `research/discover-decisions.md`。
- 以下几点讨论时没有明确说到，由我按常规做法补全，确认 PRD 时可以一起调整：
  - 全部跳过时等同 X。原因：Codex 在答案为空时会得到 `null`。
  - 回头改答后，如果其余题都已处理就直接提交（第 9 条）。这是点击即提交的直接推论，但可能不符合"只想改一下再看看"的预期。
  - 「跳过」会清空这道题已经做出的选择和输入。
  - 「跳过」的文字优先用 provider 的 `dismissLabel`；X 始终是「忽略」。
  - 自由输入行的文字沿用现有的 `otherPlaceholder`（中文是「其他...」），不新增文案。
