# 06 — 外部改动检测与健康状态

**What to build:** Osuna 显示的状态必须和磁盘上的真实情况一致，并且绝不静默覆盖用户或其他工具的改动。

- **写入时**：先计算文件 hash，原子替换前再读一次比对。如果文件已经变了，就基于新内容重新计算，最多重试 3 次，仍然不一致就报冲突。
- **展示状态时**：读取真实文件。负责的键和 daemon 上次写入的值不一致时，状态显示为「已被外部修改」，用户可以选「重新应用」或「切回官方」。
- **Codex**：启用前检查当前生效的 profile 是否覆盖了负责的顶层键；如果覆盖了，就显示提示。
- **「官方」模式下**：CLI 自身配置已经指向第三方地址时（比如用户手写的中转站），显示「当前 Claude 自身配置指向 X」这一类提示。
