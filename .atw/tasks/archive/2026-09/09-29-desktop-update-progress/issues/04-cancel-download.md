# 04 — 取消下载与切换通道

**What to build:**

下载中的卡片出现「取消」按钮。点了之后，更新服务用 electron-updater 的取消令牌中止下载，阶段回到「发现更新」；取消不算错误，不进入失败阶段。

下载中切换发布通道（正式版/Beta）时，更新服务先取消当前下载，再清空更新状态，然后按新通道重新检查。

**Blocked by:** 02 — 手动下载主链路
**Status:** ready-for-agent
**Impl:** done

- [x] 下载中点「取消」会中止下载，卡片回到「发现更新」，没有错误提示；之后可以再点「更新」重新下载。
- [x] 下载中切换发布通道会取消下载，回到「发现更新」；新通道没有更新时显示已是最新。
- [x] 更新服务测试覆盖：取消后阶段回到发现更新且不报错；切换通道会取消下载并清空状态。描述器测试覆盖下载中阶段的「取消」按钮。
- [x] 新文案补齐 9 种语言；`npm run typecheck`、`npm run lint` 通过。

**Verification:** 主进程由 `app-update-service.test.ts`（取消回到发现更新、取消后重下、排在检查后的取消、切换通道取消/清空/补查、旧通道窗口检查不取消）和 `daemon-manager.test.ts`（检查用保存的通道、保存设置触发切换，注入假 `appUpdates` 端口）验证；渲染端由 `desktop-app-updater.test.ts`、`resolve-update-callout.test.ts` 和 `packages/desktop/e2e/updates.spec.ts`（取消成功、取消失败）验证。真实的 electron-updater 取消令牌行为按 6.8.3 源码核对（取消时 promise 以 `CancellationError` 拒绝、不发 `error` 事件），打包版里的真实取消留给发版前人工 QA。

**实现中定下的约定（审查后与用户确认）：** 切换通道由保存设置触发、检查一律用主进程保存的通道，渲染端不再传通道（修掉了窗口间设置不同步导致的通道回退）；取消进行中按钮禁用为「正在取消…」，取消命令失败走错误卡片；安装交接期间切换通道被忽略；取消太晚（包已下完）时如实进入「已下载」。已知判断题：取消后立刻再点「更新」可能短暂闪回「发现更新」；切换通道后的补查失败按静默检查规则只记日志；从未检查成功过的窗口切换通道后显示 idle 而非「已是最新」。
