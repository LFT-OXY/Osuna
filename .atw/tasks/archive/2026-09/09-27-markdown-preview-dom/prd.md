# Markdown 文件预览：Web 端 DOM 渲染 + Lezer 高亮补齐

## Problem Statement

在文件面板里打开一个普通的 GitHub 风格 README（比如本仓库的 `README.zh-CN.md`），「预览」
模式几乎是坏的：

- `<p align="center">`、`<img …>`、`<h1 align="center">` 这些原始 HTML 被当成文字原样印出来；
- 本该一行排开的徽章一张一行竖着堆下去，居中完全不生效，标题也丢了标题样式；
- `> [!NOTE]` 这种 GitHub 提示块只是一段普通引用，`[!NOTE]` 几个字就那么露着；
- 仓库里用相对路径引用的截图显示不出来；
- 指向仓库里其他 `.md` 的链接点了会被当成外链去开浏览器；
- README 里最常见的 ```` ```bash ```` 命令行代码块没有任何颜色。

同样一份文件在 t3code 里渲染得就很好：HTML 生效、徽章横排、提示块是带图标和标题的
callout、代码块着色并带语言图标 / 换行 / 复制按钮、相对图片能显示、仓库内链接是带文件图标
的 chip。

根因在渲染技术：预览走的是 React Native 渲染器（markdown-it 且关闭了 HTML），原始 HTML
靠一个手写的改写层转成 markdown，转不了就当文字输出；RN 的 flex 布局也做不出浏览器那种行内
流和 `align`。高亮这边，项目自带的 Lezer 高亮包不认识 bash / shell / toml / sql / diff /
dockerfile / ini，所以这些代码块没有颜色。

## Solution

- 在 Web / Electron 上，Markdown 文件预览换成 DOM 渲染：真正解析原始 HTML（经白名单消毒）、
  支持 GitHub 提示块、徽章行内横排、`align` 居中生效。渲染管线与版式移植自 t3code（MIT，
  保留版权声明）。
- iOS / Android 保留现有 RN 渲染器，不退化。
- 代码高亮**不引入 Shiki**：给项目自带的 Lezer 高亮包补上 bash / shell / zsh、toml、sql、diff、
  dockerfile、ini，DOM 预览把高亮结果输出成带主题色的片段，跟随用户在设置里选的语法主题。
  这些语言在对话代码块和源代码视图里也会随之有颜色。
- 代码块头部：语言图标（项目自带的 Material 文件图标）、换行开关、复制按钮。
- 相对资源：相对路径图片（markdown 语法与 `<img>`）能显示；仓库内文件链接渲染成带文件图标的
  chip，点击在新文件标签打开；页内锚点可跳转；外链仍用浏览器打开。
- 提示块标题本地化（注意 / 提示 / 重要 / 警告 / 小心）。
- 版式照搬 t3code 的 markdown 样式，颜色与字体用项目主题 token，深浅色都正确。

决策依据见 `docs/adr/0001-markdown-file-preview-dom-renderer-with-lezer.md`。

## User Stories

1. 作为在桌面端打开 README 的开发者，我希望原始 HTML 被真正渲染，这样我看到的是排版而不是一堆标签。
2. 作为同一个开发者，我希望 `<p align="center">` / `<h1 align="center">` 里的内容居中，这样项目首页的头部和 GitHub 上一样。
3. 作为同一个开发者，我希望一排徽章横着排开、放不下时自动换行，这样它们不会一张一行占掉半屏。
4. 作为同一个开发者，我希望 `<a>` 包着的徽章图片可以点击跳到链接，这样徽章的用途保留。
5. 作为同一个开发者，我希望 `> [!NOTE]` 渲染成带图标和标题的提示块，这样提示信息醒目、标记文字不外露。
6. 作为同一个开发者，我希望 TIP / IMPORTANT / WARNING / CAUTION 也各有自己的颜色与图标，这样五种提示能一眼区分。
7. 作为用中文界面的开发者，我希望提示块标题显示为「注意 / 提示 / 重要 / 警告 / 小心」，这样和界面语言一致。
8. 作为用其他界面语言的开发者，我希望提示块标题跟随我的界面语言，这样不会混进别的语言。
9. 作为同一个开发者，我希望 README 里用相对路径引用的截图能显示，这样文档里的图不是一个个空框。
10. 作为同一个开发者，我希望 `<img src="相对路径">` 与 `![](相对路径)` 都能显示，这样两种写法效果一致。
11. 作为同一个开发者，我希望图片文件在磁盘上更新后预览里的图也跟着更新，这样我改图时能直接看到效果。
12. 作为同一个开发者，我希望引用不存在的图片时显示一个明确的占位而不是整页出错，这样一张坏图不影响阅读其他内容。
13. 作为同一个开发者，我希望指向仓库里其他文件的链接显示成带文件图标的 chip，这样我知道点了会打开仓库文件而不是网页。
14. 作为同一个开发者，我希望点击这种 chip 在新的文件标签里打开目标文件，这样我能在文档之间跳转。
15. 作为同一个开发者，我希望点击 `#section` 这种页内锚点滚动到对应标题，这样长文档的目录能用。
16. 作为同一个开发者，我希望外链仍然用浏览器打开，这样行为和以前一致。
17. 作为同一个开发者，我希望 ```` ```bash ```` / ```` ```sh ```` / ```` ```shell ```` / ```` ```zsh ```` 代码块有颜色，这样命令、参数、字符串、注释一眼可辨。
18. 作为同一个开发者，我希望 toml、sql、diff、dockerfile、ini 代码块也有颜色，这样常见配置和脚本片段都好读。
19. 作为同一个开发者，我希望代码块的颜色跟着我在设置里选的语法主题走，这样预览和源代码视图配色一致。
20. 作为同一个开发者，我希望切换深浅色时代码块与正文颜色一起变，这样暗色下不会出现刺眼的亮块。
21. 作为同一个开发者，我希望代码块头部显示语言图标，这样我不用读内容就知道是什么语言。
22. 作为同一个开发者，我希望能一键切换代码块的自动换行，这样长命令我可以选择换行看全或横向滚动。
23. 作为同一个开发者，我希望能一键复制代码块内容，这样我能把命令直接贴到终端。
24. 作为同一个开发者，我希望没有标注语言的代码块以等宽纯文本显示，这样不会被错误着色。
25. 作为在对话里看到 bash 代码块的开发者，我希望它也有颜色，这样补语言的收益不止于预览。
26. 作为看 GitHub 风格表格、任务列表、删除线的开发者，我希望这些都按 GFM 渲染，这样和 GitHub 上看到的一致。
27. 作为打开带 YAML front matter 的文档的开发者，我希望 front matter 仍然以表格显示在正文上方，这样现有行为不丢。
28. 作为打开含 mermaid 代码块的文档的开发者，我希望图表仍然能渲染，这样换渲染器不会让图表退化成源码。
29. 作为打开来源不明仓库的开发者，我希望 md 里的 `<script>`、事件属性、`javascript:` 链接不会被执行，这样预览一个文件不会带来安全风险。
30. 作为同一个开发者，我希望 `<iframe>`、`<style>` 之类不在白名单里的标签被剥掉，这样文档不能篡改应用界面。
31. 作为同一个开发者，我希望预览里的文字可以选中复制，这样我能摘录文档内容。
32. 作为同一个开发者，我希望在「预览 / 源代码」之间切换、以及文件在磁盘上被修改后，预览照常刷新，这样现有的编辑流程不受影响。
33. 作为同一个开发者，我希望长单行文字在预览中自动换行不出现横向滚动，这样现有的阅读体验不退化。
34. 作为 iOS / Android 用户，我希望预览维持现在的样子、不出错，这样这次改动不会让手机端变差。
35. 作为看 PR 评论、changelog、plan 卡片的用户，我希望它们的渲染不变，这样这次改动只影响文件预览。
36. 作为维护者，我希望新语言通过现有的 legacy-modes 方式接入高亮包，这样高亮引擎仍然只有一套。
37. 作为维护者，我希望移植自 t3code 的代码保留 MIT 版权声明，这样许可合规。

## Implementation Decisions

### 渲染分层

- Markdown 文件预览按平台拆开：Web 版为新的 DOM 组件；原生版为现有的 RN 渲染路径，保持
  不变。拆分沿用项目已有的 `.web.tsx` / 默认文件约定（先例：HTML 预览、mermaid host）。
- front matter 解析与表格在两端共用、行为不变；DOM 版以 DOM 元素重建同样的表格外观。
- 只替换文件预览。对话消息、PR 评论、changelog、plan 卡片继续用现有 RN 渲染器与 html-ish
  改写层，不改。

### DOM 渲染管线（移植自 t3code）

- 解析与转换：react-markdown，remark 侧 GFM + GitHub 提示块插件（及 t3code 中服务于代码块
  元信息、链接归一化的必要插件）；rehype 侧 rehype-raw 解析原始 HTML，最后 rehype-sanitize
  按白名单消毒。白名单沿用 t3code 的 schema 思路：基于默认 schema，保留 `align` 等排版属性，
  放行提示块、代码块元信息所需的 data 属性；禁止脚本、事件属性、`style`、`iframe`，链接协议
  限于 http(s) / mailto / 仓库内相对路径 / 页内锚点。不需要 t3code 特有的协议（`t3-citation`、
  `t3-context`）与 codex directives。
- 新增依赖：react-markdown、remark-gfm、rehype-raw、rehype-sanitize（及其传递依赖），只进
  app 包。
- 移植的源文件头部保留 t3code 的 MIT 版权与许可声明。
- 不需要 t3code 的流式渲染、任务列表勾选回写、「Run in terminal」按钮。

### 提示块

- 识别 `[!NOTE] / [!TIP] / [!IMPORTANT] / [!WARNING] / [!CAUTION]`（大小写不敏感，标记独占一行），
  渲染为带图标与标题的块，标记行不显示。五种各有颜色，颜色取自项目主题 token 中语义对应的
  角色；图标用项目现有的 lucide 图标。
- 标题文案走 i18n，所有 locale 补齐。

### 代码块与高亮

- 高亮包新增语言，经 `@codemirror/legacy-modes` 接入（与 swift、dart 的现有做法一致）：
  shell（覆盖 bash / sh / zsh / shell / console 这些 fence 名）、toml、sql、diff、dockerfile、
  ini（properties）。fence 语言名到高亮语言的别名表同步补齐。
- DOM 代码块用高亮包的 token 输出，每个 token 渲染为带语义角色的片段，颜色取自当前语法主题；
  切换语法主题或深浅色时即时生效。
- 无语言、未知语言、或超过现有高亮尺寸上限的代码块以等宽纯文本显示。
- 头部：语言图标（项目自带 Material 文件图标，按语言映射到代表性文件名取图标）+ 语言名、
  换行开关、复制按钮。换行默认关闭（横向滚动），状态只在当前代码块内有效。
- mermaid fence 继续交给现有的 web mermaid 渲染，不退化。

### 相对资源

- 预览组件需要知道当前文件路径、工作区目录与 host，以解析相对路径；由文件面板传入。
- 图片：相对路径（相对当前文件所在目录）或仓库内绝对路径，经现有的工作区文件读取链路
  取得可显示的地址（与对话里的助手图片、文件面板的图片预览同一条链路）；http(s) 与 data
  图片直接显示。读取失败显示占位，不影响其余内容。文件变更后随现有刷新机制更新。
- 链接：解析为仓库内文件时渲染为带文件图标（Material 图标）的 chip，点击在新文件标签打开，
  带 `#Lx` 等行号时沿用现有的文件定位能力；`#anchor` 在预览内滚动到对应标题（标题生成
  GitHub 风格的 slug id）；其余链接用浏览器打开。
- 解析规则（相对 / 绝对 / 外链 / 锚点的分类）写成纯函数。

### 样式

- 版式照搬 t3code 的 markdown 样式：段落与标题间距、标题层级、列表、表格、引用、提示块、
  行内代码、代码块、分隔线，以及 `img` 行内排列（徽章横排的关键）。
- 颜色、字体、圆角等全部换成项目主题 token（CSS 变量或等价方式），深浅色与用户主题切换时
  正确。
- 阅读宽度、外边距沿用现有预览的 `MAX_CONTENT_WIDTH` 与留白。
- 长文字自动换行，预览不出现横向滚动（代码块内部除外）。

### 不动的部分

- 原生端预览、对话 / PR / changelog / plan 卡片的渲染、html-ish 改写层及其测试。
- 源代码视图与编辑器（除自动获得新增语言的高亮外）。
- 协议与服务端。

## Testing Decisions

好的测试只断言用户可观察的结果：预览里渲染出了什么元素、居中与横排是否成立、提示块和
代码块长什么样、点击链接打开了什么；不断言 remark/rehype 插件内部如何变换语法树。

测试接缝（均为现有接缝；本 spec 一并请用户确认）：

- **e2e：`e2e/browser/file-editing.spec.ts`**（最高接缝，真实 daemon + 写入工作区文件后在文件面板
  打开）。新增用例，写一份 README 风格的 fixture（居中 HTML 头部、一排徽章、`[!NOTE]`、相对
  路径图片、仓库内 `.md` 链接、页内锚点、bash 代码块、`<script>` 与事件属性），断言：
  - 原始 HTML 不以文字出现，居中容器计算样式为居中；
  - 多个徽章图片位于同一行（纵坐标相同）；
  - 提示块以 note 角色渲染、显示本地化标题、`[!NOTE]` 文字不出现；
  - 相对路径图片加载成功（自然宽度大于 0）；
  - 点击仓库内链接 chip 打开对应文件标签，点击锚点滚动到目标标题；
  - bash 代码块内存在着色片段，复制按钮与换行开关可用；
  - 脚本未执行、事件属性被剥离。
  现有「Markdown 预览刷新」「长行换行」用例保持不变、继续通过。
- **单测：高亮包（`packages/highlight` 现有 `__tests__`）**。每种新增语言对一小段代表性代码
  产出预期的语义 token（关键字、字符串、注释等），fence 别名解析到正确语言。
- **单测：相对资源解析纯函数**，与 app 里现有的助手图片来源解析测试同风格：相对路径、`../`、
  仓库内绝对路径、外链、锚点、带行号链接、越出工作区的路径各自分类正确。
- 原生端不新增测试；现有 RN 渲染器测试保持通过即证明未改动。
- 本地只跑改到的测试文件；e2e 本机跑不通时交给 CI。

## Out of Scope

- 对话消息、PR 评论、changelog、plan 卡片换用 DOM 渲染（可在此后复用本组件另开任务）。
- 全应用改用 Shiki（访谈中否决，理由见 ADR 0001）。
- 原生端（iOS / Android）的 HTML / 提示块支持。
- 代码块「Run in terminal」按钮。
- 引入 `@pierre/trees` 图标。
- 任务列表勾选回写到文件。
- markdown 预览内的查找（find）能力的新增或改动。
