# 中转站稳健性补齐

来源：总任务 [`10-16-magpie-osuna-gaps`](../10-16-magpie-osuna-gaps/prd.md) 的第 1 个子任务。访谈分 3 轮，2026-10-16 用户确认；全部决定、依据、核实过的代码事实与两个 CLI 的行为事实见 [`research/decisions.md`](research/decisions.md)。总任务的 Constraints、Implementation Decisions、Testing Decisions 对本任务全部适用，下面只写本任务特有的。总任务第 15 条「CLI 经过中转站的请求只换模型名与认证」的措辞，以本文第 3、46 条为准。

## Problem Statement

用户靠多家中转服务（new-api、sub2api 一类）在 Claude Code、Codex 里干活，由 Osuna 的内置中转站（**Gateway**）在它们之间自动切换（**Failover**）。中转站在这些情况下不稳：

1. 只差写法的模型名不算同一个模型，比如 `claude-opus-4.6` 与 `claude-opus-4-6`，或者带不带快照日期、厂商前缀。结果是一家用完时不会切到另一家；CLI 请求的写法和接口列出的写法不一样时，直接报「找不到模型」。
2. 等上游时，CLI 收不到任何字节。Claude Code 连自定义地址时，5 分钟没有字节就断开重发，慢模型、排队久的中转服务因此报错。
3. 上游先回「开始了」再报错、回空回复、或在回复里拒答时，中转站已经算开口，不再换家，错误直接到 CLI。
4. 上游回到一半断开：翻译路径把半截回复补成「说完了」交给 CLI，CLI 以为回复完整；直通路径直接掐断 CLI 的连接，Codex 看不到原因。
5. 中转服务不收请求里的某个写法（结构化输出、strict、预填、某个认证头、某个格式地址没有这个模型……）时，这一轮直接失败。只有「不思考」的写法有补救。
6. 判错不够细：
   - 402 一律当欠费，冷却 30 分钟；
   - 智谱不带时区的恢复时间、「resets in 0h 19min」这种写法读不出；
   - 失败按整家计；
   - 明知装不下的接口照样去问；
   - 复用连接被掐算这家失败；
   - 用 403 说出的拒答会把接口标成「需要检查」。
7. 翻译出去的请求缺东西也多东西：
   - Codex 的 `prompt_cache_key` 等字段被丢掉；
   - 推理档位和回复上限按固定值填；
   - Claude Code 只对 Anthropic 有用的计费行和审查字段照发给别家，别家的缓存每轮失效；
   - 不带 User-Agent。
8. 厂商说模型下线了，中转站隔几分钟又去问，CLI 的模型列表里也一直留着它。
9. 子任务 2、9 改接法以后，Codex 会发 zstd 压缩的请求体，中转站读不懂；接口文件写坏一次，所有接口就都停了。
10. 少数模型和厂商有自己的脾气：Grok 把整数写成 `2500.0`，Codex 读错；Kimi、MiniMax、DeepSeek 的官方接口不收某些写法。中转站都不认。

## Solution

只改内置中转站内部，不加任何界面，不改协议。做完后，用户看到的是：

- 同一个模型，不管各家怎么写，都能互相切换；发给每家的是它自己的写法。
- 慢模型等再久也不会断开：中转站会给 CLI 发「我还在」。
- 回复开始前出错、空回复、拒答，都会换家再问；拒答不让任何一家冷却。
- 回复到一半断了，能接着写就让模型接着写完；接不上就在回复末尾明确告诉 CLI 是哪家、出了什么错。
- 中转服务不收某个写法时，中转站自动换个写法再问同一家，并且记住。
- 判错、冷却、粘住同一家都更准。
- 翻译出去的请求带上 CLI 的字段和身份，并按模型的真实能力填参数；发给非 Claude 模型时，去掉只有 Anthropic 用得上的部分。
- 厂商说已下线的模型，一周内不出现在给 Agent 选的列表里。
- 压缩过的请求体、写坏的数据文件，都不再让中转站停摆。

## User Stories

### 同一个模型

1. 作为用第三方接口的用户，我希望只差写法的模型名（版本号里的点、下划线或连字符，厂商前缀，快照日期）被当成同一个模型，以便一家用完时中转站能切到写法不同的另一家。
2. 作为 Claude Code 用户，我希望选 `claude-opus-4-6` 时也能用上把它列成 `claude-opus-4.6` 的那家，以便不因为写法不同报「找不到模型」。
3. 作为用户，我希望每家接口收到的都是它自己列出的写法，以便上游认得这个模型。
4. 作为用户，我希望在 Osuna 里用「接口标识/模型」指定一家时，中转站仍然先问这家，以便写法归一不打乱我的选择。
5. 作为用户，我希望模型名里的 `~` 被当作 `/`，以便 MiniMax Code 这类写法也能用。
6. 作为用户，我希望模型名写错时，错误里列出最接近的三个名字，以便一眼看出该怎么写。

### 开口、保活、空回复

7. 作为 Claude Code 用户，我希望中转站等上游超过 15 秒时先回一个开头，之后定时发「我还在」，以便慢模型思考很久时，Claude Code 不会因为 5 分钟没收到字节就断开重发。
8. 作为 Codex 用户，我希望中转站给 Codex 的保活用 Codex 认得的真事件，以便 Codex 不在 5 分钟时断开。
9. 作为用户，我希望上游 5 分钟毫无动静时中转站停止保活，以便真正卡死的请求交给 CLI 自己超时重试，而不是一直等下去。
10. 作为用户，我希望上游只回了「开始了」、还没说任何内容就报错时，中转站仍能换下一家，以便偶发的「服务器忙」不打断对话。
11. 作为用户，我希望模型的思考过程仍然实时显示，以便长任务里我能看到它在干活。
12. 作为用户，我希望上游回了空回复时，中转站先在同一家再问一次，还是空就换下一家，以便不用手动重发。
13. 作为用户，我希望所有接口都回空回复时，CLI 收到明确的「空回复」错误，以便知道不是网络问题。
14. 作为用户，我希望中转站已经发出开头之后才全部失败时，CLI 仍收到它认得的错误，以便错误不被吞掉。这时 Claude Code 会改成不流式再问一次，Codex 能看到原因。
15. 作为用户，我希望 15 秒内就失败的请求，仍然以正常的错误码和 Retry-After 回给 CLI，以便 CLI 按原来的节奏重试。

### 拒答

16. 作为用户，我希望一家的安全过滤在回复开始前拒答时，中转站把同一个请求依次交给其他有同名模型的接口，以便某家过严的过滤不卡住我。
17. 作为用户，我希望拒答不让任何一家冷却，也不把它标成「需要检查」，以便一次拒答不连累这家后面的请求。
18. 作为 Claude Code 用户，我希望所有接口都拒答时收到原样的拒答（带拒答类别说明），以便 Claude Code 能按自己的设置换用备用模型。
19. 作为 Codex 用户，我希望所有接口都拒答时收到错误和原因，以便知道这一轮为什么没有回答。
20. 作为用户，我希望「considered high risk」这类以报错形式出现的拒答也被认作拒答，以便它和别的拒答一样处理。
21. 作为用户，我希望用 403 说出的拒答不会把接口标成「需要检查」，以便不必为一次拒答去编辑接口。

### 拒收后改写重问

22. 作为用户，我希望一家接口说「这个地址没有这个模型」时，中转站改用这家另一种格式的地址再问，以便同一家的另一个地址能用时不必换家。
23. 作为用户，我希望中转服务说「两种认证头不能同时带」时，中转站只带一种再问，以便这类中转服务也能用。
24. 作为 Claude Code 用户，我希望中转服务不认自动模式的审查字段或 `display` 字段时，中转站去掉再问，以便自动模式照常工作。
25. 作为用户，我希望上游说 temperature、top_p 已经弃用时，中转站去掉再问，以便请求不因这些参数失败。
26. 作为 Claude Code 用户，我希望上游不认延后加载工具用的特殊块时，中转站去掉再问，以便工具多的会话也能用这家。
27. 作为用户，我希望结构化输出被拒时，中转站先降成「只要求回 JSON」并把格式说明写进系统提示，再不行就只用文字说明格式，以便仍然拿到能用的回答。
28. 作为用户，我希望对话以模型的话结尾、上游不收时，中转站补一句用户消息再问，以便对话能继续。
29. 作为用户，我希望工具的 strict 标记被拒时，中转站去掉再问，以便工具调用照常进行。
30. 作为 Codex 用户，我希望画图工具被裸 400 拒绝时，中转站去掉再问，以便这一轮的其他工作不受影响。
31. 作为用户，我希望中转站记住「这家的这个模型不收这个写法」，以后直接用新写法，以便不每轮都失败一次。
32. 作为用户，我希望中转站每记住一种写法，daemon 日志就记一行，以便事后知道它改过什么。

### 直通的通用修补与 User-Agent

33. 作为用 Claude Code 连非 Claude 模型的用户，我希望中转站去掉只对 Anthropic 有用的计费行，以便对方的前缀缓存不每轮失效。
34. 作为这样的用户，我希望中转站去掉 Claude Code 自动模式的审查字段，以便别家不报错。
35. 作为 Claude Code 用户，我希望 advisor 工具在同一家的 Claude 上改用上游的模型名、在别家上连说明一起去掉，以便不因为这个工具报错。
36. 作为用 4.6 起的 Claude 的用户，我希望直通时思考字段也改成它收的写法，以便请求不被拒。
37. 作为 Codex 用户，我希望对话换过家后，Osuna 翻译时自己造的推理记录不再发给直通的 Responses 上游，以便不报「找不到这条记录」。
38. 作为用 sub2api「只允许 Claude Code」分组的用户，我希望经过中转站的请求仍带 Claude Code 自己的 User-Agent，以便这类分组照常放行。
39. 作为用编程套餐 key 的用户，我希望翻译后的请求也带上 CLI 自己的 User-Agent，以便只服务点名 Agent 的套餐不把请求挡在外面。
40. 作为用户，我希望 CLI 没带 User-Agent 时，中转站写上 `Osuna/<版本>`，以便请求如实表明来源，也不会被当成无名请求拦下。

### 翻译的通用修补

41. 作为 Codex 用户，我希望 `prompt_cache_key`、`include`、`client_metadata`、`text.verbosity` 在翻译时也转给上游，以便提示缓存能命中。
42. 作为用户，我希望中转站按模型真实支持的推理档位填参数，以便请求不被上游拒绝。
43. 作为用户，我希望请求没写回复上限时，中转站按模型公布的上限来填，以便长回答不被截短。
44. 作为用户，我希望已知不收采样参数的模型和新版 Claude 收不到 temperature 这类参数，以便请求不被拒。
45. 作为用户，我希望工具参数格式最外层是「几选一」时，中转站外面包一层，以便上游收得下这个工具。
46. 作为用户，我希望中转站读得懂更多种推理字段写法，以便各家模型的思考都能显示出来。
47. 作为 Codex 用户，我希望翻译过来的回复标出哪些是过程话、哪些是最终答复，中途改档位用 Codex 认得的写法，以便 Codex 照常折叠过程、保住缓存。
48. 作为用户，我希望上游无视流式要求、回了一整份 JSON 时，中转站把它转成流交给 CLI，以便不必因此换家。
49. 作为用户，我希望上游回的是登录页、Cloudflare 验证页或空内容时（直通也一样），中转站当失败换家，并在原因里写上页面标题，以便知道是哪家出了什么问题。
50. 作为用户，我希望流里的错误保留厂商原本的类型和代码，以便 CLI 按真实原因处理。

### 改模型输出

51. 作为用户，我希望 CLI 要求 JSON 而模型用 ``` 把它包住时，中转站剥掉代码块，以便拿到能直接解析的 JSON。
52. 作为用 GLM、DeepSeek 等模型的用户，我希望模型把工具调用写成一段文字时，中转站把它转成真正的调用，以便工具会被执行、对话不卡住。

### 按厂商改写

53. 作为直接添加 Kimi 官方地址或 Kimi Code key 的用户，我希望中转站按 Kimi 的要求改推理字段和工具参数格式，以便请求不被 Kimi 拒绝。
54. 作为直接添加 MiniMax 官方地址的用户，我希望思考内容按 MiniMax 的方式写回，以便它的连续思考照常工作。
55. 作为直接添加 DeepSeek 官方地址的用户，我希望工具参数格式里 DeepSeek 不认的转义被改写，以便工具定义不被拒。
56. 作为用 Grok 模型的 Codex 用户（不论经哪家），我希望工具调用里 `2500.0` 这样的整数被改回 `2500`、工具参数里的正则改成 Grok 认得的写法，以便 Codex 读得懂、请求不被拒。
57. 作为经中转服务用 Kimi、MiniMax、DeepSeek 模型的用户，我希望中转站不照官方的规矩改我的请求，以便不把中转服务自己的处理弄坏。

### 判错与冷却

58. 作为用户，我希望 402 只有说的是用量上限时才算额度用完，以便别的 402 不让一家被误判、冷却很久。
59. 作为用户，我希望中转站认得智谱不带时区的恢复时间（按北京时间算），也认得「resets in 0h 19min」这种写法，以便冷却结束的时间准确。
60. 作为用户，我希望被厂商防火墙挡住的请求、不说原因的 400，也换下一家，以便这类偶发问题不打断对话。
61. 作为用户，我希望失败按模型计数，以便一家的某个模型坏了，不连累它的其他模型。
62. 作为用户，我希望后面剩下的接口都在额度冷却时，中转站稍等后原地再问当前这家，以便不去问明知没有额度的接口。
63. 作为用户，我希望「几点恢复」的提示带上时区，并复述我选的那家的原话，以便看懂是哪家、什么时候能用。
64. 作为用户，我希望把拒绝包在「成功」回复里的说法（如智谱）也被认作失败，以便照常换家。

### 对话太长

65. 作为用户，我希望中转站跳过已知窗口装不下这次请求的接口，以便不白白浪费一次失败。
66. 作为用户，我希望估算已经远超窗口时，CLI 直接收到「对话太长」，以便 CLI 去压缩对话。
67. 作为用户，我希望一家说对话太长、而另一家同名模型的已知窗口更大时，中转站换过去，以便不压缩也能继续。

### 粘住同一家

68. 作为用户，我希望刚写进某家缓存的对话也算粘在这家，以便下一轮还去这家，缓存不白写。
69. 作为用 OpenAI、Gemini 这类悄悄缓存的模型的用户，我希望发过的对话也算粘在这家，以便缓存能命中。
70. 作为用户，我希望写过 1 小时缓存的对话 1 小时内都粘在这家，以便停顿久一点后缓存仍然有效。
71. 作为用户，我希望找上次是谁回答的时，也比对推理档位，以便同一档位的对话留在同一家。

### 已下线模型

72. 作为用户，我希望厂商说某个模型已下线后，中转站一周内不再从这家用它，以便不每隔几分钟白问一次。
73. 作为用户，我希望这一周里，这家的这个模型不出现在 Claude Code、Codex 和 Osuna 的模型列表里，以便不会选到用不了的模型。
74. 作为用户，我希望明确指定要这家的这个模型时请求照发，一旦回答成功就恢复，以便厂商重新上线时马上能用。
75. 作为用户，我希望这条记录在 Osuna 重启后还在，以便重启后不再白问。
76. 作为用户，我希望接口页上我勾选的模型和「默认模型」设置不被改动，以便我的设置保持原样。

### 断流

77. 作为用户，我希望翻译时上游没说完就断了，CLI 不会把半截回答当成完整结果，以便我不被误导。
78. 作为用户，我希望能接着写的回复由中转站让模型接着写完，以便我看到的是一条完整的回复。
79. 作为用户，我希望接不上的回复在末尾收到一条明确的错误（哪家、什么原因、可以重试），以便知道发生了什么。
80. 作为 Codex 用户，我希望断流时收到 Codex 能显示原因的错误，以便不只看到它反复重连。

### 连接、请求体、数据文件

81. 作为用户，我希望复用的连接被上游掐断时，中转站立刻在新连接上重发，并且不算这家失败，以便偶发的网络问题不打断对话。
82. 作为用户，我希望 zstd 或 gzip 压缩过的请求体也能被中转站读懂，以便 CLI 打开压缩时照常工作。
83. 作为用户，我希望请求太大时提示我用 `/compact` 压缩对话，以便知道怎么办。
84. 作为用户，我希望中转站的数据文件写坏时，自动用上一份好的，坏的那份另存起来，以便一次写坏不让所有接口停摆，事后也能排查。
85. 作为 Windows 用户，我希望文件正被替换时中转站稍等再读，以便不偶发报错。
86. 作为 Codex 用户，我希望记忆整理和自动审查的请求没有对应模型时，用这段对话上一轮的模型，以便它们不报「找不到模型」。

### 跨子任务

87. 作为用官方 Paseo 手机 App 的用户，我希望这次改动后手机照常能用，以便不受影响。
88. 作为维护者，我希望被推翻的 ADR 0007 规则有新 ADR 说明原因和取舍，以便以后的人知道为什么这样做。

## Implementation Decisions

### 规则与边界

1. 只改内置中转站，以及它读写的接口存储。不加界面，不改协议：没有新 RPC、没有新字段，也不需要 `server_info.features`。旧客户端（包括官方 Paseo 手机 App）唯一能看到的变化，是模型列表里少了已下线的那一项。
2. 写一篇新 ADR，取代 ADR 0007 的下列规则，并在 ADR 0007 里标出被哪篇取代：
   - 「A rejected request is never re-sent to the same endpoint in a changed shape」：改为拒收后改写重问（第 18–19 条）。
   - 「minus vendor-specific rewrites (except …)」：例外加上 Kimi、MiniMax、DeepSeek、Grok（第 25 条）。
   - 「Failover happens only before the first byte of the response」：改为开口前，开口按第一段内容算，开口前可能已经发出保活（第 8–11 条）。
   - 新增：拒答换家（第 14–17 条）、已下线模型落盘（第 37–39 条；冷却本身仍只在内存里）、直通规则的新措辞（第 3 条）、User-Agent（第 46 条）。

   ADR 要写明 Q3 的取舍：助手原本推荐「不换家」，理由是同一个模型在别家多半也会拒，而把一家安全过滤拦下的内容转给别家，可能被看作绕过安全检查；用户选择照 magpie 换家。
3. 直通规则改为：直通不翻译；除了换模型名与认证，只做让目标模型收得下的通用修补，这些修补只看目标模型，不看是哪家；不改请求自称是谁，即 User-Agent 这类表明身份的请求头和字段不动。按厂商的改写只限第 25 条列出的四家。
4. 借鉴 magpie 的新文件，文件头保留 MIT 声明，`THIRD_PARTY_NOTICES` 覆盖这些文件。判错词表、拒收与拒答的认法、厂商的原话，照 magpie 原样搬过来，并注明出处。

### 同一个模型

5. 模型名的归一照 magpie 的同名判断：去掉厂商前缀；版本号里的点改成连字符（包括 Fireworks 写法里的 `p`）；下划线改成连字符；去掉快照日期。归一只用来判断「是不是同一个模型」，用在这些地方：选候选、换家、把 CLI 请求的名字对上接口列出的名字、count_tokens、相近名字建议。发给每家时，用这家自己列出的写法。
6. 「接口标识/模型」仍先按「指定某家」来认（现有规则）。只有斜杠前面不是任何一家的接口标识时，才当作厂商前缀去归一。请求里的 `~` 当作 `/`。Claude 档位名（opus、sonnet 等）的映射不变。

### 开口与保活

7. 等上游响应头的 10 分钟超时不变。
8. **开口**指上游回复里出现第一段真内容：文字、思考或工具调用。直通和翻译都按各自协议来认。
   - 在那之前收到的帧（如 `message_start`、`response.created`、`ping`）先扣在中转站，不发给 CLI；开口时按原来的顺序原样发出。
   - 开口前的任何失败（出错、断开、空回复、拒答），都按换家规则处理；开口后不再换家。
   - 思考过程不扣，不做 magpie 的推理扣留。
9. 保活只用于 CLI 要流式的请求。从请求进来开始，等满 15 秒还没开口，就先给 CLI 回 200 和事件流的响应头，之后每 15 秒发一个协议自带的保活事件：
   - Claude Code：`ping`；
   - Codex：`response.in_progress`。Codex 不认注释行，必须是带数据的事件。

   上游 5 分钟毫无动静，就停止保活。15 秒内就失败的，照现状回真实状态码和 Retry-After 等响应头。
10. 保活开始之后才失败（包括全部接口失败、全部在冷却），错误改在流里发出：
    - Claude Code 收到 `error` 事件，类型是 `api_error`；
    - Codex 收到 `response.failed`，code 是 `server_error`；
    - 消息仍是「<接口名>: <上游原文>」。

    拒答例外，见第 15 条。
11. Codex 方向要不要沿用 magpie 的「累计最多扣 4 分钟」上限，实现时对照 magpie 代码再定（全程用真事件以后可能不需要），结论写进实现记录。

### 空回复

12. **空回复**照 magpie 认（2026-10-17 用户改定，原为「没有计任何输出 token」）：上游是 Anthropic 或 Responses 格式，回复已经结束，却没有任何内容，输入、输出、缓存读写的 token 也全是 0；被截断、拒答的不算。Chat 格式的回复不一定计 token，从不算空；Claude 自己以空回复结束一轮时计了提示词，仍算回答。直通和翻译都这样认。开口前收到空回复时：
    - 先在同一家再问一次；
    - 还是空，就算这家失败（冷却分类照 magpie），换下一家；
    - 全部接口都空，CLI 收到「empty reply」错误；按第 9、10 条，决定是回状态码还是在流里发错误。

### 拒答

13. 拒答的认法照 magpie，只认错误本身，不认回答文字里引用的句子。两种形式：
    - **报错形式**：HTTP 错误体或流里的错误事件，包括整句「The request was rejected because it was considered high risk」和厂商的安全过滤错误码。
    - **结束形式**：Anthropic 的 `stop_reason: refusal`、Chat 的 `finish_reason: content_filter`、Responses 因 `content_filter` 没有完成。
14. 开口前的拒答：不冷却、不标「需要检查」，并问遍剩下所有有同名模型的候选。不设次数上限，也没有设置项。
15. 全部候选都拒答时：
    - Claude Code 收到排第一那家被扣下的原样拒答：200、`stop_reason: refusal`、带 `stop_details`，流式还是整份照 CLI 的要求。如果保活已经开始，就以流内的拒答结尾的方式发出。
    - Codex 收到 Responses 形状的 400 和原因。如果保活已经开始，就用 Codex 不会重问、并且会显示原因的终止型 code 发出 `response.failed`，具体用哪个 code，实现时对照 magpie 和 Codex 源码定。
16. 开口之后的拒答照常转给 CLI，也不让这家冷却。翻译时把 Anthropic 的 `stop_details` 带给 Anthropic 客户端。
17. 用 403 说出的拒答不算 key 有问题，不标「需要检查」。

### 拒收后改写重问

18. 在现有的「不思考写法被拒就换写法重问」机制上扩展：
    - 按「接口 + 模型 + 写法」记在内存里，daemon 重启就清空；
    - 在同一家开口之前、做换家判断之前，重问一次；
    - 重问仍被拒，就按原来的规则处理；
    - 已经记住的写法，以后直接按新写法发；
    - 同时进来的几个请求，可能各自重问一次；
    - 每记住一种写法，写一行 info 日志。
19. 新增以下 9 种，认法和改法都照 magpie：
    1. 某个格式的地址说「这里没有这个模型」：记住这家这个模型的这个格式不行，改用这家的下一个格式地址再问，按现有的格式顺序，需要时翻译。所有格式都说没有时，按现有规则只冷却这家的这个模型，然后换家。这里和 magpie 不同：magpie 会再问一次用户指定的格式，而 Osuna 没有「按模型指定格式」。
    2. 「两种认证头不能同时带」的 401：只带一种，先换哪一种照 magpie。
    3. 不收 Claude Code 自动模式的审查字段（dangerous-tool-use beta、`safeguards`、`safeguard_results`）或 `display` 字段：去掉。
    4. 说 temperature、top_p、top_k 已经弃用：去掉。
    5. 不收延后加载工具块（`tool_addition`、`tool_removal`、`tool_reference`）：去掉；只剩 `tool_reference` 的工具结果，补一句文字。
    6. 结构化输出被拒：改成 `json_object`，并把 schema 写进 system；仍然被拒，就只用文字说明格式。
    7. 以 assistant 结尾（预填）被拒：补一个 user 轮。
    8. 工具的 `strict` 被拒：去掉。
    9. Codex 的 `image_gen` 工具被裸 400 拒绝：去掉。

### 直通与翻译的通用修补

20. 直通的请求体，除了模型名和认证，只做下面这些修补，全部只看目标模型、不看是哪家：
    - 发给非 Claude 模型时，去掉 Claude Code 的计费行（system 里的 `x-anthropic-billing-header` 块）和自动模式的审查字段；发给 Claude 模型时原样保留。
    - advisor 服务端工具：同一家的 Claude 改用上游的模型名；否则连同它的说明和 `tool_addition` 一起去掉。
    - 4.6 起只认 adaptive 思考的 Claude：客户端发来的 enabled 加预算，也改成 adaptive；xhigh 照 magpie 改成 max。
    - 发往 Responses 上游之前，一律去掉中转站翻译时自己造的推理项。这和「历史思考只回原厂」的规则一致。
    - Responses 的工具往来，补上 magpie 的另外三处修补：从别的格式翻成 Responses 的请求也要修补；同一个调用的第二个答复去掉；一批调用中间夹着的模型文字，挪到第一个调用前面。
    - 已知不收采样参数的模型，不发 temperature、top_p；新版 Claude 去掉 temperature、top_p、top_k。
    - 现有的修补（思考字段、DeepSeek 推理回放、关思考的写法）不变。
21. 翻译时另外做这些，都照 magpie：
    - Codex 的 `prompt_cache_key`、`include`、`client_metadata`、`text.verbosity` 带给上游。
    - 推理档位按模型资料里的真实档位来适配（现在是固定把 xhigh、max 降到 high）。
    - 需要回复上限而请求没给时，按模型公布的上限填，不知道时才用 16384。
    - 工具 schema 的根是 anyOf、oneOf 或 allOf 时，包成 object。
    - 读得懂 Chat 上游的 `reasoning_details`，以及 Vertex 的 `extra_content.google.thought`。
    - 翻给 Codex 的 assistant 消息标上 `phase`；Codex 中途改档位时用 `configuration_update`。

    模型资料先取接口自己的模型清单，其次取 models.dev（现有来源）。
22. 回复的处理，照 magpie：
    - 上游无视流式要求、回了整份 JSON 时，转成 CLI 要的流。现在的做法是当失败换家。
    - 不是本协议回复的 2xx（HTML 登录页、Cloudflare 挑战页、空内容、不以 JSON 开头）当 502 换家并冷却，原因里写上页面标题。直通也这样认。
    - 流里的错误保留厂商的 type、code、param；Responses 流里的 `invalid_request_error` 读成 400；只用 `event:` 行命名的错误也认。

### 改模型输出

23. CLI 要了 JSON（结构化输出或 `json_object`），模型却用 ``` 包住时，剥掉代码块。流式和整份都处理。
24. 翻译 Chat 上游的回复时，把 Hermes 的 `<tool_call>`、DeepSeek 的 DSML、GLM 的 `arg_key` 这几种文字写法的工具调用，转成真正的工具调用。

两项的触发条件照 magpie，其余回复一个字都不改。

### 按厂商改写

25. 只做四家，触发条件照 magpie：
    - **Kimi**（接口地址是 Kimi 或 Moonshot 的官方地址）：消息里的 `reasoning_details` 改成 `reasoning_content`；工具 schema 里有 enum 或 const 却没写 type 的，补上 type。
    - **MiniMax**（官方地址）：Chat 历史里的思考，按 MiniMax 的方式写回 `<think>` 里。
    - **DeepSeek**（官方地址）：工具 schema 里的 `\0` 转义改成 `\u0000`。
    - **Grok**（不论谁提供，按模型名认）：回复里工具参数的 `2500.0` 改回 `2500`；工具 schema 里的正则改成 Grok 认得的写法。
    - **延后加载工具块**：照 magpie，Kimi、DeepSeek 不发，触发条件同上。

    magpie 还会按「预设」认出厂商。Osuna 没有预设（模板归子任务 3），所以只按地址认。经中转服务用 Kimi、MiniMax、DeepSeek 的模型时不做这些改写，中转服务的拒收交给第 19 条处理。
26. 按厂商读懂报错属于判错，不受第 25 条的限制：
    - 智谱把拒绝包在 200 里（`{"code":…,"success":false}`），按它的错误码当 401 或 429 处理；
    - 智谱 1308、1310 不带时区的恢复时间，按北京时间读；
    - Command Code 不说原因的 400，换家；
    - Cline 免费模型额度用完，只冷却该模型。

### 判错、冷却与粘性

27. 402 只有在说用量上限、又没提钱的时候，才算额度用完，可以只冷却该模型；其他 402 仍算欠费。
28. 恢复时间多认一种文字写法「resets in 0h 19min」，再加上第 26 条的智谱写法。
29. 被厂商防火墙挡住的请求、不说原因的 400，算值得换家，照 magpie 的词表认。
30. 模型自己的失败次数和整家接口的分开计，模型级冷却按模型自己的次数翻倍。
31. 后面剩下的候选全因额度在冷却时，把当前这家当作最后一家，原地重试。
32. 全部在冷却时交给 CLI 的提示：恢复时间带上时区；复述排第一那家（也就是用户选的那家）的原话。
33. 粘住同一家：
    - 缓存写入也算；
    - OpenAI、Gemini 这类悄悄缓存、不报数的，把这一轮发出的 prompt 当作写入；
    - 写过 1 小时缓存的，1 小时内都算热；
    - 找上次是谁回答的，按顺序匹配：接口 + 模型 + 推理档 → 接口 + 模型 → 接口。

### 对话太长

34. 发出之前，跳过已知窗口装不下这次请求的候选；窗口不知道的不跳。请求大小用现有的本地估算。
35. 上游没说原因、但估算已经超过窗口 1.2 倍时，按「对话太长」告诉 CLI。中转服务自己的单次输入上限也算超长。
36. Osuna 自己加的一条（magpie 只在路由组里这样做）：一家说对话太长时，如果后面有已知窗口更大的同名候选，就换过去；否则照旧交给 CLI 去压缩。

### 已下线模型

37. 认法沿用现有的「模型已下线」判错，包括 OpenCode Zen 的 410 和 401。
    - 按「接口 + 模型」记下时间，存成一个新的小文件，重启也不丢；一周后自动失效。
    - 这个文件按缓存处理：读不懂就当作空的，丢了只是多问一次。写入时原子替换，用 Zod 校验，并记进 `docs/data-model.md`。
38. 一周之内：
    - 所有由接口已选模型生成、给 Agent 选模型的列表，都去掉这家的这一项：中转站的模型清单、Codex 的模型目录、Claude Code 的模型选择列表、Osuna 快照里的模型列表和分组。
    - 只写模型名的请求，选路时跳过它；没有别家时回「找不到模型」，并给出相近的名字。
    - 写了「接口标识/模型」指定这家的请求照发，厂商的回答交给 CLI。
39. 这家的这个模型回答成功一次，就恢复。
    - 列表变化走现有的「接口变了」流程：重写 Codex 模型目录文件，按 ADR 0004 的改写规则重写 Claude 的模型选择列表，通知客户端刷新。
    - 接口自己的已选模型、各提供方的默认模型都不改。
    - 记下和恢复，各写一行日志。

### 断流

40. 这几种情况算回复没说完：Anthropic 没有 `stop_reason` 或 `message_stop`；Responses 没有 `response.completed`。Chat 不带 `[DONE]` 也可以是完整的，不算。翻译时不再替上游补结尾。
41. 翻译的回复断了，先「接着写」（magpie 的 continuation）：把 CLI 已经收到的部分交回上游续写，最多 2 次。要同时满足这些条件：
    - 上游能从一半接着写：Anthropic 原生支持；Chat 只限厂商自己的预填模式；
    - 还没开始任何工具调用；
    - 不是拒答；
    - 这个模型没有拒过预填。
42. 接不上，或者走的是直通时：在流尾先补一个空行，再补一个协议内的错误事件（Claude Code 收到 `api_error`，Codex 收到 `response.failed`），写明接口名和原因，文字后面加上「(<状态码>: you can retry your request)」；然后正常结束响应，不再直接掐断连接。这家照现有规则冷却。
43. CLI 不要流式时，翻译的回复断了，照现状回 502 并附上原因。

### 连接、请求体、User-Agent、数据文件、模型名

44. 复用的连接在上游回复开始前被关掉（EOF、broken pipe 一类）时，立刻在新连接上重发，不算失败，也不冷却。
45. 请求体按 Content-Encoding 解开 zstd 和 gzip；其他编码回 415。64 MB 的上限按解开后的大小算；413 的文字要说明这是中转站的上限，并建议用 `/compact`。直通发给上游的是解开后的请求体，同时去掉 Content-Encoding。
46. User-Agent：直通时原样转发 CLI 的；翻译时也带上 CLI 发来的 User-Agent；CLI 没带时写 `Osuna/<版本>`。以后子任务 3 做的自定义请求头，优先于这一条。
47. 数据文件：
    - 适用范围：接口清单、key、中转站口令这三份 JSON 状态文件。
    - 写入前，把上一份好的存成 `.bak`。读到坏文件时，改读 `.bak` 继续服务，坏的那份另存为 `.bad-<时间>`，并写一行警告日志。`.bak` 也坏时，照现状报错、不写不删。
    - 不适用：CLI 配置的接管记录，仍是「解析不了就报错」，因为用上一份旧记录去恢复 CLI 配置，可能恢复错值。CLI 自己的配置文件（Claude 的 `settings.json`、Codex 的 `config.toml`）也不变，仍是「解析不了就不写」。
    - 只有 daemon 写这些文件，所以不加跨进程锁。
    - Windows 上读文件、改名时遇到占用，重试，最多 0.5 秒。
48. 模型名：
    - 找不到模型时，404 说明原因，并给出最接近的三个 id。
    - Codex 的记忆整理和 auto-review 请求（模型名是 `codex-auto-review`，或带 `x-openai-subagent: guardian` 头）没有对应模型时，发给这段对话上一轮用的模型。

### 文档

49. 要写或要改的文档：
    - 新 ADR，见第 2 条。
    - `docs/glossary.md`：访谈中已经改过（自动切换、拒答、拒收、已下线模型），实现完要对照最终行为复核。
    - `docs/data-model.md`：加上已下线记录文件，以及 `.bak` / `.bad-<时间>` 的规则。
    - `THIRD_PARTY_NOTICES`：覆盖新借鉴的 magpie 文件。

    `docs/usage.md` 不用改：重问、续写、保活都是转发 CLI 的请求，没有新增 daemon 主动发出的请求。

## Testing Decisions

- **好测试的标准**：只测外部看得到的行为，内部结构不测。外部行为包括：CLI 收到什么（状态码、响应头、事件序列、整份内容）、每个假上游收到什么（请求体、请求头、User-Agent、被问了几次）、RPC 和模型列表返回什么，以及磁盘上留下了什么（已下线记录、`.bak`、`.bad-<时间>`）。确定性要求遵守 `docs/testing.md`：不靠等真实时间，断言写完整的预期结果。
- **接缝一（主）：daemon 端到端测试。** 进程内启动真实 daemon，在本机起假上游（HTTP 服务），用 fetch 扮演 CLI，带上中转站口令去打中转站入口。先例是现有的中转站端到端测试：直通、翻译、换家、「不思考」被拒后重问那几组，它们共用的假上游与重启 daemon 的夹具也直接复用。模型列表的变化，沿用 Claude 配置、Codex 配置那两组端到端测试的写法，检查 Codex 模型目录文件和 Claude `settings.json` 里的模型选择列表。
- **时间相关**：保活的 15 秒和 5 分钟、原地重试的等待，沿用现有的中转站测试参数覆盖项来缩短（现在已经有「等响应头超时」「原地重试等待」两个），测试按毫秒跑。已下线记录的「一周」按 `docs/testing.md` 注入时钟，不在测试里等真实时间。这是本任务唯一新增的接缝，放在中转站和存储的最外层。
- **端到端要覆盖的场景**：
  - 写法不同的同名模型互相切换，每家收到自己的写法；
  - 先回 `message_start` 再报错时换家，CLI 只看到回答那家的流；
  - 保活事件的形状与间隔（Claude Code 是 `ping`，Codex 是 `response.in_progress`），以及保活之后失败时，CLI 在流里收到 `api_error` 或 `response.failed`；
  - 空回复先在同一家问两次，再换家；
  - 拒答问遍各家、不冷却，全部拒答时 Claude Code 和 Codex 各自收到什么；
  - 9 种拒收各自被重问、被记住，第二次请求直接发新写法；
  - 断流时续写拼成一条完整回复，接不上时流尾补错误事件（前面有空行），直通断流时也补错误事件而不是掐断；
  - 复用连接被掐后重发；
  - zstd 和 gzip 请求体；
  - User-Agent 在直通和翻译时的取值；
  - 已下线模型从各列表消失、只写模型名的请求跳过它、指定这家的请求照发、回答成功后恢复、重启后仍在；
  - 接口文件写坏后从 `.bak` 继续服务，`.bad-<时间>` 文件存在。

  厂商与拒收的原话，照 magpie 测试里的写法搬过来。
- **接缝二：已有的纯逻辑套件。** 按厂商改写要靠接口地址触发，本机的假上游给不出官方域名，所以在已有的直通、翻译套件里，把接口地址设成官方域名来测。其余放进各自已有的套件：
  - 判错：402、恢复时间写法、拒答认法、防火墙；
  - 冷却：模型级失败计数；
  - 路由：归一、跳过已下线、按窗口跳过；
  - 直通：通用修补；
  - 翻译：Kimi、MiniMax、DeepSeek、Grok，剥代码块，文字工具调用，`phase`，`configuration_update`，`prompt_cache_key`，续写时怎么拼预填；
  - 拒收：9 种写法；
  - 粘性：缓存写入、悄悄缓存、1 小时缓存、推理档。

  Windows 上改名重试，用文件系统适配器的假实现模拟一次占用。
- 不新建测试套件，不加 npm 脚本或 CI 任务。所有上游都是本机假服务，不连真实中转服务或厂商。本机只跑改到的测试文件，全量交给 CI。
- 现有测试里「开口后不换家、断流直接掐断 CLI」那条，按新行为改写，不删除。
- **不在助手本机跑真实 CLI。** 两个 CLI 的超时、重试、显示行为，来自读源码（见 `research/decisions.md`），没有做过端到端核实；用户验收那一项由用户自己做。

## Constraints

- 总任务的约束全部适用：官方 Paseo 手机 App 一行不改；用 TypeScript 在 daemon 里重写，不托管 magpie；借鉴的文件保留 MIT 声明；协议遵守 `docs/protocol-compatibility.md`；中转站只服务本机；身份如实（按本文第 3、46 条）；不在用户本机测 CLI 登录。
- 不加、不改任何界面。
- 重写 Claude 的模型选择列表和 Codex 的模型目录时，遵守 ADR 0004 的文件改写规则。
- 新的数据文件遵守 `docs/data-model.md` 与持久化规范：Zod 校验、原子写入、不做迁移。
- 改动只在中转站与接口存储里。Osuna 自己发出的其他请求（测试连接、拉模型清单、自动识别格式）的 User-Agent 不在本任务改。

## Acceptance Criteria

- [ ] 只差写法的模型名（点、下划线、连字符、厂商前缀、快照日期）互相切换；每个假上游收到的是它自己列出的写法；指定「接口标识/模型」时先问那一家；`~` 当作 `/` 认。
- [ ] 开口前的出错、空回复、拒答都会换家，CLI 只看到最终回答那家的流；思考内容随上游实时转给 CLI，不被扣住。
- [ ] 流式请求等满 15 秒还没开口时，Claude Code 收到 200 和定时的 `ping`，Codex 收到 200 和定时的 `response.in_progress`；保活开始后才失败的，Claude Code 在流里收到 `api_error`，Codex 收到 `response.failed`；15 秒内失败的，仍回真实状态码和 Retry-After。
- [ ] 空回复先在同一家再问一次，再换家；全部都空时，CLI 收到「empty reply」错误。
- [ ] 拒答（含 high risk 报错形式、`stop_reason: refusal`、`content_filter`）问遍剩下的同名候选，不冷却任何一家、不标「需要检查」；全部拒答时，Claude Code 收到排第一那家的原样拒答（带 `stop_details`），Codex 收到 400；用 403 说出的拒答不标「需要检查」。
- [ ] 9 种拒收：被拒后，同一家收到改写后的请求；同一家的同一模型，下一次请求直接用改写后的写法；daemon 重启后恢复原写法；每次记住都有一行 info 日志。
- [ ] 直通的请求体，除了模型名、认证和第 20 条列出的修补以外，逐字节不变；发给 Claude 模型时，计费行和审查字段保留。
- [ ] 翻译时第 21 条各项生效：`prompt_cache_key` 等四个字段送达上游；推理档位与回复上限按模型资料填写。
- [ ] 第 22 条生效：整份 JSON 转成流；HTML、Cloudflare 页面、空内容按 502 换家，原因里有页面标题；流里的错误保留厂商的 type 和 code。
- [ ] JSON 外面的代码块被剥掉；三种文字写法的工具调用转成真调用；不满足触发条件的回复逐字不变。
- [ ] Kimi、MiniMax、DeepSeek 的改写只在接口地址是它们的官方地址时生效；Grok 的改写不论地址都生效；没有其他按厂商的改写。
- [ ] 第 26–33 条的判错、冷却、粘性规则，各有用例覆盖，结果和 magpie 一致；第 36 条的 Osuna 自加规则也有用例。
- [ ] 已知窗口装不下的候选不会被问到；估算超过窗口 1.2 倍时，CLI 收到「对话太长」。
- [ ] 已下线模型：这家的这一项从中转站模型清单、Codex 模型目录、Claude 模型选择列表、Osuna 快照里消失；只写模型名的请求跳过它；指定这家的请求照发；回答成功后恢复；daemon 重启后记录仍在；一周后自动恢复；接口的已选模型和默认模型不变。
- [ ] 断流：翻译时不再补出假的结尾；满足条件时续写成一条完整回复（最多 2 次）；否则流尾先空一行，再补协议内的错误事件，附「(<状态码>: you can retry your request)」；直通断流也补错误事件，而不是掐断连接。
- [ ] 复用连接在回复开始前被关掉时会重发，这家不冷却。
- [ ] zstd 和 gzip 请求体在直通、翻译时都能用；其他编码回 415；64 MB 按解开后算；413 的文字提到 `/compact`。
- [ ] User-Agent：直通和翻译时，上游收到的都是 CLI 自己的；CLI 没带时是 `Osuna/<版本>`。
- [ ] 接口清单、key、口令文件写坏后，中转站从 `.bak` 继续服务，坏文件另存为 `.bad-<时间>`，日志有警告；CLI 配置的接管记录和 CLI 自己的配置文件，行为不变。
- [ ] 找不到模型时，404 给出最接近的三个 id；Codex 的记忆整理和 auto-review 在没有对应模型时，用上一轮的模型。
- [ ] 文档：
  - 新 ADR 写明取代了 ADR 0007 的哪几条，以及 Q3 的取舍；ADR 0007 标出被它取代；
  - `docs/glossary.md` 的「自动切换」「拒答」「拒收」「已下线模型」和最终行为一致；
  - `docs/data-model.md` 写明已下线记录文件和 `.bak` / `.bad-<时间>` 规则；
  - `THIRD_PARTY_NOTICES` 覆盖新借鉴的 magpie 文件。
- [ ] 没有协议改动（`packages/protocol` 不变），旧客户端照常工作。
- [ ] `npm run typecheck`、`npm run lint` 通过；改到的测试文件本机通过；合入后 CI 通过（已知常红的 Nix 两项除外）。
- [ ] 用户验收（用户自己做，助手不在本机跑真实 CLI）：真实的 Claude Code、Codex 经中转站使用慢模型、等待超过 5 分钟时不断开；上游中途断开时，CLI 显示的是写明接口名和原因的错误。
