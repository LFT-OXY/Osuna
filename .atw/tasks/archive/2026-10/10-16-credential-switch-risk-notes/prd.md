# 登录凭证开关与风险提示

来源：总任务 [`10-16-magpie-osuna-gaps`](../10-16-magpie-osuna-gaps/prd.md) 的第 8 个子任务。总任务的 Constraints、Implementation Decisions、Testing Decisions 对本任务全部适用，下面只写本任务特有的。访谈的逐条决定、访谈前核实的现状与 magpie 出处见 [`research/decisions.md`](research/decisions.md)（2026-10-25，两轮，Q1–Q15，用户全部采纳推荐；测试接缝同日确认）。

对照基准：magpie `7597c132`（账号发现开关：`internal/settings/accounts.go`、`internal/provider/discovery.go`、`internal/agent/codex.go` 的 `chatGPT`、`internal/gui/assets/app.js` 的 `renderDiscovery` / `discoveryOffWarning`）；Osuna main `312e20046`。

差距明细：02·B25；03·I01 里套餐用量来源的现状；`subscription-ban-risk.md` 的 Antigravity 部分。

## Problem Statement

为了显示套餐用量（**Plan usage**），Osuna 会读 CLI 自己保存的登录：Claude Code 的钥匙串项或 `.credentials.json`，Codex 的 `auth.json`，还有 Copilot、Cursor、Grok、Kimi、MiniMax、Z.AI、OpenCode Go、Muse 的登录或 key，Claude 与 Codex 的来源还会顺带读 Pi、OMP、OpenCode 存的登录。一共 10 个套餐用量来源（**Plan usage source**），都是内置插件，常开，没有地方关掉。另外，打开 Codex 的「使用第三方接口」（**Use API endpoints**）时，Osuna 会问 Codex 是怎么登录的；从别的软件导入接口时会读 OpenCode 的 `auth.json`，里面存着 OpenCode 所有的登录。

在意隐私的用户没法确定 Osuna 不碰自己的登录。子任务 9 的多号自动轮换还要读写登录，更需要一个用户能关掉的总开关。

Antigravity 也有封号风险：Google 的 Antigravity 常见问题写明，把 `agy` 包进第三方应用使用不在消费者套餐的支持范围内，用第三方软件访问 Antigravity 违反服务条款，可能被暂停或终止账号；2026 年 2 月那一轮封号还连带封了 Gemini CLI 和 Gemini Code Assist。Osuna 正是通过 `agy` 驱动 Antigravity 的，而它的提供方页什么提示都没有。

## Solution

- 主机设置页多一节「隐私」，里面有一个 Switch「读取 CLI 登录凭证」，默认开。关掉后，Osuna 不读任何 CLI 的登录：所有套餐用量来源都不运行，内置的和用户装的插件都算；不问 Codex 怎么登录；导入时跳过 OpenCode 的登录。CLI 自己照常用自己的登录，第三方接口和接口的余额（**Balance**）照常工作。
- 关之前弹确认框，按名字列出会停止显示套餐用量的账号；开回来不弹。
- 关着的时候，套餐用量弹窗和用量页的套餐用量一节说明为什么空着，并给一个去开关的按钮；侧边栏摘要、输入框下的上下文条、上下文详情这些小地方直接不显示。
- 部署的人可以在启动 daemon 时用环境变量强制关掉，这时界面上的开关显示「已由环境变量关闭」，点不动。
- Antigravity 提供方页最上面有一块常驻的封号风险提示（**Ban risk notice**），引用 Google 的原话并附常见问题的链接。这块提示做成可复用的，子任务 9 的多号轮换风险提示直接用它。

## User Stories

### 开关

1. 作为在意隐私的用户，我希望主机设置里有一个「读取 CLI 登录凭证」开关，以便确定 Osuna 不碰我的 CLI 登录。
2. 作为用户，我希望这个开关默认开着，以便升级后套餐用量照常显示，不用我做什么。
3. 作为用户，我希望开关下面写明它管什么、不管什么（CLI 自己照常登录、第三方接口不受影响、插件里套餐用量以外的代码管不到），以便知道关掉后哪些事真的不会发生。
4. 作为用户，我希望开关是 Switch，名字是正着说的「读取」，以便一眼看懂开就是读、关就是不读。
5. 作为用户，我希望这个开关在「隐私」这一节，以便和外观、更新这些设置分开，容易找到。
6. 作为有多台设备的用户，我希望开关是整台主机的设置，以便手机、网页、桌面端看到和改到的是同一个。
7. 作为只有查看权限的设备的用户，我希望看得到开关是开是关、但改不了，以便知道主机的状态，又不越权。
8. 作为用户，我希望改开关失败时（断线、权限不够）看到原因、开关回到原来的位置，以便知道没改成。

### 关之前

9. 作为用户，我希望关掉前看到确认框，按名字列出现在显示套餐用量的账号（如「Claude（a@b.com）、Codex（c@d.com）」），以便知道代价。
10. 作为还没有任何套餐用量账号的用户，我希望确认框改说「所有套餐用量都不会显示」，以便不看到一个空列表。
11. 作为用户，我希望确认框写明第三方接口照常工作，以便放心关。
12. 作为用户，我希望在确认框里取消时开关保持开着，以便误点不出事。
13. 作为用户，我希望重新打开时不用确认，以便打开是安全操作、不多一步。

### 关掉之后

14. 作为用户，我希望关掉后 Osuna 不再读 Claude Code、Codex、Copilot、Cursor、Grok、Kimi、MiniMax、Z.AI、OpenCode Go、Muse 的登录或 key，以便确实没有任何来源在读。
15. 作为装了第三方套餐用量插件的用户，我希望这些插件的套餐用量也停，以便开关说到做到。
16. 作为用户，我希望关掉的那一刻 daemon 就丢掉已经读到的套餐用量和账号，不写进任何文件，以便关掉后主机上不留它们。
17. 作为用户，我希望关着的时候「用掉一次重置」（**Use a reset**）也做不了并说明原因，以便不会有绕过开关去用登录的操作。
18. 作为用户，我希望套餐用量弹窗里显示「已关闭读取 CLI 登录凭证，套餐用量不显示」和去开关的按钮，以便知道为什么空着、怎么恢复。
19. 作为用户，我希望用量页的套餐用量一节同样显示这行说明和按钮，以便在用量页也看得懂。
20. 作为用户，我希望侧边栏的套餐用量摘要、输入框下的上下文条、Agent 的上下文详情里不再出现套餐用量，也不放说明，以便小地方不被一句提示占满。
21. 作为钉过额度窗口的用户，我希望我钉的窗口在关掉期间保存着，开回来就回来，以便不用重新钉。
22. 作为用 Codex「使用第三方接口」的用户，我希望关掉开关不会让 Osuna 改动 Codex 的配置，以便正在用的接法不变。
23. 作为用 Codex 的用户，我希望关着的时候 Osuna 不去问 Codex 怎么登录，按上次接的样子算，以便开关管住这一处。
24. 作为从别的软件导入接口的用户，我希望关着的时候导入窗口不读 OpenCode 的登录，并说一句「已关闭读取 CLI 登录凭证，OpenCode 没读」，以便知道为什么 OpenCode 那几条没出现。
25. 作为导入 CC Switch、Alma、Claude Code、Codex 设置的用户，我希望这些照常导入，以便开关只拦登录、不拦接口配置。
26. 作为用第三方接口的用户，我希望接口的余额和套餐 key 的额度窗口照常显示，以便开关不误伤我在 Osuna 里填的 key。
27. 作为 Pi 用户，我希望 Pi 诊断里「auth.json 在不在」那一行照常显示，以便排查问题；它只看文件在不在，不读内容。

### 开回来

28. 作为用户，我希望开回来后套餐用量很快重新出现，以便不用重启。
29. 作为用户，我希望开回来后 Osuna 照常问 Codex 怎么登录、按需要重新接，以便第三方接口的接法跟上我的登录。

### 环境变量

30. 作为在 Docker 或别人部署的主机上用 Osuna 的用户，我希望启动 daemon 时设一个环境变量就强制关掉，以便从第一次启动起就不读。
31. 作为这样的用户，我希望界面上的开关显示「已由环境变量关闭」且点不动，以便知道为什么改不了。
32. 作为用户，我希望这个环境变量只能关、不能开，以便它永远不会打开我存成关的设置。
33. 作为用户，我希望去掉环境变量重启后，开关回到我存过的状态，以便环境变量不改写我的设置。

### Antigravity 风险提示

34. 作为 Antigravity 用户，我希望在 Antigravity 提供方页最上面看到封号风险提示，以便知道用消费者套餐可能被封号。
35. 作为还没装 `agy` 的用户，我希望也看得到这条提示，以便在决定要不要用之前就知道风险。
36. 作为用户，我希望提示引用 Google 的原话并附常见问题的链接，以便自己去核对。
37. 作为用户，我希望提示分开写「不支持」和「违反条款」两句话，不说成 Osuna 的用法就是违规，以便提示如实。
38. 作为用户，我希望提示常驻、不能关，也不在启用 Antigravity、新建 Agent 选提供方时另外弹窗，以便看得到又不被打扰。
39. 作为用窄窗口（手机宽度）的用户，我希望提示也在最上面、完整显示，以便小屏上也看得到。

### 兼容与跨部分

40. 作为用官方 Paseo 手机 App 的用户，我希望连新 daemon 照常能用；开关关着时套餐用量为空，没有新界面，以便手机端不受影响。
41. 作为用新 Osuna 连没升级的 daemon 的用户，我希望「隐私」一节不出现，以便不出现一个用不了的开关。
42. 作为用别的界面语言的用户，我希望开关、确认框、说明行、风险提示在 9 种语言里都有文字，中文界面全是中文，以便看得懂。
43. 作为子任务 9 的开发者，我希望能往确认框里加一句「多号自动轮换会停」，用同一个风险提示组件写多号轮换的提示，以便不另做一套。

## Implementation Decisions

### 开关的存储与生效

- 开关存在 daemon 配置里，和 `pluginsEnabled` 一样是一个主机级布尔字段（下称 `readCliSignIns`），缺省为开。读写走现有的 daemon 配置 RPC：读要 `daemon.read`，改要 `daemon.manage`。
- 环境变量 `PASEO_NO_CLI_SIGN_INS`（值不是空、`0`、`false` 就算设了；照 magpie `MAGPIE_NO_ACCOUNTS`）只在这次 daemon 运行里把生效值压成关，不改存的值。daemon 配置的读结果另带一个只读标记，说明是被环境变量关的；这时改开关的请求被拒绝，给出明确的错误。
- 生效值 = 存的值为开且没有设环境变量。daemon 内部只有一处回答「现在能不能读 CLI 登录」，下面每个闸门都问它，不各自去读配置。

### 闸门

- **套餐用量来源**：闸门放在套餐用量来源的注册表（`UsageSourceRegistry`）上，不改各个来源插件。关着时，注册表对任何来源都不调用 `discover`、`fetch`、`consumeReset`，内置与安装的来源一视同仁。
  - 新的套餐用量列表 RPC（`usage.list_reports`）返回空列表，响应里带一个可选字段说明「因为读取 CLI 登录凭证已关闭」。
  - 给旧客户端的老 RPC（`provider.usage.list`）返回空列表，不加新字段。
  - 「用掉一次重置」的 RPC 关着时拒绝，错误说明原因。
  - 从开切到关的那一刻，注册表清掉内存里的已知账号、报告缓存、正在进行的读取结果和「哪个登录答的」记录；进行中的读取完成后结果丢弃，不进缓存。这些本来就只在内存里，不落盘。
  - 从关切到开，下一次列表请求照常发现、读取；不需要重启。
- **Codex 登录方式**：关着时不起临时 Codex app-server 问 `account/read`。Codex 的登录方式按 daemon 上次判断出的结果算；daemon 重启后从没判断过，就按接管记录里现在的接法算（现有的「判断不出就保持」路径）。因此关开关本身不会重写 Codex 的 `config.toml`。开回来后，下一次需要时照常问。
- **导入**：关着时导入扫描跳过 OpenCode 的 `auth.json`（现有的「不含 OpenCode」路径），扫描结果里带一个可选标记，导入窗口据此显示「已关闭读取 CLI 登录凭证，OpenCode 没读」。CC Switch、Alma、Claude Code、Codex 的设置照常读，它们存的是接口配置。
- **不受影响**：CLI 自己的登录与运行；第三方接口、内置中转站、接口余额与套餐 key 的额度窗口（用的是用户在 Osuna 里填的 key）；Pi 诊断里只检查 `auth.json` 是否存在的那一行；用量页的 token 用量（读的是会话记录与中转站账本，不是登录）。

### 关前确认的数据

- 确认框列的名字来自客户端已经拿到的套餐用量报告：每个账号一项，写来源名加账号名（账号名缺失时只写来源名），按报告顺序，去重。没有任何报告时，改说「所有套餐用量都不会显示」。
- 确认框的正文由一组「关掉后会停的事」组成，本任务只有「套餐用量」一项；子任务 9 加「多号自动轮换」一项，不改确认框的结构。

### 封号风险提示

- 新做一个可复用的封号风险提示组件：输入标题、正文、条款链接（文字与地址），黄色（警示色）常驻块，没有关闭按钮，不要求用户做任何选择。子任务 9 用同一个组件。
- 提示内容由 app 按提供方 ID 决定，本任务只给 `antigravity` 配一条；不加新的插件清单字段或协议字段，旧 daemon 上的 Antigravity 页同样显示。
- 中文文字（其余 8 种语言照意思翻译）：

  > **Antigravity 账号可能被封禁**
  > Google 的 Antigravity 常见问题写明：把 Antigravity CLI（`agy`）包进第三方应用使用，不在消费者套餐的支持范围内；用第三方软件访问 Antigravity 违反其服务条款，可能导致账号被暂停或终止。Osuna 正是通过 `agy` 驱动 Antigravity 的。2026 年 2 月那一轮封号还连带封了 Gemini CLI 和 Gemini Code Assist。请用丢了也不心疼的账号。
  > [Antigravity 常见问题 ↗](https://antigravity.google/docs/faq/)

  英文标题「{name} account may be suspended」，{name} 填提供方名。依据见 `../10-16-magpie-osuna-gaps/research/subscription-ban-risk.md` 的 [W48]、[W45]。

### 协议与兼容

- 新增一个 `server_info.features.*` 能力位，表示 daemon 认得「读取 CLI 登录凭证」开关。客户端只在能力位为真时显示「隐私」一节、读套餐用量响应里的新字段；没有能力位就不显示，不做兜底。
- 新字段全部可选：daemon 配置的开关字段与环境变量标记、套餐用量列表响应的「已关闭」字段、导入扫描结果的「OpenCode 没读」标记。不新增 RPC。
- 旧客户端（含官方 Paseo 手机 App）连新 daemon：开关开着时一切照旧；关着时套餐用量为空，没有说明。这是可接受的结果，不加 COMPAT 分支。

### 文档与术语

- `docs/glossary.md` 已收录 **Read CLI sign-ins**、**Ban risk notice**（访谈时写入）；实现时按最终界面文字核对，补上 Code 指向。
- `docs/usage.md`：在讲套餐用量来源与「Outbound requests」的地方写明，套餐用量带着 CLI 登录去厂商的请求受这个开关管，关掉就不发。
- `docs/plugins.md`：套餐用量来源一节写明开关关着时注册表不调用任何来源。
- 不写 ADR：开关可逆，没有推翻已有规则（ADR 0010「不读 auth.json、钥匙串」不变）。

## UI and Design

- **方向**：沿用主机设置页、套餐用量弹窗、用量页、提供方页的现有样式，不另做视觉。遵守 `docs/design.md`、`docs/forms.md`、`docs/hover.md`、`docs/unistyles.md`、`docs/i18n.md` 和 `.atw/spec/app/frontend/`。用户偏好：开 / 关一律 Switch；次要操作不用蓝色链接；模型名不用等宽字体。
- **主机设置页「隐私」一节**：放在「外观」之后、本机 daemon / 更新之前。一行 Switch「读取 CLI 登录凭证」，下面是说明：
  > 让 Osuna 读取各 CLI 自己保存的登录（登录文件、钥匙串），用来显示套餐用量。关掉后 Osuna 不读这些，套餐用量不显示；CLI 自己照常用自己的登录，第三方接口不受影响。插件里除了套餐用量以外的代码，这个开关管不到。

  状态：
  - 加载中：开关不可操作，不显示错误。
  - 开 / 关：正常。
  - 保存中：开关不可操作。
  - 保存失败：开关回到原位，失败原因留在这一行下方，直到用户重试或关掉。
  - 被环境变量关闭：开关为关、不可操作，说明换成「已由环境变量 `PASEO_NO_CLI_SIGN_INS` 关闭」。
  - 只有查看权限：开关可见、不可操作。
  - daemon 不支持（没有能力位）：整节不出现。
- **关前确认框**：标题「关闭读取 CLI 登录凭证？」；正文「{账号列表} 的套餐用量会停止显示，直到重新打开。第三方接口照常工作。」，没有账号时「所有套餐用量都不会显示，直到重新打开。第三方接口照常工作。」；按钮「关闭」「取消」。
- **套餐用量弹窗、用量页的套餐用量一节**：关着时显示一行「已关闭读取 CLI 登录凭证，套餐用量不显示」和次要按钮「打开设置」，跳到主机设置页的「隐私」一节。侧边栏的套餐用量摘要、输入框下的上下文条、上下文详情直接不显示套餐用量。
- **导入窗口**：关着时在来源列表上方说一句「已关闭读取 CLI 登录凭证，OpenCode 没读」。
- **Antigravity 提供方页**：封号风险提示在页面最上方，标题下方的第一块，`agy` 装没装都显示。
- **视口**：桌面端（Electron 与浏览器，宽 1280）和窄窗口（compact 布局，宽 390）。原生端不做实机验收。
- **界面验收**（看截图能判断）：
  - 1280 与 390 下，主机设置页有「隐私」一节，开关是 Switch，说明文字完整、不被截断。
  - 确认框按名字列出至少两个账号；没有账号时显示「所有套餐用量都不会显示」那句。
  - 关着时，套餐用量弹窗与用量页显示说明行和「打开设置」按钮，按钮不是蓝色链接样式；侧边栏底部不出现套餐用量摘要。

## Testing Decisions

- **好测试的标准**：只测外部看得到的行为：RPC 返回什么、来源有没有被调用、CLI 配置文件变没变、界面显示什么；不测内部结构。确定性要求见 `docs/testing.md`。测试绝不读真实的钥匙串、`~/.claude`、`~/.codex`，不运行真的 Claude Code 或 Codex。
- **接缝一：daemon 端到端测试**（主）。先例：套餐用量来源那组端到端测试（夹具里的内置来源加目录插件，用 daemon 配置切换 `pluginsEnabled`），以及 Codex 登录方式、导入那几组第三方接口端到端测试。用例：
  - 关掉后，夹具来源的 `discover` / `fetch` 都没被调用（夹具记录调用），新 RPC 返回空并带「已关闭」字段，老 RPC 返回空；「用掉一次重置」被拒。
  - 安装的目录插件来源同样不被调用。
  - 关掉时已缓存的报告被丢掉：开回来后第一次列表重新调用来源。
  - 设了环境变量：生效值为关，读配置带环境变量标记，改开关被拒；不设环境变量重启后回到存的值。
  - 关着时打开或检查 Codex 的「使用第三方接口」，注入的 Codex 登录方式读取器没被调用，`config.toml` 不因关开关而变；开回来后读取器被调用。
  - 关着时导入扫描不读临时目录里的 OpenCode `auth.json`，结果带「OpenCode 没读」标记；CC Switch 等照常。
  - 第三方接口的余额读取在关着时照常（假的余额接口仍收到请求）。
- **接缝二：app 浏览器测试**。先例：套餐用量弹窗、用量页套餐用量、上下文条那几组浏览器测试，以及第三方接口导入窗口的测试。用例：
  - 「隐私」一节与开关；关前确认框按名字列账号、没有账号时的说法；取消后开关保持开。
  - 关掉后套餐用量弹窗、用量页显示说明行，「打开设置」跳到「隐私」；侧边栏摘要消失；开回来后恢复。
  - 改开关失败（daemon 拒绝）时开关回位、错误留在原处。
  - 被环境变量关闭时开关不可操作、说明正确。
  - Antigravity 提供方页的提示在 1280 与 390 下都在最上方。
  - 导入窗口关着时的那句说明。
- **纯逻辑**：确认框账号列表的拼法（去重、缺账号名、空列表）放进 app 现有的套餐用量逻辑测试里。
- **i18n**：靠现有的 i18n 测试保证 9 种语言键齐全、中文没有残留英文；不另写测试。
- 本机只跑改到的测试文件，全量交给 CI。

## Out of Scope

- 子任务 9 的多号自动轮换本身；本任务只给它留下开关闸门、确认框的「会停的事」列表和风险提示组件。
- CLI 子命令开关（magpie 的 `magpie accounts discovery on/off`）。
- 拦住插件里套餐用量以外的代码读文件：插件是在本机运行的代码，开关只管注册表这个入口，开关说明里如实写明。
- 其他提供方（Claude Code、Codex、Copilot 等）的风险提示：总任务定了 Claude Code、Codex 的提示在子任务 9 里做，且只在打开多号轮换时出现。
- 启用 Antigravity、新建 Agent 选提供方时的弹窗确认。
- 关掉时去掉 Pi 诊断里「auth.json 在不在」那一行。
- 把开关同步到别的主机：每台主机各自一个。
