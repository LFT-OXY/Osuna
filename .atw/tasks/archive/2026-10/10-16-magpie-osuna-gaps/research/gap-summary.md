## 主会话复核过的事实

子代理的结论中，以下几条由主会话打开源码复核：

- 中转站只认 `/v1/messages`、`/v1/responses` 两种 Agent 请求格式（另有 count_tokens、models、hello）：`packages/server/src/server/api-endpoints/gateway/gateway.ts:64-68`。
- 同名换家按模型名字面比较，`claude-opus-4.6` 与 `claude-opus-4-6` 不算同名：`gateway/routing.ts:49-56`。
- 粘性只读缓存命中数，不看缓存写入：`gateway/passthrough.ts:160-176`。
- 接管 Claude Code 时写 `permissions.deny: ["WebSearch"]`，走第三方接口时不能联网搜索：`claude-settings-patch.ts:18-19,33`。
- Claude Code 的 `settings.json` 用 `JSON.parse` 解析，带 BOM 或注释的文件被当成「解析不了」：`claude-settings-patch.ts:392-398`。
- 开着第三方接口时，Osuna 只向 Codex 要中转站那个服务商名下的线程：`agent/providers/codex-app-server-agent.ts:7407-7414`。由此推断开关前后开的 Codex 对话互相看不见、关掉开关后经中转站开的对话续不上（未实际运行）。
- Gemini CLI 在 ACP 目录里，Osuna 能运行它：`packages/app/src/data/acp-provider-catalog.ts:182-189`。上一轮 `map.md` 写的「Gemini CLI（Osuna 不支持）」已过时。
