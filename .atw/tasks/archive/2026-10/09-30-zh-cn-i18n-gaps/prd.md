# 补齐简体中文界面翻译

## Problem Statement

把应用语言切到简体中文后，界面上仍有大量英文。最显眼的是设置侧栏里的「Layout」「Agents」「Workspaces」「Providers」「Terminals」，整个「布局」设置页、终端配置、守护进程更新、诊断、提供方页面也大段是英文。添加项目、主机选择、新建工作区、终端面板、插件、PR 面板等地方同样夹着英文。

已经翻译的部分用词也不统一。同一个概念有时写「Agent」有时写「智能体」；「Worktree」和「工作树」、「Daemon」和「守护进程」、「Diff」和「差异」、「Model」和「模型」混着用；「选择 Agent Provider」也不符合 glossary 里 Provider 应译作「提供方」的规定。

产生这些问题有两个原因：

1. 很多翻译键在中文资源里直接填了英文值，或者整块引用了英文资源。
2. 约 100 处界面文案写死在代码里，没有走翻译。

现有的回归测试只要求每种语言和英文相同的文案不超过总数的 25%，所以这类遗漏一直没被拦住。

## Solution

在简体中文下，所有由客户端自己提供的界面文案都显示中文。只有按统一原则应该保留英文的专有名词不翻。

- 译法按 Git 和 VS Code 官方中文版的惯例：
  - Git 操作译作提交、拉取、推送、合并、变基、压缩合并。
  - Diff 译作「差异」，Prompt 译作「提示词」，Worktree 译作「工作树」。
- Agent 和 Subagent 是本产品的核心名词，保留英文。
- 缩写、协议名、各提供方自定义的功能名、具名主题、品牌名、占位示例值保留英文。
- 新增一条测试：中文资源里凡是和英文相同的值，必须在显式白名单里。以后再新增文案忘了翻译，测试会直接失败。
- 各术语的中文界面写法记录在 glossary 里，以后新写文案有据可查。

## User Stories

1. 作为中文用户，我希望设置侧栏的每一项都显示中文（布局、Agent、工作区、提供方、终端等），这样一眼就能找到要改的设置。
2. 作为中文用户，我希望「布局」设置页的标题、打开位置选项（主面板、侧边、资源管理器侧栏）和每个来源的说明都是中文，这样能看懂每个开关的作用。
3. 作为中文用户，我希望主机设置里「终端配置」的列表、编辑弹窗、字段名、校验提示、空状态、上移下移、删除确认都是中文，这样管理终端配置时不用对照英文。
4. 作为中文用户，我希望更新守护进程的整个流程（按钮、确认弹窗、各阶段进度、重连失败、主机离线、请求失败）都是中文，这样能看清更新进行到了哪一步。
5. 作为中文用户，我希望桌面端本地守护进程卡片里的生命周期说明（由本次桌面会话启动还是附着到已有进程、停止确认、暂停管理）是中文，这样停止前能明白会有什么后果。
6. 作为中文用户，我希望应用诊断的标题、说明、运行中状态、复制和刷新操作是中文，这样排查问题时知道每个按钮做什么。
7. 作为中文用户，我希望提供方页面的标题、操作菜单、删除确认、Models 分区和第三方接口表单的字段名是中文，这样配置提供方时不会混看中英文。
8. 作为中文用户，我希望提及 Agent 默认值里的提供方、模型、模式、思考、功能这些字段名是中文。
9. 作为中文用户，我希望插件日志的按钮、标题、加载中、刷新、错误和空状态是中文。
10. 作为中文用户，我希望主机设置里「合并 PR 后自动归档工作区」「启用终端 Agent hooks」等开关，以及它们的说明和失败提示是中文。
11. 作为中文用户，我希望「浏览器工具」卡片的标题、风险说明、更新中状态和无障碍标签是中文。
12. 作为中文用户，我希望编排技能不可用或需要升级主机时的提示是中文。
13. 作为中文用户，我希望快捷键设置和快捷键帮助里的「Pin chat」这一项显示中文。
14. 作为中文用户，我希望外观设置里的「浅色 / 深色」、关于页的「稳定版 / 测试版」是中文；具名主题（Dracula、Nord 等）保持原名，因为那是它们的名字。
15. 作为中文用户，我希望项目设置里的脚本、初始化 / 清理、拉取请求相关标签是中文。
16. 作为中文用户，我希望添加项目流程的每一步（选择主机、搜索目录、从 GitHub 克隆、选择目标位置、新建目录）的标题、占位文字、进度、空状态、错误提示和底部操作提示都是中文。
17. 作为中文用户，我希望主机选择器和主机筛选里的「全部主机」「添加主机」「本机」「搜索主机」「启用内置守护进程」是中文。
18. 作为中文用户，我希望新建工作区页面里的项目、主机、隔离方式等无障碍标签、搜索占位、空状态和校验错误是中文，启动选项里的对话 / 终端 / 管理配置 / 启动和命令占位也是中文。
19. 作为中文用户，我希望工作区标签页的「Agent 运行中」「Agent 需要输入」状态、终端面板的「找不到工作区目录」、终端的显示或隐藏键盘、粘贴、复制是中文。
20. 作为中文用户，我希望 Git 操作菜单显示「提交」「拉取」「推送」「合并 PR（压缩合并）」「自动合并（变基）」这类和 VS Code 中文版一致的写法。
21. 作为中文用户，我希望差异视图的「统一差异」「并排差异」、PR 面板的「检查」「审查」「动态」「已解决」「已过时」、草稿和打开状态是中文。
22. 作为中文用户，我希望插件界面和插件面板的「选择插件主机」「关闭插件」「插件主机离线」「插件不可用」是中文。
23. 作为中文用户，我希望会话页在某主机没有会话或加载失败时的提示是中文。
24. 作为中文用户，我希望侧栏的「显示偏好」提示和标记已读或未读失败的提示是中文。
25. 作为中文用户，我希望输入框的上传文件、拖放文件、移除附件、上传失败、文件过大提示是中文，终端提示词输入框的占位也是中文。
26. 作为中文用户，我希望 Agent 控件里的思考、功能、模式、超高等标签是中文，提供方和模型名称本身保持原样。
27. 作为中文用户，我希望同一个概念在整个界面上只有一种叫法：Agent 统一写「Agent」、Subagent 统一写「Subagent」，不在别处又出现「智能体」「子智能体」。
28. 作为中文用户，我希望「Model」统一写作「模型」、「Project」统一写作「项目」、Provider 统一写作「提供方」，不再出现「Agent Provider」这种半英文写法。
29. 作为中文用户，我希望 PR、MR、MCP、API、CLI、PID、token、Skills、Hooks 这类缩写和功能名保持英文，这样和命令、配置文件、官方文档里看到的一致。
30. 作为中文用户，我希望 app 自己生成的错误说明（例如守护进程更新时「包安装失败」「守护进程身份已变化」）是中文；守护进程或服务端返回的原始错误保持原文，方便我拿去搜索或反馈。
31. 作为维护者，我希望新增一条英文文案时如果忘了给中文填译文，测试会直接失败，而不是等用户截图报告。
32. 作为维护者，我希望少数必须和英文相同的中文值（主题名、品牌名、占位示例、纯插值）集中列在一个白名单里，每一项都是有意保留的，一眼能看出来。
33. 作为维护者，我希望 glossary 里每个核心术语都写明中文界面怎么叫，这样新写文案时不用翻资源文件去猜。
34. 作为其他语言的用户，我希望这次改动不会让我的界面变差：新增的键在我的语言里至少显示英文原文。

## Implementation Decisions

- **只修简体中文。** 迁移硬编码文案时新增的键，在其他 7 种非英语语言里填英文原文，满足键一致性测试，显示效果和现在相同。其他语言的漏翻另开任务。
- **中文资源不再引用英文资源。** 中文资源里现有的「整块引用英文」和「展开英文块」都要改成中文值。插件设置资源里对所有语言共用的英文日志文案块，要为中文单独提供译文。
- **中文译法原则**，调研依据见 `research/zh-cn-terminology-practice.md`：
  - 翻成中文：提交、拉取、推送、合并、变基、压缩合并、抓取、差异、提示词、工作树、守护进程、主机、提供方、工作区、项目、模型、终端、布局、中继、插件、思考、模式、功能、检查、审查；完整的 pull request / merge request 译作拉取请求 / 合并请求；Setup / Teardown 作为界面标签译作初始化 / 清理；Light / Dark 译作浅色 / 深色；Stable / Beta 译作稳定版 / 测试版；筛选项的 All hosts / All projects 译作全部主机 / 全部项目。
  - 保留英文：
    - Agent、Subagent。已有的「智能体」「子智能体」「代理」全部改回英文。
    - 缩写和协议名：PR、MR、MCP、API、API key、Base URL、CLI、PID、URL、Shell、token。
    - 提供方自定义的功能名：Skills、Hooks。
    - 具名主题、品牌和产品名（Osuna、GitHub、LiteLLM、OpenRouter、Claude 等）。例外：Finder 用 macOS 官方中文名「访达」（工单 04 确认）。
    - 占位示例值（命令、参数、路径、示例名称）。
    - 语言选项「English」，以及只含插值和标点的值。
  - 已有中文译文和原则一致的不动；和原则冲突的英文残留要改掉，包括 Worktree、Daemon、Diff、Prompt、Model、Project、Agent Provider 等。
- **Git 操作菜单保持同一种写法。** 合并策略写作「合并 PR（压缩合并）」「合并 PR（合并）」「合并 PR（变基）」，自动合并同理。MR 版本把「PR」换成「MR」。PR 和 MR 缩写保留，完整名词用拉取请求 / 合并请求。
- **硬编码文案全部迁移到翻译键。** 范围是排查出的约 100 处，清单见 `research/zh-cn-audit.md`，覆盖设置、添加项目流程、主机选择器、新建工作区、工作区 / 终端面板、PR 面板、插件、会话页、侧栏。沿用 `docs/i18n.md` 的边界：React 组件和自定义 hook 用 `useTranslation()`；纯函数、视图模型、常量描述对象用 `i18n.t(...)`，或者把文案改为在渲染时取值。键按产品界面分组，不按组件结构分组。
- **快捷键帮助。** 给「Pin chat」对应的快捷键补上帮助标签键，并提供中文译文。
- **客户端自己生成的错误说明要翻译**，例如守护进程生命周期里的「包安装失败」。守护进程、服务端和协议返回的原始错误文本不翻。
- **不改动的内容。** 快捷键分组的内部标识（只作 React key）、命令中心搜索关键词、诊断报告正文、日志、终端内容、Agent 输出、用户或项目 / 工作区 / 主机名称、分支名、路径，都维持原样。
- **glossary。** 各核心术语的 `zh-CN UI` 写法已写入 `docs/glossary.md`：Workspace、Agent、Daemon、Host、Worktree、Terminal、Subagent、Agent mention（提及 Agent）、Mention defaults（提及 Agent 默认值）。实现时如果还定下了其他术语（例如 Model、Project），在对应词条补上。`docs/i18n.md` 的 Progress 部分按现有格式补一条批次记录，并写明 zh-CN 白名单测试的存在和用法。
- **不涉及协议、daemon、服务端和数据存储的改动。**

## Testing Decisions

- **只用一个测试接缝：现有的翻译资源测试文件。** 不为单个组件新写渲染测试。文案是否走了翻译，由资源层断言加源码扫描来保证，这比逐个组件渲染更高层，也更不容易随实现变化而失效。
- **好测试的标准。** 只断言外部可观察的结果：资源内容，以及源码里不再出现某些英文字面量。不断言组件内部如何取值。
- **新增断言一：zh-CN 白名单。** 把中文资源和英文资源展开后逐键比较。值相同且含字母的键，必须全部出现在一个显式白名单里；白名单里的键也必须真的和英文相同，避免白名单过时。白名单只收实施决策中列出的「保留英文」类别。
- **新增断言二：源码扫描。** 沿用现有「本地连接错误保持翻译」测试的做法：维护一份本次迁移过的代表性英文字面量清单，断言 app 源码（不含测试文件和 i18n 目录）里不再出现。
- **保留现有断言。** 键一致性、插值占位符一致、回退比例这几条测试不动。现有断言里写死的中文 Model 计数文案「个 Model」要随新译法改为「个模型」。
- **参考已有测试。** 同一文件中的键一致性测试、插值一致性测试、本地连接错误的源码扫描测试。
- **运行方式。** 只跑该测试文件，并跑 typecheck 和 lint。不跑全量测试。
- **人工验收。** 在 Electron 桌面端把语言切到简体中文，逐一截图检查：设置侧栏；布局、主机（含终端配置、守护进程、浏览器工具、Agent hooks）、提供方、插件、诊断、快捷键这几个设置页；添加项目流程；新建工作区；工作区 Git 操作菜单。原生端没有模拟环境，免验收。

## Acceptance Criteria

- [ ] 简体中文下，设置侧栏每一项都显示中文或按原则保留的英文（「Agent」），不再出现 Layout、Agents、Workspaces、Providers、Terminals。
- [ ] 中文资源里值和英文相同的键，全部属于白名单中的保留类别；白名单测试通过。
- [ ] 中文资源不再整块引用或展开英文资源。
- [ ] 排查清单里的约 100 处硬编码英文都已迁移到翻译键，源码扫描测试通过。
- [ ] 中文资源中不再出现「智能体」「子智能体」「Agent Provider」，也不再有英文的 Worktree、Daemon、Diff、Prompt、Model、Project、Commit、Push、Pull 作界面名词（占位示例值和插值除外）。
- [ ] 其他语言资源的键和英文完全一致，新增键填英文原文；插值占位符一致性测试通过。
- [ ] `docs/glossary.md` 各核心术语都有 `zh-CN UI` 写法；`docs/i18n.md` 已补本次批次记录和白名单测试说明。
- [ ] typecheck、lint 通过。
- [ ] Electron 桌面端中文截图检查完成，覆盖测试决策里列出的界面；原生端注明免验收。

## Out of Scope

- 阿语、西语、法语、日语、韩语、葡语、俄语的漏翻修复。
- 服务端、守护进程、协议返回的文案和错误。
- Agent 输出、终端内容、日志、诊断报告正文。
- 提供方名、模型名、提供方自定义选项标签这类运行时数据。
- 阿拉伯语 RTL 等布局方向问题。
- 官网、CLI、桌面端主进程菜单等 app 包以外的文案。

## Further Notes

- 调研和排查依据：`research/zh-cn-audit.md`（缺口清单与访谈结论）、`research/zh-cn-terminology-practice.md`（Git、VS Code、Trae 的中文译法对照）。
- 「Model 译作模型」「Project 译作项目」是我按「官方惯例」原则推出来的，访谈里没有单独问过。目前中文资源里「Model」39 处、「模型」62 处混用；现有测试还写死了「个 Model」，它来自早前一次设置文案清理的提交。如果当时是有意保留英文，需要在确认本 PRD 时指出。
- 改动面较大，建议按界面拆工单：资源补译和白名单测试、设置、添加项目与主机选择器、新建工作区与工作区面板、Git / PR / 插件 / 会话 / 侧栏零星项。每张工单都可以单独跑资源测试验证。
