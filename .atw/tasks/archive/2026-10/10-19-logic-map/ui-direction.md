# 逻辑图面板：设计说明

2026-10-19 第 01 轮风格对比，用户选定 **04 贴近 Dify / Coze**。对比页：`style-explorer.html`（五个方向，清单 `manifest.json`）；选定方向的静态首屏：`prototype/direction-d.html`，截图 `prototype/shot-d.png`。正式界面由 atw-ui 按本说明在 `packages/app` 里重新实现，原型代码不搬进正式代码。

## 用户任务

和 Agent 讨论功能时，在右边栏看清这个功能"事情怎么走"：主路径、每个判断的每条分支、失败的那条路；点一个节点在主区域读它的文档，并在图上看到自己读到了哪里。图只能看，不能在图上编辑。

## 内容与主动作

- 内容：一层图里 7–20 个节点，种类为开始 / 结束、步骤、判断、子图；连线带条件。
- 主动作：点节点打开节点文档；点子图节点进入下一层；拖动、缩放画布。

## 用户的喜欢与不喜欢

- 用户想要的就是 Dify / Coze 工作流画布的样子。第一轮只按项目配色做的三个方向（A 卡片画布、B 分支轨道、C 分叉块），用户的反馈是"不是它们的样式"。
- 用户是在已知两条代价的情况下选的 04：在 320 像素宽的边栏里"适应宽度"要缩到约 57%，字很小；还用了项目配色以外的颜色。
- 不要：把这个方向磨回项目原有的灰蓝配色。

## 方向卡

| 字段 | 内容 |
| --- | --- |
| 北极星 | 打开就像在 Dify / Coze 里看一张工作流：一眼认出哪种节点、从哪个判断的哪一行走出去、哪条是失败的路。 |
| 调性 | 能量中等偏安静：彩色只在图标块和连线上，卡片是白的。完成度精致：统一圆角、柔和阴影。密度中等。分量轻。严肃度偏活泼：圆角图标块，颜色鲜明。依据是用户选的就是这两家的外观。 |
| 标杆与取舍 | 品类：AI 工作流编排画布。真实画面：`references/dify-1.png`～`dify-4.png`、`references/coze-1.png`～`coze-3.png`，另有 `references/n8n-*.png`、`references/archify-workflow-1.png`。**沿用**：无边框白卡加柔和阴影；每种节点一个彩色圆角图标块；判断卡片内一行一个分支（"如果 / 否则"加灰底条件），出口圆点在右缘；Coze 的靛紫连线带箭头；Dify 的灰底点阵画布；选中时 2px 蓝色描边。**换掉**：从左往右排改为从上往下排（边栏只有 320 像素宽）；卡片里的配置字段全部去掉，只留标题（图只能看不能编辑）；连线不再全是同一种颜色，失败的路用红色（PRD 要求失败分支一眼能看到，两家标杆都没有这一点）；Dify 的 ITERATION 容器改成一张带"子图 · N 个节点"标签、点进去看下一层的卡片。**撞脸说明**：这个方向有意贴近标杆，是用户的明确选择，不按"不撞脸"规则重做；不使用两家的商标、图标原稿和文案。 |
| 生成引擎 | 其他领域的整套表现形式：借 AI 工作流编排工具的画布语法。证据：PRD 点名参考 Dify、Coze，用户选定 04。 |
| 首屏骨架 | 右边栏 320 宽：标签栏（文件 / 更改 / 会话历史 / 逻辑图），一行图名下拉框加节点数，一行面包屑，下面整块是画布，右下角浮着缩放控件。画布从上往下排：主路径在左列，失败分支向右展开。 |
| 页面结构 | 只有一个面板：头部两行，画布占满剩余高度。节点文档在主区域的文件标签里打开，不在面板内。 |
| 各区块的形式 | **普通步骤**：白卡，紫蓝图标块加标题。**判断**：白卡，青色图标块加标题；下面每条分支一行，左边灰色小字"如果 / 否则如果 / 否则"，右边灰底条件，行的右缘一个出口圆点。**失败步骤**：红色图标块。**子图**：橙色循环图标块，标题后面一个 ›，卡片下方浅橙标签"子图 · N 个节点"。**开始 / 结束**：蓝色图标块（开始用房子，结束用旗子）。**"未指向文档"标记**：卡片下方浅黄底、黄边、橙色字的小标签。**选中**：2px 蓝色描边。**画布**：灰底点阵。**缩放控件**：白色小条，内容为 −、百分比、+、适应。 |
| 字体 | 系统字体（与应用一致，PingFang SC）。节点标题 14px、weight 600；分支行的标签 11px，条件 12px；子图和标记小标签 10px、weight 600。图名不用等宽字体。 |
| 色彩 | 见下方色表。来源：照搬 Dify / Coze，是用户的选择；只在逻辑图画布内部使用，面板头部和标签栏仍用应用的主题色。 |
| 主视觉 | 彩色图标块和靛紫连线就是主视觉，不另加插画。 |
| 图标 | 白色实心图形放在 24px、圆角 7px 的彩色方块里，图形本身 14px。种类：房子（开始）、分叉（判断）、横线列表（步骤）、警告三角（失败步骤）、循环箭头（子图）、旗子（结束）。正式实现时从项目已有图标库里挑形状相近的，不照抄两家的图标原稿。 |
| 控件语法 | 卡片圆角 12px，阴影 `0 1px 2px #1018280f, 0 1px 3px #1018281a`，无边框；条件灰底块圆角 6px；出口圆点 10px，外圈 2px 白边；连线 2px，带实心箭头；选中用 2px 蓝色外圈，不加粗、不放大。 |
| 动效 | 手感"嗒"：像在白板上把磁贴按住。图更新时新节点淡入（150ms），已有节点平移到新位置（200ms，减速曲线）；悬停卡片时阴影略加深；系统开了"减少动态效果"就全部直接到位。图上不做变更闪烁（PRD Out of Scope）。 |
| 结构性突破 | 判断节点不画成菱形，而是一张"条件清单"卡片：每条分支一行，线从行尾引出。这样条件文字永远不会压在线上，直接满足 PRD 的截图验收"条件文字不与线或节点重叠"。 |
| 记忆点 | 点节点打开文档时，这张卡片的蓝色描边从无到有（150ms），主区域同时打开文件标签：用户看到的是"图上这一块就是我在读的这份文档"。 |
| 放弃什么 | 菱形判断框；写在线中段的条件文字（archify、n8n 那种）；卡片里的配置字段和运行结果条；全部连线同一种颜色；从左往右的横向布局。 |

## 视觉关系

- 主角是连线和图标块的颜色，用来认路；卡片本身是安静的白色。
- 红色只出现在失败的路上：图标块、连线、出口圆点、条件文字。扫一眼红色就是全部的异常情况。
- 蓝色只用于开始、结束和选中，所以选中的蓝框不会和别的东西混在一起。

## 关键状态

按 PRD 的"必须有的画面与状态"逐个画出来，这个方向下的样子：

- **空状态**（工作区还没有逻辑图）：灰底点阵画布中间放一张白卡，写开启说明。
- **加载中**：画布上 3 张灰色骨架卡片。
- **新建后还没写入的空图**：画布中间只有一张"开始"卡片，下方一行灰字提示"Agent 还没有写入节点"。
- **子图内层**：面包屑最后一级是当前层。
- **节点选中高亮、"未指向文档"标记**：见方向卡。
- **图文件损坏**：画布换成一张白卡，左上角红色警告图标块，写明是哪张图、哪个文件出了什么问题。
- **主机版本太旧**：同样的白卡样式，图标块用灰色。
- **输入框工具栏开关和选择弹层**：沿用应用自己的 Switch 和弹层，不用这个方向的配色。

## 设备约束与已知风险

- 只做桌面端（Electron），窗口 1280 宽，右边栏默认 320 宽。
- **字太小的风险**：13 个节点的图"适应宽度"后约为 57%，标题约 8px，有几个被截成"……"。PRD 的截图验收允许"截断但有完整标题的提示"，所以每张卡片都要有悬停时显示完整标题的提示。打开面板时默认是"适应宽度"还是"原大并定位到当前节点"，留到 atw-ui 阶段决定，并截图对比。
- **超出项目设计规范**：`docs/design.md` 第 14 节禁止新增颜色。逻辑图画布要在那里登记为一个例外，写明范围只限画布内部、理由是用户在原型阶段的选择；面板头部、标签栏和弹层不在例外内。

## 验收重点

- 并排看 `prototype/shot-d.png` 和正式截图：图标块配色、判断卡片的"如果 / 否则"行加右缘出口、靛紫和红色两种连线、灰底点阵、蓝色选中描边都一致。
- PRD 的截图验收逐条过一遍，尤其是长标题截断后有完整标题的提示，以及条件文字不与线重叠。
