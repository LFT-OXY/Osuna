# 合并上游 Paseo v0.12.0 至 v0.13.0

**Status:** ready-for-agent

依据：`research/discovery.md`（范围、七段、访谈逐条确认的十六条决定）、`research/conflicts.md`（2026-10-26 的模拟合并数据）、`research/feature-overlap.md`（两边功能的三方对比与 33 条按规则的裁决）。做法沿用 `docs/release.md` 的「Fork 分发 → 从上游同步」，本文只写这一次特有的范围、裁决与验收，不重述那一节。相关既有决定：ADR 0002（改名止于桌面 App 身份）、ADR 0003（指令列表不启动进程）、ADR 0004（Agent mention 由父 Agent 派发）、ADR 0006（代码里的 usage 是上游的套餐用量）、ADR 0013（逻辑图）、ADR 0015（多号轮换）、ADR 0016（Markdown 文件预览跟随上游，取代 ADR 0001）。

## Problem Statement

Osuna 在 2026-10-13 把上游 `getpaseo/paseo` 合到了 v0.11.2（`759532509`）。上游之后发了 v0.12.0（10-19）与 v0.13.0（10-24），连同各 beta 共 328 个提交。Osuna 用户现在拿不到其中的东西：

- 不能把自己的主机连到另一台机器、让 Agent 把工作委派过去（连接的主机，`paseo host add`）。
- 没有 Hoplite 提供方；「添加提供方」目录不能按匹配度排序。
- 侧栏不能按创建时间排序、不能显示后台工作区，长项目组不会折叠成「显示更多」。
- Changes 没有把已提交与未提交合成一份的 All changes。
- 聊天里的 Markdown 不能跨段选择、表格不能横滑；终端不能粘贴图片、拖入文件。
- 插件不能提供文件面板、不能带自己的翻译。
- Claude 计划审批里没有 Implement with Auto；没有 Claude Mythos 5.1；子 Agent 的报告与结束通知各发一条，daemon 重启后结束通知会丢。
- 手机端没有全屏写消息、可折叠屏布局，Explorer 在手机、平板、桌面上是三套不同的样子。
- 还有大量缺陷修复：daemon 重启后 Agent 一直显示运行中、恢复的会话里混进 Claude 请求上下文、目录页之外的 Agent 归档不了等。
- 一个安全修复：主机设了密码时，经中继的连接仍可不带密码进来。

每多拖一个版本，两边同时改过的文件就多一批：这一次模拟合并已有 204 个文件、426 个冲突块，上一次是 150 个文件。

这一段里有几处两边各走了一条路，不处理好会丢东西或改变用户看到的效果：

- **Markdown。** 上游三端统一换成一个新的渲染器，删掉了 Osuna 改过样式的那个文件；Osuna 在 Web 上另有一套 DOM 渲染的文件预览（ADR 0001），上游这期在它自己的预览上又做了相对图片、相对链接与 Preview/Source 切换。
- **Composer 输入。** Osuna 把 Web/Electron 的输入换成了 Tiptap 并删掉了测高模块；上游给那个模块加了手机全屏编辑。
- **Explorer。** 上游删掉了手机与平板上单独的 Explorer 侧栏，三端改用一套；Osuna 的会话历史标签接在被删的文件里。
- **套餐用量的文案。** 上游新加了一套 `providerUsage` 翻译键，和 Osuna 已有的 `usage.planUsage` 说的是同一批话，中文措辞也不同。
- **中继密码。** 上游删掉了「经中继不带密码也放行」的兼容分支；Osuna 0.16、0.17 的更新日志写着旧 App 照常能连。
- **上游的补丁分支。** v0.11.2 在补丁分支上，这次合主线版本时分叉处要重解 16 个文件，`docs/release.md` 里「合 v0.12 没有要重解的文件」那句不成立。

## Solution

把上游从 v0.11.2 到 v0.13.0 的 328 个提交整版合并进 main，用保留上游历史的 git merge。

合并在分支 `merge-upstream-paseo-updates` 上进行，按上游自己的七个发布点分七段，每段一个 merge commit。七段都在本机做完、每段通过本机检查后，开一个 PR，CI 只在开 PR 时跑一次；以 merge commit 并入，main 只变一次。

合并后的 Osuna：

- 多了上游这两个版本的全部功能与修复。
- Markdown 文件预览与聊天 Markdown 都用上游的渲染器；Osuna 的 DOM 文件预览删除，逻辑图带行号的节点改为打开源码视图并定位到那一行。Web 上聊天代码块的语言标签头与复制按钮还在。
- 手机上收下上游的全屏编辑与统一的 Explorer；电脑上 Composer 仍是 Tiptap 输入，Explorer 的会话历史标签仍在。
- 套餐用量用上游的翻译键，界面上的中文措辞不变。
- 主机设了密码时，经中继的连接必须带密码；`SECURITY.md` 随上游改为现状，下次发版的更新日志写明旧 App 要重新添加主机。
- 桌面身份、更新源、签名、外链、设置页外观、界面中文、版本号与更新日志继续是 Osuna 的。
- `docs/release.md` 里记录的同步点更新到 v0.13.0，补丁分支一节与开 PR 的时机改成这次的做法。

## Implementation Decisions

### 合并方式

- 合并分支 `merge-upstream-paseo-updates` 从 main `b8d4f55e7` 开出。依次做七次 merge，每次一个 merge commit，上游发布点用提交 SHA 引用，不抓上游 tag。从 GitHub 的 `upstream` remote 取，不从维护者本地的上游克隆取。

| 段  | 上游发布点     | 提交        | 本段上游提交数 | 累计冲突文件（模拟） | 本段首次出现 | 这一段带进来的主要东西 |
| --- | -------------- | ----------- | -------------- | -------------------- | ------------ | ---------------------- |
| 1   | v0.12.0-beta.1 | `e2f4948f9` | 165            | 97                   | 97           | 新 Markdown 渲染器、手机全屏 Composer、Hoplite 与提供方目录、Agent 间消息信封与插话、后台工作区、补丁分支分叉处 16 个文件 |
| 2   | v0.12.0-beta.2 | `c517d07d6` | 27             | 109                  | 12           | 新建工作区与打开项目页、Paseo 工具 |
| 3   | v0.12.0-beta.3 | `cc748dfe1` | 22             | 122                  | 13           | 套餐用量卡片与格式化、用量来源缓存 |
| 4   | v0.12.0        | `cafe4b01c` | 22             | 130                  | 8            | 设计文档、子 Agent 选择、安卓商店说明 |
| 5   | v0.13.0-beta.1 | `3fa625701` | 52             | 180                  | 51           | 连接的主机、Explorer 三端统一、`file-pane` 改名 `file-panels` 与插件文件面板、All changes、套餐用量文案、按需加载翻译、通知批处理、setup 重写 |
| 6   | v0.13.0-beta.2 | `30d8cb044` | 27             | 199                  | 19           | 终端去掉 WebView 渲染器与粘贴图片、中继强制密码、Claude 代理重写 |
| 7   | v0.13.0        | `d34d17a90` | 13             | 204                  | 5            | 安卓商店说明、设置标签回归用例 |

- 每段的 merge commit 本身通过 typecheck、lint 和该段冲突文件对应的测试。冲突之外的适配（文案、外观、`COMPAT` 标签、豁免名单）紧跟在 merge commit 之后单独提交，进入下一段之前做完。
- 维护者 2026-10-26 确认：七段在本机全部做完，每段只跑改到的测试；全部做完再开一个 PR，目标分支 main，CI 只在开 PR 时跑一次。偶发失败只重跑失败的作业。
- 并入 main 用 merge commit，不 squash、不 rebase。合并期间 main 有新提交时把 main 合进合并分支。
- 上游这期没有占用 Osuna 已有路径或类名的新目录，不需要合并前的准备提交。

### 补丁分支

- v0.11.3、v0.11.4 不单独合：它们在 v0.11.2 之后的同一条补丁分支上，4 个修复在 v0.12.0-beta.1 之前的主线上都有等价提交，随第 1 段进来。
- 分叉处要重解的 16 个文件全在第 1 段：15 个是版本号与锁文件，按「版本号与发版元数据」处理；依赖补丁脚本取主线一侧（Osuna 同步后没改过它）。裁决按 `docs/release.md` 的固定规则：上游的部分取主线一侧，Osuna 的改动保留。
- 合完后 `759532509` 与 `d34d17a90` 都是合并分支的祖先；与上游 main 的共同祖先变成 v0.13.0 本身。

### Markdown
