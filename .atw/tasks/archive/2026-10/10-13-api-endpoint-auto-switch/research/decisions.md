# 访谈决策记录（discover 阶段）

日期 2026-10-13。用 `/atw-askme-with-docs` 逐轮追问得出，按轮次记录；「→」后是用户的最终答复。调研事实见同目录 `magpie.md`。

## 第一轮

- Q1 建 ATW 任务 → 建。
- Q2 总体做法 → **A：在 daemon 里内置本地中转站**。Agent 配置文件指向中转站，由它转发并在出错时换接口重发。（备选 B 复用 magpie 程序、C 不做中转站只改配置文件，均否决。）
- Q3 切换范围 → 用户澄清：**切换单位是整个第三方接口**（一家中转站 = 一个 URL + 一个 key），一家用尽换另一家。不做「同一接口多 key」，不做订阅账号轮换。
- Q4 覆盖 Agent → 第一版 **Claude Code + Codex**，沿用现有接线；第二期 **Pi、OMP**（它们目前没有第三方接口接线，第二期先补接线）；其他 Agent 不做；Gemini CLI 不在 Osuna 支持范围内。
- Q5 终端里直接跑的 CLI → 也走中转站，切回「官方」全部还原；daemon 不在时 Agent 连接失败，可接受。
- Q6 用尽判定 → 第一版只做被动（看上游错误）+ 冷却；主动读套餐用量第二期。
- Q7 界面位置 → 塞进现有「第三方接口」设置，不新开页面。
- Q8 术语 → 见第三轮修订。

## 第二轮（部分被第三轮修正）

- Q9 术语 → 修订为：**切换顺序**（名单里的兜底顺序）、**自动切换**、**冷却中**、**默认模型**。「密钥」「首选接口」不用。
- Q10 启用方式 → A：启用的是一份有顺序的接口名单；名单外的接口只是保存着。
- Q11 → 名单里只要有接口就一律走中转站，只保留一条路。
- Q12 换接口后模型名 → 下一家有同名模型就原样转；没有就用那家的默认模型，并在对话里加一行「本轮由接口 X 的模型 Y 回答」。
- Q13 → 被第三轮 Q19 取代：模型选择器列出名单里**所有**接口的模型，按接口分组。
- Q14 Claude 档位对应（opus/sonnet/haiku/fable）→ 每个接口各一份，中转站按**实际在用的那家**翻译。
- Q15 用尽判定与冷却时长 → 照 magpie：欠费 30 分钟；额度用完按厂商给的重置时间、没给 15 分钟；限流 1 分钟起翻倍最长 30 分钟；key 无效/无权限标「需要检查」不再自动用，直到用户编辑；其他服务器错误 1 分钟起翻倍最长 10 分钟；全部冷却时把最后一家的错误原样交给 Agent。冷却只记内存，daemon 重启清零。
- Q16 → 只在回复第一个字节之前切换；流中断的错误原样交给 Agent，那家照样冷却。
- Q17 → 不弹窗；接口设置页每家显示「使用中 / 冷却中（xx 后恢复）/ 需要检查」，composer 上方的小横条标出当前实际在用的接口。
- Q18 → 冷却中的接口可手动「立刻恢复」；可手动「暂停」某一家而不移出名单。
- 替用户定的两条：中转站挂在 daemon 现有 HTTP 服务上，不单开端口；写进 Agent 配置文件的「API key」是 Osuna 随机生成的口令，真实 key 只留在 daemon。

## 第四轮（依据 magpie 第二次调研）

- Q24 兜底 → **照 magpie**：每家接口有一份**兜底名单**（有序，每项是「接口/模型」），只展开一层；没填就不兜底，把厂商错误原样交给 Agent 并附「几点前不会再问它」。退过去时用名单里写的模型名。第二轮 Q12「自动找同名/用默认模型」与 Q10「切换顺序」作废。

- Q28 → 接受 magpie 的已知限制：推理不跨厂商携带、转换后由我们自己打缓存标记、无 URL 图片报错。
- Q19 → 确认。
