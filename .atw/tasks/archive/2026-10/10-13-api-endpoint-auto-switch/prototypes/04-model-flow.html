第三方接口：接口、开关、默认模型、兜底名单是怎么串起来的

只为说明思路，不是最终界面。三张图对应你问的三个问题。

图 1 · 为什么模型名前面要带接口标识

国内的中转站大多卖同一批模型，两家接口里经常有一模一样的模型名。

接口 A 标识 relay-a

  • claude-sonnet-4-5
  • gpt-5

接口 B 标识 relay-b

  • claude-sonnet-4-5
  • kimi-k2.5
→

Claude Code 发请求时只带一个字符串

它只会说「我要用 claude-sonnet-4-5」，不会说「我要 B 家的」。

Claude Code 和 Codex 都是别人家的程序，Osuna 改不了它们的做法。

→

只写模型名：中转站只能猜

A 和 B 都有这个模型，中转站不知道你想走哪家，只能默认挑第一家。你在模型选择器里「选 B 家的」这件事就传不过去。

写成 relay-b/claude-sonnet-4-5：一眼就知道

中转站看到前缀，直接走 B 家，再把前缀去掉发给 B。

这个带前缀的名字只会出现在终端里的 /model 命令和 CLI 配置文件里；Osuna 的界面上按接口分组显示，不露前缀。

图 2 · 开关、模型选择器、默认模型各管什么

开关决定「这家的模型能不能选」；默认模型只决定「一个全新的会话从哪个模型开始」。

电脑上保存的接口（两个 Agent 共用）

接口 A 勾选的模型：claude-sonnet-4-5、gpt-5
这家自己的默认：claude-sonnet-4-5
接口 B 勾选的模型：claude-sonnet-4-5、kimi-k2.5
这家自己的默认：kimi-k2.5
接口 C 勾选的模型：deepseek-v4
这家自己的默认：deepseek-v4
→

Claude Code 的设置

接口 A 已开启

接口 B 已开启

接口 C 关闭

默认模型：B / kimi-k2.5

开关全关 = 回到「官方」，Claude Code 用自己原来的登录。

→

模型选择器里看到的

接口 A

  • claude-sonnet-4-5
  • gpt-5

接口 B

  • claude-sonnet-4-5
  • kimi-k2.5 默认

接口 C 关着，所以不出现。开着的两家的模型都能随时选。

「默认模型」什么时候起作用

  • 终端里直接敲 claude：它必须从某一个具体模型开始，这个模型就是写进它配置文件里的「默认模型」。
  • Osuna 里新建对话：Osuna 会记住你上次选的模型；只有第一次、或者上次选的模型已经不在列表里时，才退回「默认模型」。

所以开关管「哪些能选」，默认模型管「没选之前先用哪个」，两者不冲突。

如果你不想多一个「默认模型」下拉框，也有一个更省事的做法：默认模型自动取「开着的接口里最早建的那家」自己的默认模型。省一个控件，代价是你想换起始模型时得去改那家接口的默认，或者调整开关。

图 3 · 兜底名单是接口自己的，每一项写明「哪家 / 哪个模型」

某家接口额度用尽时，中转站在回复第一个字之前，按这家的兜底名单换一家重发。

接口 A 的兜底名单

  1. 接口 B / claude-sonnet-4-5
  2. 接口 C / deepseek-v4

每项都要写明模型：B 家不一定有 A 家同名的模型，所以不能只写「换到 B」。

每项只能从那家接口勾选过的模型里挑：勾选过的才是你确认它真的有的，手填容易拼错。

→

1. 你这段对话选的是 A / gpt-5

2. 中转站发给 A，A 回「额度用完」 A 冷却 15 分钟

3. 中转站查 A 的兜底名单，第一项是 B / claude-sonnet-4-5

4. 改发给 B，用 B 的这个模型回答；对话里加一行「本轮由接口 B 的 claude-sonnet-4-5 回答」

5. 下一轮回到你选的 A（A 还在冷却就继续用 B）

兜底名单为空的接口用尽了就不换，直接把错误交给 Agent。

删掉接口 B、或在 B 里取消勾选某个模型时，所有兜底名单里引用它的那一项自动消失，不用你手动去清。
