# 余额与套餐用量显示

来源：总任务 [`10-16-magpie-osuna-gaps`](../10-16-magpie-osuna-gaps/prd.md) 的第 4 个子任务。访谈两轮（R1、R2），2026-10-22 用户逐题回答；全部决定、照 magpie 的细则与 magpie 源码出处见 [`research/decisions.md`](research/decisions.md)。总任务的 Constraints、Implementation Decisions、Testing Decisions 对本任务全部适用，下面只写本任务特有的。对照基准：magpie `7597c132`，另取最新版 `ea6be159` 的三处小改进。差距明细：块 5，02·A70–A74, B27–B28；01·F03, D08；03·I01–I10（逐行去向见 Further Notes）。

## Problem Statement

用户靠多家第三方接口（**API endpoint**）在 Claude Code、Codex 里干活，有按量付费的厂商与中转服务，也有按 5 小时 / 周 / 月限量的套餐 key。在 Osuna 里看不到：

1. 每家还剩多少钱。DeepSeek、Kimi、OpenRouter、硅基流动、阶跃这些厂商都有查余额的接口，Osuna 不去查，只能逐个登录官网看。
2. new-api、one-api、sub2api 一类中转服务里，这把 key 还剩多少、整个账户还剩多少。
3. Kimi Code、GLM Coding Plan、MiniMax、OpenCode Go 这类套餐 key 的窗口还剩多少、什么时候重置、照现在的速度会不会提前用完。Osuna 的套餐用量（**Plan usage**）只读 CLI 的登录或环境变量，不读接口里存的 key。
4. 别的中转服务有自己的余额地址，Osuna 没有地方填。
5. ChatGPT 账号持有的 Codex 额度重置次数：Osuna 的 Codex 套餐用量已经拿到这个数，却不显示，也不能用掉一次。

## Solution

做完后，用户看到的是：

- 「第三方接口」列表的每一行多一小段：余额，或这家剩得最少的套餐窗口；查不到时写「余额查不到」。
- 接口详情页新增「余额与套餐用量」分区：每项余额，每个窗口的已用 / 剩余、重置时间和配速；查不到时就地写原因，暂时查不到时显示上次读数和读数时间。认不出查法的接口，分区提示去填余额查询地址。
- 已知厂商按接口地址自动认，什么都不用填。中转服务在编辑窗口「高级」里填余额查询地址、方法、取值写法、账户令牌（new-api 另有「用户 ID」）；「自动识别」按下才试两个常见地址；「查询余额」用表单里的值当场查。
- 火山方舟、腾讯云的套餐填云账号密钥后可查；智谱团队套餐填团队组织 ID 和项目 ID 后可查。
- 列表页有一个开关「自动刷新余额与套餐用量」：开着时页面开着就每分钟刷新；关掉后只在打开页面和点刷新时查。
- Codex 的套餐用量卡片写出「还有 N 次重置」和最早的过期时间，可以先确认再用掉一次。

## User Stories

### 已知厂商的余额

1. 作为 DeepSeek 用户，我希望接口行和详情页直接显示余额，以便知道什么时候该充值。
2. 作为 DeepSeek 用户，我希望人民币和美元两种余额都列出来，有余额的排在前面，以便看清每种币各剩多少。
3. 作为 DeepSeek 用户，我希望总额下面分开写「赠送」和「充值」，以便知道真金白银还剩多少。
4. 作为 Kimi（Moonshot）用户，我希望国内站显示人民币、国际站显示美元，以便币种不出错。
5. 作为 OpenRouter 用户，我希望看到剩余 credits（总额减已用），以便知道还能跑多久。
6. 作为硅基流动用户，我希望看到余额；它的余额接口下线时看到「接口已下线，请去控制台看」，以便不把它当成我的 key 出了问题。
7. 作为阶跃用户，我希望看到余额（含代金券），以便知道还剩多少。
8. 作为 Command Code 用户，我希望看到月度、购买、赠送三项 credits 的合计，以便一眼看到总余量。
9. 作为 Ollama Cloud 用户，我希望看到购买余额（美元）；套餐没有购买余额时不出这一项，以便不看到一个没意义的 0。
10. 作为 AiHubMix 用户，我希望不填令牌也能看到 key 的剩余额；key 没设上限时提示我填账户令牌看账户余额，以便知道下一步怎么办。
11. 作为用户，我希望 Osuna 只凭接口地址就认出这些厂商，不用我做任何设置，以便加完接口就能看到余额。

### new-api / one-api 与 sub2api

12. 作为 new-api / one-api 中转服务的用户，我希望填上 key 级余额地址后看到这把 key 还剩多少（按 500000 换 1 美元），以便知道它什么时候用完。
13. 作为 new-api 用户，我希望另填系统访问令牌和用户 ID 后看到整个账户的余额，以便知道账户里还剩多少钱。
14. 作为 new-api 用户，我希望用户 ID 填在一栏里，只在查余额时发出，以便它不跟着每次聊天请求发给这家。
15. 作为已在接口请求头里加过 `New-Api-User` 的用户，我希望 Osuna 也认它，以便不用再填一遍。
16. 作为 sub2api 用户，我希望看到这把 key 的剩余额度，以及 5 小时、1 天、7 天的限额窗口和重置时间，以便安排用量。
17. 作为 sub2api 用户，我希望填了登录令牌后看到账户余额，以便知道账户里还剩多少。
18. 作为用户，我希望令牌粘错了地址（账户令牌配了 key 级地址）时，Osuna 告诉我该改用哪个地址，并能一键改，以便不用自己查文档。
19. 作为用户，我希望填了账户级地址却没填令牌时，Osuna 改查同站点的 key 级地址，以便至少看到这把 key 的余额。
20. 作为 new-api 用户，我希望缺用户 ID 时看到「补上用户 ID」的提示，以便知道为什么被拒。
21. 作为不知道余额地址的用户，我希望在编辑窗口按「自动识别」，让 Osuna 试 new-api 与 sub2api 两个常见的 key 级地址，试中就替我填好，以便不用自己找地址。
22. 作为在意 key 去向的用户，我希望「自动识别」只在我按下时才试，以便 Osuna 不在后台带着 key 乱试地址。

### 自定义余额

23. 作为 OpenAI 旧式额度的用户，我希望把余额地址填成 credit grants 的地址后看到剩余额度，以便知道还剩多少。
24. 作为别的中转服务的用户，我希望自己填余额查询地址和方法（GET 或 POST），以便任何能查余额的服务都能显示。
25. 作为用户，我希望地址和请求头里可以写 `{key}` 一类占位，Osuna 换成这家的 key，以便把 key 放进地址或别的头里。
26. 作为用户，我希望写取值写法：点分路径、数组下标、四则运算、括号，以便从对方的回复里算出余额。
27. 作为用户，我希望取值写法能加 `$` `¥` `€` `£` 前缀、`%` 后缀，带 `%` 的显示进度条，以便余额和用量比例各自显示得对。
28. 作为用户，我希望取值写法能展开列表、按条件筛选，再用 `sum` `max` `min` `count` 汇总，以便处理按模型或按套餐分项的回复。
29. 作为用户，我希望用 `;` 写几项、每项加标签，某一项取不到时显示「—」、其他项照常显示，以便一张卡上看到几个数。
30. 作为用户，我希望不填取值写法时，Osuna 按地址给出 new-api、sub2api、credit grants 的默认写法，表单里有对应的占位提示，以便常见的服务只填地址就够。
31. 作为用户，我希望在编辑窗口按「查询余额」，用表单里还没保存的值当场查一次，结果显示在按钮旁，以便边填边验证。
32. 作为用模板添加接口的用户，我希望也能在「高级」里填余额地址，填了就按我填的查，以便 Osuna 认不出查法的中转服务也能显示。

### 套餐 key 的窗口

33. 作为 Kimi Code 用户，我希望看到每个限额窗口和 7 天用量的已用比例与重置时间，以便安排用量。
34. 作为 GLM Coding Plan 用户，我希望看到 5 小时与 7 天窗口，MCP 的月度额度单独放一旁，以便分清哪个窗口卡住了我。
35. 作为 GLM 用户，我希望 key 过期或被删时看到「去某处换 key」，以便知道怎么修。
36. 作为智谱团队套餐用户，我希望填团队组织 ID 和项目 ID 后看到团队的窗口和按窗口算的重置次数，以便知道团队还剩多少。
37. 作为 MiniMax 套餐用户，我希望看到每个桶的区间窗口和周窗口，不限量的显示不限、用完的显示用完，以便知道哪个桶还能用。
38. 作为 OpenCode Go 用户，我希望看到 5 小时、周、月三个窗口，以便安排用量。
39. 作为 Command Code 套餐用户，我希望看到 5 小时、周窗口和 credits，以便安排用量。
40. 作为 Ollama Cloud 用户，我希望看到月度额度窗口（旧套餐是 Session 与 Weekly），以便安排用量。
41. 作为火山方舟 Coding Plan 用户，我希望填 AccessKey ID 和 Secret Access Key 后看到 5 小时、周、月窗口，以便安排用量。
42. 作为腾讯云 Token Plan 企业版用户，我希望填 SecretId 和 SecretKey 后看到月度窗口，以便安排用量。
43. 作为没填云账号密钥的火山或腾讯用户，我希望分区里写明「需要 AccessKey」并有按钮打开编辑窗口，以便知道还差什么。
44. 作为用户，我希望每个窗口写出配速：照现在的速度会不会在重置前用完，以便提前放慢。
45. 作为用户，我希望窗口能在「已用」和「剩余」之间切换，并和套餐用量其他地方用同一个选择，以便看法一致。
46. 作为 OpenCode Zen 用户，我希望看到「这家不给 key 查余额，请去它的控制台看」，以便不以为是 Osuna 坏了。

### 列表行与详情页

47. 作为用户，我希望列表行上有一小段余额，或这家剩得最少的窗口，以便不进详情页也能扫一眼。
48. 作为用户，我希望同时有余额和窗口的接口，行上显示剩得最少的那个窗口，以便先看到最紧的那个限制。
49. 作为用户，我希望认不出查法、也没填地址的接口，行上什么都不多显示，以便列表不被无用信息挤满。
50. 作为用户，我希望复制出的几家接口都属于同一个账户时，各自显示账户余额，以便每家页面都看得到。
51. 作为用户，我希望余额按对方给的币种显示，不换算，以便数字和厂商后台一致。
52. 作为用户，我希望详情页分区写出读数时间，并有刷新按钮，以便知道数字新不新、能马上重读。

### 查询时机与开关

53. 作为用户，我希望接口列表页或详情页开着时，开着的接口自动每分钟最多查一次，以便数字保持新鲜。
54. 作为用户，我希望关着的接口只在我打开它的页面或点刷新时才查，以便不为不用的接口发请求。
55. 作为在意 key 去向的用户，我希望关掉「自动刷新余额与套餐用量」后，只在打开页面和点刷新时查，以便控制 Osuna 何时带着 key 上网。
56. 作为用户，我希望这个开关和「价格表自动更新」互不牵连，以便关掉一个不影响另一个。
57. 作为用户，我希望 Osuna 开机时不查余额，以便启动时不发一堆请求。
58. 作为用户，我希望对方忙、断网时显示上次读数并标明是多久前的，重启 Osuna 后也还在，以便临时故障时仍有参考。
59. 作为用户，我希望改了接口的地址、key 或余额设置后旧读数作废，以便不看到别的 key 的余额。
60. 作为在意 key 去向的用户，我希望 `docs/usage.md` 写明 Osuna 什么时候、带着什么、去哪里查余额，以便我能核对。

### 查不到时

61. 作为用户，我希望查不到时看到原因：地址不对、令牌被拒、这家不给查余额、取不到值、暂时查不到，以便知道怎么修。
62. 作为用户，我希望对方自己回了说明文字时，原话（key 打码）附在原因下面，以便看到对方怎么说。
63. 作为用户，我希望列表行只写「余额查不到」，原因留在详情页，以便行不被长句撑开。
64. 作为用户，我希望 Osuna 认不出这家时，详情分区写「没认出这家的余额查法」，旁边有「填写余额查询地址」，点了打开编辑窗口的那几栏，以便马上去填。

### 凭据与身份

65. 作为用户，我希望账户令牌、云账号密钥和 key 一样只存在 daemon 里，界面上只显示打码，以便它们不发到手机或网页。
66. 作为用户，我希望复制一家接口时，令牌和云账号密钥跟 key 一样可以沿用，以便复制后不用重填。
67. 作为用户，我希望 Osuna 查余额时自报 `Osuna/<版本号>`，不冒充别的软件，以便不因 Osuna 增加封号风险。

### Codex 重置卡

68. 作为 ChatGPT 账号持有额度重置次数的 Codex 用户，我希望在 Codex 的套餐用量卡片上看到「还有 N 次重置」和最早的过期时间，以便不忘了用。
69. 作为这样的用户，我希望悬停或展开时看到每一张的过期时间，以便知道哪张快过期。
70. 作为这样的用户，我希望在卡片上用掉一次重置，用之前先看到「用掉后不能撤回」的确认，以便不误点。
71. 作为这样的用户，我希望 Osuna 用掉的是最早过期的那张，以便不浪费更久的那张。
72. 作为这样的用户，我希望用完后看到结果（几个窗口从头开始 / 没有窗口用过所以留着这张 / 已没有重置 / 这张已经用过），卡片立刻更新，以便知道发生了什么。
73. 作为这样的用户，我希望读不到每张的过期时间时仍看到次数，以便次数不因为一次失败消失。

### 跨部分

74. 作为在手机上用官方 Paseo App 的用户，我希望升级后接口列表和套餐用量照常工作，以便不受影响。
75. 作为中文界面的用户，我希望新界面全是中文，用词和术语表一致，以便看得懂。
76. 作为用户，我希望每个会失败的操作（查询余额、自动识别、刷新、用掉一次重置）都有进行中、成功、失败三种状态，失败信息留在原处直到我重试或关掉，以便知道发生了什么。

## Implementation Decisions

### 查法

1. **照 magpie 全做，只显示**：查法、取值、默认写法、纠错提示、失败文字都照 magpie `7597c132` 的 `balance.go`、`planquota.go`、`sub2api_usage.go`、`ollama_usage.go`、`commandcode_plan.go`、`volcengine_usage.go`、`tencent_usage.go`（出处见 `research/decisions.md`）。余额与窗口不进中转站选路、粘性和冷却。
2. **按地址认**：接口没填余额查询地址时，依次取它各格式地址的主机名（与路径），和内置的厂商表精确比对，认出余额查法。厂商表放在 daemon，不靠模板的 `templateId`（同一主机可以用模板或自定义加）。填了余额查询地址时余额一律走自定义余额，不再按地址认。套餐查法另按地址认（主机名与路径，先后 Chat、Anthropic、Responses），填没填余额查询地址都读，同 magpie 的 `planQuotaSourceOf`（工单 08）。
3. **自定义余额**：GET 或 POST（POST 不带正文）；请求头为 key 的 Bearer 头 + 接口自己的请求头（**Headers**）+ `Accept: application/json`；`{key}` 一类占位照 magpie 替换。取值表达式的解析器照 magpie 的递归下降语法在 daemon 里重写成纯函数。不填表达式时按地址结尾给默认写法（new-api 两个、sub2api 两个、credit grants）。
4. **账户令牌**：令牌发法照 magpie（形如 JWT 的加 `Bearer `，其余原样）。new-api 的「用户 ID」只在查余额时作为 `New-Api-User` 发出；接口请求头里已有 `New-Api-User` 时也认，二者都有时以「用户 ID」为准。
5. **自动识别**：新 RPC 接受未保存的表单值（同测试连接、自动识别格式），依次试 new-api `/api/usage/token`、sub2api `/v1/usage`，取第一个回出可用读数的，返回地址与默认写法供表单填入；都不中时返回各自的失败原因。只在用户按下时发。
6. **云账号密钥**：火山方舟用 HMAC-SHA256 签名（与官方 SDK 相同的签名头与 scope），腾讯云用 TC3-HMAC-SHA256，签名实现为纯函数，用官方文档的示例向量测试。请求发往两家的开放平台地址（不是接口的地址），只带签名与空正文。
7. **智谱团队**：填了团队组织 ID 与项目 ID、个人窗口为空时，按 magpie 请求团队窗口。不读 ZCode 的登录（R1-Q8）。团队按窗口算的重置次数只显示。
8. **不做阶跃 Step Plan 的套餐窗口**（R1-Q7）；阶跃余额照常用 key 查。
9. **magpie 最新版的三处**：DeepSeek 拆「赠送 / 充值」；OpenCode Zen 出说明（不给 key 查余额）；OpenCode Go 也认 `/inference/go`。
10. **配速**：daemon 按 magpie `window_pace.go` 给每个有重置时间与窗口长度的窗口算配速，写进读数窗口的 `pacePct`（另带窗口开始时间 `startsAt`，月窗口从重置时间往前一个自然月）；每次回读数都按当时的时刻重算，留着的、上次的读数不带着读取时的配速，过了重置时间不显示（同 magpie 每次显示时算）。界面在重置时间后写「配速 +12%」，比匀速快时用提醒色，看剩余时符号反过来（工单 08）。

### 查询时机与缓存

11. **由页面驱动**：daemon 不自己定时查。客户端在「第三方接口」列表页或某家的详情页开着时请求读数。
12. **「自动刷新余额与套餐用量」开着**（缺省）：页面开着时客户端每分钟请求一次，daemon 对每家接口的读数缓存 1 分钟；列表页只请求开着的接口；关着的接口只在打开它的详情页或点刷新时请求。
13. **开关关着**：照 magpie「仅手动」，打开列表页 / 详情页各读一次（窗口回到前台也算打开，同 magpie `quotasOpened`；30 秒内重开不再读），点刷新、「查询余额」、「自动识别」照常读；页面开着时不再每分钟重读。（访谈里把 magpie 的「仅手动」说成只在点刷新时查，写 spec 时按 magpie 源码更正，见 `research/decisions.md`。）开关是主机级设置，和「价格表自动更新」互不牵连，也不管 CLI 登录的套餐用量卡片。
14. **并发与超时**：同一家接口的几个请求并行；单次读取 15 秒超时，刷新整页 30 秒；开机不查。
15. **上次读数**：每家接口最近一次成功的读数（只有数字、窗口、读数时间，不含 key 与令牌）存进 daemon 的接口数据目录下的单独文件，重启后还在。暂时性失败（429、5xx、超时、网络错误）时返回上次读数并标明是旧的。接口的地址、key、余额设置改了，或接口被删，它的上次读数作废。写法遵守 `docs/data-model.md`（原子写入，坏了当作没有）。

### 失败原因

16. 每次读数的结果是：有读数；不支持（认不出且没填地址）；这家不给查余额（如 OpenCode Zen、AiHubMix 无上限的 key、硅基流动回 410 或 code 20092 的已下线接口）；需要额外凭据（火山、腾讯没填密钥）；失败。失败分五类：地址不对（404、回的是网页、不是 JSON）、令牌被拒（401、403、new-api 的 `success:false`）、这家不给查余额、取不到值（表达式没取到或不是数字）、暂时查不到（网络、429、5xx、超时）。其余 4xx 归「地址不对」；408 归「暂时查不到」；接口自己的请求头发不出去（头名不合法、值里有换行）照 magpie 归「暂时查不到」，不发请求，原因写明是哪个头。认得出厂商但接口没填 key 时同 magpie 不查，结果是「不支持」，详情分区写「这家没填 key，查不了余额」，不写「没认出这家的余额查法」。另带对方的 HTTP 状态（界面写在原因后，如「（HTTP 401）」）、对方原话（key、令牌打码，截到 200 字；对方回的是网页或别的非 JSON 文字时不引）和 magpie 的具体提示（令牌配错地址及该改用的地址、缺用户 ID、智谱 key 过期、硅基流动接口下线、AiHubMix 要填令牌等）。

### 数据与存储

17. **接口的新字段**（可选，缺省等于没有，不做迁移）：余额设置，含余额查询地址、方法、取值写法、new-api 用户 ID、智谱团队组织 ID 与项目 ID。存在接口自己的存储里。工单 05 起线上与存储都是 `balance: { url, method?, field? }`：方法只存 POST（GET 是缺省），空的取值写法不存，没有地址即没有这一项；工单 09 加 `teamOrgId`、`teamProjectId`，没有地址也可单独存（这时 `balance` 只有它们，`url` 在存储里可选）；保存时整份替换，省略即保留，没有地址也没有团队 ID 即清掉；方法不是 GET、POST 的拒收（`invalid_balance_settings`，同 magpie 命令行）。
18. **新的机密**：账户令牌、火山 AccessKey ID 与 Secret Access Key、腾讯 SecretId 与 SecretKey 存在 key 文件里，和 key 一样只有 daemon 读。客户端只看到有没有和打码；保存请求里可写入、可清空。复制接口时与 key 一样按「沿用哪家」拷贝。工单 06 起：账户令牌在 `keys.json` 的 `balanceTokens`，接口带 `balanceTokenMask`，保存与查询余额的 `balanceToken` 非空换上、空字符串清掉、省略保留；编辑窗口的「显示」经新 RPC `provider.api_endpoint.reveal_secret`（`secret` 为 `balance_token`）读回原文。工单 10 起：云账号密钥在 `keys.json` 的 `accessKeys`（每家 `{ id?, secret? }`），接口带 `accessKeyIdMask`、`secretAccessKeyMask`，保存的 `accessKeyId`、`secretAccessKey` 各自非空换上、空字符串清掉、省略保留（两个都省略的复制取原来那家的）；`reveal_secret` 加 `access_key_id`、`secret_access_key`。编辑窗口照 magpie 只拦「有 ID 没 Secret」。没填齐时读数 `status` 为 `needs_access_key`（不发请求）；被拒的提示 `access_key_refused`。用户 10-22 拍板：照 magpie 补上读数的可选 `planTier`（火山 Agent Plan 档位）、`stoppedPlans`（腾讯停用的套餐与原因）、`unreadTeams`（几个团队时读不到额度的团队），详情分区窗口上方各写一行。
19. **主机级新字段**：「自动刷新余额与套餐用量」开关，缺省开。

### 协议

20. 新 RPC 都在 `provider.api_endpoint.` 下，带点命名加 `.request` / `.response`（`docs/rpc-namespacing.md`）：读余额 `provider.api_endpoint.read_balance`（`endpointIds`，不存在的 id 不回；回 `readings` 与 `error`；工单 01 已做，可选「强制重读」，返回每家的结果、读数时间、是否旧读数）、查询余额 `provider.api_endpoint.check_balance`（未保存的表单值：`endpointId`、`apiKey`、`baseUrls`、`templateId`、`balance` 与请求头等附加项；回一份读数或 `error`，不进 1 分钟缓存与上次读数，可取消）、自动识别余额地址（未保存的表单值）、读写自动刷新开关（或并入现有的主机级接口设置读写）。
21. 余额项的形状：标签（`label`，null 即余额本身，界面写「余额」）、显示文字（`text`，如 `¥12.34`、`25%`）、数值（`value`）、币种或单位（`unit`）、可选的比例（`ratio`，带进度条时）。一家的读数：`endpointId`、`status`（`ok` / `unsupported` / `failed`，线上是字符串）、`items`、`readAt`（unsupported 为 null；OpenCode Zen 不发请求，也为 null）、`failure`（`reason` 五类之一、`detail`、`status`，可选的 `hint` 与 `seeAt`）；窗口沿用套餐用量现有的窗口形状（工单 06 起读数的可选 `windows`，字段名同套餐用量窗口，另带 `used`、`limit`、`unit`；工单 08 加可选的 `startsAt`、`pacePct` 与 `aside`——用完不挡模型、放一旁显示且列表行不取的窗口，如 GLM 的 MCP 月度与 MiniMax 别的桶；窗口 `id` 约定 `Nmin`/`Nh`/`Nd`/`month`/`allowance`/`mcp_month`（工单 09 加 `session`、`credits`），别的桶加「桶名:」前缀，界面按 id 翻译，认不得的写 `label`）。工单 09 加读数的可选 `team`（智谱团队套餐的窗口）与 `resets`（`count`、`until`、`byWindow`、`fiveHour`、`weekly`、`each`）。工单 08 加的提示：`glm_key_refused`（带 `seeAt` 换 key 的页面）、`opencode_go_no_subscription`、`opencode_key_refused`。工单 02 加的可选字段：余额项的 `part`（`granted` 赠送 / `topped_up` 充值，界面按它翻译，认不得的写 `label`）；失败的 `hint`（magpie 具体提示的代码：`opencode_no_balance`、`siliconflow_retired`、`aihubmix_no_limit`，界面翻成一句，认不得的不显示）与 `seeAt`（厂商控制台网址，界面给「打开控制台」按钮）。DeepSeek 多币种合成一项（「 · 」拼接，`value`/`unit` 取排第一的币种），赠送 / 充值各一项排在其后。取值写法的项：`$ ¥ € £` 对应 `unit` USD、CNY、EUR、GBP；带 `%` 的 `unit` 为 `%`、`value` 是百分数、`ratio` 是 0–1；几项里取不到的一项 `text` 为「—」、`value` 为 null，不带原因（magpie 把原因放在悬停里，这里的项形状没有这一栏）。读到了却没有单独余额（Ollama Cloud 没买过 credits）是 `ok` 且 `items` 为空：列表行不显示，详情分区写「这家现在没有单独的余额可显示」。接口与保存请求里的新字段全部可选。
22. 新能力位 `server_info.features.apiEndpointBalance`。客户端在它为真时才显示本任务的接口页新界面；没有时照旧。
23. 旧客户端保存接口时不带新字段：daemon 按「没给就保留原值」处理。

### Codex 重置卡

24. Codex 的套餐用量来源从它已在请求的 `wham/usage` 回复里读重置次数；有次数时另请求一次重置清单取每张的过期时间（4 秒超时，失败只留次数），同一份 Codex 登录。套餐用量报告新增可选的「重置次数」：次数、最早过期时间、每张的过期时间、是否按窗口计（智谱团队用，按窗口分 5 小时与周）。
25. 套餐用量来源的注册接口新增一个可选操作「用掉一次重置」；只有 Codex 的来源实现。它先读清单挑最早过期的那张（读不到就不用），再发用掉的请求，带随机幂等 id；返回结果代码与从头开始的窗口数，之后清掉这个账号的缓存并重读。这是 Osuna 第一次用 CLI 的登录改变账号状态（不改登录本身），写进 `docs/usage.md`。
26. 新 RPC `usage.` 下的「用掉一次重置」（带点命名，按 ADR 0006，`usage` 在代码里指套餐用量）：参数是报告 ID，返回结果代码与说明。新能力位 `server_info.features.planUsageResets`，客户端在它为真时才显示按钮。
27. 不做自动用掉、不做关掉「用 credits」（总任务 Out of Scope 02·B30 与块 12）。

### 身份与对外请求

28. 本任务新增的请求都写 `User-Agent: Osuna/<version>`；用户在接口上设的请求头可以盖过它（同 ADR 0008「What the user sets on an endpoint」）。套餐窗口请求照 magpie 只带认证、`Accept`、`Accept-Language`，不带接口的自定义请求头。
29. 接口设了「不校验证书」时，查余额去它自己的地址也不校验（沿用现有的上游 fetch）。
30. `docs/usage.md`「Outbound requests」写进：读余额与套餐窗口（发给谁、带什么、页面开着时多久一次、开关关着时怎样）、查询余额与自动识别（按下才发）、火山与腾讯的开放平台地址、Codex 重置清单与用掉重置（发往 `chatgpt.com`，带 Codex 的登录）。

### 文档与术语

31. `docs/glossary.md` 已在访谈中写入 **Balance**（余额，分区「余额与套餐用量」）并放宽 **Plan usage**（也可用接口的 key 查）；实现后按最终界面核对，补上「自动刷新余额与套餐用量」「余额查询地址」「查询余额」「重置次数」等界面名词。界面不出现「Quota」。
32. `docs/data-model.md` 写进接口的余额设置、新机密、主机开关、上次读数文件。
33. 借鉴 magpie 的文件（余额、套餐窗口、表达式、签名、配速、重置卡）文件头保留 MIT 声明，`THIRD_PARTY_NOTICES` 覆盖。

## UI and Design

- **方向**：沿用现有的「第三方接口」列表页、详情页、添加 / 编辑窗口，以及套餐用量卡片，不另做视觉风格。窗口与余额的显示复用套餐用量现有的窗口条、余额条组件。遵守 `docs/design.md`、`docs/forms.md`、`docs/hover.md`、`docs/menus.md`、`docs/unistyles.md`、`docs/i18n.md` 与 `.atw/spec/app/frontend/`。用户定过的偏好：开 / 关一律 Switch；模型名不用等宽字体；次要操作不用蓝色链接。
- **用词**以 `docs/glossary.md` 为准：余额、余额与套餐用量、套餐用量、配速、「3d 后重置」（与套餐用量窗口条同一写法）、自动刷新余额与套餐用量、余额查询地址 / 方法 / 取值写法、账户令牌、用户 ID、团队组织 ID / 团队项目 ID、查询余额、自动识别、余额查不到、没认出这家的余额查法、填写余额查询地址、需要 AccessKey、还有 N 次重置、用掉一次重置。不出现「额度」作界面标签（术语表禁用「Quota」）。
- **要有的界面**：
  - 列表行：一小段余额或剩得最少的窗口；查不到时「余额查不到」；认不出时不显示。
  - 列表页：底部主机级设置区加「自动刷新余额与套餐用量」Switch。
  - 详情页「余额与套餐用量」分区：每项余额（多项每项一行，带比例的加进度条，DeepSeek 的赠送 / 充值在总额下）；每个窗口的名称、已用 / 剩余、进度条、「3d 后重置」、配速；智谱团队的重置次数；读数时间与刷新按钮（这次读失败时写「刚刚读取失败」「X 前读取失败」，不写「刚刚读取」）；旧读数标明「X 分钟前」；加载中、失败原因加对方原话、认不出时的提示与「填写余额查询地址」、需要 AccessKey 时的提示（警告色「需要 AccessKey」加弱色说明）与按钮、这家不给查余额的说明。
  - 编辑窗口「高级」区：余额查询地址、方法、取值写法（带默认写法占位）、账户令牌（打码、可显示）、用户 ID、团队组织 ID / 项目 ID（智谱地址时）、AccessKey 两栏（火山、腾讯地址时）、「查询余额」与结果（余额查询地址一变就清掉，含自动识别填入新地址时）、「自动识别」与结果（用户再改地址就清掉）、令牌配错地址时的「改用 …」按钮。
  - Codex 套餐用量卡片：「还有 N 次重置 · 最早 {时间} 过期」、每张过期时间（悬停或展开）、「用掉一次重置」按钮与确认框、结果说明。
- **颜色**：余额查不到在列表行与详情分区都用 `statusWarning`（同一个状态一个色，`docs/design.md`），金额用中等字重。
- **状态**：查询余额、自动识别、刷新、用掉一次重置都有进行中、成功、失败三种状态，失败信息留在原处，直到用户重试或关掉（`docs/testing.md`「Fallible user actions」）。分区有加载状态。
- **视口**：桌面端（Electron 与浏览器，宽 1280）和窄窗口（compact，宽 390）。原生端免实机验收。
- **界面验收**（看截图能判断）：
  - 1280 与 390 下，列表页（含行上余额、窗口、「余额查不到」、开关）、详情页分区（有读数、旧读数、失败、认不出、需要 AccessKey 各一）、编辑窗口高级区（含查询结果与自动识别结果）、Codex 重置卡与确认框各一张，浅色与深色各一套。
  - 中文界面新文字全是中文，用词与术语表一致，没有「额度」作标签；英文界面没有露出翻译键名。
  - 开关是 Switch；模型名不是等宽字体；刷新、填写余额查询地址等次要操作不是蓝色链接。
  - 390 下列表行的余额小段不截断接口主名称；详情分区的窗口条、重置时间、配速不重叠。
  - 余额显示对方的币种符号；带比例的项有进度条。

## Testing Decisions

- **好测试的标准**：只测外部看得到的行为，即上游收到什么请求（地址、方法、请求头、正文）、RPC 返回什么、界面显示什么；不测内部结构。确定性要求见 `docs/testing.md`。
- **接缝一（主）：daemon 端到端测试**。进程内启动真实 daemon，本机起假余额服务，用客户端调 RPC。厂商表的真实地址在测试里换成本机假服务：沿用测试 daemon 现有的注入方式（同厂商状态页的地址注入），缺省指到本机没人听的端口，绝不连真实厂商。覆盖：
  - 每家已知厂商：请求的地址、认证头、`User-Agent: Osuna/<version>`，取到的值、币种、多币种排序、DeepSeek 拆分、硅基流动下线、Ollama 无购买余额、AiHubMix 两种情况。
  - new-api、sub2api 的 key 级与账户级：令牌发法、用户 ID 只在查余额时发、请求头里的 `New-Api-User` 也认、`success:false`、令牌配错地址、账户级没令牌改查 key 级、sub2api 窗口。
  - 自定义余额：GET / POST、占位替换、接口请求头带上、默认写法、credit grants。
  - 套餐窗口：GLM（含团队与重置次数、key 过期提示）、Kimi Code、MiniMax、OpenCode Go（含 `/inference/go`）、Command Code、Ollama Cloud、OpenCode Zen 说明；火山与腾讯的签名请求（假开放平台验证签名头）；没填密钥时「需要 AccessKey」。
  - 配速值。
  - 缓存 1 分钟、强制重读、开关关着时的读法、改了设置后旧读数作废、暂时失败回上次读数、重启后上次读数还在（用可控时钟，不真等）。
  - 五类失败原因与对方原话打码。
  - 查询余额与自动识别用未保存的表单值；自动识别的先后与都不中。
  - 机密只在 daemon：列表与读余额的 RPC 回复里没有令牌和密钥原文；复制时沿用。
  - 旧客户端保存不清掉新字段；没有能力位时不影响旧视图。
  - 先例：daemon 端到端目录下接口的 vendor-status、test-connection、detect、models 几组测试与它们的假上游写法。
- **接缝二：app 浏览器测试**。Playwright 加真实 daemon 加本机假中转服务（现有接口设置页测试共用的夹具，按需扩展出假余额回复）。覆盖列表行、详情分区、编辑窗口高级区、自动刷新开关，每个会失败的操作测成功和失败两种。测试 daemon 用假 CLI 与临时配置目录，不碰真实 `~/.claude`、`~/.codex`，不真升级 CLI。
- **Codex 重置卡**：Codex 套餐用量来源已有的测试（注入假 fetch、临时 `CODEX_HOME` 里的假登录）加用例：读次数、读清单与过期时间、清单失败只留次数、用掉一次挑最早过期的、幂等 id、四种结果代码、清单读不到就不用、登录文件一字不改。RPC 与按钮走浏览器测试，daemon 端用假的套餐用量来源。
- **纯逻辑**：取值表达式、两种签名（用官方文档示例向量）、配速、主机名到厂商的匹配加进 daemon 同目录的单元测试，不另建套件、不加 npm 脚本或 CI 任务。
- **协议**：新字段与新 RPC 的解析测试加进现有的接口协议与套餐用量协议测试；用旧形状的消息验证兼容。
