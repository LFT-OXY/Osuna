# 03 — 什么时候查：自动刷新开关与缓存

**What to build:** 列表页底部的主机级设置区多一个 Switch「自动刷新余额与套餐用量」，缺省开。开着时，列表页或详情页开着就每分钟最多查一次；列表页只查开着的接口，关着的接口只在打开它的详情页或点刷新时查。关掉后照 magpie「仅手动」：打开列表页 / 详情页各查一次（30 秒内重开不再查），点刷新照常查，页面开着不再每分钟重查。开机不查。

**Blocked by:** 01
**Status:** ready-for-agent
**Impl:** done

- [x] daemon 对每家接口的读数缓存 1 分钟，强制重读（刷新按钮）跳过缓存；保存接口后清掉它的缓存。
- [x] 开关是主机级新字段（可选，缺省开），读写走主机级接口设置或新 RPC；与「价格表自动更新」互不牵连；不管 CLI 登录的套餐用量卡片。
- [x] 开关关着时 daemon 拒绝不是用户要求的读取（同 magpie 的「Asked」标记：打开页面、刷新、查询余额、自动识别算用户要求），客户端每分钟的定时读取停掉。
- [x] 同一家的几个请求并行；单次 15 秒超时，刷新整页 30 秒。daemon 启动时不发任何查余额请求。
- [x] 端到端测试用可控时钟：缓存 1 分钟、强制重读、开关两种状态下的读法、关着的接口不随列表读、开机不读。浏览器测试：开关切换后页面的读取次数。
- [x] `docs/usage.md` 读余额一节写明两种开关状态下的时机与超时。`docs/glossary.md` 收「自动刷新余额与套餐用量」。
- [x] 9 种语言的新文字齐全。
- [x] UI：列表页底部 / 开与关 / 1280 与 390 — 是 Switch，不是复选框。
