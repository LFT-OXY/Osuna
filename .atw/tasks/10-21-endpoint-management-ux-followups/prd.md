# 接口管理好用性验收遗留

来源：10-16-endpoint-management-ux（子任务 3，已归档于 `.atw/tasks/archive/2026-10/`）2026-10-21 验收时留下的问题。用户决定：先做「合并前必做」，把分支合进 main；其余小问题合并后在新分支上做，仍属本任务。

## Problem Statement

接口管理好用性已经验收，但它的分支还不能合进 main：

- 分支是在 main 修好 CI 机器版本（#24）之前分出来的，之后 main 又多了 96 个提交，两边有冲突。
- 在分支上手动跑的 CI 里，浏览器测试一条都没跑（Ubuntu 26 装不上 Playwright），另有两处是这次改动带来的真失败：一条浏览器测试用了只有桌面端才有的桥，违反了「浏览器测试与桌面测试各归各的目录」的规矩；一条「数据库没权限打开」的测试在 Windows 上失败。
- 验收时还有 5 条验收项没勾上、几处小瑕疵：窄窗口里显示出来的 key 被截断、删除「已禁用的模型」条目失败时没有浏览器测试、几张截图没拍到要看的东西、几个用户故事只有单元测试、报错里露出原样请求地址、英文单复数不对等。

## Solution

分两段：

1. **合并前**：把 main 合进分支并解决冲突；把用到桌面端桥的「导入链接」用例挪进桌面端测试；让 Windows 上不适用的权限用例在 Windows 上跳过；在分支上重跑 CI，浏览器测试与 app 测试真正跑过且全过（已知常红项除外）；开合并请求，用 merge commit 合进 main。
2. **合并后**（从更新后的 main 开新分支）：补上 5 条没勾的验收项与 7 处小瑕疵，用户看到的界面在窄窗口里完整可读、报错不露请求地址、英文单复数正确，测试与截图证据补齐。

## User Stories

合并前：

1. 作为用户，我想让接口管理好用性合进 main，这样正式版和以后的新功能都建立在它之上。
2. 作为用户，我想在合并前看到这条分支的 CI 全过（浏览器测试真的跑过），这样合进 main 不会把 main 的 CI 弄红。
3. 作为用户，我想让合并保留分支上的每个提交（merge commit），这样以后能按工单查到每处改动。
4. 作为维护者，我想让「导入链接」的用例放在桌面端测试里，因为只有桌面端收导入链接，而浏览器测试不许装桌面端的桥。
5. 作为维护者，我想让挪过去的「导入链接」用例覆盖的行为一条不少：先问再加、名称和 key 可改、取消不加、同 id 提示替换、不安全的链接拒收、主机不支持时提示升级。
6. 作为 Windows 上的开发者，我想让「数据库没权限打开」这条用例在 Windows 上跳过，因为 Windows 不支持用文件权限造出「打不开」，其余平台照测。
7. 作为维护者，我想让合并 main 时 main 那边已有的修复（CI 机器固定 24.04、分支起点就会失败的几条测试已修）都带进来，合并后复查这几条不再失败。
8. 作为用户，我想在合并完成后由我决定删不删这个分支和工作目录（自动归档已关），删之前确认没有没推送的东西。

合并后：

9. 作为用户，我想在窄窗口（390）点「显示」后能读到完整的 key，长 key 也不被截断，中英文都一样。
10. 作为用户，我想在添加接口的模板列表里看到三组（厂商、中转服务、本机），并有截图证明三组都在。
11. 作为维护者，我想让「已禁用的模型」删除条目失败时的行为（原因就地显示、条目留着、重试成功）有浏览器测试。
12. 作为用户，我想有截图证明编辑窗口里请求头的名 / 值输入行可用。
13. 作为用户，我想让冷却设置的位置（编辑窗口的「高级」区）被正式认可并写进规范，不再与原工单字面冲突。
14. 作为用户，我想在模板列表和接口行上看到品牌图标，并有浏览器测试断言图标确实出现（用户故事 9）。
15. 作为用户，我想在模型行上看到上下文大小小标，并有浏览器测试断言（用户故事 70）。
16. 作为用户，我想让厂商状态页只在接口页或用量页开着时才去查，并有浏览器测试证明页面关着时不查（用户故事 89）。
17. 作为用户，我想在拉模型清单失败时只看到原因，不看到原样的「GET http://… HTTP 401」请求地址。
18. 作为英文界面用户，我想看到「Search 1 model」而不是「Search 1 models」。
19. 作为用户，我想在窄窗口的用量页里看到每日用量表最后一列完整的表头。
20. 作为看截图的人，我想让「第三方接口」页的截图里左侧栏高亮在「第三方接口」，而不是「概览」。
21. 作为看截图的人，我想让导入窗口截图里来源路径像真实的用户目录，而不是测试临时目录。
22. 作为读文档的人，我想让术语表里接口「导入」与「把提供方会话转成 Agent 会话的 Import」不再互相矛盾。
23. 作为读文档的人，我想在术语表里查到「忘掉拉到的清单」「内置图标」「逐个模型」。

## Implementation Decisions

合并前：

- 合并方向：把 origin/main 合进当前分支（merge，不 rebase），冲突按「两边的修改都保留」解；与上游的规矩一致（合完跑 i18n 守卫、dist 旧了重建）。
- 「导入链接」用例从 app 的浏览器测试整组挪到桌面端的 Playwright 测试（renderer 项目），沿用桌面端已有的桥注入方式与 app 的 e2e 支持代码；浏览器测试文件里不再出现桌面端的桥。用例的断言内容不变。
- Windows 上的权限用例按仓库已有写法在 win32 上跳过，不改被测代码。
- CI 在分支上手动触发（workflow_dispatch）复核；之后开合并请求到 main（`--repo LFT-OXY/Osuna`），合并方式 merge commit。已知常红的 Nix 两项与仓库记下的偶发项按惯例 rerun，不算失败。
- 合并后删本地 / 远端分支与 worktree 由用户确认后再做；删远端分支会被 Safety Net 拦，由用户手动执行。

合并后：

- 显示出来的 key 在窄窗口完整可读：输入框在显示状态下允许换行或改为可完整查看的只读展示，隐藏状态不变。
- 冷却设置位置维持在编辑窗口的「高级」区，规范与术语里写明；不挪到详情页。
- 拉模型清单失败的原因去掉「方法 + 地址」前缀，与测试模型结果的去前缀做法一致；状态码另行显示或并入原因。
- 英文「Search N models」走 i18n 单复数。
- 用量页每日用量表在窄窗口下最后一列表头完整显示（加宽、换行或缩写，择一，以截图验收）。
- 术语表：改写 Import 两条的互斥说明；补「Forget fetched list」「Built-in icons」「Each model」三条。
- 截图重拍：模板列表含三组（滚到底各一张）、编辑窗口请求头输入行、左侧栏高亮正确、导入窗口路径像真实目录。

## UI and Design

- 遵守 `.atw/spec/app/frontend/` 的组件与样式规范，以及 `docs/design.md`；不引入新组件。
- 视口：桌面 1280、窄窗口 390；英文浅色、英文深色、中文浅色三版。
- UI 验收标准：
  - 编辑窗口 / key 已显示 / 390：一个 100 字符以上的 key 在中英文下都能完整读到，「显示 / 隐藏」仍是描边按钮。
  - 模板列表 / 默认 / 1280 与 390：截图中能看到「厂商」「中转服务」「本机」三组标题（可分两张：顶部与滚到底部）。
  - 编辑窗口 / 请求头 / 1280 与 390：名 / 值输入行、「+ 添加请求头」与保留字段提示同屏可见。
  - 接口详情页 / 拉模型失败 / 390：错误文字不含 `http://` 或 `https://`。
  - 用量页 / 每日用量表 / 390：最后一列表头完整可读。
  - 第三方接口页截图：左侧栏高亮项是「第三方接口」。

## Testing Decisions

- 好测试只测外部行为（用户在界面上看到的、daemon 回的、上游收到的），不测内部实现。
- 合并前的检验点就是 CI 本身：`scripts/ci-workflow.test.mjs` 的目录归属检查、桌面端 renderer 项目跑挪过去的「导入链接」用例、server 测试在 Windows 上全过。本机只跑改到的单个文件。
- 合并后沿用已有检验点：app 浏览器测试 `settings-api-endpoints`（已禁用的模型、图标、上下文小标、厂商状态页只在页面开着时查）、用量页浏览器测试、i18n 资源测试、daemon 端到端测试（拉模型清单失败的原因）。
- 先例：浏览器测试里「a failed … stays in place」的失败分支写法；桌面端 `packages/desktop/e2e/*.spec.ts` 注入桌面端桥的写法；server 测试里 `skipIf(process.platform === "win32")` 的写法。
- 测试不读写真实 `~/.claude`、`~/.codex`、钥匙串，不跑真的 CLI，不点 CLI 升级。

## Out of Scope

- 用户故事 101（官方 Paseo 手机 App 的真实旧客户端测试）：仍以旧形状保存的端到端用例为证，不搭真实旧客户端。
- 用户故事 102（中文用词）的检验点保持为 i18n 资源测试，不另写浏览器测试。
- 深色模式警示黄偏灰（全应用共用的颜色）。
- 原任务 31 号的可选项「从 CC Switch 等软件真实导入一次」。
- 不改 magpie 对齐过的行为（Codex 用 API key 接时接口名显示方式不生效等）。
