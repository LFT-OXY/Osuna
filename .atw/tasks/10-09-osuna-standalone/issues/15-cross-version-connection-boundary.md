# 15 — 跨版本连接的边界

**What to build:** 用户用 1.0.0 的桌面端或网页端连到一台还停在 0.14.x 的主机时，看到明确的"请把这台主机升级到 1.0.0"，而不是空白、卡住或莫名报错；其他已升级的主机照常可用。1.0.0 与 0.14.x 不做互通：全量改名连同线上的消息类型名与字段一起改了，两个方向都不再兼容（决策：干净切断，不加双向别名，2026-10-09 用户确认）。

**Blocked by:** None — can start immediately
**Status:** ready-for-agent
**Impl:** done

- [x] 1.0.0 客户端连到 0.14.x 主机：握手后依据 daemon 上报的版本判定为"主机版本过旧"，该主机进入一个明确的状态并提示升级到 1.0.0；不发起任何后续请求，不出现解析错误弹窗、空白页或无限重连
- [x] 判定只在一处完成，门槛是 1.0.0；不为旧主机保留任何功能回退路径或消息别名。握手本身要能解析 0.14.x 的 `server_info`（`COMPAT(hubExecutePermission)` 为此保留，到期日不变）
- [x] 同一个客户端里其他 1.0.0 主机不受影响；旧主机升级并重连后自动恢复正常，无需删除重加
- [x] 0.14.x 客户端连到 1.0.0 daemon：daemon 不崩溃、不写坏数据，对认不出的消息按现有方式拒绝并留日志；这一方向不做界面（旧客户端改不了）
- [x] 测试：一条线兼容测试用 0.14.2 的 `server_info` 负载走到"主机版本过旧"状态；一条 daemon 侧测试喂入 0.14.x 的旧消息类型名，断言拒绝且会话仍可用
- [x] `docs/protocol-compatibility.md` 记下 1.0.0 是协议下限及其原因；1.0.0 发布说明草稿的升级段写明主机与客户端需要一起升级
- [x] UI: 主机连接界面 / 主机版本过旧 / 桌面 1280 — 截图里该主机显示升级提示与主机名，其余主机正常
