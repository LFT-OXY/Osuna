# 05 — 发布节奏：1.0.0 一次切换，还是分阶段

**Type:** interview
**Blocked by:** None
**Status:** resolved

## Question

改名、数据迁移、远程基建、Hub 移除、官网、安卓包是六块独立可交付的工作。两种节奏：

A. **单次切换**：1.0.0 一个版本同时包含全量改名 + 自动迁移 + 中继/网页端切到自己的域名 + Hub 移除；官网与 APK 可以晚几天但在 1.0.0 发布说明里有链接。好处：用户只经历一次"东西变了"，迁移代码只跑一次；坏处：一个大 PR、验收面广、出问题回滚整版。

B. **分阶段**：0.15 先做远程基建切换 + Hub 移除（不改名），0.16 做改名 + 迁移，1.0.0 收尾官网与 APK。好处：每版风险小；坏处：用户经历多次变化，中间版本还叫 paseo 的内部名，迁移代码要兼容两段。

推荐 A（迁移只做一次、与 1.0.0 的"独立起点"语义一致），但要确认用户接受"1.0.0 是一个大版本、发布前要完整走一遍 QA 矩阵"。另外确认：GitHub 脱离 fork（03）与 Cloudflare 基建（04）在 1.0.0 发布之前完成，这两件不随版本走。

## Answer

- **A，一次切换到 1.0.0**（用户 2026-10-09 访谈 Q11 确认）：全量改名 + 自动迁移 + 中继/网页端切到 `*.chinhae.cc` + Hub 移除同一个版本发布。
- 官网与安卓 APK 可晚几天，但 1.0.0 发布说明里必须带它们的链接（或"即将上线"的明确说明）。
- GitHub 脱离 fork（03）与 Cloudflare 基建（04）不随版本走，必须在 1.0.0 发布前完成；03 不影响代码，04 决定配对 URL 与中继地址的默认值，spec 要把它列为发布前置条件。
- 代价已接受：一个大 PR、发布前完整走 `docs/qa.md` 的 QA 矩阵；回滚即整版回退到 0.14.x（旧数据目录仍在，迁移永不删旧数据，所以回退可行）。
